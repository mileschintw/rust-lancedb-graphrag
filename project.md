# Project settings

What relay needs to know about this project. The coordinator and every worker read this file.

- **Repo:** mileschintw/rust-lancedb-graphrag, default branch `main`.
- **Language:** talk to the user, and write reports, in Traditional Chinese (繁體中文). Repo files, issues, PR bodies, briefs and the plan are written in English.
- **Checks before done:** the fast tier from `docs/testing.md` (#44), for the modules the lane touches (an `eval/`-only lane may skip cargo and Go): `cargo test --manifest-path engine/Cargo.toml --locked && sh scripts/engine-test-targets.sh`; `(cd gateway && go test -count=1 -short ./...) && sh scripts/gateway-test-targets.sh` (`-count=1` is required: the test cache hides config.toml changes); `uv run --project eval pytest -n auto --dist loadfile`. The slow and integration tiers (`docs/testing.md`) run when a brief names them, or when the lane changes what they cover.
- **Test bar:** the checks above pass and each new behaviour has a test. Workers build each ticket test-first by calling the `tdd` skill (one red-green slice at a time). CI (`.github/workflows/ci.yml`, path-filtered per module, fast tier only) runs on each PR to `main`; the coordinator merges once the `ci` check passes.
- **Off limits for workers:** `.planning/` and `.discussion/` (read-only v1.0 build record); `eval/runs/` (v1.0 runs of record, read-only); `eval/corpora/multihop_rag/{heldout_split.json,questions.heldout.jsonl,diag_selection.json}` (pre-registration and split hash are bound to them); `data/lancedb-eval` (gitignored live store, not cheaply rebuildable; v1.1 S1 builds a second store, never modify the original); existing decisions D-234–D-246 in `experiments/v1.1/PLAN.md` (may add, never edit); `config/` defaults unless the brief names them. Work that touches the live stack or eval drive runs only in the main checkout, one at a time, because worktrees lack the live store. Workers write only their own `status/`, `reports/` and `pr-bodies/` files in the records folder.
- **Ask the user first, with the exact scope:** creating accounts or VMs, installing into the user's real profile, large downloads, signing in to outside sites, spending money; paid LLM/rerank/embedding calls and eval runs (print a cost estimate first; D-258 amends D-246: no mid-run cap); any held-out read (D-237 allows two for all of v1.1: S0 and Confirm); rebuilding or re-embedding any store; push, merge, opening a PR.
- **Unattended, never:** none beyond relay's default list.
- **Release:** none.
- **Deny list:** none. Records on `coord` must never contain API keys or environment variable values (the OpenRouter key); batch IDs and cost figures are fine.
