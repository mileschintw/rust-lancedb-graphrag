## Summary

`_delta_dimension`, the helper behind every secondary paired delta in `report.json`, wrote the reference arm's mean as `mean_hybrid` and, for count deltas, its count as `count_hybrid`. It did this whatever the run's reference arm was. On a store-prefixed run (reference `small/hybrid`), each delta's `detail` therefore named the reference `hybrid`, and judged deltas carried those keys beside the neutral keys #36 added.

The helper now takes the reference arm and applies the same rule as `_judged_dimensions` (#36, PR #41). A `hybrid` reference keeps the v1.0 names, so v1.0 `report.json` bytes do not move. Any other reference gets `*_reference` names. Both callers (the four-arm secondary deltas and the judged deltas) pass the pre-registration's reference arm. The docstring no longer says "against `hybrid`".

```diff
 score._delta_dimension, paired delta detail
   reference == "hybrid" (v1.0 pre-registrations): unchanged
     mean_hybrid, count_hybrid
   any other reference (e.g. small/hybrid):
-    mean_hybrid, count_hybrid
+    mean_reference, count_reference
```

Readers left unchanged:
- `comparison.py` (~820) reads `detail["mean_hybrid"]`. `compare` refuses any run that is not on the 06.3.5 token or that is store-prefixed (#40), so it only ever sees a `hybrid` reference.
- `dev_reads.py` (~442, 473) builds its own `mean_hybrid` from `p4.paired_delta` and does not read `_delta_dimension` output.
- `p4.py` names `mean_hybrid` only in a docstring.
- Nothing in `docs/`, the README or the glossary names either key.
