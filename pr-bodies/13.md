## Summary

Adds `baselines/llamaindex/`, a separate uv project for the MultiHop-RAG paper's LlamaIndex configuration (D-248). It indexes the 346 documents Lancet seeds, retrieves and reranks per question, and writes a context export the harness validator accepts, plus a pipeline-config echo. It never calls a reader; `lancet-eval run-external` (#14) will drive the generate step over its export.

- `SentenceSplitter(256, 25)`, in-memory `VectorStoreIndex`, dense top 20, a custom `VoyageRerankPostprocessor` that keeps 8.
- `llama-index-core==0.14.25`, pinned. The harness (`../../eval`) is an editable path dependency: rows are checked with `lancet_eval.context_export.validate_row` / `read_export`, and metadata goes through `lancet_eval.evidence_meta.normalise`. No copy of the contract.
- Embeddings (`voyageai/voyage-4-large`) and rerank (`voyageai/rerank-2.5-lite`) go through OpenRouter with the request bodies Lancet's engine clients send. No `input_type`, because Lancet sends none.
- Title, source and published_at are embedded with the text, as LlamaIndex does by default. In the export they appear only as `document_metadata`, never in the node text.
- Document IDs are Lancet's, looked up in `document_map.json`. An unmapped article fails the run.
- A question with anything other than exactly 8 reranked entries fails the run. Nothing is written unless every row passes `read_export`.
- `pipeline_config.json` keeps a nested shape and also carries the flat keys lane 12's external clause compares: `framework`, `framework_version`, `chunk_size`, `chunk_overlap`, `dense_top_k`, `rerank_model`, `keep`, `index_fingerprint`. Chunk IDs are `<document ID>#<n>`, so the fingerprint is stable across rebuilds.
- The README records the `input_type` finding (fairness rule 7). OpenRouter's embeddings docs do not mention `input_type`, and neither arm sends it, so both get the same embedding. It also gives the command for the live check, which was not run.
