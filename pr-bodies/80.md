## Summary

`replay-init` now carries the S1 arm onto the S2 corpus, so reader arms can be scored. The replay clauses now depend on the reader's target, so a native Anthropic reader (Sonnet 5.5's fallback, D-255/D-260) can pass them truthfully. A new `prompt` clause checks that each reader saw the prompt deepseek saw.

```text
eval/src/lancet_eval/replay.py        # replay_init(corpus=...): rewrite corpus, record S1 corpus, dev-only (D-237)

```

- **`replay-init --corpus <S2 corpus>` (#80).** The CLI form is now `lancet-eval replay-init --source-run <S1 run> --arms <arm> --run <S2 run> --corpus <S2 corpus>`. The S2 header's `corpus`, every carried record's `corpus` and every carried export row's `corpus` become the S2 corpus. Nothing else changes, but records and rows are re-serialized, so they are no longer byte-identical to the S1 lines. The journal resume key (`corpus:question_id:arm`) then uses the S2 corpus, so #53 can journal reader records under it.
- **`replay_source.corpus`.** This new header key holds the S1 run's corpus, next to `run`, `arms` and `row_sha256`.
- **Row hash.** `row_sha256` covers each row *as carried*, under the S2 corpus. The S1 row is that row with `corpus` set back to `replay_source.corpus`. The reader rows #53 writes are copies of the S2 rows, so the `row_hash` clause compares like with like.
- **D-237 guard.** `replay-init` refuses a source run whose corpus's `[split] role` is not `dev`, so an S0 held-out run cannot be replayed to the readers. The S2 corpus must also be `dev`. A source or S2 corpus that does not load is refused too, and so is an S2 corpus that does not list a carried arm.
- **Target-specific clauses (#82 item 1, Q4).** `is_byok`, `provider` and `reasoning_tokens` now run in `replay_run_failures`, where the reader's declaration is known. They are no longer per-record checks.
  - OpenRouter target: unchanged. `is_byok` must be `true` and `provider` must be `"Anthropic"`.
  - Native Anthropic target: `is_byok` must be `null`, because that response reports none. `provider` must be `"api.anthropic.com"`, the endpoint host (`provenance.REPLAY_PROVIDERS`). A reader whose thinking is not `on` must record `content_block_types`, and none of them may be `thinking` or `redacted_thinking`. `reasoning_tokens` must still be 0, since native usage has no separate count.
  - A thinking-on reader (Opus 5.5 at effort low) stays exempt.
- **`prompt` clause (#82 item 2).** `parity.user_message(replay.pack_body)` must equal the carried base row's `assembled_prompt` byte for byte. The clause fails when the base row is missing or has no `assembled_prompt`. In refusals it is listed after `row_hash`.

### For #53 (batch fetch): replay record fields

`ReplayProvenance` (`journal.py`):

- `is_byok: bool | None`. OpenRouter: the response's `usage.is_byok`. Native: `null`.
- `provider: str`. OpenRouter: the response's `provider`. Native: `"api.anthropic.com"`.
- `reasoning_tokens: int`. OpenRouter: the response's reasoning token count. Native: `0`.
- **new** `content_block_types: list[str] | None` (default `null`). Native: the `type` of each block of the result message's `content`, in order (for example `["text"]`). OpenRouter: `null`.

The other fields are unchanged: `export_row_sha256`, `pack_body`, `sent_body_sha256`, `rewritten_fields`, `model`, `batch_id`.
