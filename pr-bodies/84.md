## Summary

`lancet-eval` decoded psql, git and binary output with the locale code page whenever a `subprocess.run(..., text=True)` call had no `encoding=`. On the Windows GPU box that is cp950, so a UTF-8 quote in a psql checkpoint snapshot (`0xe2`) broke `run_psql`, and every `run` ended with "context export failed (D-249)". Until now each command needed `PYTHONUTF8=1`.

This passes `encoding="utf-8"` to every remaining text-mode read in `eval/src`, as `parity.py` and `gitcheck.py` already do:

- `seed.run_psql` and the Atlas schema apply in `seed.reset_eval_schema`
- `config.get_commit_sha`
- `identity.list_lancedb_document_ids`
- `oi02._git`

`gitcheck._run` already passed `encoding="utf-8"` on `main`, so it is unchanged and covered by the new test as a guard.

## Tests

New `eval/tests/test_subprocess_encoding.py`. It forces subprocess's default text encoding to cp950 (patching `subprocess._text_encoding`, so it also fails under `PYTHONUTF8=1`), replaces each command with a child process that writes UTF-8 bytes, and checks each caller gets the text back intact.

- Without the fix: 4 failed, 1 passed (the `gitcheck` guard).
- With the fix: 5 passed.
- Eval fast tier: `uv run --project eval pytest -n auto --dist loadfile` passes.
- `ruff check` on the touched files: no new errors (`oi02.py` keeps its 109 errors from `main`).
