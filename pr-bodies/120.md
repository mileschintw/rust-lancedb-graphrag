## Summary

S1's merged chunks run longer than the 512-character `excerpt_max_chars` cap. Nearly every retrieved S1 excerpt
arrived as `is_truncated`, which failed step 1.5 (`corpus_generation`). `fact_matches_excerpt` reads a truncated
excerpt as UNDECIDABLE, so evidence Hits@4 for the merged arms would have been mostly undecidable. This PR raises the
cap for the S1 overlay only (D-273).

**This changes measurement only.** Before touching anything, I traced `citation_excerpt_max_chars` through the
engine. It cuts two things: the `RetrievalSnapshot.retrieved_chunks` excerpts (`RetrieveNode`) and the resolved
citations (`GenerateAnswerNode`, after generation). `AssemblePromptNode` builds the prompt from the full evidence block
text and never receives the cap. So "change chunking and nothing else" still holds.

**Value.** I measured the built store read-only (`data/lancedb-eval-s1`, `nodes.content`, 3,953 chunks, 2026-10-31).
The longest S1 chunk is 1,489 Unicode characters (p50 990, p90 1,201, p99 1,339), and 3,708 chunks exceed 512. The
overlay now sets 2,048, which is 37% above the longest chunk.
