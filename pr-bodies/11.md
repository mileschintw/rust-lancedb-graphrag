## Summary

A generate-only engine bin, `generate_from_context`, runs the engine's own prompt and answer code over context-export rows (D-247). It also adds a harness check that the bin rebuilds the prompts Lancet checkpointed, byte for byte.

```text
generate_from_context <pack|generate> --input <context_export.jsonl> [--levers a,b]
  per row
    rebuild the evidence blocks  EvidenceBlock::from_candidate + attach_evidence_meta
    rebuild the graph facts      GraphFact::new, refused unless the rebuilt JSON equals the row's
    AssemblePromptNode           service settings from config.toml / LANCET_*
    GenerateAnswerNode           through a recording Generator
      pack      capture the GenerationRequest -> openrouter::chat_request_body -> "body"
      generate  OpenRouterGenerator -> rendered answer (Answer: line), final_answer,
                citations, structured_citations, notices, answer_basis, usage
    refused row -> {"outcome": "error", "error_type", "error"}; the run goes on
```

```diff
 OpenRouterGenerator::execute_one_call
-  pack messages, build schema + payload inline
-  post .json(&payload)
+  body = chat_request_body(&config, &request)   # new pub fn, the one body builder
+  post .header(content-type: application/json).body(body)
```

`lancet-eval check-prompt-parity --run <dir>` reads `context_export.jsonl` and re-packs every Lancet row (a row that carries `assembled_prompt`). Rows are grouped by the levers their journal record echoes (`snapshot.levers`). The check fails closed and names the question and arm for:

- a row with no success record;
- a record with no lever echo;
- a row the bin cannot pack;
- any character where the packed user message differs from `assembled_prompt`.

External rows are counted and are not checked.

Design points:

- An export row has no `chunk_index`. The bin reads it from an engine chunk ID (`<document_id>:<n>`, as `ingest.rs` mints it) and uses `0` for any other ID. This only affects the provenance line of external rows.
- A row's `suspicious` flag can raise a block's flag, never lower it.
- `--levers ""` means no lever. Leaving the flag out applies the configured defaults, as for a request that names none.
- Parity packs under the current engine configuration. A config change since the run therefore also fails parity, and the message says so.

## Merge Danger

**Door:** two-way

The live adapter now posts pre-serialized bytes with an explicit `Content-Type: application/json` instead of `.json(&payload)`. The bytes are the same `serde_json::to_vec` of the same payload. Everything else is new code.

**Blast Radius:** reader-request

A regression would change what the engine sends to OpenRouter for every query. The existing generation tests and the new byte-equality test both cover that path.
