## What

`RawEventSink` now names an arm's raw-event directory with `arms.arm_slug(label)` for every label `arm_slug` accepts. That includes the D-251 store-prefixed S1 labels, so `small/hybrid+rerank+metadata` writes to `raw_events/small_hybrid_rerank_metadata/`. Before, it wrote into a nested `small/hybrid+rerank+metadata/` folder.

Some labels keep their current directory names:

- Legacy aliases such as `graph-on`. `arm_slug` would canonicalise these, so they skip it.
- Labels `arm_slug` refuses (an unknown label, or an unknown prefix or base).

Unprefixed registry arms still get the same slug as before. The external arm `llamaindex` slugs to its own name, so its directory doesn't change either.

## Why

Every other reader of the raw-event layout uses `arm_slug(label)` as the directory name. The old rule slugged only bare `ARM_REGISTRY` rows, so S1 arms would have landed somewhere those readers never look.

## How

- `eval/src/lancet_eval/raw_events.py`: a new `_arm_dir(graph_arm)` helper.
  - It returns the label verbatim for a legacy alias.
  - Otherwise it returns `arm_slug(graph_arm)`, or the label verbatim if that raises `ValueError`.
  - It replaces the inline `graph_arm in ARM_REGISTRY` check.
- `eval/tests/test_raw_events.py`, two parametrized tests:
  - One per S1 prefix: the event lands at `raw_events/<arm_slug(label)>/q1.jsonl`, the literal slug is pinned, and no nested store folder appears.
  - The other checks that a registry arm (`hybrid+rerank+metadata`), a legacy alias (`graph-on`), the external arm (`llamaindex`) and a refused label (`no-such-arm`) keep their directories.

No reader needed a change. `test_run_arms.py::test_raw_events_directory_uses_the_slug_for_canonical_labels` and `oi02.py`'s `raw_events/*/` glob both match the new layout.
