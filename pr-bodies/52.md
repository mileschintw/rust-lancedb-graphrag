## Summary

S2's reader arms can now be labelled, journalled, checked and scored. A reader arm `<S1 arm>@<reader>` replays its base arm's context to a declared Claude reader (D-257). Its records are a new replay record kind with their own zero-tolerance clauses, and `lancet-eval replay-init` carries S1's deepseek records into a new S2 journal so the S2 run directory scores by itself (Q9). Nothing here makes a paid call. `batch submit/fetch` (#53) will write the reader records, and the reader comparison and cost (#54) will read them.

```text
replay-init --source-run <S1 dir> --arms <arm>[,<arm>] --run <S2 dir>
  copy every record of each arm, as written, error records included
  copy the export row of each success record, as written
  header: context_export: true, replay_source: {run, arms, row_sha256}
  refuse: a success record without an export row, a populated S2 journal or export,
          an arm the source run does not hold, a reader arm, an unreadable source record

score / compare-levers on a run with reader arms
  replay clauses (all zero tolerance) -> refuse naming "<clause> <arm> <question>: ..."
  reader arm scored like an external arm: answer metrics, no snapshot, no engine notices
```

- **Labels** (`arms.py`). `READERS = ("haiku-5.5", "sonnet-5.5", "opus-5.5")`. The base is any canonical label, store-prefixed or not, but never a legacy alias. An unknown reader fails closed. `canonical_arm` keeps the suffix and `resolve_arm` returns the base row. A reader arm runs on its base arm's store and sorts after its base. Its slug maps `@` and `.` to `_`. `request_fields` refuses it, and `judged_arms` leaves it out: its records carry no evidence of their own, as with an external arm. New helpers: `arm_reader`, `reader_base_arm`, `is_reader_arm`.
- **Replay record kind** (`journal.py`). `RunRecord.replay: ReplayProvenance | None`. A reader arm's success record carries it. An engine or external record never does.
- **Replay clauses** (`provenance.py`, `REPLAY_CODES`). The engine and external clauses never run on a replay record.
  - per record (`provenance_failures`, so `is_ok` reads them): `replay_record` (a reader record has a snapshot or an external block, or a success record has no replay block; or an engine or external record has a replay block), `is_byok`, `provider` (`"Anthropic"`), `batch_id` (non-empty);
  - run level (`replay_run_failures`): `row_hash` (the record's hash equals the header's carried hash, and the base row and the reader row in the S2 export both hash to it), `body_hash` and `rewritten_fields` (re-run #51's `rewrite_pack_body` on the recorded `pack_body` for the declared reader), `model` (equals the declaration's `slug`), `reasoning_tokens` (must be 0 unless the reader's `thinking` is `on`: `off` and `between_tools` both, per D-260; Opus 5.5 is exempt).
- **Pre-registration** (`thresholds.py`, `preregistration.py`). `StagePreRegistration.readers: tuple[tuple[str, ReaderDeclaration], ...] = ()` (types only, no S2 constant). `readers_of(prereg)` returns `{name: ReaderDeclaration}`. It refuses an unknown name, a duplicate, a value that is not a `ReaderDeclaration`, and any reader arm whose reader is undeclared. `resolve` runs this check whenever the constant has reader arms or a `readers` table. `arms_of` needs no change.
- **D-260** added to `experiments/v1.1/PLAN.md` after D-259 (owner ruling 7: Sonnet 5.5 `between_tools` over OpenRouter keeps #51's encoding; the pilot checks `reasoning_tokens`). No existing D-ID is edited.

### For #53 and #54: field names to copy

Replay record block, `RunRecord.replay` (`journal.ReplayProvenance`, `extra="forbid"`):

| Field | Type | What `batch fetch` writes |

| `reasoning_tokens` | int | from the response usage |
| `batch_id` | str | the batch the request went in |

Token counts go in `workflow_meta.prompt_tokens` and `completion_tokens`, as on other records. An errored or expired request is an `outcome: "error"` record with no replay block. Each reader success record also needs an export row: the carried base row with `arm` set to the reader arm's label (D-249's `require_export_rows` asks for it, and `row_hash` checks it).

S2 journal header (`replay.REPLAY_SOURCE_KEY = "replay_source"`):

```json
{"type": "header", "corpus": "...", "partial": false, "created_at": 0.0, "context_export": true,
 "replay_source": {"run": "<S1 dir as given>", "arms": ["<carried arm>"],
                   "row_sha256": {"<carried arm>": {"<question_id>": "<sha256>"}}}}
```

`order_seed` and `split_sha256` are copied from the S1 header when present. The entry points are `replay.replay_init(source_run=, arms=, run=)`, `replay.require_replay_provenance(records, journal_path, token)` and `provenance.replay_run_failures(records, export_rows=, source_row_sha256=, readers=)`.
