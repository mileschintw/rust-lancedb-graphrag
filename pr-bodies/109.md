## What this changes

Before this change, the S2 path only checked D-73 after the Claude spend. A pilot's reader records also landed in the run of record, where they could not be replaced. `replay-init` and `batch submit` now run the D-73 check before any paid call. A pilot now gets its own run, and the code enforces that.

- **`replay-init`, run of record (default).** It refuses before writing anything unless all of these hold:
  - D-73: the S2 corpus's pre-registration is committed in an ancestor of HEAD, on a clean tree, and unchanged since. This is the gate `score` and `compare-levers` apply later.
  - `--arms` carries exactly the constant's `replay_source_arm`. The value must be a known, non-reader arm label, so a placeholder left before S1's Result is refused.
  - The source run is not partial, and its arm has a record for every question of the source corpus.
- **`replay-init --pilot`.** It makes a pilot run in its own directory, marked with `replay_source.pilot: true` in the journal header. It skips the three checks above, so the constant can still be uncommitted while the pilot settles the readers' targets (D-260).
- **`batch submit`, run of record.** It refuses `--limit`, since a run of record submits every question (D-258). It also re-runs D-73 against the journal header's `created_at`, which is exactly compare-levers' gate, and does so on `--retry-errors` too.
- **`batch submit`, pilot run.** It accepts `--limit N`, skips D-73 and prints that the run is a pilot.
- **`require_replay_provenance`.** It refuses a pilot run that holds reader records, so neither `score` nor `compare-levers` ever reports one.

The intended order is:

1. Fill in the winner and the readers in the working tree.
2. `replay-init --pilot` into a throwaway directory, then `batch submit --limit N`.
3. Commit the S2 constant once.
4. Run a fresh `replay-init` into the run of record.

Lane 110 writes these steps into RUN-S2.md.

`PREREGISTRATION_S2.replay_source_arm: str` is read with `getattr`. Lane 110 adds the field. Until it lands, the test fixture's constant carries the field itself (`replay_fixture.S2PreRegistration`).
