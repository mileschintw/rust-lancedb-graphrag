- **Same shape as #149's stores.** It has an overlay, an Atlas env, a schema file that is `schema.eval.hcl` renamed,
  an `EvalStore` and a store prefix, as `eval-full` and `eval-2wiki` do. The existing tests on those stores now cover
  this one too.
- **Chunking.** `[stores.fullmerged]` is structure-merge 256/25, as S1's merged store. `[stores.full]` is
  structure-aware 500/50, as #149's `eval-full`, which is reused as built. A test pins each chunking to its source
  corpus.
- **Overlay.** It sets `ingest_extraction = false` because the confirm arms never read the graph. It also sets
  `excerpt_max_chars = 2048`, as `config.eval-s1.toml` does, because merged chunks run past the 512-character default
  (D-273).
- **`multihop_rag_confirm_dev`.** It reads the same pinned `corpus.json`, fresh dev questions and fresh split as run
  C's corpus (a test pins this). It has no `[preregistration]` token, so it is pre-registered for no run. Seeding the
  merged store writes `eval/corpora/multihop_rag_full/document_map.eval-full-merged.json`, beside `eval-full`'s map.
- **Nothing is built and nothing is paid.** Building the store is one later step in the main checkout:
  `seed --corpus multihop_rag_confirm_dev --store eval-full-merged`, about $0.19 of embeddings by the D-258 estimate.
