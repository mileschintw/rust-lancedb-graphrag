## Summary

`debounce_coalesces_burst` asserted the process-wide `REBUILD_COUNTER`. Every rebuild in the process bumps that counter, including rebuilds that other tests run in parallel, so a foreign rebuild inside the burst window could push the count to 2. Rebuild counts in tests are now per thread, the same way #61 made the rebuild fault hooks per thread.

## Changes

- `engine/src/ingest.rs`: adds a `#[cfg(test)]` thread-local `THREAD_REBUILD_COUNTER`, bumped next to `REBUILD_COUNTER` at the start of each rebuild, with the accessors `thread_rebuild_invocation_count` and `reset_thread_rebuild_invocation_count`. A `#[tokio::test]` runs on a current-thread runtime, so the debounce task it spawns rebuilds on the test's own thread and is still counted. `REBUILD_COUNTER`, its increment and its two `pub` accessors are unchanged.
- `engine/src/tests.rs`: `debounce_coalesces_burst` resets and reads the thread counter. The new test `debounce_burst_count_ignores_another_threads_rebuild` runs a rebuild on another thread during the burst and joins it before the assertion. On the old process-wide accessor it fails every time (count 2, expected 1); with the fix it passes.
