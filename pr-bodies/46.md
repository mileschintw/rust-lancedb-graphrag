## Summary

`lancet-eval run-external` now stops at the stage spend cap the same way `run` does (D-86). The S0 paid run drives the LlamaIndex arm through this command under D-246's cap.

```text
run-external ... --stage-cap USD          (required, validated by _validate_stage_cap)
  refuse a cap that cannot fire (0, negative, NaN, inf) before any call or write
  ... the existing refusals, then copy the arm's rows into the run's export ...
  for each batch of 16 rows not yet in the journal:
    spend = compute_spend(every record in the journal + this invocation's)
    spend >= cap  -> stop before this batch (stopped_by_cap)
    pack, generate, journal the batch
```

- **CLI.** `--stage-cap` is required with no default, the same as `run`, and reuses `_validate_stage_cap` unchanged. A missing or invalid cap exits 2 before any call. A cap stop prints `Drive stopped early: reached stage spend cap ...` with the observed spend and exits 0, as `run`'s cap stop does. The finished batches stay journalled, and a resume under a raised cap continues.
- **Library.** `run_external(..., stage_spend_cap=...)` is required. It refuses a cap that cannot fire with `ExternalRunError` before anything is written, because the paid path should not depend on the CLI callback. `ExternalRunResult` gains `stopped_by_cap` and `observed_spend`.
- **What counts.** Spend is `compute_spend` over the whole journal: the Lancet arms' records, the external records already there, and this invocation's. This is the same set `drive()` counts.
- **Complete drives.** The cap is checked only while a batch is waiting, so a drive with nothing left to send is never labelled capped (WR-01).
- **Overshoot.** The check runs before a batch, not on a prediction of what the batch will cost, so spend can pass the cap by at most one 16-row batch. `run` overshoots the same way by its in-flight window. The brief specifies this rule, and the module docstring states it.
- **No shared helper.** The check is a single comparison, so none was factored out of `drive()`. `run.py` is unchanged.
