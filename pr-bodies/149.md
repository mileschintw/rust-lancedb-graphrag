- **C's fresh split** (seed 149, split sha256 `30d3dee8…`): the pool is every MultiHop-RAG question whose ID is in no
  committed question file and not in the D-105 split, 2,056 of 2,556. 1,000 go to dev and 1,056 to held-out for #146.
  It reads only each committed file's `question_id` field. The held-out IDs are never sorted into G and null, and only
  the dev rows are written.
- **Stores:** both are built with no graph, since neither run reads one. That saves about 26,000 paid extraction calls
  on C (hours). The full store uses the v1.0 chunking (structure-aware 500/50). In B each 2Wiki passage is one
  document and one chunk (fixed-size 8,192; the longest passage is 6,457 characters).
- **Texts stay out of git:** MultiHop-RAG's 609 article texts (ATTRIBUTION.md) and the 2Wiki passages (#145) are
  seeded from gitignored `.cache/` files, pinned by sha256.
- **K** (accepted principle 3): deepseek and Haiku 5.5 2, Sonnet 5.5 1 (sync), Opus 5.5 1 (batch, effort low). Readers,
  transports, thinking and prices are S2X's.
- Estimate in the run guide: about $28-39 of Claude credit and $0.75-1.25 of OpenRouter credit, against the $70 and $3
  ceilings.

## Review

Code review against origin/main, two axes: standards and spec. There were no blockers. Fixed:

- `reader_replicates` accepted a reader twice; it is refused now.
- `seed` let a non-object row in a JSON documents file raise a `TypeError`; it is a `SeedError` now.
- `explore_readout` divided reasoning tokens by G answers only; it uses every answer now.
- `fresh_split` built each held-out row into a full question to get its ID; it reads the `question_id` field alone.
- Two tautological Rust asserts removed; module order fixed.
- EXPLORE-B now reports the #147 yes/no split too. The readout prints #147's balanced accuracy.

Notes, left as they are:

- `fresh_split.json` records the D-105 input hashes, not those of the files its pool comes from. It cannot change
  without moving the split sha that the frozen constant cites. A drift in the pool is caught by
  `test_no_fresh_question_was_read_by_an_earlier_run` (exactly 500 excluded) and by the rebuild test.
- The constants carry S2X's frozen guard numbers and `matching_rule`, which nothing reads, since `score` and
  `compare-levers` are not run on these runs (one K per arm, no gold-chunk rows).
- B and C share the same `readers=` literal: D-73 freezes each constant as a literal.
- C's pool is stricter than the issue's "not in `questions.diag.jsonl` and not in the current split's held-out set".
  It also drops the 49 other v1.0 sample questions, the rehearsal set and the canaries, all of which an earlier run
  read.
- The store prefixes are `full/` and `twowiki/`, not `small/`, so the new stores never share a prefix with v1.0's.
- `multihop_rag_full_dev.toml` drops its arm canaries after C's freeze, because a reader arm sends no request. That is
  config, not the constant.
