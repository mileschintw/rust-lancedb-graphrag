## Summary

Fixes the four code findings of the S2 audit that block the paid pilot (#133: B1, B2, L5, L6), and puts deepseek's Wafer price into the S2 pre-registration (P1). Two owner decisions are recorded as new IDs: D-277 (the price) and D-278 (the deepseek transport).

**B1, D-278: deepseek's replicates go through OpenRouter's sync API.**

The OpenRouter batch path for deepseek could never work, for two reasons:

- OpenRouter's Batch API takes only `only` and `allow_fallbacks` in its batch-level `provider`. It rejects `order`, `sort` and every other routing preference, and a `provider` inside a request body does not route the batch.
- `deepseek/deepseek-v4-flash-0731` has no batch variant. The only deepseek batch model is `deepseek-v4.1-flash`, served by Sail Research and DeepInfra.

Sources, checked 2026-10-31:

- https://openrouter.ai/docs/batch-quickstart
- https://openrouter.ai/docs/api/api-reference/batch/create-a-batch
- `GET /api/v1/models`

The owner chose the sync API ("改走同步 API (Recommended)"). The change:

- `batch submit` on the carried deepseek arm now prints the D-258 estimate first. It then posts each `pack` body, unrewritten, to `/chat/completions` through the new `batch_client.OpenRouterChatClient`. D-271's whole pin routes every request: `order: ["wafer/us"]`, `allow_fallbacks: false`, `max_price`.
- Answers are journalled every 20 requests (`batch.SYNC_CHUNK`) under a `sync-` ID.
  - A crash loses at most 20 billed answers, and a rerun sends only the replicates that hold no record.
  - A chunk with a misrouted answer stops the run before more is spent.
  - Transport failures and HTTP or API errors are retryable error records. An unreadable reply, or a read timeout after the request went out, counts as probably billed and is not retried.
- The deepseek replay clauses are unchanged: the body hash, nothing rewritten, the body's model, `is_byok` false, the pinned provider, reasoning off with 0 tokens.
- The Claude readers keep their batches.

**B2: the Sonnet answer judge stops off BYOK.** A Sonnet reply whose `usage.is_byok` is not true, or that names a provider other than Anthropic, raises before its verdict is cached. gpt-4o-mini is not checked: it is billed to OpenRouter credit by design.

**L5: routing at fetch.** `batch fetch`, and the deepseek sync submit, print per arm how many billed records break `is_byok` or the provider. A misroute therefore shows before every arm has spent, not only at `score`.

**L6: billed render-rejected records are checked.** An error record that keeps its `replay` block, because it was billed and `render` rejected the answer, now runs the request and target clauses. It skips `row_hash` and `prompt`, since it has no reader row.
