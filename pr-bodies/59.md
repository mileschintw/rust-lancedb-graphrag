## Summary

Two test-only races in the engine lib tests.

**#59, the telemetry hang.** It was a deadlock inside tracing-core, reached through test teardown:

```text
thread A: first hit of some callsite         -> holds LOCKED_DISPATCHERS read lock
  for each live subscriber: upgrade Weak     -> A now holds test T's subscriber
test T: drops its set_default guard          -> A holds the LAST reference
thread W: next test calls set_default        -> waits for the write lock
thread A: drops T's subscriber, still under the read lock
  OTel layer -> SdkTracerProvider/SdkLoggerProvider last ref -> shutdown
    otel_debug!(...)  (internal-logs, a first-time callsite)
      register callsite -> read lock again, queued behind W  => deadlock
every later set_default / new callsite blocks; 4 test threads hang
```

The fix is `testkit::ScopedSubscriber`, used in place of `tracing::subscriber::set_default`. When it drops, it waits until the subscriber is gone. The provider locals are declared before the guard, so they always hold the last reference and shut down on the test thread, outside the lock. If another thread still holds the subscriber after 10 s, the guard panics with a message that starts `ScopedSubscriber:`, so a stuck thread fails the test instead of eating the 45-minute job limit.

```diff
 let tracer_provider = SdkTracerProvider::builder()...build();
 let subscriber = Registry::default().with(otel_layer);
-let _guard = tracing::subscriber::set_default(subscriber);
+let _guard = ScopedSubscriber::install(subscriber);
```

**#61, the rebuild fault hooks.** `REBUILD_FAIL_NEXT`, `REBUILD_CHECKOUT_FAIL_NEXT` and `REBUILD_DOC_META_FAIL_NEXT` were process-wide, so an armed failure hit whichever `rebuild_and_swap` ran next. They are now `thread_local!`. Every arming test is a current-thread `#[tokio::test]`, and those tests poll their rebuild on the arming thread, including the debounced rebuild in `telemetry_ingest`.

Files:

```text
engine/src/
├── testkit.rs                  # + ScopedSubscriber and its two tests
├── tests/telemetry_query.rs    # 26 sites; one test keeps a logger-provider clone past the guard
├── tests/telemetry_ingest.rs   # 16 sites
├── tests/telemetry_metrics.rs  # 1 site (no provider; converted for uniformity)
├── telemetry/mod.rs            # 4 sites in the cfg(test) module; no product code changed
├── ingest.rs                   # cfg(test) fault hooks -> thread_local!
└── tests.rs                    # + an_armed_rebuild_failure_stays_on_the_arming_thread
```

The 13 other `set_default` sites in test code are unchanged: graph, generation, rerank, graph_boost, levers_pins, workflow_phase5 and `tests.rs`. None of their subscribers holds an OpenTelemetry layer or provider, so dropping them emits nothing and they cannot deadlock. (The subject of commit abeb63a5 says "every test subscriber site"; it means every site whose subscriber can own a provider.)

  [A] dropping S: emitting a first-time event (provider shutdown stand-in)

## Review

- **Blocker, fixed:** `engine_log_records_survive_bounded_shutdown` moved its logger provider into a handle declared after the guard, so the bridge layer could still hold the last reference and turn the deadlock into a 10 s panic. A clone declared before the guard now outlives it (567145e1).
- **Fixed:** the new #61 test ran three rebuilds without `REBUILD_TEST_MUTEX`, which bumps the counter `debounce_coalesces_burst` asserts. It now takes the mutex.
- **Fixed:** the guard's panic is documented in a `# Panics` section, and the reason for the 10 s deadline is written down. `install` has a doc line. The redundant `#[cfg(test)]` on the testkit tests module is removed.
- **Opened #64:** `REBUILD_COUNTER` is process-wide product code. `debounce_coalesces_burst` can count other tests' rebuilds, which is the same class of race as #61 but outside this lane's test-only scope.
- **Left as is (judgement calls):**
  - About 40 telemetry tests repeat the provider → layer → subscriber → guard setup, and a helper could gather them.
  - `telemetry_query.rs` imports `ScopedSubscriber` while the other files use the full path.
  - `rebuild_on_a_fresh_store` repeats the `configured_service(... FakeGenerator ...)` block found throughout `tests.rs`.
  - The `thread_local!` block moved `REBUILD_DOC_META_FAIL_NEXT` away from its arm function.
  - The `telemetry/mod.rs:339` doc line still says tests use `set_default`. It is product code, so it was not touched.

## Merge Danger

**Door:** two-way

**Blast Radius:** tests

Only `cfg(test)` code changes. The `ingest.rs` hooks exist only in test builds. A test that arms a fault hook and then runs its rebuild on a different thread (a `multi_thread` runtime, or `spawn_blocking`) would no longer see the fault, and its `is_err()` assertion would fail loudly rather than pass silently.
