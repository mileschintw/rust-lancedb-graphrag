## Summary

Three test-only races in the engine lib tests. Two live in tracing-core, one in our own fault hooks.

**#59, the telemetry hang.** A deadlock inside tracing-core, reached through test teardown:

```text
thread A: first hit of some callsite         -> holds LOCKED_DISPATCHERS read lock
  for each live subscriber: upgrade Weak     -> A now holds test T's subscriber
test T: drops its set_default guard          -> A holds the LAST reference
thread W: next test calls set_default        -> waits for the write lock
thread A: drops T's subscriber, still under the read lock
  OTel layer -> SdkTracerProvider/SdkLoggerProvider last ref -> shutdown
    otel_debug!(...)  (internal-logs, a first-time callsite)
      register callsite -> read lock again, queued behind W  => deadlock
every later set_default / new callsite blocks; 4 test threads hang
```

**PR #62's flake** (`tests::graph_augmentation_attempted_and_failed_is_observable_end_to_end` saw `[]`, CI run 41174946378). While at most one dispatcher is registered, tracing-core computes a new callsite's interest from the *hitting* thread's default subscriber alone:

```text
test T: set_default(capture layer)          -> the only registered dispatcher
test X (no subscriber): first hit of C      -> JustOne path: X's default is none
  C.interest = never, cached for every thread
test T: hits C                              -> skipped; capture layer sees []
```

Both are fixed by `testkit::ScopedSubscriber`, which every test subscriber site now uses in place of `tracing::subscriber::set_default`:

```diff
 let tracer_provider = SdkTracerProvider::builder()...build();
 let subscriber = Registry::default().with(otel_layer);
-let _guard = tracing::subscriber::set_default(subscriber);
+let _guard = ScopedSubscriber::install(subscriber);
```

```text
ScopedSubscriber::install(subscriber)
  register an always-on, do-nothing, OFF-level dispatcher once per run
    -> two dispatchers are always registered, so tracing-core asks every live subscriber   (PR #62)
  keep an Arc of the subscriber; Dispatch::new(Arc clone); set_default
drop(ScopedSubscriber)
  drop the thread-local guard
  wait until the guard's Arc is the only reference left
  drop the subscriber here
    -> the subscriber and the providers it references always drop on the test thread,
       outside tracing-core's lock                                                           (#59)
  still held after 10 s -> leak it and panic "ScopedSubscriber: another thread still holds ..."
```

**#61, the rebuild fault hooks.** `REBUILD_FAIL_NEXT`, `REBUILD_CHECKOUT_FAIL_NEXT` and `REBUILD_DOC_META_FAIL_NEXT` were process-wide, so an armed failure hit whichever `rebuild_and_swap` ran next. They are now `thread_local!`. Every arming test is a current-thread `#[tokio::test]`, which polls its rebuild on the arming thread, including the debounced rebuild in `telemetry_ingest`.

## Review

Round 1 (standards and spec, against origin/main):

- **Blocker, fixed:** `engine_log_records_survive_bounded_shutdown` moved its logger provider into a handle declared after the guard, so the bridge layer could still hold the last reference. A clone declared before the guard now outlives it.
- **Fixed:** the new #61 test ran three rebuilds without `REBUILD_TEST_MUTEX`, bumping the counter `debounce_coalesces_burst` asserts. It now takes the mutex.
- **Fixed:** the guard has a `# Panics` section, the 10 s deadline has a written reason, `install` has a doc line, and the redundant inner `#[cfg(test)]` is gone.
- **Opened #64:** `REBUILD_COUNTER` is process-wide product code, so `debounce_coalesces_burst` can count other tests' rebuilds. It is outside this lane's test-only scope.

Round 2 (the PR #62 fix and the remaining sites), no blocker:

- **Fixed:** `NoSubscriber` as the keeper reports no max level, which tracing reads as TRACE, and that switched off the global level fast path. The keeper is now a subscriber that enables nothing and reports `OFF`.
- **Fixed:** the guard's doc now says to use it for every test subscriber.
- **Noted:** with two dispatchers always registered, every first-time callsite takes the dispatcher read lock. That is the #59 path, now covered at every site by the guard.
- **Noted:** the interest regression test pins the fix only when run alone. In the full suite, another live subscriber can mask the bug.

Round 3 (found by the repeat runs, not by a reviewer):

- **Fixed:** the first guard waited on a `WeakDispatch`. That stops upgrading as soon as the last strong reference is released, before the subscriber's drop has run on the releasing thread. The 4-thread loop caught it once (19/20, `scoped_subscriber_drop_waits_for_another_threads_reference`). The guard now owns an `Arc` of the subscriber, waits until it holds the only reference, and drops the subscriber itself. tracing-core's `impl Subscriber for Arc<S>` forwards every method, `downcast_raw` included.

Left as is (judgement calls):

- About 40 telemetry tests repeat the provider → layer → subscriber → guard setup.
- `telemetry_query.rs` imports `ScopedSubscriber` while the other files use the full path.
- The logger-provider clone added in round 1 is now redundant, since the guard drops the subscriber on the test thread, but it is harmless.
- `rebuild_on_a_fresh_store` repeats the `configured_service(... FakeGenerator ...)` block.
- `REBUILD_DOC_META_FAIL_NEXT` sits apart from its arm function.
- The `rerank/tests.rs` warm-up loop is now redundant but harmless.
- The `telemetry/mod.rs:339` doc line still says tests use `set_default`. It is product code, so it was not touched.

## Merge Danger

**Door:** two-way

**Blast Radius:** tests

Only `cfg(test)` code changes; the `ingest.rs` hooks exist only in test builds.

- A test that arms a fault hook and then rebuilds on another thread (a `multi_thread` runtime, or `spawn_blocking`) would no longer see the fault. Its `is_err()` assertion would fail loudly.
- A future test subscriber added with plain `set_default` reopens both tracing races for that test. The guard's doc says to use it for every test subscriber.
