## Summary

Each lane now runs a fast default tier with a measured budget. Slow checks move to a documented opt-in tier. The Rust
and Go test counts are floors, not exact counts. GitHub Actions runs only the fast tier, per module, on pull requests to
`main`.

```text
fast tier (every lane, and CI)                  slow tier (opt-in, before merge / main checkout)
  cargo test + engine-test-targets.sh             LANCET_SLOW_TESTS=1 pytest   (@pytest.mark.slow)
  go test -count=1 -short + gateway floors        python -O -m pytest scripts/test_phase02_live_evidence.py
  pytest -n auto --dist loadfile                  go test -count=1 ./...       (adds the two engine-building tests)
                                                  LANCET_EVAL_INTEGRATION=1 pytest test_run_external.py test_prompt_parity.py
live tier (never in CI): TEST_DATABASE_URL Go tests, LANCET_RUN_D04_FIXTURE, Rust #[ignore] paid tests, eval drives
```

```text
.github/workflows/ci.yml
  changes (dorny/paths-filter) ──┬─ engine     clippy -D warnings, cargo test, floors    engine/**, config/**, deploy/**
                                 ├─ gateway    go test -short, floors                    gateway/**, config/**
                                 ├─ eval       ruff (no new findings), pytest -n auto     eval/**, scripts/**, + shared paths
                                 ├─ llamaindex its offline tests                          baselines/llamaindex/**, eval/src/**, ...
                                 └─ ci         green when every triggered job passed (the one check to require)
```

- **Count gates:** `scripts/engine-test-targets.sh` and `scripts/gateway-test-targets.sh` check a floor per target or
  package. A target that vanishes, drops below its floor, or appears without a floor fails by name. Adding tests needs
  no edit. `scripts/test_test_targets.py` drives both scripts against fake `cargo`/`go` listings.
- **Slow tier:** `eval/tests/slow_tier.py` skips tests marked `slow` unless `LANCET_SLOW_TESTS=1`
  (`test_slow_tier.py`). The marked tests:
  - the v1.0 lever-run re-score, which was opted in by `LANCET_EVAL_RESCORE_LEVER_RUN=1`;
  - `test_decay.py::test_restart_discriminator_spans_zero_inconclusive`;
  - `test_decay_materiality.py::test_contiguous_window_noise_flat_320_records_has_121_windows_and_no_fires`.
- **The `python -O` failure (#16 in the brief):** it belongs to the opt-in tier.
  `test_wrong_model_is_rejected_in_optimized_isolated_subprocess` needs pytest itself under `-O`. It now skips in a
  default run instead of failing, and runs with `python -O -m pytest scripts/test_phase02_live_evidence.py`, where it
  passes.
- **Go:** `TestRAGQueryCrossRuntime` (builds the engine) and `TestRAGQueryClientDisconnectCancelsRustWorkflow` (runs
  those bins) skip under `-short`.
- **Speed fixes without moving tests:**
  - pytest-xdist (`-n auto --dist loadfile`);
  - the Rust redaction test runs one retry instead of six, which cuts it from about 90 s to 2 s;
  - the judge transport-failure test no longer sleeps through tenacity's backoff.
- **CI:** pinned actions, `contents: read`, no `pull_request_target`, no secrets. Only `main` saves the Rust cache, and
  debug info is off for the 14 GB runner disk. The ruff step fails only on findings a PR adds to a changed file, because
  `main` has about 740 legacy findings.
- **Held-out files:** the owner allowed CI to read committed held-out files offline. CI makes no D-237 held-out read.
- **Docs:** `docs/testing.md` has the tier commands (later briefs copy these), budgets, the CI jobs and path map, the
  branch-protection setting, and the GitHub limits checked on 2026-10-30. `docs/quickstart.md`, `eval/README.md` and
  the README index point to it.

## Evidence

Measured on this machine (12 cores, Windows), warm build, `CARGO_BUILD_JOBS=2`:

| Suite | Before | After |
|---|---|---|
| `cargo test` run | 102 s (lib 90 s) | 65 s (lib 50 s) |
| `go test -count=1` (`-short` after) | 10 s | 3 s |
| `pytest` | 428 s serial, 1 failed (the `-O` gate) | 85 s with `-n auto`, 0 failed (325 s serial) |
| cold `cargo test --no-run` | 1,178 s | not in the budget |

- **Before:** `uv run --project eval pytest` gave `1 failed, 2636 passed, 4 skipped`, and every lane that added a Rust
  test had to bump `TOTAL`/`lib` in `engine-test-targets.sh`.
- **After:**
  - the fast tier gives `2632 passed, 7 skipped` (the 15 owner-approved deletions account for the drop from 2,647);
  - `LANCET_SLOW_TESTS=1` gives `2650 passed, 4 skipped`;
  - `python -O` gives `26 passed`;
  - `LANCET_EVAL_INTEGRATION=1` on the two integration files gives `45 passed` once the release bin is built;
  - `go test -count=1 ./...` passes, including `TestRAGQueryCrossRuntime`;
  - `cargo test` gives lib `852 passed, 2 ignored`;
  - `cargo clippy --all-targets -- -D warnings` is clean;
  - both floor gates pass;
  - `actionlint` 1.7.12 reports no error.

- **First CI run** (run 41151415388, head `d58d083d`): `changes` and `gateway` passed. Three jobs failed on gaps in
  the CI environment, not on test regressions. Each is fixed in `ci.yml` and reproduced locally, and no test assertion
  changed:
  - **`engine`:** lance's build scripts need `protoc`. Ubuntu's `protobuf-compiler` 3.21 is now installed; the lance v8
    protos are plain proto3, and both lance-encoding versions build with 3.21 under WSL Ubuntu 24.04.
  - **`eval`:** 26 CLI-help assertions saw ANSI codes, because Typer forces a Rich terminal under `GITHUB_ACTIONS`.
    `GITHUB_ACTIONS=true` reproduces the 26 failures locally, and `_TYPER_FORCE_DISABLE_TERMINAL=1` on the pytest step
    clears them (`2632 passed`).
  - **`llamaindex`:** nltk refused a hardlinked data file, because uv hardlinks from its cache on Linux. The failure
    reproduces under WSL with default links (1 failed); `UV_LINK_MODE=copy` gives 30 passed.
- **Second CI run** (run 41152529969, head `67908324`): `eval`, `gateway` and `llamaindex` passed. `engine` failed on
  `google/protobuf/empty.proto: File not found`, because Ubuntu's `protobuf-compiler` ships no `.proto` files. The job
  now also installs `libprotobuf-dev`. The earlier WSL check passed only because that machine already had it. A protoc
  copy without an include directory reproduces the CI error verbatim, and with `/usr/include` all 13 lance protos
  compile.
- **Third CI run** (run 41152987283, head `d7b91020`): protoc, clippy and `cargo test` passed; only the floor step
  failed (`listed no target`). The job sets `CARGO_TERM_COLOR=always`, which wraps cargo's `Running` lines in ANSI
  escapes. `engine-test-targets.sh` now passes `--color never` and strips escapes, and `test_test_targets.py` covers a
  coloured listing. With real cargo and `CARGO_TERM_COLOR=always`, the old script fails with CI's message and the new
  one passes (`TOTAL: 980`).
