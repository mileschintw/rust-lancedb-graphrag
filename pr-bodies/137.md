## Summary

Fixes how `batch fetch` reads a finished OpenRouter batch. In the S2 pilot, no Claude answer from an OpenRouter batch could be journalled as a success, and a failed batch's reason was lost (#137). Also sends the Sonnet 5.5 reader through the sync API, because the Batch API refuses its `between_tools` (#138, D-280).

- **Row shape.** Each row of a batch's `results` wraps its chat completion in `response.body`, beside a `status_code`. `_openrouter_result` now reads `response.body`. A row is `errored`, with the row's error text when there is one, if it:
  - carries an `error`;
  - has no `response` or no `body`;
  - has a non-2xx `status_code`.
- **`is_byok` comes from the batch (D-279, the owner's decision).** A row's usage reports no `is_byok`; only the batch-level `usage` does. Every row of a batch now takes the batch's `usage.is_byok`, so a batch that reports none, or false, fails the `is_byok` clause on every row. The row's own provider and model are still checked per row; the batch-level model is the dated slug. D-278's sync replies report `is_byok` themselves and are unchanged.
- **Failed batch.** A batch that fails as a whole (`status: "failed"`, `results: null`, one `error.message`) now returns a `BatchResults` list carrying that message. Each request's `batch_no_result` record includes it.

Checked against the pilot's raw batches (no keys), read through the new client with only `httpx.get` stubbed:

- Haiku 5.5 and Opus 5.5: 25 of 25 rows each read as `succeeded`, with the undated model, provider `Anthropic`, `is_byok` true and 0 reasoning tokens.
- Sonnet 5.5's failed batch yields its `between_tools` message.
