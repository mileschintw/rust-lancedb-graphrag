## Why

Three groups of engine lib tests failed now and then in a full `cargo test` run on a loaded machine, and passed every time when run alone. In each case the test depended on wall-clock timing or on state shared across the process:

- `telemetry_metrics_corpus_generation_gauge_is_numeric` got `1` instead of `42`. The metrics tests installed their in-memory provider as the process-global meter provider, so an index rebuild in any other test, running at the same time, overwrote the gauge.
- The `telemetry_ingest::index_rebuild_*` tests slept a fixed time and then shut the debounce task down. Under load the sleep could end before the debounce timer fired, and the shutdown cancelled the rebuild. A document that finished slowly could also land its link in a second rebuild.
- `startup_recovery_exceeds_queue_capacity_without_deadlock` put one 60 s "deadlock" bound around processing all 101 documents. On this machine that processing alone takes about 90 s.

## What changed

- `engine/src/telemetry/metrics.rs`: `meter()` gets a `#[cfg(test)]` thread-local override, set through `set_thread_test_meter_provider`. This test seam is the only product-file change, and release builds are unchanged.
- `engine/src/tests/telemetry_metrics.rs`: `setup_test_meter` installs the provider on the test's own thread, not globally. The gauge test now records the gauge from a second thread on purpose, so it reproduces the old failure every time instead of by chance. That was the red step: before the seam it failed with exactly `left: 1, right: 42`.
- `engine/src/tests/telemetry_ingest.rs`: the five rebuild tests wait for the exported `index_rebuild` span (`recv_rebuild_spans`, bounded at 120 s) instead of sleeping. The two batch tests start the debounce task only after the worker has buffered the batch's links, so the link counts no longer depend on how long each document takes.
- `engine/src/tests.rs`: the 60 s deadlock bound now covers only the enqueue loop, which is where a deadlock would show. Processing all the recovered jobs gets a separate 600 s bound.

No test was added, removed or ignored, and no retries were added. The lib target still has 856 tests.
