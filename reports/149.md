## Decided while unattended

1. **Store 前綴**
   - 問題：issue 寫 `small/hybrid+rerank+metadata`，但 `small/` 對應的是 v1.0 的 346 篇 store。
   - 選項：沿用 `small/`；或開新前綴。
   - 選擇：新前綴 `full/` 和 `twowiki/`。brief 規定 `data/lancedb-eval` 不能動，而且 arm 的前綴就代表它所在的 store（D-251）。chunking 一樣是 500/50 structure-aware。
2. **Fresh pool 的範圍**
   - 問題：issue 字面是「不在 diag、不在 held-out」。
   - 選項：照字面；或也排除 v1.0 sample 剩下的 49 題、rehearsal 和 canary。
   - 選擇：一律排除。這些題目都被以前的 run 讀過，符合「never read by any run」。結果 pool 2,056 題，dev 1,000、held-out 1,056。
3. **全 609 篇的文字**
   - 問題：要不要 commit。ATTRIBUTION.md 只允許 commit 子集。
   - 選擇：不 commit，從 `.cache/corpus.json` 讀，用 sha256 釘住。
4. **Store 不建 graph**
   - 問題：建 store 時的 extraction 怎麼辦。C 大約要 26,000 次付費 extraction，需要好幾個小時，會超過 OpenRouter 上限。
   - 選擇：加 engine 開關，新 store 不建 graph。兩個 run 本來就都不讀 graph。
5. **2Wiki 的 chunking**
   - 問題：「ingested as given」怎麼落實。
   - 選擇：每段一份文件、一個 chunk（fixed-size 8192，最長的段落 6,457 字元）。body 是 `title\ntext`，HippoRAG 2 的格式。
6. **2Wiki 的 gold facts**
   - 用題目自帶 context 裡的 supporting 句子當 gold facts。少數列的 sentence index 超出段落範圍（2Wiki 的資料缺陷），這時改用整段。
7. **B、C 都不跑 score 和 compare-levers**
   - 原因：每個 reader 的 K 不同，而且這些題目沒有 gold-chunk 列。
   - 改用 `explore_readout` 加 `evidence_split` 手讀。
8. **分階段 PR**
   - 這個 PR 用 `Refs #149`，第 2 階段的 PR 才 `Closes`，比照 #144。
