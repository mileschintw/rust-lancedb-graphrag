## 各檔案改了什麼

- `eval/src/lancet_eval/arms.py`
  - `ArmSpec` 新增 `kind`（`engine` / `external`）。外部 arm 的 `retrieval_mode` 是 `external`，validator 保證兩者一致，且外部 arm 不帶 lever 或 alias。
  - 新增 `EXTERNAL_ARMS` 表，含 `llamaindex` 列。它刻意不放進 `ARM_REGISTRY`，因為 drive 與 preflight canary 會逐列對 `ARM_REGISTRY` 發 request。
  - `resolve_arm` / `canonical_arm` 兩張表都認得；新增 `is_external_arm`。
  - `request_fields` 拒絕外部 arm。
  - `ARM_REGISTRY` 末尾新增 `hybrid+rerank+metadata`（rerank + evidence_metadata，graph off）。
  - 新增 `ExternalPipeline`：pydantic dataclass，`extra="forbid"`，欄位為 framework、framework_version、chunk_size、chunk_overlap、dense_top_k、rerank_model、keep。
- `journal.py`（只動 record kind）：新增 `ExternalProvenance`（pipeline、index_fingerprint、generation_model、generation_provider_order），並在 `RunRecord` 加上 optional 的 `external` 欄位。之後新寫入的 journal 行會多一個 `"external": null`；舊 journal 照常 parse。
- `provenance.py`
  - 外部紀錄只跑自己的 per-record clause `external_record`，不跑 engine clause a–j。engine 紀錄若帶 `external` 區塊也算這條 clause 失敗。
  - 新增 `external_run_failures`，跑整個 run 層級的五條 clause：`export_k8`、`document_map`、`pipeline_echo`、`index_fingerprint`、`generation_model`。
  - 新增 `EXTERNAL_CODES` 與 `is_zero_tolerance`。`ZERO_TOLERANCE_CODES` / `_OK_CODES` 維持原本的 engine 字母，因為 `test_drive_environment` 把它們釘住了。
- `preregistration.py`：新增 `external_pipelines_of(prereg)`，讀 `external_pipelines`（`(label, ExternalPipeline)` 的 tuple）。外部 arm 沒有宣告 pipeline、重複宣告、label 不是外部 arm、或值的型別不對，都 fail closed。
- `score.py`
  - 新增 `require_external_provenance`：只在 journal 有外部紀錄時才跑。它先讀出 stage 常數的 pipeline，以及 `config.toml` 的 `generation_model` 和 `generation_provider_order`；兩者任一讀不到就指名 clause 拒絕。之後讀 context export，再呼叫 `external_run_failures`。
  - `index_generation` 改成每個 arm 各一個值。
  - 為外部 arm 加的修正：
    - per-arm 指標迴圈不再要求 GRAPH_ABLATION，答案照常計分，chunk-ID 檢索指標則略過；
    - P4 的 reference 改讀 pre-registration 的 `reference_arm`，token 解析不到時拒絕，不退回預設值；
    - four-arm 維度把 `EXTERNAL_ARMS` 也納入。
  - 有多個 generation 時，`report.json` 的 `metadata.index_generation` 會寫成 `arm=gen; arm=gen`。
- `lever_comparison.py`：重新檢查外部 clause，避免過期的 `report.json` 放行。chunk-ID 指標（`_hit4_value`、paper hit10/MRR/MAP、`all_gold_at_4`）對外部紀錄回傳 None（D-250）。ITT 的 code 集合也加入外部 clause。
- `eval/tests/levers_fixture.py`
  - 新增 `make_external_record` 與 `write_external_export`，以及兩者用到的 `external_pipeline`、`EXTERNAL`、`EXTERNAL_FINGERPRINT`、`_engine_generation`。
  - `ARMS` 排除 S0 列，讓 06.3.6 的 fixture 維持 7 個 arm。
  - 現有 helper 的簽名都沒變。
- 測試：
  - `test_arms.py`：S0 列、外部 arm、ArmSpec validator。
  - `test_provenance.py`：per-record clause；S-A 的 score 與 lever comparison；每條 clause 的破壞 fixture；兩個 fail-closed 修正。
  - `test_p4.py`：P4 配對外部 arm。
  - `test_preregistration.py`：外部 pipeline 宣告；`_built_lever_arms` 排除 S0 列。
- `usability.py`、`p4.py`：不需要改。P4 本來就逐 arm 問 `is_ok`。

**已修：**
1. `_p4_reference` 在 token 解析不到時默默退回 `hybrid`，現在改成拒絕，並補了測試。
2. `config.toml` 讀不到 `generation_model` 時，原本每筆紀錄都只報 `!= ''`；現在指名 `generation_model` clause 並拒絕，並補了測試。

**保留為 note，未修：**
