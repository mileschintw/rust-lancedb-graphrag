## Decided while unattended

1. **預設 submit 的選題語意。**
   - 問題：issue 說「當某題已有 success 記錄時拒絕」，但 pilot（`--limit N`）之後還得能送出剩下的題目。
   - 選項：(a) arm 只要有任何記錄就整個拒絕，pilot 只能另開 run 目錄；(b) 預設只選沒有 reader 記錄的題目，沒有可送的題目時才拒絕，並在訊息中列出 success／error 數量。
   - 選 (b)：pilot 的花費可以沿用，也不會重複購買。
2. **fetch 冪等的標記方式。**
   - 選項：(a) 只靠 manifest 的 `fetched` 狀態；(b) 另外把 `session_id` 設為 batch ID，逐題跳過同一 batch 已寫入的記錄。
   - 選 (b)：fetch 中途中斷後重跑也不會重複寫入。
   - 副作用：score 的 `run_traceability` 會把這些記錄算作有 session。
3. **OpenRouter 回應缺少 reasoning count 時記為 `-1`。**
   - 選項：(a) 記 0；(b) 寫成 error 記錄；(c) 記 -1。
   - 選 (c)：fail closed，replay 子句會拒絕。記 0 會讓子句錯誤地通過；寫成 error 則會遺失已計費的 usage。
4. **manifest 的寫入時機。** issue 要求在送出前寫 manifest，但 batch ID 要送出後才拿得到。
   - 做法：先寫 `submitting`（ID 為 null），送出後更新為 `submitted`。端點拒絕時改為 `rejected`；崩潰則保持 `submitting`，視為 pending，需要人工確認。
5. **只有新的 base error 可寫時的處理。** 寫入後再拒絕（其他拒絕情況都不寫入日誌）。
6. **`anthropic-version: 2023-06-01`。** 是否需要更新的版本才能用 `output_config` 或 `between_tools`，由 pilot 確認（已寫入 PR body 的 pilot 清單）。
7. **無法讀取的回應（`batch_unreadable_response`）不列入 `--retry-errors`。** 理由：很可能已計費，避免重複購買。
