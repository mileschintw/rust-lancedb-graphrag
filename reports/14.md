## Review 結果與處理

共三輪：一輪雙軸 review（standards、spec），再兩輪複查修正。

- **Blocker（已修）：整份 export 只呼叫一次 bin。** `parity.run_bin` 只有一個 1800 s timeout；約 300 題的 S0 export 一題一題讀下去可能超時，一旦超時，這批付費答案全部遺失。改為每 16 列一批、批批寫進 journal，並在呼叫 reader 前先把列寫進 run export。commit `874bf28a`。
- **Blocker（已修）：`export-context` 遇到共用 journal 會 fail closed。** 改走 `write_context_export`，commit `16bcdbef`。第二輪 review 確認兩個 blocker 都已修好、沒有新缺陷。
- **小修：** 兩處過時的 docstring，commit `ce6faac8`。
- **Note（未改）：**
  - **header 與 `run` 不完全一致：** run-external 寫的 header 沒有 `max_retries` marker，只拒絕 gate-stage journal，不比對 `max_retries`。這樣 `run --retries 2` 與 run-external 才能共用同一個 journal。
  - **重複的原子寫入：** `export_context`、`write_context_export`、`_write_run_export` 三處的原子寫入幾乎一樣，可以抽成 `context_export.py` 的共用 helper，但那是別的檔案。
  - **沒保留的欄位：** `RunRecord` 沒有對應欄位，所以 generate 回傳的 `citations`、`answer_basis`、`final_answer` 沒保留。
  - **`duration_ms` 一律 0.0：** #6 story 35 說 external 的延遲不可端到端比較，所以不填。
  - **export 列先寫入的副作用：** 列在呼叫 reader 前就寫進 run export，所以中斷後若換另一個 index 的 export 重跑，整個 run 目錄都會被拒（訊息會叫你用新目錄）。
  - **命名與 seam（判斷題）：** `_require_matching_split_marker` 仍是私有卻被跨模組 import；有兩個 runner seam（`bin_runner` 全域與 `runner=` 參數）；`_read`、`_bin`、`_sent` 名稱偏薄。
