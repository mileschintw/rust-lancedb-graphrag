<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rust workflow to bounded event channel | Backpressure can otherwise drop lifecycle, terminal, or checkpoint evidence. |
| Node errors to wire-level failure categories | Internal failures must become typed safe NodeFailed payloads without misleading retry advice. |
| WorkflowContext to checkpoint JSON | Full debugging state crosses a persistence boundary and must retain identity and field separation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-10-01 | Denial of service | Workflow event backpressure | high | mitigate | Use explicit bounded pending ownership, cancellation-aware terminal delivery, and typed saturation failure instead of an ignored send result. |
| T-05-10-02 | Tampering | Sequence and event identity | high | mitigate | Allocate ordinals once and bind session and trace identity to every outer event and checkpoint. |
| T-05-10-03 | Information disclosure | Checkpoint serializer | medium | mitigate | Serialize only the defined WorkflowContext snapshot into checkpoint events; keep it out of the client response DTO and use safe failure messages. |
| T-05-10-04 | Spoofing | Retryable failure flag | medium | mitigate | Derive retryability from typed error and retry state rather than accepting a caller-provided or hardcoded value. |
| T-05-10-05 | Repudiation | Workflow lifecycle history | medium | mitigate | Preserve coarse node lifecycle events, terminal event ordering, and full context checkpoints for reconstruction. |
</threat_model>
