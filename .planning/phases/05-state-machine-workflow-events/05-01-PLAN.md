## Review dispositions carried into this plan

- The 05-01/05-06 generated-API landing dependency is deliberate: this plan regenerates only the Rust side while the existing Go unary output remains until 05-06 performs the coordinated full-template generation and Go migration. Therefore this plan does not claim an unfiltered Go runtime suite pass.
- The tracer defines `run_inline_query_rag_remainder(&mut WorkflowContext, &WorkflowDependencies, &WorkflowEventSink, &CancellationToken) -> Result<(), NodeError>` as the compatibility bridge. Its input preserves `session_id`, `trace_id` (equal to `correlation_id`), `original_query`, ordered `variants`, and the variant-0 embedding; it may mutate only `graph_context`, `vector_results`, `bm25_results`, `final_candidates`, `assembled_prompt`, and `answer` as its inline nodes run. It owns `NodeStarted`/`NodeCompleted`/`NodeFailed` and one full snapshot for each inline node it actually invokes, stops at the first typed error, and returns that error. It never emits `WorkflowCompleted`: `WorkflowRunner::emit_terminal_once` is the sole terminal emitter. 05-02 replaces the graph/retrieve portion with runner-owned nodes and hands the same context to `run_inline_prompt_generation_remainder`; 05-03 removes that second bridge when prompt/generation become explicit nodes.
- Checkpoint delivery is represented as a reliable workflow event plus a pending/overflow contract at the Go dispatcher boundary. This Rust plan verifies that the envelope retains full snapshot bytes and explicit pending ownership without constructing `CheckpointDispatcher`; the sixth-envelope dispatcher handoff test belongs to the Go-owned 05-06 task. The valid service path has five checkpoint boundaries.
- D-12 is retained exactly: generation retry has no backoff. A reviewer suggestion for jitter/backoff is rejected because it conflicts with the locked decision.
- The spec-less edge probe remains unresolved. The flagged assumptions in `must_haves.truths` are intentional executable coverage obligations, not silently accepted behavior.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> Rust tonic stream | Untrusted request fields and client cancellation cross into the workflow runner. |
| Rust workflow -> generated protobuf | Internal state and failure details are serialized into a client-visible event envelope. |
| Rust checkpoint event -> Go dispatcher | Full snapshot payloads cross the runtime boundary and must remain bounded, ordered, and non-blocking to query progress. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05-01 | Tampering | QueryRAG request validation | high | mitigate | Validate and mint identity before stream creation; malformed input is a plain typed Status. |
