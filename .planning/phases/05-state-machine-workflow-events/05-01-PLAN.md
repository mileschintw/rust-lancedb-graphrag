<objective>
Formalize the very start of Lancet's RAG pipeline into a real, wire-complete streaming state machine: one node (ReformulateQuery, ORCH-05's pass-through port + D-08's embedding step) proven end-to-end from a real `curl`/gateway request through Rust's new `Node`/`WorkflowRunner` machinery, over a server-streaming gRPC `QueryRAG` RPC, through Go's new SSE-forwarding handler, back to an SSE client — including real per-node timeout enforcement and real cancellation-vs-timeout disambiguation (D-16/D-17/D-22), not stubbed.

This is the phase's tracer bullet. It is not a prototype: the proto contract, the `Node`/`NodeError`/`WorkflowRunner` machinery, the D-04 pre-stream validation boundary, and the Go transport are all production code that the remaining four plans extend by appending more `Box<dyn Node>` entries to the same `Vec` — zero architectural rework required.

Purpose: Retire the phase's two highest-risk unknowns in the same commit — (1) can Rust's hand-rolled `Node`/`WorkflowRunner` correctly disambiguate timeout from cancellation over a real streaming RPC, and (2) does Go's net-new SSE-forwarding pattern actually work against chi's existing middleware stack (RESEARCH Assumption A3, flagged for a Wave 0 spot-check) — before committing four more plans of node expansion on top of an unproven transport.
Output: `proto/lancet/v1/lancet.proto`'s streaming `QueryRAG` + `WorkflowEvent` contract; `engine/src/workflow/{mod,node,runner,events}.rs` + `nodes/{mod,reformulate}.rs`; `engine/src/main.rs`'s `query_rag` handler rewired to open the stream and delegate to `WorkflowRunner`; new in-process Tier 1 scenarios added to `engine/src/tests.rs` (no new external test file — see this plan's Interfaces section); `gateway/main.go`'s streaming `engine.QueryRAG` interface + first-frame-prefetch SSE `queryRAG` handler + route-scoped timeout; `gateway/main_test.go` rewritten for the new streaming contract.

Explicit out-of-scope boundaries this plan (and the whole phase) respects, so the executor does not accidentally widen scope: the standalone `QueryGraph` RPC (04.1's induced-neighborhood query) is NOT wrapped into state-machine nodes/events — it stays a separate one-shot gRPC-only endpoint, untouched by this phase (D-10). The proto's `WorkflowEvent` oneof carries exactly one `NodeStarted`/`NodeCompleted`-or-`NodeFailed` pair per node plus `AnswerChunk`/`FinalAnswer`/`WorkflowCompleted` — no sub-step events are ever added (D-20's coarse granularity is a ceiling on the wire contract itself, not just a convention future plans should remember). The SSE handler adds no `Last-Event-ID`/reconnect-replay support — a dropped connection means the client re-issues the query, not that the server buffers events for resume (D-21). `WorkflowCompleted` and `RetrievalSnapshot` carry no workflow-metadata fields (`started_at`/`completed_at`, `reformulation_used`, `vector_count`, `degraded_mode`, token counts) this phase — that instrumentation is explicitly Phase 6's OpenTelemetry/observability work (D-30), so the proto messages defined in Task 1 below must NOT grow these fields even though they might feel like natural additions while designing the wire contract.
</objective>
