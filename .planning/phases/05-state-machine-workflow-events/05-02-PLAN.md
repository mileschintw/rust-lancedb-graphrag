<objective>
Extend the proven single-node pipeline from 05-01 with the next two nodes in D-06's real execution order — `ExtractGraphContext` then `RetrieveHybrid` — appended to the same `WorkflowRunner`'s `Vec<Box<dyn Node>>`. No architectural change to the runner, proto, or Go transport: this plan is pure node expansion inside `engine/src/workflow/nodes/` plus the D-03 short-circuit and D-07 cross-variant merge logic these two nodes require.

Purpose: retire the phase's two remaining Rust-side open design questions — whether a graph *timeout* degrades like a logical graph failure (D-09) or hard-fails the query, and how RRF-merging across N reformulation variants (D-07) actually composes with the existing single-pass `fuse_candidates` — before 05-03 adds generation and 05-04 builds fault-injection coverage on top of an unresolved semantic.
Output: `ExtractGraphContextNode`, `RetrieveHybridNode`, a new cross-variant RRF merge function in `engine/src/retrieval/fusion.rs`, the D-03 short-circuit wired generically into `WorkflowRunner`, `main.rs`'s node `Vec` extended to 3 entries, and a `FakeQueryReformulator`/graph-timeout-stall test double proving both open questions land on deterministic, asserted behavior.

Neither new node adds a per-node `tracing::info_span!` beyond the existing `query_rag` span carried over from 05-01 — new span instrumentation (`hybrid_retrieval`, `graph_context_extraction`, etc.) is explicitly deferred to Phase 6's OpenTelemetry work (D-31); this plan only mirrors the existing `Span::current().record("graph_augmentation", ...)` field-recording pattern main.rs already uses, it does not open new spans.
