## Review dispositions carried into this plan

- The inline-remainder handoff from 05-01 is made concrete: after `ReformulateQuery`, this plan moves graph and retrieve into runner-owned nodes, then calls `run_inline_prompt_generation_remainder(&mut WorkflowContext, &WorkflowDependencies, &WorkflowEventSink, &CancellationToken) -> Result<(), NodeError>`. The input preserves identity, original query, ordered variants, variant-0 embedding, graph context, and retrieval fields; this bridge may mutate only `assembled_prompt` and `answer`, owns only prompt/generation lifecycle events and full snapshots, returns the first typed error, and never emits a terminal. `WorkflowRunner::emit_terminal_once` remains the sole `WorkflowCompleted` owner. 05-03 removes this bridge when prompt/generation become explicit nodes.
- Cross-variant fusion is not left to an implementation guess. The bounded contract admits at most eight ordered variants immediately after `ReformulateQuery`; a ninth or later input is a typed `InputValidation` rejection before `ExtractGraphContext`, embedding, graph, dense/BM25/RRF work, reranking, or provenance allocation, never truncation or sampling. ExtractGraphContext obtains one variant-zero embedding through `QueryEmbeddingPort` and stores it in the request-local context; RetrieveHybrid consumes that value for dense retrieval and never calls the embedding port. BM25 is evaluated for every admitted variant, each source is deduplicated before rank assignment, total fused score is the sum of finite source contributions, public source rank/score fields use the highest-scoring contribution with lowest variant-index tie-break, and bounded per-variant provenance retains every contribution used in the sum. One variant must match the existing fusion score/order behavior, while the exact nine-variant regression drives the full runner and proves zero downstream calls and no D-07 contribution/provenance allocation.
- Graph timeout follows one explicit `GraphTimeoutPolicy` shared by the graph node and runner: the graph operation's 4000ms inner deadline invokes the typed empty-context degrade, and a 15000ms runner expiry, if reached, is routed to that same successful degrade handler rather than generic `NodeFailed`. The 10000ms embedding prelude plus 4000ms graph operation leaves explicit slack inside the 15000ms outer budget, eliminating the reviewed timer-jitter race. Embedding transport/invalid-payload failures map to D-22 `RetrievalFailed`, embedding timeout maps to `Timeout`, and only graph no-match/logical failure/graph-operation timeout uses successful D-09 degradation. D-30 means no new durable degraded-mode field is added.
- The Rust graph node consumes the config-owned `engine.workflow.query_embedding_timeout_ms=10000`, `engine.workflow.graph_operation_timeout_ms=4000`, and `engine.workflow.graph_node_timeout_ms=15000` contracts; 05-06 Task 2 owns their declarations in all three config overlays, the `engine.workflow` allowlist, annotations, and `10000 + 4000 < 15000` checks in `engine/src/tests.rs`. This plan must use those shared keys and must not introduce a second hardcoded timer policy.
- Reranker failure is a retrieval failure and is included in the phase matrix; it is not converted into zero evidence.
