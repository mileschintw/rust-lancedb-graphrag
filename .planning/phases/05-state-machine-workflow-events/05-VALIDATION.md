## Sampling Rate

- **After every task commit:** Run every automated command in that task's verification block. Each registration guard lists exact test names and captures the native command exit code before inspecting output.
- **After Wave 1:** Run the coordinated Rust/Go transition checks and code-generation/order guard; do not claim a partial pre-migration suite as evidence.
- **After Wave 2:** Run the graph/retrieval Rust focused checks against the completed Wave 1 stream contract.
- **After every later wave:** Run the full suite command above plus the current wave's focused commands.
- **Before `/gsd-verify-work`:** Full suite must be green; database tests may skip only for an absent `TEST_DATABASE_URL` where their plan explicitly permits it.
- **Max feedback latency:** 60 seconds for local checks, excluding an explicitly unavailable PostgreSQL environment.

## Evidence Classes

The additive closure uses two deliberately different evidence classes. Fast sub-second in-process deterministic tests use fake ports, paused time, or bounded local faults to prove semantic behavior such as event ordering, retry classification, cancellation, and snapshot shape; their speed is a test property, not evidence that a committed wall-clock timeout is consumed. The committed `config/config.verify.toml` check is a live runtime timeout proof: it loads `generation_node_timeout_ms = 7000` and runs a slow provider/engine harness, so its observed timeout is expected near 7000ms and must not be replaced by a sub-second semantic test. The additive rows remain draft/pending until their owning plans execute and record evidence; the historical 05-07 row points to its completed summary and does not alter that executed artifact.
