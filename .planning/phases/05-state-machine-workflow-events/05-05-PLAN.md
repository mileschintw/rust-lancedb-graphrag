<objective>
Complete ORCH-04 by giving the checkpoint payloads 05-01 through 05-04 have been carrying inside `WorkflowContext` an actual durable home: a new `workflow_checkpoints` Postgres table, written by Go (never by Rust directly, per D-26) as a fire-and-forget side effect of the same SSE-forwarding loop 05-01 built, sourced from a full-snapshot JSON payload the `WorkflowRunner` attaches to each `NodeCompleted` event.

Purpose: every other plan in this phase produced in-memory/in-stream correctness; this plan is what makes that correctness durable and inspectable after the fact, which is the entire point of ORCH-04 ("checkpoints... for workflow state during development and debugging"). It also closes the AI-SPEC's Tier 2 half of the cancellation-atomicity dimension — the one property Tier 1 (engine-only) tests structurally cannot prove, since it requires a real cross-process Postgres write racing a real cross-process disconnect.
Output: `gateway/db/schema.hcl`'s new `workflow_checkpoints` table, `gateway/db/query.sql`'s `InsertWorkflowCheckpoint` query (+ regenerated `query.sql.go`), `engine/src/workflow/runner.rs`'s checkpoint-snapshot attachment on every `NodeCompleted`, `gateway/main.go`'s fire-and-forget persistence dispatch, and Tier 2 Go+Postgres tests proving payload fidelity and cancellation atomicity.
</objective>
