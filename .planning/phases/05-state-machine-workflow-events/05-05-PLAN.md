<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Rust WorkflowEvent → Go gateway | Checkpoint payload and correlation identity cross the internal streaming boundary. |
| Go gateway → PostgreSQL | Untrusted/provider-derived snapshot bytes enter a parameterized JSONB insert. |
| Test process → PostgreSQL schema | Integration fixtures create and drop per-test schemas against a local database. |
| Client connection → detached write lifecycle | Client disconnect can cancel the stream while a bounded background insert is in flight. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-05-18 | Tampering | Checkpoint SQL insert | high | mitigate | Use generated parameterized sqlc queries, UUID row IDs, explicit trace/node fields, and no dynamic values in SQL. |
| T-05-19 | Denial of Service | Detached persistence | high | mitigate | Use a five-second context timeout, never await persistence in the SSE loop, and require blocking fakes to return on cancellation. |
| T-05-20 | Information Disclosure | JSONB checkpoint content | medium | accept | D-23 explicitly accepts raw corpus content in local PostgreSQL for debugging; the service is localhost-scoped, no new redaction system is introduced, and SSE excludes the payload. |
| T-05-21 | Tampering | Integration schema fixtures | high | mitigate | Use unique per-test schemas, clone the exact public table, bind every pool's search_path before queries, and drop only the owned schema after pools close. |
| T-05-22 | Repudiation | Trace/session checkpoint identity | medium | mitigate | Pass event.TraceId explicitly, assert it equals correlation_id and remains separate from session_id, and persist node_name with every row. |
</threat_model>
