<objective>
Closes UAT gap G-05-1's Blocker A: the local `./data/lancedb` `nodes` table predates the Phase 04.1-01 schema restructure (commit 2302f79, 2026-08-07) and still carries the pre-restructure 23-field shape (it still has `community_ids`, `summary`, `summary_vector`, `unsummarized_refs`, which that commit moved onto a new `entities` table). `validate_schema`'s strict fail-closed equality check (`engine/src/db/mod.rs:161-174`) has no migration path, so the engine exits with code 1 on startup before the gateway or `/rag/query` can even be reached. This is confirmed stale local dev data (`.planning/debug/g-05-1-engine-startup-blockers.md` root-cause section), not a code bug — the fix is operational (regenerate the store) plus a small error-message improvement so the same failure is instantly diagnosable if it recurs on another developer's machine.

Design call made here (per the debug session's request for a planner decision): `validate_schema` stays strict-only. It is a deliberate Phase 02-03 safety property ("Fail startup on any LanceDB schema field drift — indexing must not proceed against incompatible persisted storage"), it is invisible to automated tests (they use isolated temp paths), and it only ever surfaces against a long-lived, manually-run local store. Building a generic reconciliation framework for arbitrary column removals would weaken that guarantee for all 7 tables to fix what is, in practice, a one-time local artifact. The existing precedent for schema evolution (the additive `generation` column special-case for `staged_documents_v2`) is reserved for genuinely additive, backward-compatible changes — not for tables where fields moved to a different table entirely, as happened here.

Review feedback incorporated:
- Portable binary execution in verify block: dynamically resolves either POSIX `./engine/target/debug/engine` or Windows `./engine/target/debug/engine.exe`.
- Explicit retry / cleanup handling in Task 1: if `data/lancedb.pre-05-25.bak` already exists and `data/lancedb` is present (from a prior interrupted or failed reseed), clean up the partial `data/lancedb` directory before re-running `seed_rag_fixture`, keeping the backup intact.

Purpose: Unblock UAT Test 1 (live end-to-end `/rag/query` run) by giving the engine a schema-current local store to boot against, and make the strict-validation decision self-documenting in code rather than only living in STATE.md.
Output: A regenerated `./data/lancedb` store with fresh fixture data (old store preserved as a backup, not deleted), and a `validate_schema` error message that tells the next person exactly what to do.
</objective>
