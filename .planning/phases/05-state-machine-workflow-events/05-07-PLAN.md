<objective>
Close the D-22 taxonomy gap that is blocking 05-02: append `NODE_ERROR_KIND_INPUT_VALIDATION = 9` to the shipped `NodeErrorKind` enum in `proto/lancet/v1/lancet.proto` and regenerate the checked-in Rust and Go bindings via `buf generate`, so `NodeErrorKind::InputValidation` exists and compiles before 05-02 needs to construct it.

Purpose: 05-02's `must_haves` require the runner reject a ninth-or-later reformulation variant with a *typed* `InputValidation` wire error (D-22, `05-CONTEXT.md` line 52). The `NodeErrorKind` enum Wave 1 shipped (`UNSPECIFIED, TIMEOUT, CANCELLED, LLM_GENERATION_FAILED, RETRIEVAL_FAILED, GRAPH_FAILED, PROMPT_ASSEMBLY_FAILED, REFORMULATION_FAILED, INTERNAL`) omits `INPUT_VALIDATION`. This is a genuine Wave 1 omission of an already-decided taxonomy member, not a new requirement — 05-02 correctly refused to touch the proto contract itself (its `<scope_rationale>` is Rust-only / no-unlisted-files) and escalated instead of weakening the typed-error contract by reusing `Internal`. This plan is the narrow, additive fix that unblocks it. It is infrastructure for ORCH-02's client-facing `NodeFailed` event contract (typed error `category` field) — 05-01 built the event/category machinery for ORCH-02 but shipped the taxonomy one variant short; this plan completes it. It does not implement ORCH-01/ORCH-03/ORCH-05 admission/retrieval logic — that remains 05-02's job.
Output: `proto/lancet/v1/lancet.proto`'s `NodeErrorKind` enum with the new member, and the four cross-runtime generated files buf produces from it, regenerated (not hand-edited).
</objective>
