<objective>
Close the one genuine testability gap 05-RESEARCH.md flagged and left unresolved through 05-01/05-02/05-03: the graph-query and dense-retrieval paths were built directly against concrete `DatabaseManager`/`DenseRetriever` types with no injectable seam, unlike `Generator`/`EmbeddingProvider`/`QueryReformulator`, which all already support deterministic fault injection. This plan introduces the minimal trait seam needed, then uses it (plus the now-complete 5-node pipeline from 05-03) to write the fault-injection scenarios that could not be written deterministically before this plan: graph-timeout-degrade, parametrized per-node timeout enforcement, backpressure isolation under real load, full-pipeline trace_id consistency, and genuine-error-vs-zero-evidence disambiguation.

Purpose: RESEARCH.md's Open Question 3 explicitly asked the planner to choose between "introduce this seam" and "accept it as untested debt, consistent with this project's DEBT-* tracking pattern." Given ORCH-03 explicitly names "cancellation, timeouts, and retry/fallback behavior for node execution" as a phase requirement (not just for the generation node), leaving two of five nodes' timeout enforcement unverifiable would silently under-deliver ORCH-03 rather than explicitly defer it — this plan closes the gap instead.
Output: `engine/src/workflow/ports.rs` (new trait seam + fakes), `ExtractGraphContextNode`/`RetrieveHybridNode` refactored to depend on the new ports, and the remaining AI-SPEC reference-dataset scenarios (4, 8, 13, 14, 15) proven deterministically in `engine/tests/workflow_events.rs`.
</objective>
