<objective>
Prove the whole corrected-drive chain on one thin slice before any of it carries real weight:
committed decision inputs, a live micro-drive into the corrected run directory, an offline score,
a gate evaluated against the committed floors, and a recorded verdict. Then land the two pieces of
machinery the chain cannot run without — the staged-gate evaluator that reads a journal the
scoring command refuses to render, and the header reconciliation that lets a journal which began
as a staged prefix be published once the full sample has actually been driven.

Purpose: the staged-then-full design in D-44 collides with a latch in the existing harness.
`Journal.write_header` (`eval/src/lancet_eval/journal.py:113-124`) writes the header only when the
file is new or empty, so a drive that begins with the sampling knob stamps the journal as partial
permanently. `score_run` carries that flag into report metadata and declines to write `report.json`
for it (`eval/src/lancet_eval/score.py:1040-1057, 1065-1069`); `render_markdown` and `render_json`
raise on it (`eval/src/lancet_eval/report.py:149-153, 190-194`); and the `score` command calls
`render_markdown` unconditionally (`eval/src/lancet_eval/cli.py:348-355`). Verified empirically
against a synthetic partial journal: `score_run` completes and returns a full report, `report.json`
is not written, and the `score` command exits with `Cannot render report for partial run`. Without
this plan the staged drive cannot be scored at all and the full drive that resumes into it can never
be published.

Two further hazards, both confirmed against the live tree by the cross-AI review, are closed here
because both fire on this plan's own first paid query and cannot be deferred to a later plan:

- `resolve_run_dir` (`eval/src/lancet_eval/cli.py:214-227`) globs `????-??-??-{corpus}` and returns
  the lexicographically newest match when `resume=True`, which is the `run` command's default
  (`cli.py:256-262`). `eval/runs/2026-09-03-multihop_rag/` matches that glob and is currently the
  newest. A first `lancet-eval run` taken on defaults would therefore append to the superseded
  evidence journal — the one outcome D-45 forbids outright — and `write_header`'s one-shot rule
  would silently keep that run's old header. The recipe below (`--no-resume --limit 2`) is the fix,
  and the identity assertion is a `<precondition>` of the paid task rather than a later ledger row,
  because a `git diff --quiet` afterwards is detection after damage.
- `06.3.3-BUDGETS.md`'s per-stage cap entry requires each 06.3.4 paid driver to enforce its cap "at
  these values (or equivalent fail-closed config) with no silent default". Today only
  `lancet-eval measure` has a stop rule (`eval/src/lancet_eval/measure.py:505-514`), and its
  `--stage-cap` carries a `= 5.0` default (`cli.py:746-752`) — which is exactly the silent default
  the entry forbids. `drive()` (`eval/src/lancet_eval/run.py:155-168`) reads spend nowhere at all.
  This plan ports the stop rule onto the drive loop and makes the cap a required input.

Under D-46's back-edge rule a harness defect discovered *by* the drive lands in this seam, not back
in 06.3.2 — whose landed plans carry no work on the header flag, on `write_header`, or on drive-loop
spend enforcement.

Output: `gate.py`, the reconciliation on `journal.py`, the fail-closed cap on `run.py`, the required
`--stage-cap` option plus two new CLI commands, three test modules, the committed drive-preconditions
ledger, and the corrected run directory opened by a real micro-slice.

These are the values this phase treats as **inputs to a comparison**, not outputs of a measurement.
They are locked by `06.3.1-AI-SPEC.md` §5 and must be committed before the staged drive runs.

| Input | Value | Source |
|---|---|---|
| Staged pairing-coverage floor | `0.80` | AI-SPEC §5 "Staged drive integrity" |
| Graph-yield investigation floor | `graph_presence_rate >= 0.20` on usable graph-on records | AI-SPEC §5 D-32 note |
| Complement trigger | `NoMatchFound` rate `> 0.80` among graph-on whose graph node completed | AI-SPEC §5 D-32 note |
| Floor suspension | Suspended entirely when the store inspection found node, edge and entity counts of zero | AI-SPEC §5 D-32 note; read from `06.3.3-STORE-BASELINE.md` |
| Influence floor | None. `graph_influence_rate` has no floor at all | AI-SPEC §5 D-32 note |
| Calibration size | `12` dual scores, `24` ratings | AI-SPEC §5 D-48 note |
| Agreement target | Quadratic weighted kappa **and** Spearman rho, each `>= 0.70` | AI-SPEC §5 D-48 note |
| Staged size | `50` questions across both configured arms | AI-SPEC §5 "Staged drive integrity" |
| Per-stage spend caps | Read from the dated go/no-go entry in `06.3.3-BUDGETS.md` | D-47, set by the human at 06.3.3's closing checkpoint |

**Boundary semantics are part of the lock.** The yield floor is satisfied at exactly `0.20` because
it is stated as at-or-above. The complement trigger does not fire at exactly `0.80` because it is
stated as strictly above. The staged coverage floor is satisfied at exactly `0.80`.

**A miss is not a run failure.** Missing the yield floor triggers a bounded investigation before the
results are published in Phase 6.4. It does not fail the run, and it does not apply in production
(D-32). The only place a missing graph hit may refuse to start a drive is the preflight canary, and
only on its two designated rows (D-31).

Everything else this phase touches — the observed coverage, the observed yield, the observed
`NoMatchFound` rate, the observed agreement, the observed spend, the derived judged-slice size —
is a **measured value** and is never asserted in advance.
