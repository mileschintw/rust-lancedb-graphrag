<objective>
Write down what went wrong, why the corrected numbers can be believed, and close Phase 6.4's entry
so the family ends where it said it would.

Purpose: the 2026-09-03 run reported a thousand successes over a system in which 966 queries
produced nothing. That is the failure this family exists to correct, and a corrected run without a
record of what it corrects is just a second set of numbers. Three artefacts carry that record: the
full forensic trail beside the phase that fixed the engine, a short public-facing note a reader
outside this project can follow, and a marker on the old run saying plainly that it is retained as
evidence rather than as a result.

Then the closing act. Phase 6.4 depends on this family and documents its output; two edits to its
ROADMAP entry were deliberately deferred to this moment. One adds the forensic record to what 6.4
must read. The other adds the new notice code to the vocabulary 6.4 documents as part of the API
contract — and the name for it is read out of the proto file rather than assumed, because the
decision record's version of that name was illustrative and was never locked.

Output: `06.3.1-ROOT-CAUSE.md`, the distilled note under `docs/`, the supersede marker, and the two
scoped ROADMAP edits.
</objective>
