<objective>
Make the evaluation harness's run-level completeness signal honest, then apply that honesty to the
artifacts that currently carry a false one.

Purpose: `06.3.4-VERIFICATION.md` gap 0, `06.3.4-REVIEW.md` CR-01 and `06.3.4-SECURITY.md`

at drive-start from whether `--limit` was passed, so a drive that halted at 658 of 1000 work units
is stamped `partial: false` and is one ordinary command away from being published as a finished run
of record. The only thing standing between that header and a wrongly-labelled report today is that
nobody has run the command. This plan replaces "nobody ran it" with "the system refuses it."

Output: a completeness signal derived from the computed comparison at every exit path, a
publication path that fails closed when completeness cannot be positively verified, the live
journal's header corrected through that fixed path, and four records — a findings section, a plan
summary, a staged-gate amendment and a public note — corrected to say what is true.
</objective>
