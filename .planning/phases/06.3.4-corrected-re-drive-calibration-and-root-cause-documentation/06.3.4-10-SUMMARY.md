## 1. Accomplishments & Architecture Changes

### Task 1: T-06.3.4-25 — Make the Judged-Spend Meter Advance on a Usage-Absent Response, End to End
- **Meter Fallback Charge (`eval/src/lancet_eval/score.py`)**:
  - Initialized loop-scoped `usage_absent_fallback_count = 0` (and `score_run` default `usage_absent_fallback_count = 0` for `no_judge` paths).
  - Added the missing `else` branch to the metering check in the judge loop (`score.py:506-508`). When `judge_once` returns `usage=None`, `accumulated_judge_spend` advances by `cost_per_question` (the pre-estimate already in scope) and increments `usage_absent_fallback_count`.
  - Observed responses reporting zero tokens (`prompt_tokens=0, completion_tokens=0`) charge `$0.00` and do not increment `usage_absent_fallback_count`, preserving the required discrimination between observed-zero and usage-absent responses.
- **Disclosure in `RunMetadata.notes` (`eval/src/lancet_eval/score.py`)**:
  - When `usage_absent_fallback_count > 0`, composes a `fallback_note` into `final_notes` via the existing conditional concatenation mechanism (`score.py:1417-1434`), disclosing that provider token usage was omitted and charges fell back to estimated cost per question. Fully-observed passes omit this note.
  - When a pass cap-stops (`cap_stopped = True`), the cap-stop note (`judge_stop_note`) explicitly names `usage_absent_fallback_count` when non-zero, ensuring readers know the reported spend mixes observed and estimated charges. No new `judged_slice_state` code was minted.
- **Carried Fallback Count into Both Judged Dimensions (`eval/src/lancet_eval/dimensions.py`, `eval/src/lancet_eval/score.py`)**:
  - Added defaulted keyword-only `usage_absent_fallback_count: int | float | None = None` parameter to `make_groundedness_result` and `make_faithfulness_result`.
  - Emitted `usage_absent_fallback_count` as a `float` into both `detail` and `err_detail` under an `is not None` guard.
  - Forwarded the count from both call sites in `score.py`, and populated `usage_absent_fallback_count: 0.0` in the inline `no_judge` `detail` dictionaries.
- **Preserved Report Schema Integrity**:
  - `eval/report.schema.json` was unmodified and remains byte-identical. `test_schema_file_byte_identical` passes without regeneration.
- **Discriminating Cap-Break Regression Test**:
  - Written and observed failing before implementation: pre-fix call count was **4** calls (never cap-stopping, reaching `cap_bound` and exhausting the slice); post-fix call count was **3** calls (cap check tripped before 4th call, state `cap_stopped`, verdicts obtained 3 < committed 4, published fallback count 2).
  - *Non-discriminating fixture note:* An all-usage-absent fixture cannot discriminate the fix from the defect because `derive_judged_slice_size` bounds the slice using `cost_per_question` and the fallback charges exactly `cost_per_question`, causing an all-absent slice to exhaust at precisely the same call count at which the cap would have stopped it.

### Task 2: T-06.3.4-42 / WR-07 — Define the Judgeable Predicate Once and Size the Slice Against It
- **Single Judgeable Predicate (`eval/src/lancet_eval/score.py`)**:
  - Defined module-level helper `_is_judgeable(rec: RunRecord, gold_map: dict[str, Any]) -> bool` at `score.py:136`, checking gold presence (`bool(gold_map.get(rec.question_id))`) AND non-empty structured citations (`bool(rec.structured_citations)`).
  - Deliberately not widened to record usability: parity with the judge loop's predicate was the design requirement.
  - Replaced the three separate restatements with calls to `_is_judgeable`:
    1. Candidate selection: `score.py:441`
    2. Judge loop: `score.py:488`
    3. Calibration worksheet selection: `score.py:892`
- **Selection Sizing & Published-Number Change (D-34)**:
  - `distinct_qids` in candidate selection filters questions having at least one primary-arm record satisfying `_is_judgeable`, ensuring `derive_judged_slice_size` receives the actual judgeable count.
  - Preserved the no-evidence diagnostic (D-34): computed selection-time exclusions `selection_skipped_no_evidence = sum(1 for r in p_records if gold_map.get(r.question_id) and not r.structured_citations)`. Passed as `skipped_no_evidence` to both dimension builders with `total_sampled = selection_skipped_no_evidence + judged_sample_count`.
  - In a mixed population, `detail["skipped_no_evidence"]` publishes the selection-time exclusion count (rather than a loop-scoped 0). `RunMetadata.sample_size_judged` remains bound to `judged_sample_count`.
- **Scoped `--sample` Refusal (`score.py:456-465`)**:
  - Scoped the `ScoreError` refusal exclusively to `judged_slice_binding == "cap"`.
  - When the slice was bound by data, coincident, or zero-judgeable populations, requested samples exceeding `derived_slice_size` are clamped rather than raised.
  - Existing tests `test_zero_citations_record_skipped_from_judged` and `test_score_run_sample_exceeds_cap_derived_bound_raises` pass unmodified.
- **WR-07: Scoped Cached Verdict Count (`score.py:144, 374`)**:
  - Extracted module-level helper `_reusable_verdict_count(cache, prompt_version, judge_model) -> int`.
  - Counts only cache entries where `verdict is not None` and `prompt_version` and `judge_model` match configured values.
  - Called once in `score_run` to feed both `derive_judged_slice_size` and the calibration file safety guards.
- **Preserved `gate.py` Integrity**:
  - `eval/src/lancet_eval/gate.py` was untouched and unmodified.
