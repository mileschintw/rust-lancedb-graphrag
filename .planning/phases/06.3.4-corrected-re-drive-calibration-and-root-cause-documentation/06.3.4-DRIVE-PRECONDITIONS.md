# 06.3.4 Drive Preconditions Ledger

This ledger records every invariant and assumption that the Phase 06.3.4 staged and full drives depend on, verified directly against the codebase, stores, and configuration before the drives proceed. Each entry states what was checked, the verification method used, the observed value, and the consequence if the condition were ever violated.

## 1. Sample File Ordering & Staged Prefix Equivalence

- **Check**: The committed benchmark questions sample file `eval/corpora/multihop_rag/questions.sample.jsonl` has its `question_id` column in strictly sorted order.
- **Verification Method**: Python script iterating over all rows in `eval/corpora/multihop_rag/questions.sample.jsonl` comparing `qids` against `sorted(qids)`.
- **Observation (2026-09-09)**: Total rows: 500. `qids == sorted(qids)` is `True`.
- **Consequence If Untrue**: If `question_id` were not sorted, taking `--limit 50` on the sampled dataset would not yield the deterministic first 50 questions of the committed sample, breaking reproducibility and staged/full prefix comparability.

## 6. Stage Cap Operating Semantics & Overshoot Bound

- **Check**: Spend accumulator is cumulative over the journal for the stage, and the maximum overshoot bound is bounded by `effective_workers`.
- **Verification Method**: Unit tests `test_cap_stops_dispatch_bounded_window` and `test_accumulator_is_cumulative_over_journal` in `eval/tests/test_stage_cap.py`.
- **Observation (2026-09-09)**:
  - Cumulative accumulator: Seeded from `journal.load_records(journal_path)` when `resume=True`. A resume invocation does not reset the spend meter to zero.
  - Dispatch stop: Evaluated before submitting each next work unit via bounded-window dispatch.
  - Overshoot bound: `effective_workers * max_per_query_cost`. With CLI default `workers=1`, `effective_workers = 1`, bounding overshoot to at most 1 query.
- **Consequence If Untrue**: A per-invocation accumulator would silently turn a $5.00 stage cap into "$5.00 per retry", leading to unbounded spend. An unbound dispatch loop would queue all 1000 queries before observing spend.

## 7. Coverage Denominator Distinction & Gate Rules

- **Check**: D-44 coverage is recomputed gate-side and distinguished from harness journal-relative coverage.
- **Verification Method**: Unit tests `test_coverage_statistic_separation_and_recomputation` and `test_short_journal_fail_closed_hold` in `eval/tests/test_gate.py`.
- **Observation (2026-09-09)**:
  - Recomputed D-44 coverage: `n_pairs / <locked_stage_size>` (50 staged, 500 full).
  - Landed harness coverage: `n_pairs / join_res.total_distinct_questions` (carried as `harness_pairing_coverage` diagnostic only).
  - Short-journal fail-closed rule: If distinct questions in journal < locked stage size, coverage outcome is `hold` with shortfall reason, never `pass`.
- **Consequence If Untrue**: A truncated 10-question journal with 8 pairs reporting 0.80 journal-relative coverage would falsely pass the staged gate despite achieving only 8/50 = 0.16 coverage against the committed sample.
