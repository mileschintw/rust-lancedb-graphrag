### Gaps Summary

9 of the phase's 10 numbered Success Criteria are solidly achieved, verified against actual code and, where practical, against a live re-score of real committed data rather than SUMMARY.md self-reports. The one gap (SC-7) is narrow in scope but structurally significant: it is the same class of defect ("a quality dimension silently disagrees with another over which records count in its denominator") that this entire phase was chartered to eliminate, now relocated from the unusable/usable boundary into the usable population itself, for records with no answer/snapshot payload but no hard node failure. I independently reproduced it against real data (a live 16-vs-18 record denominator split) rather than accepting either the code reviewer's trace or the phase's SUMMARY at face value — this is not a theoretical edge case, it manifests in the corpus of committed real data this repository already carries. It is also invisible to a reader of `report.md`: the one counter that would expose it (`retrieval_skipped_count`) is computed and immediately discarded, and the report's own caveat 6 asserts a symmetry claim the code does not fully deliver on. Given the phase goal's explicit closing clause — "so the next run can be read honestly" — this is treated as a phase-blocking gap (not a warning), consistent with 06.3.2-REVIEW.md's own critical severity rating, which I confirmed independently rather than adopted uncritically.

The fix is narrow and localized to `score.py`'s per-record scoring loop (lines ~230-278) plus surfacing `retrieval_skipped_count`, and does not require re-architecting `is_usable()` or the pairing/ablation machinery, all of which verified cleanly.
