## Independent Fix Verification

### CR-01: `abstention_rate()` missing `notices` argument

**Code read directly (post-fix), `eval/src/lancet_eval/score.py:283-287`:**
```python
if gold.is_null:
    snap_chunks = rec.snapshot.retrieved_chunks if rec.snapshot else None
    abs_out = abstention_rate(
        gold, rec.answer or "", snap_chunks, rec.notices
    )
```
Confirmed against `abstention_rate`'s actual signature in `eval/src/lancet_eval/metrics.py:466-471`: `abstention_rate(question, answer, citations=None, notices=None)`. The 4th positional argument now binds `rec.notices` (a `list[Notice]`, confirmed present with `Field(default_factory=list)` on `RunRecord` in `journal.py:57`) to the `notices` parameter, which `abstention_outcome` (metrics.py:441-463) checks first via `getattr(n, "typed_code", None) == 1` before falling back to text-matching. Pre-fix, this call passed only 3 positional args, so `notices` defaulted to `None` → `[]` inside `abstention_outcome`, permanently disabling the typed-notice branch. This is the exact defect CR-01 described, and the fix restores the documented "prefer typed notice" priority that was already implemented (and already unit-tested at the `metrics.py` level in the pre-existing `test_metrics.py:286` `test_abstention_outcomes_on_null_query`) but unreachable from `score.py`.

**Diff is minimal and load-bearing, not cosmetic** (`git show cc1e71d`): only the missing `rec.notices` argument was added; no other logic changed.

### Regression tests are genuine (traced against pre-fix code shape, not run against a reverted checkout)

Both new tests live in `eval/tests/test_denominators.py` (added by `0cc78b9`):

1. **`test_abstention_credits_notice_based_no_evidence_over_text_match`** — constructs a null-gold record with `answer="The requested information isn't present."` (matches neither hardcoded refusal phrase) and a `Notice(code="NO_EVIDENCE", typed_code=1)`, asserting `abs_dim.score == 1.0`. Traced against the pre-fix call site (`abstention_rate(gold, rec.answer or "", snap_chunks)`, no `notices`): `abstention_outcome` would receive `notices=[]`, skip the typed-notice branch, fail the text-match (answer doesn't contain either phrase), fail the hallucination branch (`citations` is the empty `retrieved_chunks` list, which is falsy), and return `"other"` → score `0.0`. The test's assertion `score == 1.0` would fail pre-fix. This is a genuine regression test.
2. **`test_abstention_skip_reason_distinguishes_payload_excluded_from_absent`** — constructs 2 answerable + 2 null-gold (both payload-excluded via `answer="", snapshot=None`) records, asserting `"no unanswerable questions" not in abs_dim.reason` and `"payload" in abs_dim.reason.lower()`. Traced against pre-fix code: the `else` branch unconditionally set `reason="Corpus contains no unanswerable questions"`, so the first assertion would fail pre-fix. Genuine regression test.

### Checked for a new hazard the fix could introduce (not just that it fixes what it claims to)

`abstention_outcome`'s priority order checks the typed notice *before* the hallucination/citation check — meaning a null-gold record with a `typed_code=1` notice AND a confident cited answer would now score `correct_abstention` (1.0) instead of `hallucinated_on_null` (0.0), a combination that was inert pre-fix because `notices` was always `[]`. Investigated whether this is a new risk introduced by `cc1e71d`:

- This priority ordering lives entirely in `eval/src/lancet_eval/metrics.py`, which is **not** part of the `cc1e71d`/`0cc78b9` diff and **not** in `06.3.2-REVIEW.md`'s `files_reviewed_list` — it is pre-existing code, unmodified by this phase.
- It was already unit-tested before this phase's fix, independent of `score.py`: `eval/tests/test_metrics.py:286` (`test_abstention_outcomes_on_null_query`, untouched by either commit) asserts the notice-first priority directly against `abstention_outcome`.
- `cc1e71d` makes this pre-existing, pre-tested contract *reachable* from `score.py` — it authors no new semantics.
- Confirmed on the one committed real run this repository has: re-scoring `eval/runs/2026-09-03-multihop_rag` from a scratch copy with current HEAD shows `abstention_on_unanswerable` is `status: skipped`, `excluded_payload_records: 0` — the corpus/run sample contains zero null-gold questions, so the dimension isn't scored at all and this hazard cannot manifest on any existing evidence.

Conclusion: not a new escalation. This is a closed, pre-existing design question outside this phase's diff, and it's inert on the only real data this repo has.
