# Phase 06.3.6 Plan 12: Graph chunk precision (lever 2, branch B) Summary

**`ChunkSelection { All, EdgeEvidence, MultiCited }` filters the chunk list fed to the third RRF list at the `rank_chunks` call of `build_paths`, selected per request by the `graph_v2` lever from a new `[engine.graph] graph_v2_chunk_precision` key (default `all`, env override, `graph_v2` unavailable while it is `all`), with the `hybrid+graph` v1 control arm always on `All`.**

## Accomplishments

- Task 0: the committed D-137 selection is `graph_list_precision` (commit `81f1b41476a9603dbbfa0b569790c8689ad5fce6`), so branch B applies and the plan ran in full.
- `chunk_candidates` returns the uncapped candidate set of a variant and `rank_chunks_among` orders it with the unchanged `rank_chunks` keys computed over every entity on the kept paths. `All` passes `None`-equivalent filtering, so its list is the old list; the property test checks it against `seed_chunk_candidates`, which still calls the unchanged `rank_chunks`.
- Kept hops are the consecutive entity pairs of each kept path; `MultiCited` counts distinct citing entities (a chunk an entity lists twice counts once). The path facts, `DEGREE_CAP` (33) and `MAX_PATH_FACTS` (8) are untouched.
- The nesting `EdgeEvidence` within `MultiCited(2)` within `All` is asserted on the uncapped sets over 300 seeded random graphs, with counters proving it is not vacuous (161 rounds with edge evidence, 107 with multi-cited beyond it, 269 with all beyond multi-cited; thresholds of 50 in the test).
- `request_graph_settings` gives a `graph_v2` request the configured variant and every other graph-on request `All`; `build_production_workflow_with_levers` builds its graph port from it (source-pinned), and `query_rag` reaches that builder with the admitted levers.
- `graph_v2` is `lever_unavailable` while the configured value is `all` (T-06.3.6-41), admitted and echoed once a variant is configured, and still refused beside `disable_graph_context` (D-165).

## Decisions Made

- `GraphSettings` holds both the configured `graph_v2_chunk_precision` and the `chunk_selection` in force, so `path_settings()` has one source and a request without the lever never sees the configured variant.
- The configured value is a serde enum (`ChunkPrecision`), so an unknown value fails when settings load; the env override parses the same names and refuses an unknown value naming the variable.
- `graph_v2` is unavailable while the value is `all`: an arm that changed nothing would still be echoed as having run.
