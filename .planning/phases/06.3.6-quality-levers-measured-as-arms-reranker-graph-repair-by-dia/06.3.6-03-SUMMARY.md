## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Existing tests encoded the old prices**
- **Found during:** Tasks 2 and 3 (full-suite run)
- **Issue:** `test_stage_cap.py` (two tests) hard-coded caps ($0.005, $0.01) calibrated to the 0.32 output price, and
  `test_judge_stage.py` asserted a literal `0.012` judge spend; all are direct, expected consequences of D-173 / D-153.
- **Fix:** caps rescaled to $0.009 and $0.022 so the same record counts (3 and 2/3) hold at the new prices; the judge
  spend assertion now derives from `JUDGE_INPUT_PRICE_PER_1M`.
- **Files modified:** `eval/tests/test_stage_cap.py`, `eval/tests/test_judge_stage.py`
- **Committed in:** `80f24cc1`, `884dda7d`

**2. [Rule 1 - Bug] Module-level gitcheck import broke the network-free import test**
- **Found during:** Task 3 (full suite, `test_metrics.py::test_network_freedom_import_isolated`)
- **Issue:** `corpus.py` importing `gitcheck` at module level pulled `subprocess`/`socket` into `lancet_eval.metrics`.
- **Fix:** the import moved inside `CorpusConfig.__init__`.
- **Files modified:** `eval/src/lancet_eval/corpus.py`
- **Committed in:** `884dda7d`

**3. [Rule 3 - Blocking] Module-scoped `written` fixture in test_comparison.py hit the live gate**
- **Found during:** Task 4
- **Issue:** a module-scoped fixture runs before the function-scoped autouse gate fixture, so `write_comparison` read the
  dirty live tree.
- **Fix:** that fixture isolates itself with a local `pytest.MonkeyPatch`; the file still holds exactly one autouse
  fixture and `conftest.py` is untouched.
- **Committed in:** `b73afe4e`

**3b. [Rule 2 - Missing Critical] D-153 was only enforced on `score --judged`**
- **Found during:** pre-return review
- **Issue:** a 06.3.6 corpus has no `[judge]`, so its protocol is `legacy`; `score_run(no_judge=False)` (legacy
  `--judge`) and `--emit-calibration-worksheet` returned early from `_ordered_protocol_guard` and could reach the judge
  client, and `lancet-eval judge` (`judge_stage.load_inputs`) had no protocol check at all, so a 06.3.6 heldout corpus
  could have issued paid judge calls.
- **Fix:** the D-153 refusal moved to the top of `_ordered_protocol_guard` and covers `--judged`, `--judge`, the
  worksheet emit and calibration inputs; `judge_stage.load_inputs` refuses a 06.3.6-token corpus. Three new tests.
- **Files modified:** `eval/src/lancet_eval/score.py`, `eval/src/lancet_eval/judge_stage.py` (not in the plan's
  `files_modified`), `eval/tests/test_preregistration.py`, `eval/tests/test_judge_stage.py`
- **Committed in:** `ec9f416c`

**4. [Process] IN-04 and corpus/run/score tests were written after the implementation** for those pieces (RED was
demonstrated for the price, IN-03 and corpus-less parts only). The new tests pass and exercise the planned behaviours.

**5. [Plan note] `cli.py` unchanged.** Its existing `compare` handler already turns any refusal (including the new
`ComparisonError` from the gate) into `typer.Exit(code=1)` with the problem text printed; a dedicated CLI test pins that.
