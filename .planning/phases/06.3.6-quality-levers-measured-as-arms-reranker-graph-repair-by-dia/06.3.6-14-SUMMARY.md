## Accomplishments

- **THE schema commit is `e620a0b2`.** From that commit every opener of the eval store (`DatabaseManager::initialize`, `open_and_validate`, so the engine, `inspect_lancedb` and `reconcile_eval_store`) fails closed on a 19-column `nodes` until plan 06.3.6-15 runs the backfill. - Staging gained `doc_title`, `source`, `published_date`. Both legacy forms upgrade in place with one `SqlExpressions` call of `CAST(NULL AS STRING)` (plus the generation literal for the 6-column form), proven on empty and populated tables by strict `fields()` equality. `nodes` and every other table are validated before the staging table is upgraded, and a failing validation leaves the staging schema and version unchanged.
- Ingest writes the three values on every chunk row and in the staging row; staged recovery restores them into the job's metadata. `title` is untouched.
- `validate_ingest_metadata` re-validates in the engine, on the first stream frame, before any write: titles at most 512 characters, sources at most 256 (characters, as the gateway counts runes), no control characters, `published_date` a strict `YYYY-MM-DD` calendar date with the leap-year rule. Errors name the key and never echo the value.
- `ingest::load_doc_meta` builds the `DocMetaMap` from one named-projection scan. `main.rs` attaches it to the first snapshot (`GraphIndex::build(&database)` still appears once, the four warm-up strings untouched); the rebuild path scans at the version it just read and degrades like BM25 and graph builds on failure.
- `db::backfill` and the bin: dry run by default; `--apply` needs `--snapshot-dir` and the eval store; `--verify-on-copy` refuses the eval and dev stores and prints the five COPY assertions; `--migrate-only` refuses the eval store. The real corpus sidecar (346 rows, built from committed `eval/corpora` into the scratchpad, not `data/`) passes the same validators: no control characters, no title over 512 or source over 256, every date a calendar `YYYY-MM-DD`, no null or empty value, every key a UUIDv4.

## Interface for plan 06.3.6-15 (read this before Task 2 and Task 4 there)

**The four modes and their flags** (`engine/target/release/backfill_evidence_metadata`)

| Mode | Flags | Notes |
|------|-------|-------|
| dry run (default) | `--lancedb-path PATH --sidecar PATH` | path must resolve to the configured eval store; writes nothing |
| apply | `--lancedb-path PATH --sidecar PATH --apply --snapshot-dir DIR` | DIR must hold `nodes.lance` and sit outside the live store; `--snapshot-dir` is valid only with `--apply` |
| verify on a copy | `--verify-on-copy DIR --sidecar PATH` | takes no `--lancedb-path`; DIR is the copied store itself and the bin WRITES to it; refused when it resolves to the configured eval or dev store (compared by canonical path, so a copy named `lancedb-eval` elsewhere is fine) |
| migrate only | `--migrate-only --lancedb-path PATH` | takes no `--sidecar`; adds three null columns; refused for the eval store |

- **Config resolution:** the configured eval and dev paths are read from the cwd: `config/config.toml` layered with `config/config.eval.toml` from the repo root (or `../config/` from `engine/`), no environment source.
- **Exit status:** `--verify-on-copy` prints the JSON report to stdout and exits non-zero when any assertion is false (the report is complete either way); every refusal prints only to stderr.
- **Apply report keys:** `mode`, `outcome` (`version_before`, `version_after`, `rows`, `documents`, `uncovered_document_ids`, `scan_stable`), `versions_before` and `versions_after`, each listing EVERY table of the store (7 keys), so plan 15 can check `nodes` moved by exactly one and every other table did not.
- **COPY report keys:** `assertions` with `schema_strict_22_columns`, `rows_unchanged_and_no_indices`, `digests_versions_and_files`, `scan_stable_and_sidecar_covered`, `uncovered_null_and_second_run_refused`; also `column_digests_equal` (19), `old_data_files_byte_identical`, `rows_before`/`rows_after`, `version_before`/`version_after`, `indices_before`/`indices_after`, `uncovered_document_ids`, `value_mismatches`, `short_reader_error`, `long_reader_error`, `second_run_error` (contains "already exists").
- **Sidecar rules:** `{"schema": 1, "rows": {"<uuidv4>": {"doc_title", "source", "published_date"}}}`; `schema` must be 1; unknown fields are denied; keys must be UUIDv4; an empty string becomes null; every value goes through the same validators as an ingest request. Assertion 4 requires the sidecar to cover every `nodes` document, so a sidecar with fewer than all documents fails it.
- **Stores that now fail closed:** the engine and `open_and_validate` refuse BOTH the eval store and the dev store `data/lancedb` (and any other 19-column store). The dev store needs `--migrate-only`.
- **First engine start after the backfill:** `DatabaseManager::initialize` upgrades `staged_documents_v2` from 7 to 10 columns, which is one new staging version. That is the C4 record plan 15 step 4 takes; `nodes` and the other tables do not move.
