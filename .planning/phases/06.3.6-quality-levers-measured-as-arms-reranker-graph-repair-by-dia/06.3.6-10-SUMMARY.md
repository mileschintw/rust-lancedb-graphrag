## Accomplishments

- **Families and Holm (D-150, D-160, D-161).** One `build_p4` call per comparison over `(hybrid, X)`; the exact two-sided sign-flip p; `holm_fixed_m` with m = the registered arm count and p = 1 for a comparison below the exact `Fraction` floor (247 of 308 evaluable, 246 not); deltas on P_X with bootstrap CIs (B and seed from the pre-registration) labelled "unadjusted, estimation only"; D-40 stratum deltas with no p-value; `hybrid`'s mean printed per P_X.
- **Guards (D-148, D-162, D-163).** Guard 1 on N_X by `metrics.is_abstention`: PASS iff `|N_X| >= ceil(0.80 x 43) = 35` and `(b - c) / |N_X| <= 0.10`, both exact; equality passes at (4, 0) of 40; fewer than 35 pairs fail closed; decisional for the O4 arms, "would pass / would fail" for the others; the one-sided 95% Clopper-Pearson net-loss bound beside it reproduces the AI-SPEC figures (b = c = 2 gives 7.5 points, b = c = 4 gives 11.4). Guard 2 reports Yes/No/Insufficient/other shares, gold shares, the constant-Yes and constant-No `answer_usable` twins, the binary-gold subset, the non-binary-gold check and a transition table that reconciles with the delta exactly.
- **Default rows (D-150, O16).** `decide_default` applies the pre-registered rule: Holm rejection, positive delta, coverage, the provenance block, the guard if bound, and SC-1/SC-2 PASS on `hybrid` and the lever; a rejection with a negative delta reads "significantly worse, stays off"; a gate MISS alone is an owner disposition; absent `gates-heldout.json` reads "stays off: gates not read" without refusing the comparison. Hits@4 is shown beside each lever as "a retrieval claim only".
- **D-73 inside the build function (D-158).** `gitcheck.preregistration_problems((token,), created_at=..., require_clean_tree=True, unchanged_since_introduction=True)` runs before anything is read or written; the pre-registration is resolved from the corpus token at run time; a corpus left on the 06.3.5 token (no `families`) is refused; the module never names a judged-result file.
- **Descriptive rows and sensitivity lines.** The three D-140 rows (each on its own two-arm population, unadjusted), `degree_capped_count` per graph-on arm, the P_dec re-read and the rerank intention-to-treat reading, per-arm degrade-by-class, rerank latency and cost, (h)/(j) and `query_embedding_retries` counts, `all_gold_at_4`, and the 13 secondaries on P_X.
- **Dev reads (D-135, D-154).** `derive_from_observations` orders observations by time (uncensored first on ties): exact iff `k <= n - ceil(0.95 n)` and every censoring time is at or above the 95th order statistic; the upper CI end is `null` ("unbounded") for an exact p95 with censoring; `T = ceil(1.5 x p95)` through `latency.derive_budget`; 1137 ms nests at 2500 and 1138 does not; a lower bound that already does not nest decides "does_not_fit", otherwise "undecided_lower_bound". `lint-ledger` enforces at most 2 reads per lever, the read-2 reason committed before read 2, dev IDs only, the rules entry before read 1, the freeze before any held-out-side journal and no read after the freeze.
- **Latency relations.** `RETRIEVE_SEARCH_ALLOWANCE_MS = 294` with the rerank relation, and the D-152 graph relation behind `retry_aware=True`.
- **Wave 0 (A2).** Synthetic journals built from `ARM_REGISTRY` and the committed selection score with `--no-judge` and render with `report` at 7 arms (graph-v2 registered, branches A/B), the reduced shape (6), a degrade and a low-P_all journal.

### Departures from the plan text

- **D-152 relation is opt-in.** The plan says `check_nesting_invariants` checks both relations and skips those whose keys are absent. Every existing caller (`measure.derive_budgets_from_records`, `budget_review`, `test_full_nesting_report_and_conflict_resolution`) already has the three graph keys, so an always-on relation would raise `graph_node_timeout_ms` to 24750 in the pin that asserts 14500 and move recorded 06.3.3 derivations. It is `retry_aware=True`; no caller passes it yet. **Plan 18 and any freeze-time nesting check must pass it.** The rerank relation is gated by `rerank_timeout_ms` being present, so it is on whenever it can apply.
- **P_all label home.** The label cannot be a dimension reason (an ok `DimensionResult` forbids one), so it is in `RunMetadata.notes`, only for lever corpora. The note carries `|P_all|` and the coverage.
- **No `eval/tests/fixtures/levers_arms/` directory.** The fixtures are generated at test time from the registry by `eval/tests/levers_fixture.py`; there is no committed journal or TOML.
- **Branch C is exercised as a reduced shape only.** The committed selection is `graph_list_precision`, so the registry holds `hybrid+graph-v2` and `hybrid+all` carries `graph_v2`. The 6-arm shape drops `hybrid+all`, and the "m = 3 and m = 1" test drops `hybrid+graph-v2` from the pre-registration and the corpus; a true branch-C registry cannot coexist with this commit.
- **Plan-commit ledger file not written** (the worktree guard refuses `.git/worktrees/...`, as in plan 07); `plan_head_before` is the spawn-time base and `commits: 7` is `git rev-list --count 828bb6bc..HEAD` before the SUMMARY commit.
- The plan's `git log --format=x -S` style checks were not needed here.

**Total deviations:** 3 auto-fixed (3 Rule 1), 5 departures. **Impact:** the fixes are corrections to numbers or crashes that a later plan would have read; none widens scope.
