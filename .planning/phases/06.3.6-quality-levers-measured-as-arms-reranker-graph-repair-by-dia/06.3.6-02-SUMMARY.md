## Decisions Made

- **Seeded mention.** The seed probe does not link a mention to the seed it produced, so a mention is "seeded" when some seed's name tokens are token-contained with its tokens (written into `alias_predicate`). A mention matched only through a vector seed with a different name counts as unseeded: it cannot make `missing_edge` hold, and it can still reach the mention case of `alias_split`. Fixed blind; no data was consulted.
- **Row evidence.** `evidence_ids` is one object with `gold_chunk_ids`, `seed_entity_ids` and `alias_entity_ids` (the witnessing entities of `alias_split`), so the spot-check has the ids it needs from the table alone.
- **Inputs mix.** Seeds, mentions and paths come from the seed probe; `path_found` and `degree_capped_count` come from the journal's `workflow_meta`, as the plan specifies. A journal field that was not recorded (None) does not satisfy `missing_edge`.
- **`select`** refuses on any dirty tree (whole tree, `gitcheck.is_clean()`), on an untracked table, and when the rule has no introducing commit.
- **Dump contract.** `dump_meta.json` keys are `entities_version`, `entity_edges_version`, `row_counts.{entities, entity_edges}`, `sha256.{"entities.jsonl", "entity_edges.jsonl"}`, each digest over the exact bytes written. The Python reader verifies both digests and both row counts before use. Rust and Python agree on this shape and a Rust test pins the keys and the digests.
- `--out` is now valid with `--chunk-text` and with `--graph-dump`; its stray-option message reads "--out is only valid with --chunk-text or --graph-dump" (still contains the old text).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Plan inconsistency] The alias_split + absent behaviour line cannot be satisfied by the plan's own predicates**
- **Found during:** Task 1 (writing the first-match fixtures)
- **Issue:** The plan asks for a fixture that satisfies both `alias_split` and `absent` and is labelled `alias_split` with both in its membership set. `alias_split` requires an entity that cites a gold chunk; `absent` requires that no entity cites a gold chunk. They are exclusive. The same reasoning excludes the other pairs: `missing_edge` requires `alias_split` false, and it requires every mention seeded, which means some entity names each mention, so `absent` is false. The three non-residual classes are pairwise disjoint, so the D-171 precedence can never change a label and the published multi-membership matrix will show only single-class sets. This follows from the predicate text alone (no data was computed).
- **Fix:** Encoded the predicates exactly as the plan and AI-SPEC state them (an owner pre-registration, not mine to loosen). First-match machinery is tested by monkeypatching overlapping predicates (`test_classification_is_first_match_in_the_rule_precedence`, including a reordered precedence), and the exclusivity is pinned by `test_alias_split_and_absent_are_exclusive_by_construction`.
- **Files modified:** `eval/tests/test_graph_diagnosis.py`
- **Commit:** `fc1ab4e3`
- **Owner note for plan 06.3.6-04:** D-171's "effect" paragraph assumes overlap (an alias question "even if an unnamed mention may still block it"). Under the committed predicates that overlap cannot occur; the run of record should say the matrix is diagonal by construction. This does not change any count or the selection: with disjoint predicates the label equals the unique membership under any order.
