## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Proto, generated trees and engine landed in one commit**
- **Found during:** Task 2
- **Issue:** the plan orders "proto with both trees" before "engine", but after `buf generate` the Rust tree does not compile until the engine fills the new `RetrievalSnapshot`/`WorkflowMetadata` fields and the new `NoticeCode` arm. A proto-only commit would leave HEAD red.
- **Fix:** committed proto, both generated trees and the engine together (`b34dee48`); gateway and harness are separate commits as planned.
- **Commit:** `b34dee48`

**2. [Rule 1 - Bug] Two harness drive sites did not map the new `WorkflowMetadata` fields**
- **Found during:** Task 3 (full `pytest eval/tests`: `test_every_wire_metadata_field_is_mapped_at_each_drive_site` failed)
- **Issue:** `measure.py` and `eval/scripts/drive_measurement_pass.py` build `WorkflowWireMeta` by hand; without `rerank` and `query_embedding_retries` the journal model would silently default them and drop a measured value. Neither file is in the plan's `files_modified`.
- **Fix:** mapped both fields at both sites; `run.py` switched to the single-line form the pin regex requires.
- **Files modified:** `eval/src/lancet_eval/measure.py`, `eval/scripts/drive_measurement_pass.py`, `eval/src/lancet_eval/run.py`
- **Commit:** `f00b7636`

**3. [Rule 3 - Blocking] `retrieval_mode_pins.rs` widened for the identity pin**
- **Found during:** Task 3
- **Issue:** the plan's "explicit empty `levers` equals `retrieve_node_default.golden` through `render_scenarios`" needs `render_scenarios` and `Variation`, which were private to a file not in `files_modified`.
- **Fix:** `render_scenarios`, `Variation`, `Variation::DEFAULT` made `pub(super)`; `Variation` gained a `levers` field (default empty) with `with_levers`, applied in `apply`. The default variation renders exactly what it did, and all ten existing tests there still pass against the unregenerated golden.
- **Commit:** `d83b3d5e`

- **Task 3 is marked `tdd="true"`, but the admission code already existed from Task 2.** The Task 3 rows and tests were therefore written against existing behaviour and passed on first run, so there is no separate RED commit. The mutation check above is the evidence that the new rows can fail.
