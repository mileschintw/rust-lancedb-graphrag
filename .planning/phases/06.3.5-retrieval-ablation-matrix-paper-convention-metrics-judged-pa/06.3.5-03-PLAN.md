    D-99 and D-100 are costly: once these fields are on the public query contract, removing them later breaks any
    client that set them. Already decided, and not re-asked here:

    Recommended shape (RESEARCH U1, U2; the AI-SPEC §4 `optional` variant is superseded here only if the owner
    picks it):
    - **Request:** `enum RetrievalMode { RETRIEVAL_MODE_UNSPECIFIED = 0; RETRIEVAL_MODE_HYBRID = 1;
      RETRIEVAL_MODE_DENSE_ONLY = 2; RETRIEVAL_MODE_BM25_ONLY = 3; }`. `QueryRAGRequest`:
      `RetrievalMode retrieval_mode = 6;` and `bool include_pre_truncation_ranking = 7;`, both plain (not
      `optional`). Proto3 default semantics already mean "absent == default", which keeps the default request
      byte-identical on the wire, and the 19 `..Default::default()` request literals need no edit.
    - **Snapshot:** `RetrievalSnapshot`: `RetrievalMode retrieval_mode = 13;` echoes the request value, 0 when
      absent. `repeated RankedCandidate pre_truncation_ranking = 14;`.
    - **`RankedCandidate`:** `string chunk_id = 1; string document_id = 2; int32 fused_rank = 3; int32
      vector_rank = 4; int32 bm25_rank = 5; int32 graph_rank = 6; bool graph_boosted = 7;`, ranks 1-based, 0 =
      not in that list.
    - **Provenance carrier:** the snapshot field, not a `NoticeCode`. A notice would need three new codes (next
      free 23) placed in the exhaustive `derive_degraded_mode` match, and it would pollute every client's
      `notices`. The snapshot seed at `retrieve.rs:180` also keeps a failed record attributable.
    - **Gateway JSON:** request keys `retrieval_mode` (one of `"hybrid"`, `"dense_only"`, `"bm25_only"`; any
      other string is HTTP 400) and `include_pre_truncation_ranking`. The snapshot echo is the same lowercase
      string, omitted when 0, so a default snapshot keeps its 10 keys.
    - **Capture point:** pre-rerank, after cross-variant fusion, `.take(candidate_limit)`.
  </context>
