# Phase 06.3.5 Plan 06: Registry-aware readers (score, dimensions, pairing, unpark_gates) Summary

**Every journal reader now resolves arm labels through the D-101 registry: `score_run` groups by the configured arms and fails closed on any label it cannot attribute, `unpark_gates` takes an `ArmRoles` pair, and drives 1, 1b and 2 re-read and re-score exactly as recorded.**

## Performance

- **Duration:** about 60 min
- **Completed:** 2026-10-07
- **Tasks:** 2 (each a RED test commit and a GREEN feat commit)
- **Files modified:** 9 (5 source, 4 test), all under `eval/`

## Accomplishments

- `score_run` no longer drops a record with an unrecognised label (the old `{"graph-on": [], "graph-off": []}` grouping is gone). Records go to the configured label whose `canonical_arm` matches theirs; an unknown label, a label the corpus does not configure, or a question held under both an alias and its canonical label raises `ScoreError` naming the label and its record count.
- The GRAPH_ABLATION count-and-exclude applies to every arm with `disable_graph_context`, and the primary arm for the legacy-named dimensions is the configured `hybrid+graph` label (else `hybrid`), which removes the `KeyError` of RESEARCH Pitfall 6. `graph_ablation_delta` now pairs `hybrid+graph` against `hybrid`.
- `attempted_graph` and the graph presence and influence dimensions test the canonical `hybrid+graph` arm; an unreadable label is `False`, never a raise.
- `form_arm_pairs` and the `ArmPair.treatment` / `.reference` aliases pair any registry arm pair on a shared `_join_pairs`; `form_pairs` and its historical fields are behaviourally unchanged.
- `unpark_gates` gains `ArmRoles` / `DEFAULT_ARM_ROLES` / `_record_for_role`, threaded through SC-2..SC-5, `_unpaired_boost_share`, `_form_drive2_pairs` and `graph_off_invariance`. `legacy_records_digest`, the legacy registry and `test_recorded_gate_verdicts.py` are untouched.
- Proofs: a tmp copy of the drive-2 run re-scores to every `(name, status, score, n)` of the committed `report.json`; a tmp relabelled copy (`graph-off` to `hybrid`, `graph-on` to `hybrid+graph`) reads SC-3, SC-4, SC-5 and graph-off invariance equal to the legacy readings; no file under `eval/runs/` changed.

## Decisions Made

- SC-3 derives the reference arm's usable value from each row's per-arm results by role. `build_rows` (in `diagnostic.py`, not owned by this plan) sets `e_answer_usable` from the literal `graph-off` arm, so a relabelled journal would read n=0. `e_answer_usable` remains the fallback, only when the reference is `hybrid`, so every existing fixture and recorded row reads as before.
- SC-2's both-arm-error question count counts errors on the two role arms. On the legacy journals, which hold only those arms, the count and the printed labels are identical.
- `graph_ablation_delta` moved from `form_pairs` to `form_arm_pairs(hybrid+graph, hybrid)` so a canonical-labelled journal does not silently report no pairs; on legacy journals the two joins are equal element by element (tested).
- OBS-06 is not marked complete (D-98).
