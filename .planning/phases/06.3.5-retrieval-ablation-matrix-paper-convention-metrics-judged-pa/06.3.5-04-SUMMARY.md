## Accomplishments

- D-125: `ExtractGraphContextNode` computes `needs_query_embedding` before its embedding prelude and skips `embed_variant_zero` only for an explicit `bm25_only` request with `disable_graph_context`. The ablation early return stays byte-for-byte in place and the node still has exactly one `graph_port.query_graph(` call, so `graph_cutover.rs` (unmodified) passes. Embedding `calls()` is pinned at 0 for bm25_only graph-off and 1 for bm25_only graph-on, dense_only, explicit hybrid and the default request, graph off and on.
- Nine new `retrieval_mode_pins` tests. The 06.3.5-01 renderer is generalised through a `Variation` (mode, flag, strip-additions) and a `Fixture` that keeps the fakes so call counts are readable; the default golden test calls it with `Variation::DEFAULT` and its golden file is untouched. New pins: bm25-only call counts and BM25 order with `vector_count` 0 and no `vector_rank`; dense-only top `final_limit` in dense order with no `bm25_rank`; bm25-only over two variants equals `fuse_cross_variant_candidates` over per-variant `fuse_candidates(vec![], bm25_i, ..)` (computed from the production functions, not hand-derived); flag-on (ranking cleared) and explicit-hybrid (echo zeroed) scenarios equal the golden, including `result_hash`, the prompt and the runner `final_response`; ranking head, contiguous `fused_rank`, `graph_boosted` and the `candidate_limit` bound; and an exact fused-score tie across the final limit keeps the truncation order in the ranking.
- Engine admission: `v1::RetrievalMode::try_from(req.retrieval_mode)` beside the `disable_graph_context` read returns `InvalidArgument` with disposition `invalid_retrieval_mode`. `bad_input_matrix` gains reject rows for 99 and -1 and admitted rows for 0..3 (doc table updated; it stays one table-driven test).
- Gateway: seven subtests (unknown, wrong-case, capitalised, empty, numeric `retrieval_mode`; string and numeric `include_pre_truncation_ranking`) each assert HTTP 400 `invalid request body` with the engine fake failing the test if called. `TestRetrievalSnapshotDTOKeySets` pins exactly the 10 default keys, 12 keys for an explicit mode with a ranking, and that a ranking row with `bm25_rank` 3 carries only `chunk_id`, `document_id`, `fused_rank`, `bm25_rank`, `graph_boosted`. The existing 10-key pins at `main_test.go:2837` and `:2919` are untouched and pass.
