**Exact paired sign-flip and Holm in stdlib arithmetic, a P4 complete-case population, one abstention predicate with a judgeable policy, and a single pre-registration commit enforced by git-ordering refusals in `drive` and `score`.**

## Accomplishments

- D-118 abstention: `is_abstention` is true for a NO_EVIDENCE notice (typed code 1 or the string) or a final `Answer:` line equal to `insufficient information` after normalisation. `Evidence says insufficient information` then `Answer: Yes` is not an abstention and shows up in `abstention_leak`.
- D-112 judgeable policy: `_is_judgeable(rec, gold_map, *, policy="legacy")` is unchanged by default (197 of 200 on drive 2, asserted record by record against the old expression). `policy="06.3.5"` adds non-null gold, `provenance.is_ok`, citations and `not is_abstention`. An unknown policy raises `ValueError`.
- D-123 inference: `exact_signflip_p(5, 0) == Fraction(1, 16)`, `(0, 0) == 1`, symmetric; the 10,000-flip seed-42 Monte Carlo lives only in `test_stats.py` and agrees within 3 SE on the four named cases. `holm_stepdown([0.001, 0.02, 0.04])` rejects all with adjusted `[0.003, 0.04, 0.04]`; tied `[0.02, 0.02, 0.9]` rejects none.
- D-121/D-122 P4: `build_p4` keeps held-out G questions where all four arms are ok, reports each arm's exclusions by reason, each pairwise join size with `hybrid`, and coverage over the split's G size (8/10 on the synthetic fixture). A usable blank NO_EVIDENCE bm25-only record stays in P4, scores `answer_usable` 0 and counts as an abstention.
- D-73 pre-registration: `AblationPreRegistration`, `PREREGISTRATION_06_3_5`, `JUDGE_QWK_TRUST_FLOOR = 0.70`, `CALIBRATION_MIN_SCORED_PAIRS = 16`, `CALIBRATION_DRAW_SEED = 42` and the three judge tripwire constants are in commit `ac2bf45d371467851c63934fa81be28ca03d3d0d`, which touches only `thresholds.py` and `test_preregistration.py`. `gate.py` is byte-identical to `5d73669f`.
- D-73 enforcement: `drive` refuses a `[split]` corpus (held-out and rehearsal) unless the introducing commit is an ancestor of HEAD and `eval/src/lancet_eval/` is clean, before any journal I/O. `score_run` refuses a `[split]` report unless both pre-registration commits are older than the journal header's `created_at`, and also refuses a header with no numeric `created_at`.

## Decisions Made

See `key-decisions` in the frontmatter. Two choices worth restating:

- `introducing_commit` uses `git log -S`, which walks HEAD's history only, so the `is_ancestor` check is belt and braces for the live repository; it is still tested on its own against a side branch.
- `is_clean` counts an untracked file under `eval/src/lancet_eval/` as a change, so a new untracked module cannot slip into a pre-registered drive.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] gitcheck strips repository-redirecting environment variables**
- **Found during:** Task 3 (gitcheck design)
- **Issue:** a test run from inside a git hook inherits `GIT_DIR` and friends, which override `cwd` and would point a "throwaway repo" call at the live repository (T-06.3.5-27).
- **Fix:** `_run` drops `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR` from the child environment, with a test.
- **Files modified:** `eval/src/lancet_eval/gitcheck.py`, `eval/tests/test_preregistration.py`
- **Committed in:** `206b4f89`

**2. [Rule 2 - Missing critical] gitcheck validates option-like and non-hex arguments**
- **Found during:** Task 3
- **Issue:** a token or path starting with `-`, or a revision that is not a hex id or `HEAD`, could be read by git as an option.
- **Fix:** `_require_plain` and `_require_rev` raise `GitCheckError`; the token is passed as `-S<token>` and paths after `--`.
- **Committed in:** `206b4f89`

### Plan wording interpreted

- **Null test in the 06.3.5 policy:** the plan says `question_type != "null_query"`; the code treats a question as null when `gold.is_null` or `question_type == "null_query"`, the stricter union (both agree on every drive-2 question).
- **Record type for `is_abstention`:** a `Protocol` with `.answer` and `.notices` instead of a `TYPE_CHECKING` import of `RunRecord`, which keeps the import graph acyclic and lets tests pass a plain dataclass.
- **`preregistration_problems` and `PreregistrationError`:** added to `gitcheck.py` beyond the plan's listed functions so the refusal logic is written once and `run.py` / `score.py` only wrap it. The token strings therefore live in `gitcheck.py` (`PREREGISTRATION_TOKEN`, `TRUST_FLOOR_TOKEN`), and `run.py` / `score.py` carry no literal.
- **Fixture applied to seven existing tests:** the seven `[split]` drive tests in `test_run_arms.py` that reach the new gate use `@pytest.mark.usefixtures("preregistered_clean_tree")`. The legacy-corpus test does not, so it shows that a legacy corpus is never checked.
- **OBS-06 not marked complete:** the plan declares `requirements: [OBS-06]`, but the orchestrator note (D-98) forbids marking OBS-06 complete because 06.3.6 owns its lever half. `requirements-completed` is therefore empty and `requirements.mark-complete` was not run; this departs from the template's copy-verbatim rule on instruction.

**Total deviations:** 2 auto-added (Rule 2), 5 interpretations. **Impact:** no scope creep; both Rule 2 additions are mitigations for T-06.3.5-27.

## Issues Encountered

- The harness shell and the editing tool collapse backslash escapes in heredocs, which corrupted two generated test strings (a literal newline inside a Python string). Both were caught by the first pytest run and rewritten without escapes.
- Working copies of several eval files use CRLF while the index uses LF (`core.autocrlf=true`). Edits kept each file's own endings; `git diff` shows only the intended lines.
