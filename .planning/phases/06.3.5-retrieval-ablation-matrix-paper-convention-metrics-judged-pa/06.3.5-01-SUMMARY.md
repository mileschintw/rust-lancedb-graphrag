## Decisions Made

- The golden's pre-change HEAD is the Task 1 commit, because Task 1 changed only a shell script.
- SHA-256 is written out in the binary rather than adding `sha2` as a direct dependency (see Deviations).
- `--chunk-text` never opens the store until the ID file has validated, so a malformed ID file cannot touch the store.
- A malformed-ID error names the line number only. A line that is not a JSON object with a string `chunk_id` gets the same treatment, and serde's own error text is not echoed.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] SHA-256 implemented in-file instead of using a crate**
- **Found during:** Task 3
- **Issue:** The plan requires `content_sha256` (lowercase hex SHA-256) and also requires `engine/Cargo.lock` unchanged under `--locked` (T-06.3.5-SC: no package added). `sha2` is only a transitive dependency; declaring it in `Cargo.toml` would edit the `engine` entry of `Cargo.lock`.
- **Fix:** a small FIPS 180-4 implementation in `inspect_lancedb.rs`, pinned by `chunk_text_sha256_matches_the_published_vectors` (empty, `abc`, the 56-byte two-block vector, a 200-byte multi-byte UTF-8 case, and a string with an embedded newline and a non-BMP-adjacent character; reference digests computed with Python `hashlib`).
- **Files modified:** `engine/src/bin/inspect_lancedb.rs`, `engine/src/inspect_lancedb_tests.rs`
- **Verification:** `git diff --quiet e2cbcd12 HEAD -- engine/Cargo.lock engine/Cargo.toml` exits 0; `cargo test --locked` passes.
- **Committed in:** `caf318a1`

**2. [Rule 2 - Missing critical] Fail-closed store checks the plan did not list**
- **Found during:** Task 3
- **Issue:** a requested ID with two rows, or a requested row with null content, would otherwise be silently resolved to one value or an empty string, which would corrupt a cross-check.
- **Fix:** both are `ChunkTextFailure::Store` errors (exit 1). A defensive re-validation of IDs also sits inside `inspect_chunk_text`, so a caller cannot bypass `read_chunk_id_file`. An empty ID file is an input error (exit 2).
- **Files modified:** `engine/src/bin/inspect_lancedb.rs`
- **Committed in:** `caf318a1`

### Judgement calls inside the plan's latitude

- **Exit 3 still writes the rows that were found.** The plan says "exits non-zero when a valid requested ID is missing"; it does not say whether partial rows are emitted. Callers must check the exit status. The stderr summary carries counts only.
- **`render_default_scenarios` is `async`** (the plan wrote `-> String`) because the scenarios drive async nodes and `WorkflowRunner`; the pin is a `#[tokio::test]`.
- **`add_nodes` helper extracted from the test `fixture`** so a test can add a row after a recorded table version (the "row added after N is not emitted" behaviour).
- **TDD in a `tdd_mode: false` run:** the RED commit (`c4979b88`) carried compile stubs in `inspect_lancedb.rs` that return inert values, so all nine tests failed on assertions (parse `unwrap` on an unknown-argument error, empty vectors, `Store("not implemented")`) rather than on compile errors. No gate applies, noted for the record.
- **Root-pin guard:** I ran a shortened equivalent (pinned toplevel equals actual toplevel) before each commit rather than the full block verbatim; the check it performs is the same equality and passed every time.
