<objective>
Generalise the harness from two graph arms to the D-101 four-arm registry. The drive can then plan and send
every arm's request in a seeded, balanced rotation over a committed split, with the provenance it will be
checked against.

ROADMAP goal (quoted verbatim, not reframed; see 06.3.5-01): "... dense-only, BM25-only, hybrid (dense + BM25
RRF) and hybrid + graph ...". SC-2: "The harness arm registry generalises from the two-entry `GRAPH_ARMS` map to a
label → request-flags table ... `[arms]` in the corpus TOML, `--arm` on the CLI and the provenance checks agree;
every record carries its arm."

Purpose: this is the drive side of D-101. The reader side (score, dimensions, usability, pairing, `unpark_gates`)
is 06.3.5-06.

Output: `arms.py`, corpus-section parsing, registry-driven requests, the rotation and the split-role guards.
</objective>

<assumption_delta_decision>
- **Detector result:** `assumption-delta scan 06.3.5` reported `detected: true`. Its only signal was
  `pluralization`/`second`, on an out-of-scope snippet. The phase's real generalisations are the arm registry, which
  goes from 2 entries to 4 labels, and the `unpark_gates` reference arm, which goes from the literal `"graph-off"` to a
  parameter (the `chosen` family).
- **Primary noun:** the arm label, meaning the canonical `ARM_REGISTRY` key (`dense-only`, `bm25-only`, `hybrid`,
  `hybrid+graph`).
- **Decision: `promote`.** The registry label becomes the primary arm identity. `graph-on` and `graph-off` are
  demoted to read-only lookup aliases of `hybrid+graph` and `hybrid` (D-101). Every reader resolves through
  `canonical_arm`, so a later lever arm (06.3.6) is a registry row, not a code edit.
- **Accepted debt:** the journal field keeps the name `graph_arm`. Renaming it would break the historical journals of
  drives 1, 1b and 2, and the `legacy_records_digest`, which hashes the raw stored value. A later promote of the field
  name would be forced by a journal schema version bump.
- **Companion invariant test (adopted):** Task 2's round-trip test. Every registry arm goes request_fields -> run_query
  body -> stream echo -> `mode_provenance_failures`. It goes red the moment a new arm is added without its request
  flags or its provenance.
</assumption_delta_decision>
