    1. **Full suites on HEAD.**
       - `cargo test --manifest-path engine/Cargo.toml --locked && sh scripts/engine-test-targets.sh`
       - `bash -c "cd gateway && go test -count=1 -p 2 ./..." && sh scripts/gateway-test-targets.sh` (about 7 min; always `-count=1`, since the Go cache masks config, memory go-test-cache-masks-config)
       - `uv run --project eval pytest eval/tests -q -p no:cacheprovider` (about 5.5 min; never bare `pytest` from the root)
       - `bash -c "buf generate && git diff --quiet -- engine/src/pb gateway/proto"`
    2. **Note-10 acceptance re-run.**
       - `bash .planning/phases/06.4-docs-suite-verified-quickstart-debt-backlog-promotion-and-v1/research/rescore_journal_only.sh` must print `dimensions equal: True` and `result_hash equal: True`;
       - `uv run --project eval python .planning/phases/06.4-docs-suite-verified-quickstart-debt-backlog-promotion-and-v1/research/zero_tolerance_scan.py` must exit 0.
    3. **The file list.** Product paths changed by the wave, deletions excluded, generated bindings excluded. Write it to
       `data/qs-evidence/review-files.txt`:
       `git diff --name-only --diff-filter=d 234578f2..HEAD -- engine gateway proto eval/src eval/scripts eval/tests config scripts | grep -v -E '^(engine/src/pb/|gateway/proto/)' | paste -sd, -`.
       `234578f2` is the planning HEAD before plan 06.4-01; every commit between it and the wave's first code commit is
       planning-only.
    4. **The review.** Run `/gsd-code-review 06.4 --files=<that comma list>` in the `=` form, with no `.claude/` or
       `.planning/` path in the list.
    5. **Fix cycle.** Run the code-review fix step for the findings, which writes `06.4-REVIEW-FIX.md`, and commit the
       fixes. Then run the review again with the same `--files=` list plus any file the fixes touched. A fix that
       changes a counted engine or gateway test updates `scripts/engine-test-targets.sh` /
       `scripts/gateway-test-targets.sh` in the same commit.
    6. **Steps 1 and 2 again** on the post-fix HEAD.
    7. **Pass rule.** The re-review leaves no open critical or warning finding, or the owner dispositions each remaining
       one in `06.4-REVIEW.md`'s findings ledger. Info findings may stay open with a disposition and are carried into
       plan 06.4-16's ledger work.

    If a suite or the acceptance fails and the fix is not obvious, stop for the owner. The gate never passes on red.
