## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `cargo test` (Rust engine, tonic 0.14.6, lance via `lancedb`), `go test` (Go gateway, `go 1.25.0` in `gateway/go.mod`), pytest via `uv run --project eval` (Python harness). Proto is regenerated with `buf generate` (remote plugins; needs network; host `buf 1.72.0`). |
| **Config file** | `engine/Cargo.toml`, `gateway/go.mod`, `eval/pyproject.toml`, `buf.gen.yaml`, `scripts/engine-test-targets.sh` (engine test-count invariant, TOTAL 937 at HEAD `d209331a`: lib 822, inspect_lancedb 58, reconcile_eval_store 18, backfill_evidence_metadata 14, config_startup 25), `scripts/gateway-test-targets.sh` (`EXPECTED_TOTAL=124`) |
| **Quick run command** | Engine: `cargo test --manifest-path engine/Cargo.toml --locked <filter>`. Gateway: `cd gateway && go test -count=1 -run <Name> ./...`. Harness: `uv run --project eval pytest eval/tests/<file>.py -q -p no:cacheprovider` |
| **Full suite command** | `cargo test --manifest-path engine/Cargo.toml --locked && sh scripts/engine-test-targets.sh`; `(cd gateway && go test -count=1 ./...) && sh scripts/gateway-test-targets.sh`; `uv run --project eval pytest eval/tests -q -p no:cacheprovider`. **Always `-count=1` for Go**: the Go test cache masks config changes (`.planning/config.json` `workflow.test_command` omits it, so run the gateway half by hand). **Never bare `uv run --project eval pytest` from the repo root**: it collects `scripts/` and reports 5 pre-existing Phase-02 live-evidence failures. |
| **Estimated runtime** | Harness about 320 s on a fresh Windows clone (`2193 passed in 321.12s`, run it as its own Bash call). Gateway about 7 min with `-count=1` (gateway package 413 s). Engine suite not timed at research; a cold release build of the engine takes about 21 min (`research/cold_cargo_build.out:28`). |

**Test-count invariants are part of every gate.** A plan that adds, removes or moves an engine or gateway test bumps
`scripts/engine-test-targets.sh` / `scripts/gateway-test-targets.sh` with an invariant-history line naming the plan and
task, in the same commit as the tests (the convention every 06.3.x plan followed).

---

## Sampling Rate

- **After every task commit:** the quick command for the touched area (engine filter, `go test -count=1 -run`, targeted
  pytest file).
- **After every plan wave:** all three full suites, including both test-count scripts.
- **Code-review gate (D-205 step 2, SC-8):** the full suites are green on the code-first wave's last commit before the
  orchestrator-run `/gsd-code-review`, and again after its fix cycle.
- **Before `/gsd-verify-work`:** all full suites green.
- **Max feedback latency:** about 420 s (the gateway full suite); task-level quick commands stay under 120 s.
