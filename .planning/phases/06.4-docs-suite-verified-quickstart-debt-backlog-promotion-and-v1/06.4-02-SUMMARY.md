## Contract C1: the coverage line format (plans 06.4-05, 06.4-09 and 06.4-11 quote it)

Every rebuild swap logs, at INFO, in the message text:

```
index.swap.metadata_coverage: documents_with_metadata=<n> documents=<m>
```

For the 5-document quickstart sample: `index.swap.metadata_coverage: documents_with_metadata=5 documents=5`. A falling covered ratio also logs a WARN:

```
index.swap.metadata_coverage_fell: prior_documents_with_metadata=<a> prior_documents=<b> documents_with_metadata=<c> documents=<d>
```

An empty to non-empty swap also logs the INFO `evidence_metadata became available again: the swapped-in corpus snapshot holds document metadata`. The test `d203_every_swap_logs_coverage_at_info` asserts these substrings on output captured with ANSI styling on. The coverage line appears only after a rebuild swap, so it is absent from the empty-store start below.

The order differs from the pre-plan startup in one place: `Prompt tokenizer ready` now comes before `Staged ingestion jobs replayed` (the warm-up and the bind moved ahead of the replay). `build_ms` varies per run.
