# Phase 06.4 Plan 04: Stack Preflight, Re-score Checker, Measure Guard and IN-05 Summary

**`lancet-eval preflight --stack` checks a running quickstart stack with no eval store (drive environment, reachability, then every arm over a `qs-` canary manifest), `compare_rescore.py` proves a re-score reproduces the published values, `lancet-eval measure` refuses held-out and role-less corpora without a committed pre-registration token, `drive_measurement_pass.py` is gone, and `gen_paper_golden.py` hashes the fetched file before it executes it.**

## Accomplishments

- **D-200 stack preflight.** `run_stack_preflight(settings, canary_path, client=None)` runs `check_drive_environment`, then both results of `check_gateway_and_engine`, then `check_arm_mode_canaries(arms=tuple(ARM_REGISTRY), split_path=None)`. A drive-environment failure returns that one result before any client is built; an unreachable or unhealthy stack returns before any canary. There is no `openrouter_api` check and nothing is written under `eval/runs/`. The request count is rows times nine arms (27 for the three-row quickstart manifest) and is stated in the docstring.
- **Split-less canaries.** `check_arm_mode_canaries(split_path=None)` skips `load_split` and the banned-ID block and refuses any ID without the new `QUICKSTART_ID_PREFIX = "qs-"` before any request, naming the IDs. A given split path behaves as before (`test_preflight_canary.py` is unedited and green).
- **CLI.** `preflight --stack [--canaries PATH]`, default manifest `eval/corpora/quickstart/canary.arms.jsonl`; one table row per check, exit 1 on any failure, the key is never printed.
- **Re-score checker.** `eval/scripts/compare_rescore.py <committed_run> <rescored_dir>` (stdlib only, read only): equal `dimensions` and `metadata.result_hash`, and differing metadata keys limited to `commit_sha`, `run_date`, `dependency_lock_hash`; otherwise one line per failing reason and exit 1.
- **D-211.** `_enforce_measure_split_role(corpus_name, preregistered_override)` sits after `require_index_identity` and the stage-cap check and before `run_dir.mkdir`; it refuses `heldout` and role-less corpora with "refusing to measure". `--preregistered-override TOKEN` accepts only a `PREREGISTRATION_*` constant that `preregistration.resolve` accepts and `gitcheck.introducing_commit` can date; an accepted override is written to `run_record.json` and `measurement.json` as `preregistered_override`. `drive_measurement_pass.py` is deleted in the commit that drops its drive site from `test_every_wire_metadata_field_is_mapped_at_each_drive_site`.
- **D-212 IN-05.** `OFFICIAL_FILE_SHA256` equals the committed fixture header's `official_file_sha256`; `load_official` raises `SystemExit` naming both digests before `exec_module`.

## Issues Encountered

- **The plan's second Task 1 `<verify>` command exits 120, and the code is not at fault.** `bash -c "set -o pipefail; uv run --project eval lancet-eval preflight --help 2>&1 | grep -q -- '--stack'"` returned `plan_rc=120`. The cause is `grep -q` closing the pipe at the first match, so Python raises a broken pipe on exit and `pipefail` reports it. Evidence: `lancet-eval preflight --help > file` exits 0, and `--stack` appears in that file at line 15 (and `--canaries` at line 21) with no ANSI escapes. This check is therefore NOT reported as passed as written; the equivalent without the early-closing `-q` finds the flag. The pytest half of that verify (stack preflight, checker, existing canary tests) passed. The command was not rewritten in the plan.
- Working copies are CRLF with an LF index (`core.autocrlf=true`); edits went through a CRLF-preserving script, and git reports only the usual "LF will be replaced by CRLF" notices.
- `eval/src/lancet_eval/cli.py`, `measure.py`, and `tests/test_measure.py` carry pre-existing `ruff` E501/E303 findings elsewhere in the files; none is in this plan's lines, and they were left alone (scope boundary).
