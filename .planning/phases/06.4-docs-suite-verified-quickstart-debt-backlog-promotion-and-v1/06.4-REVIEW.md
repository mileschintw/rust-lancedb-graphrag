## Warnings

### WR-07: The SVG cross-check accepts a Holm-significant point drawn open with any fill other than exactly `#ffffff`

**File:** `eval/tests/test_forest_plot.py:319-320`
**Status:** partially fixed. The value-text, x-position and shape parts of the original WR-07 are closed (see the
closure evidence above). The significance-fill part remains open.

**Issue:** `test_d218_each_drawn_cell_matches_its_json_row` decides "filled" with a denylist:

```python
filled = point.get("fill") != "#ffffff"
assert filled == (row["mark"] == "holm-significant"), where
```

Any fill other than the exact lowercase string `#ffffff` counts as filled. The scratch mutation probe confirmed the gap.
A holm-significant point rewritten with any of these fills draws an open marker, and the test still passes:
- `fill="none"`;
- `fill="white"`;
- `fill="#FFFFFF"`;
- `fill="transparent"`.

Only the opposite direction is enforced: an open-mark row given a non-white fill fails. The fix report says "a filled
point must coincide exactly with a `holm-significant` row". That overstates what the test enforces: its own probe only
filled a descriptive point, which is the direction that works.

A template or generator edit could swap the open fill for `none`, or change its case. Then the legend's "filled =
Holm-significant" claim could break on the significant rows with no test failing. That is the drift class D-218 and
WR-07 exist for.

**Fix:** Assert the exact fill for each mark, using the generator's colour contract rather than a negative test:

```python
fill = (point.get("fill") or "").lower()
stroke = (point.get("stroke") or "").lower()
if row["mark"] == "holm-significant":
    assert fill == stroke == "#1f4e79", (where, fill, stroke)
else:
    assert fill == "#ffffff", (where, fill)
```

### IN-12: The WR-08 decision check can raise an uncaught `TypeError`, and its "not evaluable" case is not the stored value

**File:** `eval/scripts/render_forest_plot.py:98-101,116-120`, `eval/tests/test_forest_plot.py:342`
**Status:** new. Introduced by the WR-08 fix diff (`851f156a`).
**Issue:**
- **Unhashable decision.** `comparison.get("decision") in DECISION_MARKS` is a dict-membership test. A `decision` that
  is a list or an object raises `TypeError: unhashable type`, not `SourceLayoutError`. `main` catches only
  `(SourceLayoutError, KeyError, IndexError)` (`:469`), so that malformed source escapes as a raw traceback. The `_mark`
  this check replaced compared with `==` and could not raise. No current source row holds such a value.
- **Wrong "not evaluable" string.**
  - The generator comment (`:98-100`), the teeth case `("baseline", "decision", "not evaluable")` (`:342`) and the
    fix report all call the comparison modules' third decision `"not evaluable"`.
  - The stored constant is `DECISION_NOT_EVALUABLE = "not evaluable: coverage"` (`eval/src/lancet_eval/comparison.py:67`,
    `eval/src/lancet_eval/lever_comparison.py:82`).
  - Behaviour is still correct, because the allowlist refuses both strings. But the parametrised case does not exercise
    the value a real run would store, and the comment names a value that does not exist.

**Fix:**

```python
decision = comparison.get("decision")
_expect(
    isinstance(decision, str) and decision in DECISION_MARKS,
    f"{source} {path} decision is {decision!r}, expected one of {sorted(DECISION_MARKS)}",
)
```

- Change the teeth case to `"not evaluable: coverage"`, and add a `["significant"]` case.
- Correct the comment at `:98-100` to quote `"not evaluable: coverage"`.
