### WR-01 (compare_rescore fail-open): CLOSED

Evidence, `eval/scripts/compare_rescore.py:45-70`:
- Same-directory input is refused (`:46-48`) after both reports load. It uses `resolve()`, so a symlink or `..` alias to the same directory is caught.
- `dimensions` must be a non-empty list or dict on both sides (`:53-57`). The `dims_old != dims_new` comparison runs only when both are valid, so one missing side gives a clear "no scored dimensions" reason instead of a misleading "differ".
- `metadata.result_hash` must be a non-empty string on both sides (`:67-70`).
- The metadata-not-an-object early return still comes before the hash loop, so there is no `.get` on a non-dict.
- Four tests pin the new behaviour (empty objects, no dimensions, no result_hash, same directory). Each asserts exit 1 and that the "reproduces" line is absent.
- Real committed run-of-record reports use top-level `dimensions` and `metadata.result_hash`, so the legitimate path (D-200/D-201) is unaffected.

One limit that is inherent and not a defect: a byte-for-byte copy of the committed directory passed as the "re-scored" directory still reproduces. The script cannot tell a copy from a re-score.

## Info

### IN-01 (carried forward, still open): `explicit_field_failures` "graph ran" evidence is effectively vacuous for `graph_seed_count`

**File:** `eval/src/lancet_eval/arms.py:487-497`
**Issue:** Unchanged by the fix cycle. The docstring says the seed count is always on the wire when metadata exists, so the "graph node ran" branch reduces to "workflow metadata exists". The real discrimination is the absence of notices 18 and 25. A future off path that emits no notice would slip through, and a test pins a measured zero seed count as proof the node ran.
**Fix:** Count only `graph_node_count > 0` or a graph failure notice as evidence. If seeds are the intended proof, assert `graph_seed_count > 0`.

### IN-02 (carried forward, still open): `load_official` verifies the SHA-256 and then re-opens the path for execution

**File:** `eval/scripts/gen_paper_golden.py:61-79`
**Issue:** Unchanged. The hash is taken from `path.read_bytes()` and then `spec_from_file_location(path)` / `exec_module` re-reads the file, so there is a TOCTOU window. The comment promises a tampered download never runs.
**Fix:** Compile and execute the bytes that were hashed (`exec(compile(data, str(path), "exec"), module.__dict__)`), and catch `OSError` on the read.

### IN-03 (carried forward, still open): compiled-in `context_default_enabled = true` is the opposite of the shipped default

**File:** `engine/src/config.rs:204-221`, `config/config.toml:137-148`
**Issue:** Unchanged. A config that lacks the key (an older operator copy, a pre-6.4 `LANCET_CONFIG_DIR`, no file) silently runs graph-on with neither code 25 nor a startup line. Eval arms are protected by explicit fields; a plain API client is not.
**Fix:** Log the resolved value once at startup (for example in the "Rust RAG Engine serving" line), or log a WARN when the key is absent and the compiled-in `true` is used.

### IN-04 (carried forward, still open): the port is bound while the replay can still block

**File:** `engine/src/main.rs:186-229`
**Issue:** Unchanged. `TcpIncoming::bind` precedes the replay `send(...).await` loop, so with a full queue the kernel accepts connections that nothing serves. A TCP-level readiness probe sees the engine as up before gRPC is serving. This is the intended D-202 trade-off, so it is a readiness-contract note.
**Fix:** State in the quickstart that readiness is the `Rust RAG Engine serving` line or a successful gRPC health RPC, not an open port. Optionally move the replay loop into a spawned task.

### IN-05 (new, from the fixer's residual): the `--preregistered-override` help and the no-override refusal omit the held-out binding

**File:** `eval/src/lancet_eval/cli.py:1482-1493`, `eval/src/lancet_eval/measure.py:699-709`
**Issue:** Classified info, not warning. The guard itself is correct and fail-closed, and the mismatch error names the token the corpus declares, so the operator gets a precise message at the point of failure. Only the help text and the generic "no override given" refusal say "any committed `PREREGISTRATION_*` constant", which is now wrong for a held-out corpus. Cost: one extra failed invocation, caught before any request or journal I/O.
**Fix:** Reword both to say that a held-out corpus needs its own declared `[preregistration] token`, and that a corpus with no `[split]` accepts any committed token.

### IN-06 (new, from the fixer's residual): other engine-spawning Go tests can still reach the real rerank endpoint

**File:** `gateway/main_test.go:4316-4324` (`TestRAGQueryClientDisconnectCancelsRustWorkflow`; the repo-wide grep shows no other `ragChildEnv(` engine spawn)
**Issue:** Classified info, not warning, because the hermeticity gap here does not affect any assertion and does not predate this fix in kind:
- The engine env sets `OPENROUTER_API_KEY=test-key` and no `LANCET_CONFIG_DIR`, so the committed default levers (rerank) make the engine call `https://openrouter.ai/api/v1/rerank` with the dummy key and the fixture query.
- The test asserts only chat-call cancellation and a chat-call count. The rerank call is bounded by `rerank_timeout_ms` (2286 ms) and degrades on failure, well inside the test's 10 s chat wait.
- The cost is a non-hermetic outbound request to a third party (and a latency dependency) in an otherwise local test. The prior WR-03 was a warning only because the assertion's meaning depended on that call.

**Fix:** Extract the mocked-config setup from `TestRAGQueryCrossRuntime` (`:2653-2680`) into a helper and use it in both engine-spawning tests, or pass `disable_default_levers: true` in the disconnect test's request body, since it does not need rerank.
