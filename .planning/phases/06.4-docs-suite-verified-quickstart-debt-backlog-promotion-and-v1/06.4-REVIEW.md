### WR-05: `test_notice_docs` checks that the doc states the `answer_basis` early return, but never that the engine still has it

**File:** `eval/tests/test_notice_docs.py:108-116,169`
**Issue:** The doc makes this claim at `docs/api-contract.md:147-149`: "`degraded_mode` is true whenever `answer_basis`
is not `retrieval` ... This is the early return in `derive_degraded_mode`." The test only asserts that the sentence
fragment is in the doc (`:169`).

`_engine_degraded_classes` slices the function from `match code {` onward. That skips the guard at
`engine/src/workflow/mod.rs:352-354`:

```rust
if answer_basis != AnswerBasis::Retrieval { return true; }
```

If that guard were deleted or inverted, the doc would be false and every test in this module would still pass. The
module docstring says the test exists so that "neither a new proto value nor a moved match arm can land without the
doc changing too". The early return is part of the same published contract.

**Fix:** Assert the guard in the sliced function, before the match:

```python
def _engine_has_basis_early_return() -> bool:
    text = _read(_WORKFLOW)
    start = text.find("pub fn derive_degraded_mode")
    body = text[start:]
    head = body[: body.find("match code {")]
    return re.search(
        r"if\s+answer_basis\s*!=\s*AnswerBasis::Retrieval\s*\{\s*return\s+true;\s*\}", head
    ) is not None

# in test_d76_degraded_mode_column_matches_derive_degraded_mode:
assert _engine_has_basis_early_return(), "derive_degraded_mode lost its answer_basis early return"
assert _ANSWER_BASIS_FRAGMENT in _doc_text()
```

The fix is test-only and does not touch `engine/`.

### WR-06: The span-table checker silently skips any attribute that is not a backticked `` `k` = `v` `` pair

**File:** `eval/tests/test_observability_doc.py:32,131-137`
**Issue:** `_row_errors` checks only what `ATTRIBUTE.findall(attributes_cell)` matches. Anything else in the cell is
never compared to the trace, and none of these fail:
- an unbackticked value (`` `lancet.rerank.latency_ms` = 256 ``);
- a different separator (`` `k`: `v` `` or `` `k`=`v` ``);
- prose with a number in it.

The module docstring promises "every `key` = `value` pair in the attributes cell must equal that span's tag" and "a
value cannot be invented" (D-214). An edit that drops one pair of backticks makes that value unchecked, and nothing
reports it. All 28 current rows happen to be well-formed.

**Fix:** After removing the matched pairs and their separators, require the cell to be empty:

```python
residue = ATTRIBUTE.sub("", attributes_cell)
if residue.replace(",", "").strip():
    errors.append(f"{name!r}: unchecked text in attributes cell: {residue.strip()!r}")
```

Add an "unbackticked value" case to `test_a_row_naming_a_span_absent_from_the_trace_json_fails` so the teeth test
covers it.

### WR-07: Nothing tests that the drawn SVG matches the JSON rows; the committed-asset test is circular

**File:** `eval/tests/test_forest_plot.py:107-129,160-205,208-216`
**Issue:** D-214 ("never re-derive") is enforced only for the sidecar `eval-forest.json`: every row's
`delta/ci_lo/ci_hi` is re-read from its source path. The SVG is checked only for this structure:
- cell keys and `data-mark`;
- one `line.ci` per plotted cell;
- panel order, caption and legend text.

Three kinds of error ship undetected:
- the printed value text (`_value_text`), for example `ci_lo` and `ci_hi` swapped, a dropped sign, or the "Holm" suffix
  on the wrong row;
- the x mapping (`x_of`), for example a point outside its whisker or a panel offset swapped;
- the fill and shape of the significance marking.

`test_d218_committed_assets_equal_a_fresh_render` cannot catch these. Both sides come from the same code, so after a
regenerate it passes. The independent re-parse in this review found the current SVG correct. The gap is in the test,
not in today's output.

**Fix:** Cross-check each SVG cell against its JSON row:

```python
for row in rows:
    cell = cells[(row["group"], row["panel"], row["arm"])]
    if row["delta"] is None:
        continue
    value = _by_class(cell, "text", "value")[0].text
    assert f"[{row['ci_lo']:.4f}, {row['ci_hi']:.4f}]".replace("-0.0000", "0.0000") in value
    assert ("Holm" in value.split("]")[1]) == (row["mark"] == "holm-significant")
    ci = _by_class(cell, "line", "ci")[0]
    x1, x2 = float(ci.get("x1")), float(ci.get("x2"))
    point = next(e for e in cell.iter() if "point" in (e.get("class") or "").split())
    cx = float(point.get("cx") or point.get("points").split()[0].split(",")[0])
    assert x1 <= cx <= x2
    filled = point.get("fill") != "#ffffff"
    assert filled == (row["mark"] == "holm-significant")
```

### WR-08: The generator never checks the comparison reference or the decision vocabulary, and the test mirrors its rule

**File:** `eval/scripts/render_forest_plot.py:97-98,101-125`, `eval/tests/test_forest_plot.py:173-177`
**Issue:** Two source-layout checks are missing:
- **Reference.** Every group title and the caption say "vs same-day hybrid". `_family_row` copies
  `comparison["reference"]` and never checks it. If a family row's reference were anything other than `hybrid`, it
  would be plotted under the "vs hybrid" header. The descriptive path does check its label
  (`_descriptive_row`, `:132-135`), so the two paths are inconsistent.
- **Decision.** `_mark` maps every decision other than exactly `"significant"` to `not-significant`. A stored
  `"Significant"`, `"significant (Holm)"` or `None` would silently draw an open circle.

The test recomputes the same rule at `:176` (`"holm-significant" if row["decision"] == "significant" else
"not-significant"`), so it agrees with whatever the generator does.

The hard-coded `significant` list at `:178-187` pins today's five cells. That is the only real guard, and it does not
cover a decision value outside the vocabulary. The module docstring claims `SourceLayoutError` catches "a source file
[that] does not hold the arms at the paths this generator reads". Both of these drifts get past it.

**Fix:** Fail closed in `_family_row`:

```python
_expect(comparison.get("reference") == "hybrid",
        f"{source} {path} reference is {comparison.get('reference')!r}, expected 'hybrid'")
_expect(comparison.get("decision") in ("significant", "not significant"),
        f"{source} {path} decision is {comparison.get('decision')!r}")
```

In the test, assert `row["decision"] in {"significant", "not significant"}` for family rows, and assert
`row["reference"] == "hybrid"` for all 16 plotted rows. Do not re-derive the mark from the same predicate.

### IN-07: The severity and gRPC-type columns of `api-contract.md` are published contract but untested

**File:** `eval/tests/test_notice_docs.py:71-82,182-190`
**Issue:** `_doc_notice_rows` skips the severity column (`[^|\n]*`), and `_proto_message_fields` keeps only field
names. Two published claims are therefore unchecked:
- The doc says "The severity column gives the severity the shipped engine emits the code with" (`api-contract.md:122`).
- The request table's `gRPC type` column publishes field presence (`optional bool` against `bool`). That is

Every severity was verified by hand against the emission sites, and every type against the proto. Both match today.

column. Severity would need engine-source scraping of `notice(NoticeCode::X, ..., NoticeSeverity::Y)` call sites,
which is fragile. At minimum, pin `allow_model_only`, `disable_graph_context` and `disable_default_levers` as
`optional bool` in both the proto and the doc.

### IN-08: `render_forest_plot.main` catches only three exception types, and it writes the SVG before the JSON

**File:** `eval/scripts/render_forest_plot.py:248-251,449-462`
**Issue:**
- **Uncaught exceptions.** These escape as raw tracebacks, not as the `render_forest_plot: ...` message and exit 1:
  - `FileNotFoundError` or `json.JSONDecodeError` from `_load`;
  - `AttributeError` or `TypeError` when `families[i]` is not an object;
  - `ValueError` from `max()` when no row is plotted;
  - `ZeroDivisionError` in `x_of` when every CI bound is 0 (`_domain` returns 0).
- **Partial write.** `_write(out_svg)` runs before `_write(out_json)`, so a failure writing the JSON leaves a new SVG
  beside a stale JSON.
- **`-OO`.** Under `python -OO`, `__doc__` is `None` and `__doc__.split(...)` raises.

None of these happens with today's frozen inputs.
**Fix:**
- Widen the `except` to `(SourceLayoutError, KeyError, IndexError, TypeError, AttributeError, ValueError, OSError)`.
- Add `_expect(half > 0, ...)` in `_domain`.
- Render both strings before writing either file.
- Use a literal argparse description.

### IN-09: `test_d218_the_generator_reads_only_the_two_run_files` checks imports, not reads

### IN-10: The observability test checks neither the caption trace IDs nor the "(not exported)" parent claim

**File:** `eval/tests/test_observability_doc.py:117-128`, `docs/observability.md:83,171`
**Issue:**
- **Trace IDs.** The captions quote trace `6b986b3d...` and `120b35f5...`. The test never compares them with

- **Parent claim.** The parent check accepts "client span (not exported)" whenever `_parent_of` returns `None`. That

### IN-11: `_render` captures the generator's stderr and then hides it on failure

**File:** `eval/tests/test_forest_plot.py:38-43`
**Issue:** `subprocess.run(..., check=True, capture_output=True)` raises `CalledProcessError`, and its `str()` omits
stderr. The module-scoped fixture fails, and the generator's `render_forest_plot: <reason>` message is not in the
pytest output.
**Fix:** Use `check=False`, then `assert proc.returncode == 0, proc.stderr.decode()`.
