### WR-01: `compare_rescore.py` reports "reproduces" when `dimensions` or `result_hash` is missing from both reports

**Files modified:** `eval/scripts/compare_rescore.py`, `eval/tests/test_compare_rescore.py`
**Commit:** f484be6e
**Status:** fixed: requires human verification (a fail-open condition, logic change)
**Applied fix:** `compare()` now fails closed. It refuses when the two directories resolve to the same path, when either report has no non-empty `dimensions` (list or dict), and when either report's `metadata.result_hash` is missing or not a non-empty string. The existing "dimensions differ" and "result_hash differs" checks are unchanged. The module docstring states the new requirements. Four tests were added: empty objects, two reports without `dimensions`, two reports without `result_hash`, and the same directory passed twice. `eval/tests/test_compare_rescore.py`: 19 passed.

### WR-02: The D-211 `--preregistered-override` matches the spec but is not bound to the corpus and is weaker than the sibling guard in `run`

**Files modified:** `eval/src/lancet_eval/measure.py`, `eval/tests/test_measure.py`
**Commit:** 1defd228
**Status:** fixed: requires human verification (guard logic)
**Applied fix:**
- `_override_problem` keeps the `PREREGISTRATION_` prefix check and `preregistration.resolve`. It replaces the bare `introducing_commit` lookup with `gitcheck.preregistration_problems((token,), require_clean_tree=True, unchanged_since_introduction=True)`. The override therefore needs an introducing commit that is an ancestor of HEAD, a clean `eval/src`, and an assignment unchanged since introduction, the same proof `run` demands.
- `_enforce_measure_split_role` now requires, for a `heldout` corpus, `preregistered_override == config.preregistration_token`. A valid but foreign token (for example `PREREGISTRATION_06_3_5` on `multihop_rag_levers_heldout`) is refused, and the message names the token the corpus declares.
- A role-less corpus declares no role to bind to, so it still accepts any committed token. The docstring now says so.
- No `PREREGISTRATION_*` constant was touched, and every D-211 refusal and its tests still pass.
- Tests: four new tests cover the foreign token on a held-out corpus, a dirty tree, a drifted assignment and a non-ancestor commit. A `_source_tree_clean` fixture pins `gitcheck.is_clean` for the success-path D-211 tests, so they no longer depend on the live working tree.
- Full suite: `UV_PROJECT=./eval uv run pytest eval/tests -q -p no:cacheprovider`, 2323 passed.

**Behaviour change to be aware of:** a supplied override, even on a dev corpus where none is needed, is now also refused while `eval/src` has uncommitted changes. This matches `run`'s drive-time gate.

**Residual:** the `--preregistered-override` CLI help and the final "no override given" refusal message do not mention the held-out binding to the corpus's own token. Only the mismatch error does.

### WR-03: The Go cross-runtime `d198_opt_out_runs_no_lever` check only discriminates through an uncontrolled real-network call

**Files modified:** `gateway/main_test.go`
**Commit:** 8c08d540
**Status:** fixed
**Applied fix:** `TestRAGQueryCrossRuntime` no longer reaches the real `openrouter.ai`.
- The suggested `LANCET_OPENROUTER__RERANK_ENDPOINT` override cannot work. `engine/src/config.rs` documents the rerank endpoint as "not overridable by environment" (it carries the bearer key), and the first attempt confirmed it: the call still went to the real endpoint and came back as a 401 `RERANK_DEGRADED`. The test therefore writes a copy of the committed `config/config.toml` into the test temp dir with only the `rerank_endpoint` line pointed at the local mock, and sets `LANCET_CONFIG_DIR` to it. `LANCET_CONFIG_DIR` was added to the `assertCleanRAGChildEnv` allowlist. The default levers, budgets and graph default stay the committed ones, and no engine code changed.
- The mock serves `POST /api/v1/rerank`. It checks the model, a non-blank query and non-empty documents, counts calls in a new `ragMockState.rerankCalls`, and returns the fused order with falling scores, so the existing citation assertions are unaffected.
- The baseline request, which names no opt-out, is the positive control. It asserts that the snapshot echoes `rerank`, that there is no `RERANK_DEGRADED` notice, and that the mocked rerank endpoint was called exactly once.
- `d198_opt_out_runs_no_lever` keeps its two original assertions and adds that the mocked rerank call count did not move. That is a direct discriminator, not "no degrade notice".
- No top-level Go test was added, so `scripts/gateway-test-targets.sh` is unchanged. `sh scripts/gateway-test-targets.sh` reports TOTAL 124 and the invariants pass.
- `cd gateway && go test -count=1 -p 2 ./...` passes in all packages, and `TestRAGQueryCrossRuntime` with its two subtests passes against a fresh worktree-built engine.

**Residual (outside the finding's named test):** `TestRAGQueryClientDisconnectCancelsRustWorkflow` (the engine env near `main_test.go:4244`) and the other tests that start a real engine also set no rerank config, so with the default levers they can still reach the real `openrouter.ai`. Applying the same mocked `LANCET_CONFIG_DIR` there is a candidate follow-up.
