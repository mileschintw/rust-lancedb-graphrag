## Issues Encountered

- **Line endings (note for plan 06.4-11).** `core.autocrlf` is `true` on the Windows dev repository, so git warns that LF will become CRLF in the working copy the next time git touches the new `.sh` files. The committed blobs are LF and the WSL clone checks out LF, but `qs-wsl-run.sh` and its siblings run from the dev copy through `/mnt/d`; a CRLF rewrite there would break them. If plan 06.4-11 hits that, run `dos2unix` on the scripts or add a `*.sh eol=lf` rule.
- The first install call exceeded the Bash tool's 120 s foreground limit and was moved to the background; the retry ran under `timeout 110`.
