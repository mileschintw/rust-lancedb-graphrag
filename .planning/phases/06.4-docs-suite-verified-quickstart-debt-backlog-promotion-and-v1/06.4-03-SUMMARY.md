## Decisions Made

See `key-decisions`. The one worth carrying forward: **`graph_seed_count` is always on the gateway wire when metadata exists** (`gateway/internal/sse/sse.go:137`, an unconditional map key, zero included), so "the graph seed count is present" is true for a graph-off response too. For graph-on arms the real discriminator is the absence of notices 18 and 25; the seed/node-count half only catches a response with no metadata at all. A stronger rule (`seed_count > 0`) would false-fail a legitimate graph-on query whose seeds found nothing, which would break the quickstart preflight on a small sample, so the plan's wording is kept.
