<assumption_delta_decision>
The detector fired on the prose word "also". The semantic change is real, though: D-207 turns a fixed "absent means
graph on" into a configured default that is now off, and D-198 adds an opt-out from the configured default levers.

- **Primary noun:** the request's *effective configuration*, meaning its graph state and admitted lever set. It is
  resolved once at admission from the configured default plus the explicit request override.
- **Decision:** `promote`. The configured default (`[engine.graph] context_default_enabled`, `[engine.levers]
  defaults`) becomes the primary source for an absent field. The request fields are demoted to explicit overrides, in
  the D-12 pattern `allow_model_only` already uses. A second "graph on" path is not kept alongside the old fixed
  default.
- **Rationale:** keeping "absent = graph on" beside a new config key would let a configured default exist that a
  default request could never receive, which is exactly the add-alongside failure.
- **Companion invariant test (accepted):** every canonical arm round-trips its declared graph state and lever set
  through the snapshot echo and notices. That is the D-199 per-arm canary, implemented in plan 06.4-03 and run live by
  the per-platform preflight (plans 06.4-09 and 06.4-11).
