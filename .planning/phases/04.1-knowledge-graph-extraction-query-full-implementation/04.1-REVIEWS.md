## Antigravity Review

### Executive Summary & Plan Set Assessment

Phase 04.1 is designed to transition Lancet's knowledge graph capability from a feature-gated proof-of-concept (`graph-spike`) into a fully integrated, production-grade RAG and GraphRAG data plane. The 7 implementation plans (`04.1-01` through `04.1-07`) represent an exceptionally well-structured, TDD-grounded, and wave-sequenced architecture.

Crucially, the replan iterations (Waves 6 and 7, Plans `04.1-06` and `04.1-07`) directly address prior cross-AI review findings by:
1. Enforcing structural table separation between chunk-sequence edges (`edges`) and entity-relationship edges (`entity_edges`).
2. Factoring out multi-batch Arrow IPC decoding in `engine/src/graph/bridge.rs:68-72`.
3. Ensuring `GenerationRequest` in `engine/src/generation/mod.rs:374-388` derives `Serialize`-only to prevent `serde` deserialization from bypassing private `GraphFact` escaping constructors.
4. Establishing response-affecting Cypher membership constraints (`narrow_via_cypher`) during graph context compilation and `QueryGraph` calls.

Verification against the active codebase confirms that major foundational elements — such as `entities`/`entity_edges` LanceDB schemas in `engine/src/db/mod.rs:231-255` and multi-batch IPC stream decoding in `engine/src/graph/bridge.rs:10-66` — have already landed cleanly. However, source-level tracing reveals a subtle fallback edge case in `narrow_via_cypher` when Cypher finds 0 reachable neighbors, as well as a tie-breaking order discrepancy in `pack_evidence_and_graph_prompt`'s candidate sorting.

### Plan 04.1-01: Schema Foundation & Spike Un-Gating (Wave 1)

**Summary:** Promotes the `graph` module out of the `graph-spike` feature flag, adds dedicated `entities`/`entity_edges` LanceDB tables, strips dormant placeholder columns from `nodes`, migrates test fixtures to the 19-field `nodes_schema()`.

**Strengths:**
- Enforced table disjointness — `entity_edges_schema()` in `engine/src/db/mod.rs:245-255` guarantees by table membership (not loose ID-string convention) that chunk-structural edges can never be accidentally traversed as entity relationships.
- Clean schema drift validation — schema definitions integrate directly with `validate_schema()` at `engine/src/db/mod.rs:161-174`, preserving fail-fast startup behavior.

**Concerns:**
- LOW — `engine/Cargo.toml:29-32` already lists `lance-graph`/`arrow-ipc` etc. as unconditional dependencies, and `pub mod graph;` is already unconditional in `engine/src/lib.rs:6`. Task 1's action text assumes `optional = true` is still present, making Task 1 partially a no-op against current main.

**Suggestions:** Update Task 1's verification steps to validate that `cargo check` compiles without `--features graph-spike` on clean builds.

**Risk:** LOW — schema migration is already largely in place and verified by 7-table schema validation in `engine/src/db/mod.rs:144-159`.

### Plan 04.1-02: End-to-End Tracer & Graph Context Compilation (Wave 2)

**Summary:** Establishes the vertical MVP slice: extraction data structures, context assembly strategy, bounded neighborhood fetching, Cypher membership narrowing, RAG prompt integration.

**Strengths:**
- Delimiter-escaping type invariants — private string fields on `GraphFact` force construction through `GraphFact::new(...)`, guaranteeing all corpus-derived text passes through `escape_evidence_delimiters` before prompt assembly.
- Wire-payload verification boundary — a local TCP mock server (`captured_chat` pattern in `engine/src/generation/tests.rs`) verifies `<GRAPH_FACT>` text reaches the actual HTTP body sent to OpenRouter.
- Citable evidence reservation — reserving the highest-scoring chunk `EvidenceBlock` before token budget allocation prevents graph facts from crowding out citable evidence.

**Concerns:**
- **MEDIUM — Empty Cypher neighborhood fallback behavior.** In `engine/src/graph/mod.rs:623-627`, `narrow_via_cypher` checks `if confirmed_ids.is_empty() { return (entities.clone(), edges.clone()); }`. If Cypher pattern matching (`-[r:RELATED*1..hop_cap]-`) evaluates a neighborhood and finds 0 reachable neighbors (Cypher disagrees with BFS and eliminates all neighbors), this treats the empty result as a failure trigger and falls back to returning the full unconstrained BFS neighborhood — silently defeating the narrowing guarantee on total disagreement.

**Suggestions:** Differentiate a Cypher execution error (`Err`) from an empty confirmed set (`Ok(HashSet::new())`). An empty `Ok` set should narrow the returned neighborhood down to the seed entity only (or empty edges), not fall back to unconstrained BFS.

**Risk:** MEDIUM — core prompt assembly and wire delivery are solid, but the `confirmed_ids.is_empty()` branch weakens Cypher's authority on complete disagreement.

### Plan 04.1-03: Concurrent Extraction, Multi-Batch IPC & Idempotency (Wave 3)

**Summary:** Hardens ingestion/data-plane layers: bounded concurrent chunk extraction (`buffer_unordered(5)`), minimum chunk length filtering, bounded retries, multi-batch Arrow IPC decoding (`decode_all_batches`), atomic re-ingestion rollback.

**Strengths:**
- Multi-batch Arrow IPC fix (WR-01) — `decode_all_batches` in `engine/src/graph/bridge.rs:10-72` resolves the critical stream-truncation defect where `.next().transpose()` dropped IPC batches past the first.
- Two-phase re-ingestion safety — `extract_and_persist_entities` splits into a read-only Phase A (LLM extraction) and an atomic Phase B (mutation with `restore_version`) in `engine/src/main.rs:2475-2670`, preventing partial extraction failures from wiping existing graph data.
- Measurable concurrency verification — `FakeExtractionGenerator` tracks in-flight calls via atomic counters, proving `2 <= max_concurrency <= 5`.

**Concerns:**
- LOW — logging in `extract_with_retry` omits raw model output on validation failure (privacy constraint, T-04.1-07/`GraphSpikeError::Display`). Sound, but debugging schema-validation mismatches against new OpenRouter models may require inspecting structured output in test logs.

**Suggestions:** Add a `tracing::debug!` event inside `validate_extraction_output` (`engine/src/graph/extraction.rs`) that outputs field-level validation failure details (e.g. `confidence out of range: 1.5`).

**Risk:** LOW — excellent data-plane safeguards and error-handling boundaries.

### Plan 04.1-04: Structured QueryGraph gRPC API (Wave 4)

**Summary:** Replaces the legacy JSON-string `QueryGraph` stub with a typed, hop-bounded gRPC contract, enforcing byte-length limits on string inputs and using `fetch_neighborhood` + `narrow_via_cypher` at all hop depths.

**Strengths:**
- Prevents the variable-hop property-projection defect — sourcing edge properties from `fetch_neighborhood`'s `entity_edges` batch rather than projecting `r.relation_type` from a variable-length Cypher pattern avoids `lance-graph` projection failures (Pitfall 6 in `04-RESEARCH.md`).
- Input validation and escaping — `engine/src/main.rs:1737-1748` enforces `MAX_SEED_ENTITY_NAME_BYTES` (512) and `MAX_RELATION_TYPE_FILTER_BYTES` (128) before any LanceDB query; `seed_entity_id` is strictly validated via `Uuid::parse_str` at line 1754.

**Concerns:**
- **MEDIUM — Whole-table scan on name lookup.** Name-based seed lookup at `engine/src/main.rs:1773-1804` projects `entity_id`/`name` across all rows in `entities_table()`. Documented as an accepted v1 trade-off (local-first, single-user), but unbounded corpus growth will degrade `QueryGraph` response latency.

**Suggestions:** Consider pushing down a prefix or exact-match filter on `entities.name` in the LanceDB query when `seed_entity_name` is provided, reducing the in-memory case-folding loop volume.

**Risk:** LOW — clean gRPC service boundary with strict input validation and hop-cap bounding.

### Plan 04.1-05: Score-Interleaved Prompt Integration & Observability (Wave 5)

**Summary:** Implements normalized score-interleaving between `EvidenceBlock` candidates and `GraphFactBlock` items under a configurable `graph_weight` multiplier, plus `graph_augmentation` tracing span instrumentation.

**Strengths:**
- Hard exclusion on zero weight — `graph_weight = 0.0` (`engine/src/prompt.rs:270`) short-circuits graph fact processing immediately, guaranteeing zero `<GRAPH_FACT>` blocks regardless of token budget.
- Empty-slice panic protection — `pack_evidence_and_graph_prompt` (`engine/src/prompt.rs:263-265`) guards empty `evidence` slices; lines 329-335 handle equal-score normalization (`max == min`) without NaN or division-by-zero panics.
- Async-safe tracing subscribers — tests use `#[tokio::test(flavor = "current_thread")]` to prevent thread-local subscriber state loss across async yield points.

**Concerns:**
- **LOW — Candidate tie-breaking direction discrepancy.** In `engine/src/prompt.rs:363-369`, `scored.sort_by(...)` uses `is_graph_b.cmp(&is_graph_a)` as the tie-breaker inside a descending sort. This evaluates to `Ordering::Greater` when `b` is `Graph` and `a` is `Evidence`, which in a descending sort places `Graph` **before** `Evidence` on exact score ties — contradicting the doc comment at lines 356-362, which states ties break "in evidence's favor".

**Suggestions:** Change line 367 to `is_graph_a.cmp(&is_graph_b)` so the implementation matches the documented intent (evidence wins ties).

**Risk:** LOW — high-quality implementation with strong token budget management and tracing coverage; the tie-break bug is real but narrow (exact-score ties only).

### Plan 04.1-06: Gap Closure — Cypher Narrowing, Edge Dedup & Frontier Caps (Wave 6)

**Summary:** Addresses specific technical debt: proves Cypher narrowing on disagreement, fixes edge-deduplication identity (CR-01) via `edge_id` keying, relocates the `MAX_FRONTIER_SIZE` check (WR-01), tests `MAX_TOTAL_EDGES` overflow.

**Strengths:**
- Correct CR-01 edge-identity fix — keying `dedup_edges_by_identity` on `edge_id` instead of `(source_node_id, target_node_id, relation_type, weight)` prevents distinct edges from separate documents that extract identical facts from collapsing into a single edge.
- Relocated WR-01 frontier bound — checking `next_frontier.len() > MAX_FRONTIER_SIZE` after frontier expansion bounds the final hop's frontier size before `visited_in_list` predicate strings are built.

**Concerns:**
- LOW — as of this review, `engine/src/graph/mod.rs:353` and `:505-515` have not yet applied Plan 06's changes (`edge_id` missing from `select()`; `dedup_edges_by_identity` still uses the 4-tuple key). Expected, since Plan 06 is an unexecuted plan — but execution must land to actually eliminate the CR-01 bug.

**Suggestions:** Verify `dedup_edges_by_identity` handles any legacy or test `RecordBatch` that might lack an `edge_id` column gracefully, with a clear `GraphSpikeError` rather than a panic.

**Risk:** LOW — crucial correctness fixes that solidify graph traversal integrity, pending execution.

### Plan 04.1-07: Gap Closure — Worker Queue Integration & Orientation Preservation (Wave 7)

**Summary:** Completes the gap-closure suite with end-to-end characterization tests for worker-queue extraction (`spawn_worker_with_boundary`) and target-as-seed relationship orientation preservation.

**Strengths:**
- Full worker-queue traceability — proving documents processed asynchronously via `spawn_worker` populate `entities`/`entity_edges` and reach `query_rag` outbound HTTP payloads guarantees background processing works identically to direct calls.
- Orientation directionality guard — testing `attempt_graph_augmentation` when the seed entity is an edge's `target_node_id` verifies rendered triples maintain stored direction (`source —relation→ target`).

**Concerns:** LOW — no architectural or code-level concerns identified.

**Suggestions:** Ensure test teardowns clean up temp LanceDB directories created during `spawn_worker` test runs.

**Risk:** LOW — excellent verification closure for production pathways.
