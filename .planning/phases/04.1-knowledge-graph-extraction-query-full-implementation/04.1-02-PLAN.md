## Phase Goal

**As a** Lancet engineer, **I want to** extract entities and relationships from chunks during ingestion, persist them as a knowledge graph in LanceDB, and traverse them at query time via the now-confirmed `lance-graph` integration, **so that** RAG queries are grounded with graph context alongside the existing hybrid-retrieval evidence.

This plan is the first working slice of that story end-to-end: one document, a handful of entities/relations, one query, and — critically — proof that the graph text actually reaches the real OpenRouter request body, not just an intermediate Rust string. Plans 03-05 expand it (concurrency, idempotency hardening, the standalone `QueryGraph` RPC, and score-weighted interleaving) without changing this slice's shape.

<assumption_delta_decision>
**Detector signal (assumption-delta scan, advisory):** the phase scope pluralizes "evidence" — RAG prompt context previously had exactly one source (chunk `EvidenceBlock`s); this phase adds a second (`GraphFact`s).

**Noun now primary:** "RAG prompt context" (was: "evidence," singular-sourced from chunk retrieval only).

**Decision: add-alongside (not promote).** This was already locked by CONTEXT.md D-27/D-29, not a new choice this replan makes — recorded here for traceability since the detector fired. Rationale: promoting `GraphFact`s to be full, citable `EvidenceBlock`-equivalent citizens (a unified "evidence" type) would blur the citation/grounding trust boundary Phase 3 already hardened (`ModelOutput::validate_grounding_with_limits`) and reintroduce exactly the trustworthiness-indistinguishability risk Phase 4's judgment-tier prohibition #3 flagged (graph-derived facts are LLM-extracted, not citation-grounded corpus text — a materially different reliability class). The two sources share only a token budget (D-29) and a common relevance-scoring mechanism (D-30, upgraded to Cypher-confirmed membership + normalized score in Plan 05) — they remain structurally distinct types (`GraphFactBlock` vs. `EvidenceBlock`, non-citable `<GRAPH_FACT>` delimiter vs. numbered `[N]` markers) by design, not by omission.
</assumption_delta_decision>
