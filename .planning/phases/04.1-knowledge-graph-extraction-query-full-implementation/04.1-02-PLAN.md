## Phase Goal

**As a** Lancet engineer, **I want to** extract entities and relationships from chunks during ingestion, persist them as a knowledge graph in LanceDB, and traverse them at query time via the now-confirmed `lance-graph` integration, **so that** RAG queries are grounded with graph context alongside the existing hybrid-retrieval evidence.

This plan is the first working slice of that story end-to-end: one document, a handful of entities/relations, one query, and — critically — proof that the graph text actually reaches the real OpenRouter request body, not just an intermediate Rust string. Plans 03-05 expand it (concurrency, idempotency hardening, the standalone `QueryGraph` RPC, and score-weighted interleaving) without changing this slice's shape.

<objective>
Prove — with real, runnable end-to-end tests against a real (temp-dir) LanceDB store and a real mock HTTP server — that a document's chunks can be extracted into entities/relations, persisted as `entities`/`entity_edges` rows (Plan 01's schema), traversed via `lance-graph`, and rendered into a distinct, non-citable "Related Entities & Relationships" section that is verifiably present in the outbound OpenRouter chat request (D-01 through D-28, D-31, D-32).

Purpose: catch an architectural dead end (arrow-version bridge under real writes, Cypher traversal against a real narrowed neighborhood, the two-pass evidence-packing plumbing that a prior review found silently discarded graph text, prompt-injection boundary discipline for LLM-extracted text) after one task, not after ten already-committed layers.
Output: a working `ExtractionGenerator` seam; `ContextAssemblyStrategy` (RAG-05); graph context flowing all the way into the real `/rag/query` -> OpenRouter request.
</objective>
