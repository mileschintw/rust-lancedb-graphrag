Plan 06's own declared regression guard (`query_graph_bidirectional_seed_as_target`, protecting the deleted empty-confirmed-set Cypher fallback) was independently run and passes. This gap does not map to any later milestone phase and is not deferrable — it sits squarely inside this phase's own delivered `fetch_neighborhood` bound-enforcement mechanism. Recommend a small, targeted follow-up plan (Plan 09) that: (1) fixes the pre-dedup counting to track distinct `edge_id`s (the review's own proposed fix is small and well-scoped), and (2) adds a regression test constructing a `hop_cap>=2` bidirectional fixture whose true distinct edge count is under `MAX_TOTAL_EDGES` but whose raw per-hop-summed count would exceed it, asserting `Ok`, not `Err`.
