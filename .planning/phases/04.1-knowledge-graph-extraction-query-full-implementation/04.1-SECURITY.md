# Phase 04.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|----------------|
| LanceDB schema drift on startup | `entities`/`entity_edges` join the existing fail-fast/no-auto-migrate contract (D-14) | Schema shape only — no row data |
| Ingested document content → extraction LLM prompt | Untrusted corpus text becomes `chunk_text` in `ExtractionRequest`, sent to OpenRouter | Untrusted corpus text |
| Extracted entity/relation text → RAG-answer prompt | LLM-extracted entity names/relation types are corpus-derived, untrusted, flow into the final-answer prompt | Corpus-derived entity/relation strings |
| Caller-supplied query text → `entities.name_vector` seed search | Already-Phase-3-validated `QueryRequest.query` string | Validated query text |
| BFS frontier entity IDs → LanceDB `IN (...)` predicate | Seed UUID-validated; subsequent frontier IDs are self-read-back and quote-escaped; frontier size capped | Entity ID strings |
| Concurrent extraction results → shared in-memory known-entities accumulator | `buffer_unordered(5)` results gathered into a `Vec`, re-sorted before sequential merge | In-memory extraction results |
| Multi-batch IPC stream → bridged RecordBatch | A real `entities`/`entity_edges` read may split across multiple Arrow IPC stream messages | Arrow IPC batches |
| gRPC caller → `QueryGraph` seed/hop_depth/relation_type_filter | First genuinely caller-controlled `hop_depth` in this phase | Caller-supplied hop depth |
| gRPC caller → `seed_entity_name` lookup | Case-folded exact-match predicate against `entities.name`, escaped via `escape_sql_literal` | Caller-supplied entity name |
| gRPC caller → `relation_type_filter` | In-memory Rust string-equality filter, never interpolated into a predicate string | Caller-supplied filter string |
| `graph_augmentation` outcome tag → tracing/log output | Purely observational metadata; must not leak entity/relation row content | Outcome enum + counts only |
| `entity_edges` bidirectional BFS re-query → `dedup_edges_by_identity` → caller response | Two structurally distinct persisted rows must not be collapsed into one | Edge identity keys |
| Caller-controlled `hop_cap` → per-hop frontier size → terminal SQL predicate length | An entity's fan-out at the final hop must not reach an unbounded predicate | Frontier size / predicate length |
| `narrow_via_cypher`'s Cypher-vs-BFS disagreement resolution → returned neighborhood | A genuine zero-confirmed-neighbor Cypher result must narrow the response, not silently fall back to unconstrained BFS | Neighborhood result set |
| `cypher_confirmed_neighbor_ids`'s directional matching → `narrow_via_cypher`'s narrowing | Once Cypher confirmation becomes authoritative for narrowing, one-sided direction checking would silently exclude real neighbors | Confirmed-neighbor ID set |
| Worker-queue ingestion (`spawn_worker`) vs. direct-call test coverage | Test-only boundary — closing a coverage gap, no new production surface | N/A (test coverage) |
| RAG-path `GraphFact` orientation → LLM prompt context | A silently-reversed relationship triple would present false information to the LLM | Relationship triple orientation |
| Shared evidence/graph-fact token budget → packed prompt composition | Which of two exactly-tied candidates is admitted into the LLM prompt when budget cannot fit both | Prompt admission tie-break |
| `validate_extraction_output`'s failure path → tracing/log output | Diagnostic detail added to a failure log must stay numeric-only, never raw extracted text | Numeric confidence value only |
| Caller-controlled `QueryGraph` RPC `hop_depth` → `fetch_neighborhood`'s `MAX_TOTAL_EDGES` resource bound | A caller-reachable request shape previously could be wrongly rejected even when genuinely within bounds | Distinct edge count |
| Persisted `entity_edges_table` row data → `fetch_neighborhood`'s `edge_id`-column read at the bound-check site | An unreadable `edge_id` column must not silently be counted as contributing zero edges | Edge row data |
