## Accomplishments

- `InspectMode::DocumentIds` (`--document-ids`) on `inspect_lancedb`: read-only `document_id` sets over `documents`/`nodes`/`edges`/`entity_edges` (`BTreeSet`, sorted+de-duplicated by construction) plus `staged_documents_v2` row count — the exact JSON contract `eval/src/lancet_eval/identity.py` (06.3.4.1-02) already consumes. TDD RED→GREEN.
- New bin `reconcile_eval_store`: dry-run-by-default cascade that computes (or takes, via `--target-document-ids`) a delete set, deletes dependent rows in `edges → nodes → documents → staged_documents_v2 → entity_edges` order, and prunes `entities.source_chunk_ids` down to the surviving-chunk allow-list — deleting fully-orphaned entities and their incident `entity_edges`, rewriting partially-orphaned ones with every other column preserved byte-for-byte. `--apply` requires an existing `--snapshot-dir` containing `nodes.lance` and refuses any `--lancedb-path` other than the configured eval store (config files only, no env override). Never calls `optimize`/compaction/`cleanup_old_versions`. TDD RED→GREEN, 18 tests.
- Added `DatabaseManager::communities_table()` accessor (Rule 2 deviation) so the reconcile's version record can cover all 7 LanceDB tables, not just the 6 that had accessors before this plan.
- Live read-only census against the real eval store (`./data/lancedb-eval` + PostgreSQL `lancet_eval`, engine stopped, `db` compose service healthy): confirmed **exactly** RESEARCH A1's four LanceDB extras and RESEARCH's predicted 21 PostgreSQL extras, with a new finding (17/21 PG extras are `status: failed` — never reached LanceDB — and the other 4 are `status: queued`, exactly the 4 LanceDB extras, whose retry succeeded but was never marked `completed`). Recorded in `06.3.4.1-RECONCILE-DRYRUN.md` with per-table before/to_delete/after, entity rewrite/orphan/untouched/isolated_untouched counts, all seven table versions (unchanged, proving nothing was written), and the three rollback layers 06.3.4.1-06 must create before `--apply`.
