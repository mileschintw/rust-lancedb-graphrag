# Phase 06.3.4.1 Plan 22: Default log filter, startup-line fields and rejected-output capture Summary

**The engine now filters every tracing layer to `info,engine=debug` by default (RUST_LOG overrides, malformed values fall back), reports `build_profile` and `log_filter` on its startup line, and leaves one bounded, secret-free `generation_output_rejected` event for every rejected GenerateAnswer output.**

## Accomplishments

- D-90: `resolve_log_filter` and `assemble_subscriber` in `telemetry/mod.rs`. The `Targets` layer is registered first, so one filter gates the fmt layer, the trace layer and the OTLP log bridge. Both branches of `build_providers_and_layers` build their subscriber only through `assemble_subscriber`; the tests drive the same helper in its console-only and OTLP shapes on in-memory exporters, proving TRACE `h2::codec` reaches no layer while `request_process_state` and `retrieve_hybrid_substages` reach all of them, and that a `RUST_LOG=warn` override reaches every layer.
- D-92: `build_profile` (`release` or `debug` from `cfg!(debug_assertions)`) and the effective `log_filter` are fields of the `Rust RAG Engine serving` line, so drive 1's release-build and filter preconditions are checkable from the log.

Provider side, `RejectionContext::reject` wraps the existing `GenerationError` and returns it byte-identical. ## Decisions Made

- `Targets` over `EnvFilter` (plan-prescribed): keeps `engine/Cargo.toml` and `Cargo.lock` untouched. The consequence, stated in the doc comment, is that a `RUST_LOG` using span-field directives is rejected with a stderr warning and the default applies.
- Correlation ID in node events is `ctx.trace_id`. The service seeds it with the UUID that the journal records as the run's `correlation_id`, so the plan's "add both if they differ" branch did not apply. The provider events carry the same value, since the node copies `trace_id` into `GenerationRequest.correlation_id`.
- Accepted D-90 confounder (from the plan and CONTEXT): 06.3.4 ran unfiltered, so a flat drive 1 cannot by itself show the filter was irrelevant to OI-02. Recorded on `DEFAULT_LOG_FILTER`.

**1. [Scope note] Provider capture extends past parse and finish_reason**

- **Files modified:** `engine/src/generation/openrouter.rs`
