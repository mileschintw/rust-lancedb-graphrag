# Phase 06.3.4.1 Plan 34: Gate reader acts on retry provenance Summary

**`unpark_gates` now MISSes every reading on a journal that was not driven as that gate stage with `--retries 0` (missing or mismatched header marker, `max_retries` above 0, or any record with prior attempts), grandfathers only the three recorded drives through a closed `(corpus, created_at)` registry, and counts each work unit's first attempt in SC-2 and the D-69 companion so a retry cannot clear a timeout or a rejection; the run of record and drives 1 and 1b re-read exactly as recorded.**

## Accomplishments

- CR-03 reader side, Task 1. `_journal_preconditions(journal_path, stage)` is still the single precondition site; it now returns `(corpus, completeness, failures, provenance)` and calls the new `_retry_provenance`. With a `max_retries` key in the header: `gate_stage` must equal `--stage` and `max_retries` must be a non-bool 0. With `gate_stage` but no `max_retries`: an incomplete marker, MISS. With neither key: a hit in `_LEGACY_UNMARKED_GATE_DRIVES` under its own label is the `legacy` case; a hit under another label, or a miss, is a failure (`journal header carries no gate-stage marker (driven without --gate-stage)` for a miss). The records are scanned too (`N record(s) carry retried attempts`), because the header is written once. Every failure joins plan 32's path, so every reading is MISS and nothing is computed.
- SC-1 is forced to MISS on a provenance failure (it was only re-worded before, which would have left an honest, complete, report-bearing journal at PASS) and carries `detail["retry_provenance"]` on every path of `main`, including `not assessed: <reason>` when there is no journal, header or corpus. One `Retry provenance: <text>` line is written below the tables in the drive-1 layout and, in the drive-2 layout, before the invariance section so it prints on the not-computed path too. `main` also prints a `retry provenance:` line.
- Closed registry: `("multihop_rag_diag", 1790752043.476702)` to drive1, `1790892253.3635316` to drive1b, `1791278008.6136012` to drive2, each with the `retries=0` console evidence. The recorded headers and consoles were checked at the start (all three `created_at` values and `retries=0` match) and a test pins them.
- CR-03 / D-67 / D-69, Task 2. `evaluate_sc2` classifies `first_attempt_view(rec)` for the error-mode tally and the both-arm error pairs; the flatness clause keeps the final records. `citation_rejection_rate` takes the GenerateAnswer reach test and the rejection class from the first-attempt view, null-ness still from the gold question. Both report `retried_records` (also on the D-69 `n=0` early return).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] A header with `gate_stage` but no `max_retries` MISSes, and `max_retries` must be a non-bool 0**
- **Found during:** Task 1 (`_retry_provenance`)
- **Issue:** the plan keys the marker branch on `max_retries` alone. A header carrying `gate_stage` only would have fallen into the registry lookup, and `False == 0` in Python would have let a forged `max_retries: false` read as retry-free.
- **Fix:** `gate_stage` without `max_retries` is an incomplete marker (MISS, reason `journal header carries gate_stage without max_retries ...`); the retries check rejects a bool. Both are test-covered (`half_marker` case; the bool guard is reached only by a forged header and is not separately tested, disclosed).
- **Files modified:** `eval/src/lancet_eval/unpark_gates.py`, `eval/tests/test_unpark_gates.py`
- **Committed in:** `38fd040e` (test), `718c306d` (feat)

**2. [Rule 1 - Bug] ASCII-only provenance text and reasons**
- **Found during:** Task 1
- **Issue:** the new reasons embed header values (`gate_stage`, `max_retries`, a registry label); `main` prints every reason, and a redirected Windows stdout in a legacy code page raises on non-ASCII (the issue plan 32 hit).
- **Fix:** header values are rendered with the `!a` conversion or `_ascii`, so all provenance text is ASCII.
- **Files modified:** `eval/src/lancet_eval/unpark_gates.py`
- **Committed in:** `718c306d`
