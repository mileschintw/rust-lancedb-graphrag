`p99` and the histogram below were not available from the pre-existing `--graph-population` output (it emitted only min/median/p95/max) — a Rule 2 (missing critical functionality) deviation added `p99` and a 10-bucket decile histogram to `DegreeDistribution`/`GraphPopulationReport` in this plan's Task 3, computed with the same linear-interpolation `(n-1)*q` rule `p95` already used (see Deviations section and `f99f2095`). `highest_degree_entity_name` is resolved for free from the same entities-table read that already fetches `entity_id` — no extra table scan.

### Bucketing rule

The histogram below uses **equal-count (decile) buckets**, not equal-width buckets. This store's degree distribution is heavy-tailed (median degree 1, but max degree 543) — 10 equal-width buckets spanning `0..=543` would put the overwhelming majority of the 27,855 entities into the first bucket (`0..54`) and leave most of the remaining 9 buckets empty, conveying nothing about the tail's shape. Decile buckets instead hold ~2,785-2,786 entities each by construction, and each bucket's own `min_degree`/`max_degree` shows where the distribution's mass actually sits.
