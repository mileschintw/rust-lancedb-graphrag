## Fixed Issues

### WR-01: Legacy exemption is bound to header text only, so it is spoofable by any unmarked journal

**Files modified:** `eval/src/lancet_eval/unpark_gates.py`,
`eval/tests/test_unpark_gates.py`, `eval/tests/test_recorded_gate_verdicts.py`
**Commit:** f04e89a1
**Status:** fixed: requires human verification (logic change on a gate fail-open surface)
**Applied fix:**
- Each registry entry is now a `_LegacyDrive` NamedTuple `(label, evidence, n_records,
  records_sha256)`, and the registry is a `MappingProxyType` over them.
- The digest is `legacy_records_digest(records)`: sha256 over the canonical JSON of the
  sorted parsed rows `[corpus, question_id, graph_arm, outcome, duration_ms,
  correlation_id]`. It never hashes file bytes or lines, so CRLF checkouts cannot change it.
- Values were computed read-only from the three recorded journals: 200 records each, and
  digests `84c8adf8...`, `d2778029...` and `a5f9bb5a...` for drive1, drive1b and drive2.
- `_legacy_drive(header, records)` returns an entry only when the header key, the record
  count and the digest all match.
- The tests that injected fixture entries by monkeypatching the registry now patch the
  lookup function `_legacy_registry` with an entry whose digest is computed from the
  fixture's own records.
- Tests added: a journal with a copied registered header over different records (wrong
  digest, wrong count) is not exempt and MISSes; the real registry rejects a copied real
  header over other records; the registry is read-only. The registry test now requires
  every `retries=(\d+)` match in each console to equal 0 and pins each entry's count and
  digest against the recorded journal.
- Acceptance: `test_recorded_gate_verdicts` still re-reads drives 1, 1b and 2 exactly as
  recorded (no MISS flip). Two truncated-drive2 tests had to carry a gate-stage marker in
  their synthetic header, because a truncation no longer matches the registered digest by
  design. That keeps their exact-reason asserts intact; nothing was loosened.
- Also lint-fixed the E302 and one E501 introduced during this commit and committed with WR-02.

### WR-02: SC-3, SC-4 and SC-5 evaluators pass on thin populations when `expected_*` is omitted

**Files modified:** `eval/src/lancet_eval/unpark_gates.py`, `eval/tests/test_unpark_gates.py`
**Commit:** c7340a65
**Status:** fixed: requires human verification (logic change on a gate fail-open surface)
**Applied fix:**
- `expected_g` (SC-3, SC-4) and `expected_v` (SC-5) are keyword-only and required, with no
  default. There are no other `expected_*` coverage arguments.
- `_coverage_clause` no longer has a skip path: a non-integer value (including an explicit
  `None`, and a bool) returns a MISS reason "coverage not assessed: no expected population
  for ...".
- Callers: `main` was the only non-test caller and already passes integers. Repo-wide grep
  of `eval/`, `scripts/` and docs found no others. All 36 test callers that omitted it now
  pass the population size they wrote to their selection file (`_expected_g` /
  `_expected_v` helpers).
- The two "without an expected population skips the clause" tests were replaced by tests
  that omitting the argument raises `TypeError` and an explicit `None` is MISS. The SC-4
  "full coverage keeps its recorded reason" test no longer compares against a bare call,
  and asserts no coverage text in the reason and coverage 1.0.

### WR-03: The stage spend cap is per invocation, so a reused journal restarts spend at zero

**Files modified:** `eval/src/lancet_eval/journal.py`, `eval/src/lancet_eval/measure.py`,
`eval/src/lancet_eval/run.py`, `eval/tests/test_measure.py`, `eval/tests/test_stage_cap.py`
**Commit:** a923eb0c
**Status:** fixed
**Applied fix:**
- Chose "refuse". `journal.py` gains `JournalReuseError` and `refuse_populated_journal`.
- `run_measurement_pass` raises it, naming the path and saying to use a fresh run
  directory, before the journal is opened for append (and before the allowance check).
  `measure` in `cli.py` already catches and prints it as a non-zero exit (exit 1), so no
  CLI change was needed.
- `drive(resume=False)` raises it when the journal already holds records, before
  anything is appended. The existing marker-mismatch guard still fires first. `resume=True`
  is unchanged. The CLI default (`--resume`) is unaffected, and a missing or empty
  journal still works. Only `--no-resume` onto a same-day populated journal is now refused.
- Tests added: second measure pass into the same journal is refused and leaves the file
  byte-identical; the CLI exits non-zero with the message and leaves the file alone;
  `drive(resume=False)` on a populated journal is refused and leaves it byte-identical;
  fresh runs (missing and empty journal) and `resume=True` still work. The old companion
  assertion in `test_accumulator_is_cumulative_over_journal` that re-drove a populated
  journal under `resume=False` now asserts the refusal.
