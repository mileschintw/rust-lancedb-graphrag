- Added `InspectMode::GoldChunks` to `inspect_lancedb`: a read-only `--gold-chunks`/`--map` probe that classifies every non-empty-fact evidence item's containment in the live `nodes` table as `in_chunk` / `split_across_chunks` / `absent` / `unmapped_title`, with UUIDv4-validated and `escape_sql_literal`-escaped batched `IN (...)` predicates (500 IDs/batch) and a `normalize_ws` Rust twin pinned against the same rule as `metrics.py`.

## Decisions Made

- **(b)=no rate is 11.0%, not "a few percent"**: measured tri-state over the live store's 1185 evidence items is `in_chunk=1136 / split_across_chunks=0 / absent=49 / unmapped_title=0`. Question-level (b) is yes for 398/447 non-null questions, no for 49. RESEARCH's A2 assumption ("a few percent at most") is empirically wrong by roughly 3-4x. This plan does not act on it (Task 1's acceptance criteria only required recording it) — it directly affects 06.3.4.1-10's reconcile sizing and G population, which should re-read this number rather than RESEARCH A2.
- **retro_lenient.py reimplements D-69 classification locally** rather than importing `classify_record` from `lancet_eval.diagnostic`, because the plan's own prohibition requires the script's import surface to be statically provable as excluding the scoring/report path, and importing `diagnostic.py` (which itself imports `metrics.py` and could grow towards `score.py` later) would weaken that guarantee. A few lines of duplicated message-prefix matching bought a strictly simpler AST-provable contract.
- **D-72 split**: `ArmResult.answer_usable` stays `None` for null questions (never feeds (e)/G), but `final_answer`/`final_answer_missing` are still populated for null questions, so a null question's abstention behavior remains visible in the table without contaminating the yes/no denominator.
