## How the answer path works

These facts were checked while writing this brief.

- **Structured output:**
  - The engine asks OpenRouter for strict `json_schema` output, set in `engine/src/generation/openrouter.rs` around lines 540 to 620. The schema is named `model_output`, and its required fields are `answer`, `cited_evidence_ids`, `answer_basis`, `notices` and `warnings`.
  - The prose answer, including the D-71 final line, lives inside the JSON string `answer`. A line break there is an escaped `\n` that the model has to emit itself.
- **The final-line instruction:** it is in `engine/src/prompt.rs` (lines 212, 215, 722, 729 and 743): "end with exactly one final line in this form: Answer: ...".
- **The extractor:** `eval/src/lancet_eval/metrics.py` `extract_final_answer`, with the regex `_ANSWER_LINE` at about line 63, is multiline and anchored at line start. It reads only an `Answer:` that begins a line. The last match wins.
- **What the engine drops from the response:** `OpenRouterChatResponse` (`openrouter.rs` about line 963) deserialises only `choices` and `usage`. OpenRouter's response `id`, `model` and `provider` fields are dropped.
- **What the engine logs:** the `llm_attempt` span carries only `gen_ai.request.model`.
- **No generation IDs were kept.** A search of `data/oi02-evidence/drive1-2026-09-30*` and the run directory for OpenRouter `gen-...` IDs finds none.

**Required:**

- Drive 1b's final answer can be recovered whether or not the served model emits line breaks.
- The fix is committed and tested **before** any drive-1b data.
- The fix does not depend on the provider's whitespace.

**Decided: option (b1), a structured field that the engine renders.** This is D-95, chosen by the user at plan time on 2026-09-30.

- **Schema and struct:**
  - The strict `model_output` schema in `engine/src/generation/openrouter.rs` gains a required short-answer property, `final_answer`.
  - `ModelOutput` in `engine/src/generation/mod.rs` gains the matching field, optional with a serde default.
  - Both change in one commit, because the struct is `deny_unknown_fields`.
- **Rendering:** the engine renders `Answer: <final_answer>` as the last line of the answer text, after the explained, cited answer. The streamed answer text (`answer_chunk`) and the `final_answer` event carry the same text.
- **Prompt:**
  - The system policy is reworded so the model gives the short answer in `final_answer`. That policy is `engine/src/prompt.rs` `base_system_policy()`, plus any other policy carrying the same instruction.
  - It keeps every guard sentence, the citation contract, the injection guard and plan 26's F-1 clause (no text outside the JSON object).
  - The prompt goldens are extended, never deleted.
- **Guards on the rendered line:**
  - It adds no citation markers and cannot trip grounding or citation validation, so it cannot raise D-69's rate. Either render after validation, or prove with a test that it cannot matter.
  - Square brackets and citation markers in the field are stripped.
  - The `MAX_ANSWER_CHARS` overflow edge is handled.
  - An empty or whitespace-only field renders no line, and scores as `final_answer_missing`.
- **A model-written `Answer:` line:** the model may still write its own `Answer:` line in the prose. The committed rule, where the last line-start match wins, then reads the rendered line. The plan decides whether to strip a trailing model-written `Answer:` line, so the visible text carries only one.
- **Unchanged:**
  - the extractor (`eval/src/lancet_eval/metrics.py` `extract_final_answer`);
  - the SC-3 metric (D-70) and the committed literals;
  - the proto and the gateway.
- **Tests:**
  - A Rust test shows that an output with no line breaks plus `final_answer` becomes answer text ending in a line-start `Answer: <field>`.
  - An eval test shows that `extract_final_answer` reads that exact shape: single-line prose, then `\nAnswer: X`.
- **Not chosen:**
