## Phase Boundary

**What this phase delivers:** find out *why* both arms were near floor in
06.3.4's halted drive, by testing each hypothesis in order: index identity drift,
`RetrieveHybrid` latency accumulation, answer-format and metric mismatch, graph
seeding architecture. Then repair each in the ROADMAP's mandatory layer order,
so that graph-on vs graph-off shows a paired effect a reader can see on a
gold-in-index subset. The phase's final drive is the **run of record** that
Phase 6.4 unparks against.

**The layer order in ROADMAP.md is fixed and is not re-discussed here:**
(1) completeness/fail-closed → (2) index identity (OI-03) → (3) `RetrieveHybrid`
health (OI-02) → (4) vector-only diagnosis → (5) graph repair (OI-01).

**Evidence gathered during this discussion (verified against
`eval/runs/2026-09-09-multihop_rag/journal.jsonl` and the repo, 2026-09-22):**

- **Graph-off's EM 0 / F1 0.02 is mostly an answer-format artifact.** The median
  graph-off answer is **105 words**. The gold answers are short (`Yes` ×167,
  `no` ×106, entity names), and the prompt at `engine/src/prompt.rs:206` never
  asks for a short answer. **106 of 150** successful graph-off answers contain
  the SQuAD-normalized gold string (inference 50/51, comparison 38/68, temporal
  18/28). Recall@4 is 0.36, so retrieval is not at floor either.
- **The `RetrieveHybrid` slowdown is monotonic and linear.** Median node time
  per 50-record slice: 5.0s → 10.5s → 14.0s → 16.8s → 21.4s → 24.7s → 29.0s,

  *reset* after a mid-run engine restart (13.5s → 2.3s,

- **D-66:** **Restore `config/config.eval.toml` to `lancedb_path`-only now; re-derive

  restored.
- **D-67:** **Diagnostic drives use `--retries 0`.** Every timeout appears once in

- **D-68:** **Diagnostic sample ≈ 100 questions × 2 arms**, drawn from the

  (06.3.4's degradation was visible from the first 100 records). The exact selection and seed are up to planning;
  the selection must be recorded.
- **D-69:** **The "answer citation constraints" failures get a bounded
  diagnosis** (~15% of records even in 06.3.4's healthy early slice). The
  06.3.4 journal breaks them down as: 25× `answer basis 'mixed' requires at
  least one cited evidence ID`, 8× `answer basis 'retrieval' requires at least
  one cited evidence ID`, 10× `ModelOnly answer basis is not supported on Phase
  03 QueryRAG path` (all `GenerateAnswer`). Classify
  them per question in the diagnostic table. Fix only if it's an outright bug

### Answer usability (layer 4, SC-3, column e)

- **D-70:** **Both a short-answer format and a lenient deterministic metric.**
  Existing EM/Token-F1 stay unchanged and are still reported. A new metric
  (final-answer EM against the extracted final-answer line, plus normalized
  gold-containment) is reported next to them. SC-3 is judged on the new metric.
- **D-71:** **The short-answer instruction goes into the PRODUCTION prompt,
  additively:** the full explained, cited answer stays, and a structured
  final-answer line is added (e.g. `Answer: <short>`). Eval scores the extracted
  line. Eval and production run the same prompt (OBS-05), so there's no
  eval-only variant and no proto change. It must keep the existing citation
  contract and injection-guard behaviour in `engine/src/prompt.rs`. The
  grounding validator (`engine/src/workflow/nodes/generate.rs`,
  `validate_grounding_with_limits`) requires at least one cited evidence ID per
  *answer*, not per line, so an uncited final-answer line should not add
  rejections. Research must confirm this, and confirm how the line interacts
  with the model's structured output (`answer_basis`), before planning. It must
  not raise D-69's rejection rate.
  — **Reversibility:** costly — changes the shipped answer text every API
  client sees. Undo is a prompt revert plus making every scored run after it
  non-comparable again.
- **D-72:** **null_query questions (53/500, gold "Insufficient information.")
  get a separate abstention-correctness metric.** They are excluded from the
  gold-in-index subset (no evidence) and never mixed into SC-3's number.
- **D-73:** **The SC-3 floor is committed in `thresholds.py` BEFORE the first
  paid drive**, in the same pattern as 06.3.3/06.3.4's pre-committed thresholds.
  Research proposes the value. Missing it triggers investigation, not
  suppression.
- **D-74:** **Attribution: compute the lenient metric on the 06.3.4 journal
  first** (free, no drive), so the gain from answer *format* is separated from
  the gain from index/latency fixes. The 06.3.4 and 2026-09-03 EM/F1 values are
  marked non-comparable (the D-43 pattern). A missing or garbled final-answer
  line scores as a miss, with a separate `final_answer_missing` count/rate. The
  record stays in denominators (it is a model output, not an infra failure,
  per D-34).
  **Guardrail (SC-1 / T-06.3.4-19):** the 06.3.4 journal is a halted `partial`
  run, and `score_run`/`report` correctly refuse it. The retro computation is a
  **read-only offline analysis over journal records**. It never calls
  `lancet-eval score` or `report`, never writes `report.json`, adds no bypass
  flag to the fail-closed path, and its output is labelled "partial-run
  diagnostic" with n stated (150 graph-off successes).

### Graph repair (OI-01, layer 5)

- **D-75:** **Seed step: mention extraction + per-mention match, with NO
  query-time LLM call.** Extract candidate entity mentions from the question
  (e.g. capitalized spans / n-grams), match exact/alias against entity names
  first, then per-mention `name_vector` top-k. Allow multiple seeds. This
  replaces `nearest_to(full-question embedding).column("name_vector").limit(1)`
  at `engine/src/service.rs:242-273`.
- **D-76:** **Graph contribution: seed-to-seed paths (≤ 2 hops) + chunk boost.**
  Find short paths that *connect* seeds (the bridge relation). Inject only
  path facts, not unfiltered 1-hop neighbourhoods (the source of 06.3.4's
  -0.0024 F1). Use the source chunks of path entities (`source_chunk_ids`) to
  boost or add retrieval candidates, so the graph visibly changes retrieval
  composition.
- **D-77:** **Traversal cost is bounded by a degree cap on hub expansion + a
  cap on the injected path/fact count.** Values are derived from the
  post-reconcile degree distribution (D-62) and recorded with the derivation
  (current store: max degree 724, p95 10). `graph_operation_timeout_ms` is
  re-derived with the other budgets (D-66) after this lands.
- **D-78:** **Ships as the production default; the old seeding path is
  removed.** No config flag, no eval-only mode. graph-off remains the ablation
  arm. If the result is negative, it is reported per D-49, not toggled off.
  — **Reversibility:** costly — removes the old seeding code path and changes
  production graph behaviour. Undo means re-implementing or restoring from git,
  and re-measuring.
- **D-79:** **Column (d) "graph seed hit" = at least one seed entity sourced from
  a gold evidence document** (via entity → `source_chunk_ids` → document). Also
  record the seed count and whether a seed-to-seed path was found.
- **D-80:** **D-31 canaries are re-validated under the new seeding and
  extended.** Add at least one canary whose gold answer needs a seed-to-seed
  path. The canaries stay hard preflight gates (`check_canary_floors`).
