# Phase 06.3.4.1 Plan 31: Measure stage-cap window and validation Summary

**`lancet-eval measure` now dispatches through one cap-checked bounded window at every worker count (workers=4 with a binding cap measures 4 units instead of 20), records `stopped_by_cap`, and every `--stage-cap` rejects NaN, infinity, zero and negatives.**

## Accomplishments

- CR-01 closed: `run_measurement_pass` primes at most `max(1, workers)` units, then after each completion takes the next unit first and compares `compute_spend(records, include_embeddings=True)` with the cap before submitting. The fire-all `as_completed` branch is gone (AST-verified, not a text grep).
- WR-01 ordering fixed in `measure` and `run.drive`: `stopped_by_cap` is true only when a unit was still waiting when the cap was reached. A cap first reached by the final record reads false.
- WR-02 closed: shared `_validate_stage_cap` typer callback on `run`, `measure`, `score` (usage error, exit 2); `measure --stage-cap` required; the library raises `ValueError` on the same values after the identity gate and before any I/O.
- A capped pass is visible: `measurement.json` and `run_record.json` carry `stopped_by_cap`, `workers`, `work_units_planned`; the CLI prints a yellow "stage spend cap" notice with measured-of-planned counts. The cap-hit log now uses `%.4f`.

## RED and GREEN evidence (acceptance criteria)

- **Task 1.** Against the pre-change code the workers=4 binding-cap test failed with `assert 20 == 4` (20 of 20 units dispatched). After the change: 4 calls, `stopped_by_cap` true, `workers` 4, `work_units_planned` 20. The in-flight bound test failed with `assert 20 <= 4` before, passes after. The five invalid-cap cases failed with `DID NOT RAISE ValueError`. 12 of 13 new tests failed RED; the workers=1 journal-order test passed in RED by design (a regression pin: a window of one preserves serial order).
- **Task 2.** Against the pre-change `drive` the boundary test failed with `assert True is False` (`stopped_by_cap` true on a complete 6-of-6 drive). After: 6 units run and `stopped_by_cap` is false. The companion (cap reached after the 2nd record) reads true before and after. The four existing cap tests stayed green unchanged.
- **Task 3.** Before the change `measure --stage-cap nan` reached the callee (`assert 0 == 2`, 15 cases across run, measure, score) and `measure` without `--stage-cap` exited 0 (`assert 0 != 0`); the capped-notice test failed on a missing "stage spend cap" line. After: all exit 2 / non-zero without calling the callee.
