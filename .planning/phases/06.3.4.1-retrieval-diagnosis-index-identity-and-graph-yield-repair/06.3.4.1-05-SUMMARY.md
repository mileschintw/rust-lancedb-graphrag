## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `evaluate_sc3` corpus resolution would silently drop strata on every real drive**
- **Found during:** Task 2 GREEN, self-review before commit (surfaced by consulting the advisor before declaring the task complete)
- **Issue:** The first GREEN implementation read `corpus` only from the `populations_path` selection file's own `"corpus"` key. Grepping `06.3.4.1-10-PLAN.md` (the plan that actually writes `diag_selection.json`) showed its committed field list is `method, seed, quotas, strata_counts_in_G, drawn_question_ids, g_question_ids, v_question_ids, g_size, v_size, null_included, source_index_generation, date` -- no `corpus` field at all. Strata (a required output per the Task 2 `<behavior>` bullet) would therefore be silently empty on every real drive.
- **Fix:** Added a keyword-only `corpus: str | None = None` parameter to `evaluate_sc3` (falls back to the selection file's `corpus` key if present, for callers/tests that supply one there); `main()` now derives `corpus_name` from the journal header (already available for other gates) and passes it explicitly.
- **Files modified:** `eval/src/lancet_eval/unpark_gates.py`
- **Verification:** New test `test_evaluate_sc3_corpus_kwarg_works_without_selection_corpus_key` builds a `diag_selection.json`-shaped file with no `corpus` key and confirms strata still populate via the kwarg.
- **Committed in:** `7d83c5ae` (Task 2 GREEN commit)

**2. [Rule 1 - Bug] `excluded_generate_answer_failures` counted the wrong population**
- **Found during:** Task 2 GREEN, self-review
- **Issue:** The first implementation counted every G row with `e_answer_usable is None` (any unusable graph-off record: not_run, timeout, transport, D-69 rejection alike). AI-SPEC #5 specifically wants "the count of GenerateAnswer failures that D-34 excluded" -- the n-shrinkage signal that a D-71-induced citation-constraint rejection rise would show up as, not general unusability.
- **Fix:** Scoped the count to `arms["graph-off"].outcome == "error" and error_class in` the D-69/marker-mismatch class set (`classify_record` only ever emits those classes for the GenerateAnswer node).
- **Files modified:** `eval/src/lancet_eval/unpark_gates.py`
- **Verification:** New test `test_evaluate_sc3_excludes_d69_generate_answer_failures` discriminates a D-69 rejection (counts) from a transport error and a not_run row (must not count).
- **Committed in:** `7d83c5ae` (Task 2 GREEN commit)

**3. [Rule 2 - Missing Critical] Two committed literals were imported but never actually read**
- **Found during:** Task 2 GREEN, self-review
- **Issue:** `SC2_TIMEOUT_DOMINANCE_RULE` and `FINAL_ANSWER_MISSING_REVIEW_RATE` were committed to `thresholds.py` and pinned by existence tests, but `evaluate_sc2`/`evaluate_sc3` never actually consulted them -- the plurality-tie-is-dominant behavior and the 0.10 review threshold were hardcoded logic, not policy reads. This defeats D-73's whole point (every number a pass rule uses must be a committed, re-derivable literal, not baked-in code): changing the committed value would silently do nothing.
- **Fix:** `evaluate_sc2` now branches on `SC2_TIMEOUT_DOMINANCE_RULE`, refusing with MISS `unknown dominance rule` if it isn't the one reading (`plurality_tie_is_dominant`) this module implements. `evaluate_sc3` now computes the graph-off `final_answer_missing` rate over G and surfaces `final_answer_missing_rate` / `final_answer_missing_review_triggered` in `detail`, comparing against `FINAL_ANSWER_MISSING_REVIEW_RATE`.
- **Files modified:** `eval/src/lancet_eval/unpark_gates.py`
- **Verification:** New tests `test_evaluate_sc2_unknown_dominance_rule_is_miss` and `test_evaluate_sc3_final_answer_missing_review_triggered`.
- **Committed in:** `7d83c5ae` (Task 2 GREEN commit)
