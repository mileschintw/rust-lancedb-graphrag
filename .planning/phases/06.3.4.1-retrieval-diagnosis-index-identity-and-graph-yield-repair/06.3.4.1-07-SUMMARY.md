## Accomplishments

- **Zero-cost forensics** established from the live 06.3.4 journal, Prometheus counters, Loki logs, and PowerShell history: the engine was fresh at record 1 (2 prior queries), the collector was reachable throughout the drive, the build was debug (not release), and the drive ran on an uncommitted code state predating commit `33e774bd`. Ranked six hypotheses by evidence strength.
- **A reusable full-stack replay harness** (`scripts/oi02-replay.ps1`, `provider_stub.py`, `oi02.py`'s `forensics`/`replay-summary`/`check-arm`) that stands up isolated store/database copies, launches the real engine and gateway (optionally from a pinned historical git worktree), runs the real harness against a loopback provider stub (flat or per-slice-scheduled delays, real or hash-fallback embedding vectors), and tears down with before/after proof the live store and schema were untouched.
- **Two real fidelity/tooling bugs found and fixed before results were trusted**: the first primary replay served 100% hash-fallback embedding vectors (no real graph traversal ever ran) because the vector-map builder's caller-side wiring didn't exist yet — fixed and re-run as `primary-r2`; and `classify_m2`'s "not grows" branch compared against a fixed slice instead of literally the plan's own "last full slice" — found and fixed test-first, reclassifying two arms from a mis-scored "not grows" to the correct "ambiguous" (a labeling correction that did not change routing).
- **Nine replay arms**, none reproducing production's growth: `primary`/`primary-r2` (HEAD code, reconciled store, ambiguous M2), `drive-era`/`drive-era-prewarm`/`paced` (drive-era commit, pre-reconcile store, not-grows/ambiguous), and `paid-drive-era` (same whole stack, real OpenRouter provider and embeddings, one $0.25-capped paid run — not grows). - **Two PowerShell tooling bugs found and fixed** during the investigation itself: a comma-bearing stub-delay-schedule value being re-parsed as an array literal by the launcher (fixed before the `paced` arm ran), and a benign harness retry-warning line being misread as a script-terminating error by `oi02-replay.ps1` (fixed after being caught on the paid replay, verified via a standalone three-case repro).
- **`06.3.4.1-OI02-MEMO.md`**: a standalone, session-independent account of what OI-02 is, the full investigation history with every arm's readings, the current negative result and its one consistent clue (every replay starts ~0.2x of production's own first-slice latency), and exactly what paid drive 1 needs to capture (already-built instrumentation, how to recreate the replay environment) to diagnose OI-02 live.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `primary`'s embedding vectors were 100% hash-fallback, not real per-question vectors**
- **Found during:** Task 2/3 (primary replay review, before Task 3's checkpoint was presented)
- **Issue:** Task 2's action text specifies building `data/replay/stub-vectors.jsonl` via `retrieval_soak --export-embeddings` before the primary run, but the caller-side pipeline matching each replay question to production's real top-ranked chunk had never been built — every graph-on record got `GRAPH_ABLATION`/`GRAPH_UNAVAILABLE`, invalidating the graph-path test.
- **Fix:** Built `extract-chunk-ids`/`build-stub-vectors` subcommands (test-first), re-ran as `primary-r2` with 172/175 questions matched to production's real vectors (98.3%).
- **Files modified:** `eval/src/lancet_eval/oi02.py`, `eval/tests/test_oi02.py`
- **Verification:** smoke validation (9 questions) confirmed 18/18 records' top-ranked chunk exactly matched production's; `primary-r2`'s own `stub-stats.json` confirmed the fallback rate.
- **Committed in:** `12e965d8`/`0d339ae3` (RED/GREEN), `74cf1a57` (primary-r2 run)

**2. [Rule 1 - Bug] `classify_m2`'s "not grows" branch read the wrong slice**
- **Found during:** Task 3 (self-review of the primary/primary-r2 write-up before presenting the checkpoint)
- **Issue:** The plan specifies "not grows" against literally the last full slice, but the code compared against a fixed slice-3 — at the 350-record/7-slice scale these are different slices (slice-3 vs slice-6), silently mis-classifying two arms as "not grows" when the real last-slice ratio was over the ceiling.
- **Fix:** `classify_m2` now reads the actual last available slice for the "not grows" ceiling (test-first).
- **Files modified:** `eval/src/lancet_eval/oi02.py`, `eval/tests/test_oi02.py`
- **Verification:** Both `primary` and `primary-r2` reclassified from "not grows" to "ambiguous" — a labeling correction only; the plan's own routing table treats both classes identically, so Task 3's routing conclusion (Route B) was unaffected.
- **Committed in:** `23ea0209`/`1ec7aa33` (RED/GREEN), `69a779b5` (profile correction)

**3. [Rule 1 - Bug] `replay_summary`'s M1 always used the reconciled-store ratio formula**
- **Found during:** Task 4 setup (before the first Route B arm ran on a pre-reconcile store copy)
- **Issue:** Pre-reconcile-store arms need a direct comparison against `m1_reference_ms`, not the reconciled-store ratio formula; the code applied the ratio formula unconditionally.
- **Fix:** `replay_summary` now reads `store_source` from the arm's own header and applies the correct formula (test-first).
- **Files modified:** `eval/src/lancet_eval/oi02.py`, `eval/tests/test_oi02.py`
- **Verification:** `drive-era`'s M1 read correctly against the direct-comparison band immediately after the fix.
- **Committed in:** `89ef0648`/`d6010483` (RED/GREEN)

**4. [Rule 3 - Blocking] Launcher argument-quoting bug broke a comma-bearing schedule value**
- **Found during:** Task 4 Route B step 4 (first attempt to launch the `paced` arm)
- **Issue:** `scripts/oi02-replay-launch.ps1` joined argument tokens unquoted into the inner script's source text; a value containing a comma (`-StubEmbedDelayScheduleMs "308,399,442,481,462,859,2043"`) was re-parsed as a PowerShell array literal, not a string, and binding failed.
- **Fix:** Quote every value token (anything not starting with `-`) as a single-quoted PowerShell string literal before splicing it in.
- **Files modified:** `scripts/oi02-replay-launch.ps1`
- **Verification:** Standalone smoke confirmed the comma-bearing value now binds as a single `String`, not an array; the `paced` arm then ran successfully.
- **Committed in:** `79406d2d`

**5. [Rule 3 - Blocking] A benign harness retry-warning aborted the replay script's own summary step**
- **Found during:** Task 5 (the `paid-drive-era` paid replay)
- **Issue:** The harness's own `logger.warning()` retry line, under PowerShell 5.1's nested `*>`-redirection + `$ErrorActionPreference = 'Stop'` interaction, was promoted into a script-terminating `NativeCommandError` — aborting `oi02-replay.ps1` before it could write an accurate `header.json`/run `replay-summary`, even though the underlying 350-record harness run had completed successfully and written a valid journal.
- **Fix:** Locally relax `$ErrorActionPreference` to `'Continue'` around the two harness invocations and check `$LASTEXITCODE` explicitly, restoring `'Stop'` immediately after.
- **Files modified:** `scripts/oi02-replay.ps1`
- **Verification:** Standalone three-case repro (benign stderr + exit 0 → no false abort; benign stderr + exit 0 with the fix → correct pass-through; a genuine nonzero exit → still correctly caught). Recovered the paid run's own data by hand (manually re-ran `replay-summary`/`check-arm` with the correct forensics arguments) before the fix landed, so no result in the profile depended on the buggy path.
- **Committed in:** `d50694dc`
