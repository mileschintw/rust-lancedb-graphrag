# Phase 06.3.4.1 Plan 33: Retry provenance, per-attempt spend and the gate-stage drive marker Summary

**Every attempt a harness retry supersedes now stays on the journaled record and is charged to the stage cap, and `lancet-eval run --gate-stage <label>` writes `gate_stage` and `max_retries` into the journal header, refuses `--retries` above 0, and refuses to append to a journal its header does not describe.**

## Accomplishments

- CR-03 recording half closed: `drive_one` keeps an `AttemptRecord` for each superseded attempt (outcome, error, node failures, node timings, wire metadata, duration, ids, answer length) on the final record's `prior_attempts`. The retry conditions, sleeps and never-raise contract are unchanged.
- `first_attempt_view` exposes the first attempt as a `RunRecord`; `classify_record` on it returns `timeout` for a timeout that a retry later answered, the same class a `max_retries=0` run gets, and `citation_basis_mixed` for a retried-away D-69 rejection.
- CR-03 spend half closed: `compute_spend` and `count_failed_generation_attempts` sum over each record's prior attempts and the record itself. For a retried record, spend equals the first attempt's charge plus the final attempt's, exactly. A drive's cap check sees retried spend and stops earlier (3 records without prior attempts, 2 with, same cap).
- Gate-stage marker (owner decision, D-67): `run --gate-stage`, `drive(gate_stage=...)`, header keys, and the header-versus-drive refusals. `--retries` keeps default 2 for non-gate drives, whose retries are now recorded and charged.
- Back-compat pinned line by line: 200 + 200 + 200 recorded drive lines validate as `RunRecord` and 324 pass A lines as `MeasurementRecord`, all with empty `prior_attempts`. Pass A prices identically under the pre-change and post-change `compute_spend` (0.31991896, 0.31525336 without embeddings), 135 failed-generation attempts.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] `write_header` rejects `gate_stage` without `max_retries`**
- **Found during:** Task 3
- **Issue:** the plan writes the marker only when `max_retries` is not None, so a caller passing a label alone would silently get a four-key header with no marker.
- **Fix:** `Journal.write_header` raises `ValueError("gate_stage requires max_retries (D-67)")` for that combination.
- **Files modified:** `eval/src/lancet_eval/journal.py`
- **Verification:** reached only by a direct caller; no test pins this guard (disclosed, not covered).
- **Committed in:** `cc742070`

**2. [Rule 1 - Bug] Gate-stage label check uses `re.fullmatch`**
- **Found during:** Task 3
- **Issue:** the plan's pattern `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` with `re.match` accepts a trailing newline, because `$` matches before it.
- **Fix:** the pattern is compiled without anchors and applied with `fullmatch`; `"drive3\n"` is a tested refusal.
- **Files modified:** `eval/src/lancet_eval/run.py`, `eval/tests/test_run_arms.py`
- **Committed in:** `cc742070`
