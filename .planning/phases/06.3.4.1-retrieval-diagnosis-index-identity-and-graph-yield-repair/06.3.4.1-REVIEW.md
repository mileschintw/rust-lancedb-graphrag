## Summary

Scope was `git diff 6d4c99ce..HEAD` over the listed files. `gate.py` is an unchanged anchor.
`uv run --project eval pytest eval/tests -q` gives 1078 passed. No paid call was made and no
engine was launched.

### Closure verdicts for the three prior blockers

- **CR-01 (measure ignored the stage cap at workers>1): CLOSED.** `run_measurement_pass`
  (`measure.py:664-729`) now uses a single bounded in-flight window for every worker count.
  It primes at most `effective_workers` units. After every completion batch it checks
  `compute_spend` against the cap before submitting each further unit. `stopped_by_cap` is set
  only when a unit was still waiting. The cap is validated finite and positive in the library
  (`measure.py:591`) and in the CLI callback (`cli.py:393`). `measure` now requires `--stage-cap`
  with no default. The priming window cannot bypass the cap: spend is 0 and the cap is greater
  than 0. The unreserved in-flight overshoot is noted as IN-01. The per-invocation scope of the
  cap is WR-03.
- **CR-02 (unpark gates scored partial journals, no coverage floor): CLOSED.**
  `_journal_preconditions` (`unpark_gates.py:~1530`) runs before any reading is computed. Every
  failure (absent, headerless, unmeasurable, incomplete, retry provenance) yields all-MISS
  readings with nothing computed from the records. Completeness is measured once. SC-3, SC-4 and
  SC-5 apply `_coverage_clause` against sample-scoped denominators computed once in `main`.
  The expected population is never corpus-wide and never journal-relative. Coverage at or above
  0.80 passes, and the float comparison is exact for 4/5. A zero or missing expected population
  is MISS. `thresholds.UNPARK_GATE_COVERAGE_FLOOR` (0.80) equals `gate.STAGED_PAIRING_COVERAGE_FLOOR`
  (0.80). A test pins the equality, but the literals are duplicated (IN-04). The one fail-open
  surface is the optional `expected_*` argument on the public evaluators (WR-02). `main` always
  supplies it.
- **CR-03 (harness retries erased earlier attempts): CLOSED for gate evidence.**
  - `drive_one` keeps every superseded attempt in `RunRecord.prior_attempts`. Both the
    success-but-empty and the exception paths append the attempt before `continue`.
  - `compute_spend` and `count_failed_generation_attempts` charge every attempt. Each attempt
    gets its own wire tokens, failed-generation ceiling and embedding estimate. `MeasurementRecord`
    inherits the field.
  - `first_attempt_view` feeds SC-2 and D-69 with the first attempt.
  - A gate drive must declare `--gate-stage` with `--retries 0`. This is enforced in the CLI,
    in `drive()`, and by `_require_matching_journal_marker` on append and resume.
  - The reader MISSes a header marker that names a different stage or a non-zero `max_retries`.
    It also MISSes any unmarked header that is not one of the three registered legacy drives. It
    MISSes any journal whose records carry `prior_attempts`, so a retry that happened after the
    header was written is still caught.
  - I checked the three registered legacy drives' `drive-console.txt` files. Each holds exactly
    one banner, `retries=0`. The retry evidence is real. The registry is a module-level
    constant, and nothing loads from data, so it cannot be widened from journal or header
    content. It can still be spoofed by header content (WR-01).

No BLOCKER-level defect was found in the delta. The remaining findings are fail-open surfaces
that hold only under hand-crafted input or direct evaluator calls, plus robustness and
maintainability items.

## Warnings

### WR-01: Legacy exemption is bound to header text only, so it is spoofable by any unmarked journal

**File:** `eval/src/lancet_eval/unpark_gates.py:772-788, 1160-1166`
**Issue:** An unmarked journal is exempt from the retry-provenance requirement when its header
`(corpus, created_at)` equals one of three registered keys. The exemption is not tied to the
journal's records.
- Any pre-marker journal can inherit the exemption by copying one of those header lines. That
  includes a `--retries 2` 06.3.4-era journal, which cannot be told apart because the old code
  erased `prior_attempts`. It also includes a journal later appended to by a pre-33 build.
  The records scan (`_retry_provenance`) cannot catch these, because they never carried
  `prior_attempts`.
- The comment says a file hash was rejected because CRLF checkouts change it. A hash over the
  canonical record content (not the raw bytes) would be CRLF-immune and would bind the exemption
  to the evidence.
- The dict is also a plain mutable module global. "Closed" holds by convention only.
- The test `test_the_legacy_registry_is_exactly_the_three_recorded_drives` asserts
  `b"retries=0" in console` rather than that every `retries=` banner equals 0.

**Fix:** Extend each registry value with `n_records` and a sha256 over the sorted
`(question_id, graph_arm, outcome, duration_ms)` tuples of the loaded records.
`_legacy_drive` would then return the entry only when those match too. Wrap the registry in
`types.MappingProxyType`. Tighten the test to assert that all `retries=(\d+)` matches in the
console equal `0`.

### WR-02: SC-3, SC-4 and SC-5 evaluators pass on thin populations when `expected_*` is omitted

**File:** `eval/src/lancet_eval/unpark_gates.py:118-123, 493, 828, 1092`
**Issue:** `_coverage_clause` with `expected is None` returns `(None, {"coverage_note": "coverage not assessed"})`.
The evaluator then goes on to PASS on whatever n it scored. The public evaluators default
`expected_g` and `expected_v` to `None`. Only `main` supplies them. Any other caller (a future
script, a notebook, a test helper) gets exactly the CR-02 behaviour of PASS on a partial
population. The only trace is a detail note. The gate defaults open.

**Fix:** Make the argument required (keyword-only with no default). If a "not assessed" mode must
stay, return MISS with `reason="coverage not assessed"` and let tests opt out explicitly
(for example `expected_g=_SKIP`).

### WR-03: The stage spend cap is per invocation, so a reused journal restarts spend at zero

**File:** `eval/src/lancet_eval/measure.py:649, 668, 721`; `eval/src/lancet_eval/run.py:353, 378`
**Issue:** The cap compares only this invocation's `records` against `stage_spend_cap`.
- `run_measurement_pass` starts with `records = []` and opens `journal.jsonl` in append mode.
  `resolve_measurement_run_dir` is date-keyed, so a second same-day pass lands in the same
  journal and begins at $0 spend. The combined spend can exceed any single cap, and the journal
  mixes two passes. `summary`, the budget derivation and `total_records_emitted` cover only the
  second pass.
- `drive(resume=False)` has the same shape. `records = []`, `done_keys = set()`, and every unit
  is re-driven and appended to the existing journal. Duplicate keys then also make
  `build_rows` raise `DiagnosticError` at gate time.
- The cap is fail-closed within one invocation, which is what CR-01 asked for. A repeat
  invocation is a bypass of the stage cap as a stage-level budget.

**Fix:**
- In `run_measurement_pass`, refuse to start if `journal_path` exists and is non-empty, or load
  its records into the spend accumulator.
- In `drive`, refuse `resume=False` when the journal already holds records, or seed `records`
  from it. Keep `done_keys` empty only for a truly new journal.

## Info

### IN-01: In-flight spend is not reserved, so overshoot is bounded by workers times the per-unit ceiling

**File:** `eval/src/lancet_eval/measure.py:717-729`; `eval/src/lancet_eval/run.py:447-469`
**Issue:** The cap check counts only completed records. After the first completion with
`workers=N`, the window refills to N units on the strength of one record's spend. Overshoot is
bounded (up to N units), and the docstrings describe it as a bounded in-flight window. It is
still weaker than "fail-closed" reads in the CLI help.
**Fix:** Add a worst-case per-unit reservation (`failed_generation_attempt_usd` plus the
embedding estimate) per in-flight unit to the cap comparison, or document the N-unit overshoot
in the `--stage-cap` help.

### IN-02: Two header readers with different semantics

**File:** `eval/src/lancet_eval/journal.py:140-162` (`read_journal_header`);
`eval/src/lancet_eval/unpark_gates.py:~175` (`_read_journal_header`)
**Issue:** Both parse the journal header. The journal.py one skips leading blank lines. The
unpark_gates.py one reads only the first line. Neither catches `UnicodeDecodeError` raised
during line iteration. The writer-side guard (`_require_matching_journal_marker`) and the
reader-side gate can therefore disagree about what the header is. A journal with a leading blank
line is "marked" to the drive but "no header" (MISS) to the gate. That fails closed, so it is not
a correctness hole, only a drift risk.
**Fix:** Have unpark_gates import and use `journal.read_journal_header`. Wrap the iteration in
`try/except (OSError, UnicodeDecodeError)`.

### IN-03: `_ascii` guard is incomplete

**File:** `eval/src/lancet_eval/unpark_gates.py:~1535, 1255-1263`
**Issue:** The `_ascii` helper exists so that `main`'s `print` cannot raise on a legacy-code-page
Windows stdout. The completeness failure text interpolates `{exc}` and `{corpus_name!r}` raw.
`repr` keeps non-ASCII characters. The corpus name comes from header data. The `print` runs
after the md and json files are written, so the result is a late `UnicodeEncodeError` and a
non-zero exit rather than a clean MISS.
**Fix:** Wrap those two interpolations with `_ascii(...)`, or apply `_ascii` once when building
the output lines in `main`.

### IN-04: The 0.80 floor literal is duplicated between thresholds.py and gate.py

**File:** `eval/src/lancet_eval/thresholds.py:157`; `eval/src/lancet_eval/gate.py:21`
**Issue:** The two values are equal and a test pins the equality. They are still independent
literals, so a future edit to one drifts silently until that test runs. `gate.py` already
imports from `thresholds`.
**Fix:** In `gate.py`, set `STAGED_PAIRING_COVERAGE_FLOOR = UNPARK_GATE_COVERAGE_FLOOR`, or have
`thresholds.py` define the value and `gate.py` re-export it. Keep the equality test.

### IN-05: Duplicated gate-stage label validation with different rules

**File:** `eval/src/lancet_eval/cli.py:~474`; `eval/src/lancet_eval/run.py:65, 324-329`
**Issue:** The CLI rejects only an empty or whitespace-containing label. `drive()` enforces a
64-character `[A-Za-z0-9][A-Za-z0-9._-]*` regex. A label such as `a/b` passes the CLI check and
fails later inside the generic `except Exception` as "Run error", rather than as a usage error.
The `--retries 0` rule is also implemented twice.
**Fix:** Export `_GATE_STAGE_LABEL` from `run.py` (made public) and validate with it in the CLI
callback, or drop the CLI-side rule and let `drive()` be the single validator.
