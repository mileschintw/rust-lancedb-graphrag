## Summary

That covers graph seeding, paths and index, the boost fusion, `retrieve.rs`, `graph_context.rs`, `service.rs`, the config, proto and gateway wire, `reconcile_eval_store`, and the eval harness core: `run`, `measure`, `journal`, `identity`, `preflight`, `score`, `unpark_gates`, `diagnostic`, `flatness`, `decay_materiality` and `cli`.

Coverage limits, stated plainly:
- **Grep-level only:** every test file, the `oi02-replay-launch.ps1` and `oi02-replay-sampler.ps1` scripts, `eval/scripts/retro_lenient.py`, and the `inspect_lancedb.rs` modes other than `--document-ids` and `main`.
- **Partial reads:** `diag_probe.rs` (arg parsing and the two paid paths), `retrieval_soak.rs` (arg parsing and `main`), `oi02.py` (forensics section), `oi02-replay.ps1` (lines 120 to 380 plus a grep), `diagnostic.py` (lines 1 to 650).
- **Not read:** `gate.py`'s non-trigger logic, `latency.py` and `decay.py` beyond what callers use.

The Rust seeding and path core is largely sound. Seed IDs are UUID-validated before any predicate. Mention text never reaches a predicate. `GraphFact::new` escapes at construction. Path direction, degree-cap and ranking logic checked out on a trace. The wire tags (proto, `lancet.pb.go`, `lancet.v1.rs`) agree.

The defects cluster in the eval harness fail-closed machinery, which is the area this review was asked to stress. Three issues can fail open:
1. The parallel measurement path has no spend cap.
2. The unpark gates score a partial journal.
3. Harness-level retries erase billed spend and failure evidence from the journal.

Context for severity: the three recorded drives (`drive1`, `drive1b`, `drive2`) all ran with `--workers 1 --retries 0 --no-resume`, and their journals are complete. Their recorded readings are therefore not contradicted by CR-01 or CR-03. These are latent defects in tooling the next operator will run with defaults, and the CLI default is `--retries 2`.

## Critical Issues

### CR-01: `measure` ignores the stage spend cap when `workers > 1`

**File:** `eval/src/lancet_eval/measure.py:660-683` (CLI entry `eval/src/lancet_eval/cli.py:1049-1056`)
**Issue:** The serial branch calls `compute_spend` before each unit. The `workers > 1` branch submits every work unit to the executor at once (`futures = [executor.submit(...) for u in work_units]`) and never consults `stage_spend_cap`. The cap appears only in the summary dict afterwards. `lancet-eval measure --workers 4 --sample-size 500` therefore spends without bound. This is exactly the "fail-closed stage cap" the module and `run.drive` promise. `run.drive` bounds an in-flight window; this path does not.
**Fix:** Reuse the bounded-window loop from `run.drive` (prime `workers` futures, then check `compute_spend(records) >= stage_spend_cap` before each further submit). Minimal form:
```python
in_flight, it = set(), iter(work_units)
def _submit_next() -> bool:
    spend, _ = compute_spend(records, include_embeddings=True)
    if spend >= stage_spend_cap:
        return False
    u = next(it, None)
    if u is None:
        return False
    in_flight.add(executor.submit(measure_one, ...))
    return True
# prime with `workers` submits, then wait(FIRST_COMPLETED) and top up after each completion
```
Also record `stopped_by_cap` in the summary so a capped pass cannot be mistaken for a full one.

### CR-02: Unpark gates score a partial or incomplete journal; SC-1 can PASS on one

**File:** `eval/src/lancet_eval/unpark_gates.py:78-160` (`evaluate_sc1`), `:1274-1401` (`main`), `:163-268`, `:271-380`, `:383-536`, `:698-800`, `:955-1138`
**Issue:** The requirement is that a partial journal must never be scored as a gate. Nothing enforces it.
- `evaluate_sc1` checks only that the header flag is consistent with `completeness_comparison`. A journal that is incomplete and honestly labeled `partial: true`, with no `report.json`, produces no `reasons` and returns `status="PASS"` (line 142). The test fixtures confirm the drive-gate CLI is run on `partial: true` journals (`eval/tests/test_unpark_gates.py:105`, `:905-960`, `:1555-1580`).
- `main` computes SC-2, D-69, SC-3, SC-4 and SC-5 over whatever records exist. None of them calls `completeness_comparison`, and none refuses when the journal is incomplete.
- Thin partial populations can pass:
  - SC-5 rule (a) has no minimum `n`: `rule_a = rate >= floor` at line 1078, with `n_pairs(V) >= 1`. One pair with one boosted chunk gives 1/1 and PASS.
  - SC-3 uses the point estimate `p >= floor` (line 436) over `n = len(scored_rows)`, with no comparison of `n` to `len(g_ids)`.
- The gate table presents these readings side by side with a PASS SC-1, so an incomplete run reads as clean.

**Fix:** Compute completeness once in `main` and carry it into every reading.
```python
is_complete, missing = completeness_comparison(journal_path, corpus_name)
if not is_complete:
    # SC-2..SC-5 and D-69 become MISS("journal incomplete: N work units missing")
    # SC-1 detail["journal_complete"] = False and status MISS when run as a gate stage
```
Also have SC-3, SC-4 and SC-5 report `n` against `len(g_ids)` or `len(v_ids)` and MISS below a committed coverage floor. Add the floor to `thresholds.py` before the drive, as D-73 requires.

### CR-03: Harness retries drop billed attempts and erase failure evidence from the journal

**File:** `eval/src/lancet_eval/run.py:87-225` (retry loop); `eval/src/lancet_eval/cli.py:433-440` (default `--retries 2`)
**Issue:** `drive_one` overwrites `last_record` on each attempt and journals only the final one. Two consequences follow when `retries > 0`:
1. **Spend.** Tokens and failed-generation charges from earlier billed attempts never reach `compute_spend`. `drive` can overshoot `--stage-cap` by up to `retries` extra provider calls per unit, on top of the in-flight window.
2. **Gate inputs.** A D-69 rejection, a timeout, or an empty answer that succeeds on retry leaves no trace. `citation_rejection_rate`, `classify_record` counts and SC-2's error-mode tally read only the post-retry outcome, so a run with real rejections can PASS the tripwire.

The three recorded drives used `--retries 0`, so their readings are unaffected. The default CLI invocation is.
**Fix:** Accumulate per-attempt evidence on the final `RunRecord`, for example `attempts: list[AttemptSummary]` with outcome, `error_type`, node failures, token counts and duration. Have `compute_spend` charge every attempt. Have `classify_record` and the gate tallies read first-attempt failures. Alternatively, refuse `retries > 0` for gate-stage drives.

## Warnings

### WR-01: Spend accounting undercounts the failure paths it claims to cover

**File:** `eval/src/lancet_eval/measure.py:155-175`, `:578`; `eval/src/lancet_eval/run.py:269-270`, `:360-364`
**Issue:**
- `_failed_generation_attempts` charges a record that "reached generation but carries no GenerateAnswer outcome" via the `AssemblePrompt in timed and GenerateAnswer not in timed` branch (lines 170-174). A harness deadline or read timeout never produces such a record. `run_query` raises before returning, so `drive_one` and `measure_one` build the record in `except Exception` with empty `node_timings` and `node_failures`. The branch the comment describes is unreachable, and these records are charged zero.
- Provider-error detection is a string-prefix match on engine messages (`_RETRIED_MESSAGE_PREFIXES`, `_RETRIED_HTTP_PREFIX`). An engine message edit silently turns 2 charged attempts into 1.
- `check_provider_allowance(...)` at `measure.py:578` discards its return value. The remaining provider allowance is never compared to the stage cap, so "cannot verify allowance" passes whenever the endpoint answers 200.
- `drive` with `resume=False` sets `records = []` (line 270) but appends to the existing journal. Prior spend is excluded from the cap base and `write_header` is a no-op on a non-empty file.
- `run.py:360-364` sets `stopped_by_cap = True` when the final record pushes spend over the cap even though no units remain, so a complete run is labeled capped.

**Fix:** Have `run_query` attach partial node evidence to the exception, for example `StreamAborted.node_timings`, and have the exception-path record carry it. Compare `limit_remaining` to `stage_spend_cap` and halt if lower. Refuse `resume=False` on a non-empty journal. Move the cap check after `next(remaining_iter)` so `stopped_by_cap` is set only when units remain.

### WR-02: `--stage-cap` accepts NaN, infinity and non-positive values

**File:** `eval/src/lancet_eval/cli.py:441-447`, `:1034-1040`; `eval/src/lancet_eval/run.py:294`, `:362`
**Issue:** typer parses `--stage-cap nan` to `float('nan')`. `spend >= nan` is always False, so the cap never fires. `inf` does the same, and a negative cap stops before the first unit. The Rust `diag_probe` already validates "non-negative finite" (`diag_probe.rs:165-177`); the Python CLI does not. `measure --stage-cap` also silently defaults to 5.0 where `run --stage-cap` is required.
**Fix:** `if not (math.isfinite(stage_cap) and stage_cap > 0): raise typer.BadParameter(...)` in `run`, `measure` and `score --stage-cap`. Drop the silent default on `measure`.

### WR-03: `score` and `measure` CLI messages mislabel what happened

**File:** `eval/src/lancet_eval/cli.py:644`, `:1027-1033`
**Issue:**
- `score_benchmark` prints `Score report written to {run}/report.json` unconditionally. For a partial journal `score_run` writes no `report.json` (`score.py:1664`), so the message is false and the exit code is 0.
- `measure --cheap-model` is declared and documented ("Generation model to use for measurement pass") but never read. An operator can believe the model changed when it did not.

### WR-04: SC-3 shrinks its denominator for failures it does not disclose

**File:** `eval/src/lancet_eval/unpark_gates.py:417-436`, `:447-460`
**Issue:** `scored_rows` keeps only rows with `e_answer_usable is not None`. Any graph-off `outcome == "error"` (timeout, transport, other) drops out of `n`. `excluded_generate_answer_failures` counts only the four D-69 classes. With several of 60 G questions erroring for a non-D-69 reason, SC-3 can PASS on `n = 50`, with no `n / len(g_ids)` figure in `detail`. The config now sets `prompt_timeout_ms=120` and `retrieve_timeout_ms=2500`, hard node budgets whose failures remove records exactly this way. Check the committed AI-SPEC #5 wording before treating the point-estimate-versus-Wilson choice as a defect; the missing coverage disclosure is a defect either way.
**Fix:** Report `g_total`, `scored_n` and `excluded_by_class` (every `classify_record` class) in `detail`. Make a coverage shortfall (`scored_n < g_total`) at least a flagged reason, and a MISS under a committed floor.

### WR-05: Proto3 scalars carry no presence, so unmeasured reads as measured zero

**File:** `proto/lancet/v1/lancet.proto:255-267`; `engine/src/workflow/nodes/graph_context.rs:138-158`; `gateway/internal/sse/sse.go:109-156`; `eval/src/lancet_eval/journal.py:43-49`; `eval/src/lancet_eval/diagnostic.py:433-445`; `eval/src/lancet_eval/unpark_gates.py:658-664`
**Issue:** `graph_seed_count`, `graph_path_found`, `graph_degree_capped_count` and `graph_seed_document_ids` are plain proto3 scalars. `graph_context.rs` sets them only in the `Ok` arm, so graph-off, `GRAPH_TIMEOUT` and `GRAPH_DEGRADED` records all arrive as `0 / false / []`, and the gateway forwards them unchanged. The Python side documents "None means the record predates the field; a measured zero is 0". For any current-engine record `None` is unreachable, so every timed-out or degraded graph-on record is read as a measured "0 seeds, no path".
- `diagnostic.build_rows` lets these values override the offline probe, so a timeout reads as `path_found=no` and `d=no`.
- `_presence_stats` folds those records into `seed_count_n`, `path_found_n` and `degree_capped_n`.
- The gateway's `meta == nil` branch (`sse.go:136-155`) additionally invents an all-zero metadata block. The engine always sends metadata today (`runner.rs:678`, `:694`), so this only bites older engines.

**Fix:** Add presence. Use proto3 `optional uint32 graph_seed_count`, `optional bool graph_path_found` and so on. Alternatively add `bool graph_diagnostics_recorded` set only on the `Ok` arm. Have the gateway emit `null` when absent, and make the Python readers exclude records without it from those denominators. Until then, correct the `journal.py` and `client.py` comments, which promise a distinction the wire cannot make.

### WR-06: `no_match_rate` can no longer measure no-match

**File:** `eval/src/lancet_eval/dimensions.py:631-658`; `engine/src/workflow/nodes/graph_context.rs:145-158`; `eval/src/lancet_eval/unpark_gates.py:641`
**Issue:** Every empty-facts outcome, which includes no seeds and seeds with no path, adds a `GRAPH_UNAVAILABLE` notice. `no_match_count` excludes exactly the records carrying that notice, so every genuine no-match is excluded. The surviving numerator is `GRAPH_DEGRADED` records, which have zero counts and no excluded notice. The reported `no_match_rate` is therefore close to the graph error rate. It feeds the SC-4 disclosure (D-82's "no-match rate") and the staged gate's "Complement trigger fired" reason text. `gate.py:~270` shows the trigger changes only the reason string, not `overall_status`, so the impact is a mislabeled disclosure. The defect predates this phase but is newly surfaced.
**Fix:** Define no-match from the seeding fields once WR-05 gives them presence (`graph_seed_count == 0` among completed graph queries), and drop the notice-based exclusion.

### WR-07: Graph reads are not pinned to the snapshot generation the comments promise

**File:** `engine/src/service.rs:473-480`, `:506-513`; `engine/src/graph/paths.rs:500-523`; `engine/src/graph/seeding.rs:205-231`; `engine/src/graph/index.rs:137-208`; `engine/src/ingest.rs` (`rebuild_and_swap_with_graph_builder`)
**Issue:** The `ProductionGraphQueryPort` comment says a query "sees one generation of the index however many rebuilds happen". Only `GraphIndex` is snapshot-pinned.
- The vector scan of `entities.name_vector` and the seed-edge scan of `entity_edges` run against the live tables every query.
- Dense and chunk fetch correctly `checkout(nodes_version)`.
- The index itself is built from the latest `entities` and `entity_edges`, not at the `nodes_version` it is stored beside.
- After a rebuild or re-ingest (entity IDs are re-minted with `Uuid::new_v4()` in `ingest.rs`), seeds from the pinned index or live vector hits can fail to match live edges. Paths then disappear silently, and `seed_count` and `path_found` come out inconsistent.

**Fix:** Pin `entities` and `entity_edges` at snapshot-build time and store their versions in `CorpusSnapshot`. `checkout` them in the seeding and path scans, as `fetch_chunks_by_id` does for `nodes`.

### WR-09: Preflight edge cases that crash or pass silently

**File:** `eval/src/lancet_eval/preflight.py:875-879`, `:421`, `:377`, `:454`, `:881-904`
**Issue:**

### WR-10: `drive_measurement_pass.py` writes attestations it does not measure and is destructive

**File:** `eval/scripts/drive_measurement_pass.py:84`, `:164`, `:344-393`, `:441-467`, `:514-516`
**Issue:**
- `verdict` strings ("passed (single largest budget 65s < read timeout 300s)") are hardcoded and printed whatever `exceeds_ceiling` computes. The budgets (`60000.0`, `210,000 ms`) are literals, not read from `RAISED_ENGINE_ENV`.

**Fix:** Compute every attestation from data (read the effective config, compare the two ceilings, treat a `-1` count as "unknown"). Kill the PID this script spawned. Open the journal in append mode with a non-empty-file guard. Call `require_index_identity`. Meter the probe.

### WR-11: `reconcile_eval_store --apply` guard gaps

**File:** `engine/src/bin/reconcile_eval_store.rs:352-367`, `:316-340`, `:235-280`, `:557-567`
**Issue:**
- `load_allow_list` accepts an empty `entries` map (`#[serde(default)]`), so a mis-shaped or truncated `document_map.json` makes `extras` equal every document in the store and `--apply` deletes all of it. The Python counterpart `delete_pg_extras` explicitly refuses an empty `allow_ids` for this reason.
- `check_snapshot` requires only that `nodes.lance` exists under `--snapshot-dir`. It then rewrites `entities`, `entity_edges`, `documents` and `staged_documents_v2`, whose copies are not required.
- `rewrite_entities` deletes the entities first and re-adds them from in-memory batches. A failure between the two leaves them missing. LanceDB version restore is the only rollback.
- `delete_by_column_chunked` is not transactional across tables.

**Fix:** `if allow.is_empty() { return Err("document map has no entries; refusing") }`. Require all seven `*.lance` directories in the snapshot and a non-empty `nodes.lance`. Add-then-delete, or write a pre-apply version manifest and verify it before `--apply` proceeds.

### WR-12: `diag_probe --vector-top-k` embedding cache is keyed by question ID, not text

**File:** `engine/src/bin/diag_probe.rs:562-566`, `:606-611`
**Issue:** The cache key is `(question_id, embedding_model)`. If a questions file keeps an ID but changes the text, the stale vector is silently reused and column (c) is computed from the wrong embedding. The mention cache next to it is keyed by text and is correct.
**Fix:** Key by `(blake3(question_text), embedding_model)` or store and compare the text.

### WR-13: Rejected model output is logged verbatim at INFO and exported

**File:** `engine/src/generation/mod.rs:589-665`; `engine/src/generation/openrouter.rs:1009-1033`; `engine/src/workflow/nodes/generate.rs:27-50`
**Issue:** `emit_generation_output_rejected` records the first 2000 and last 500 characters of the model's output (`raw_head`, `raw_tail`).
