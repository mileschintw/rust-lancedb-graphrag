## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Added p99, decile histogram, and highest-degree entity name to `--graph-population`**
- **Found during:** Task 3 (preparing to write `06.3.4.1-STORE-BASELINE.md` §4)
- **Issue:** The task's own action text and §4 write-up require the baseline to state p99 entity degree (D-77 derives its production traversal caps from it) and the highest-degree entity's name, but `--graph-population`'s `DegreeDistribution` only emitted min/median/p95/max, and `GraphPopulationReport` only emitted `highest_degree_entity_id` (no name, no histogram). Estimating p99 from p95/max would not be a real measurement of this store's actual degree distribution.
- **Fix:** Added `p99` (factored `p95`'s existing linear-interpolation `(n-1)*q` formula into a shared `linear_interpolated_percentile` helper, no behavior change to `p95` itself), a `decile_histogram` function producing 10 equal-count buckets (documented rationale: equal-width buckets would collapse almost everything into the first bucket on this heavy-tailed distribution), and `highest_degree_entity_name` resolved from the same entities-table read that already fetches `entity_id` (added `name` to the existing column selection — no extra table scan).
- **Files modified:** `engine/src/bin/inspect_lancedb.rs`, `engine/src/inspect_lancedb_tests.rs`, `scripts/engine-test-targets.sh`
- **Verification:** 2 new property-based tests (`empty_store_has_no_degree_histogram`, `hub_and_spoke_percentiles_and_histogram_partition_every_entity`); `sh scripts/engine-test-targets.sh` — all 8 invariants pass (TOTAL 540); grep confirmed no `eval/` Python code consumes the old field shape, so the addition is safe
- **Committed in:** `f99f2095`

**2. [Rule 3 - Blocking] Invoked `delete_pg_extras` directly via `python -c` instead of the `pg-delete-extras` CLI**
- **Found during:** Task 2, step 5 (PostgreSQL apply)
- **Issue:** The plan's action text specifies `uv run --project eval lancet-eval identity pg-delete-extras --apply ... → reconcile/pg_deleted.json`, but the CLI command prints Rich-formatted, line-wrapped text (`Deleted 21 extra document(s): [...]`), which cannot be reliably redirected or parsed back into valid JSON.
- **Fix:** Called the same underlying function the CLI itself calls (`identity.py:254`'s `delete_pg_extras`, with `apply=True` and the pg_dump path) directly from a `python -c` one-liner, and wrote its returned ID list to `pg_deleted.json` as proper JSON.
- **Files modified:** none beyond the intended `reconcile/pg_deleted.json` output
- **Verification:** the 21 deleted IDs are set-identical to `reconcile/pg_extras.json`'s recorded 21 extras; PostgreSQL post-apply shows 346 rows, all `completed`
- **Committed in:** `d8a63cd4`
