## Accomplishments

- CR-02 completeness: `_journal_preconditions` is the single precondition site on `main`'s path. It resolves the journal, its header and its corpus and calls `completeness_comparison` exactly once. Failures are `no journal file`, `no header`, `no corpus in header or records`, an unmeasurable-completeness reason, and `journal incomplete: N work unit(s) missing`. On any failure every reading is a MISS carrying that reason, `n` is the record count, `detail` carries `journal_complete` and `missing_units`, and no evaluator, `build_rows` or invariance is called. Payload key set and order are unchanged on both paths; the drive-2 invariance entry is `{"not_computed": <reason>}` and `_drive2_markdown` renders `not computed: <reason>`.
- SC-1 (D-87a) is honest header AND complete journal AND `report.json`. `evaluate_sc1(run_dir, *, is_complete=None, missing_count=None)` measures completeness itself only when called directly; `detail` gains `journal_complete`.
- CR-02/WR-04 coverage: `thresholds.UNPARK_GATE_COVERAGE_FLOOR = 0.80` (pure 13-line insertion, no existing literal touched). `_coverage_clause(n, expected, label)` is applied at or above the floor to SC-3 (`len(scored_rows)`), SC-4 (pairs(G) headline n) over |sample & G|, and SC-5 (`composition["n"]` over pairs(V)) over |sample & V|. `main` computes both denominators once as integers from the header corpus's sample intersected with the populations file (a missing list is 0 and reads `expected population is empty`). Evaluators called without a denominator skip only the clause and say `coverage not assessed`. `GateReading.n` is unchanged for all three gates.
- WR-04: SC-3 `detail["excluded_by_class"]` counts every graph-off error class over G (a `None` class is labelled `unclassified`), beside the unchanged `excluded_generate_answer_failures`.
- Real-data tests: truncations of the drive-2 journal to 40 and 2 records (header `partial: true`, no `report.json`) read MISS on all six readings with `journal incomplete: 160 / 198 work unit(s) missing`; drive 1 (PIDs 2316), 1b (35940) and 2 (7372, baseline 1b) re-read into `tmp_path` equal their recorded `gates-<stage>.json` in `status`, `n` and `value`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] ASCII coverage label instead of U+2229**
- **Found during:** Task 2 (`_coverage_clause`)
- **Issue:** the plan's reason format uses the label `sample ∩ G`. `main` prints every reading's reason to stdout, and a redirected stdout on Windows uses the locale code page (the recorded drives ran through detached scripts), so a non-ASCII reason raises `UnicodeEncodeError` after the gate files are written.
- **Fix:** the reasons read `(sample & G)` / `(sample & V)`. Comments and provenance text keep the same meaning.
- **Files modified:** `eval/src/lancet_eval/unpark_gates.py`, `eval/src/lancet_eval/thresholds.py` (comment)
- **Committed in:** `795afe31`

**2. [Rule 2 - Missing critical] Unmeasurable completeness fails closed; corpus falls back to the first record**
- **Found during:** Task 1 (`_journal_preconditions`)
- **Issue:** the plan lists four failures. `completeness_comparison` can raise (unknown corpus config) and `evaluate_sc1` already falls back to the first record's corpus when the header has none; treating those differently in `main` would crash or double-measure.
- **Fix:** an exception becomes the failure reason `journal completeness could not be measured for corpus ...` (SC-1 is then a bare MISS built in `_unmet_precondition_readings`); the corpus derivation matches `evaluate_sc1` (`no corpus in header or records`). `completeness_comparison` is still called at most once per `main`.
- **Files modified:** `eval/src/lancet_eval/unpark_gates.py`
- **Committed in:** `a4776c68`

**3. [Rule 3 - Blocking] Shared header reader**
- **Found during:** Task 1
- **Issue:** `main` and `evaluate_sc1` each parsed the header line; the precondition helper would have been a third copy.
- **Fix:** one `_read_journal_header` used by `evaluate_sc1` and `_journal_preconditions` (behaviour unchanged).
- **Committed in:** `a4776c68`
