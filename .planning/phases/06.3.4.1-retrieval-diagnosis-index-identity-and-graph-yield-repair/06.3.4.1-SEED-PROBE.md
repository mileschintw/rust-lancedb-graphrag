## 8. D-77 caps and their inputs

**`DEGREE_CAP` = 33.**

- Input: the p99 of the post-reconcile entity degree distribution is **33.0** (source:
  `reconcile/graph_population_post.json`, `degree_distribution.p99`; the probe's index recomputes 33.0 over the same
  27,855 entities). Rounded up: 33.
- Formula: `ceil(p99)`. A two-hop neighbour with degree above 33 is excluded.
- The constant is in `engine/src/graph/paths.rs` with this derivation in its doc comment (committed in `173185fc`).

**`MAX_PATH_FACTS` = 8.**

- Inputs: evidence token budget 8192 and answer (max output) budget 2048, both read from the engine settings by the
  probe; **p95 tokens per rendered path fact = 69** over the 338 paths (p50 56, max 86, mean 55.3).
- Formula: `min(16, floor(0.10 × (8192 − 2048) / 69))` = `min(16, floor(8.90))` = **8**.
- What was counted: one fact per path (a two-hop path is one `GraphFact` whose relation text is the chain
  `r1→X→r2`), as the `<GRAPH_FACT …>` block that `prompt::pack_evidence_and_graph_prompt` builds, tokenised with
  cl100k. The section header is counted once per prompt there and is not in the per-fact figure. A reading that
  renders a two-hop path as two facts was not measured.
- The derivation helper `derive_max_path_facts` is in `paths.rs`. The user confirmed both caps on 2026-10-05 (section 9),
  and `pub const MAX_PATH_FACTS: usize = 8` is in `paths.rs` with this derivation in its doc comment, pinned by the test
  `the_confirmed_path_fact_cap_is_the_budget_formula_at_the_measured_p95`.

## 9. Task 3 decision: the boost when a question has seeds but no seed-to-seed path (decided 2026-10-05)

The decision is the user's. The plan's two options, verbatim:

- **paths-only** - Paths only (D-76 literal): no path means no graph chunk candidates.
  Pros: Strictest reading; injects only bridge evidence.
  Cons: If paths are rare, graph-on barely changes retrieval composition.
- **paths-plus-seed-chunks** - Paths first, and when no path exists use the top seeds' source chunks (a length-0
  path), capped at max_graph_chunk_candidates.
  Pros: The graph contributes entity-anchored chunks on questions without a bridge.
  Cons: An extension of D-76's wording that needs this explicit approval; hub seeds are still demoted by specificity.

### Decision

- **Chosen option: `paths-only`.** When a question has seeds but no seed-to-seed path, graph chunk candidates are
  empty. The seeds' own source chunks are not used.
- It ships as the production default with **no flag** (D-78). If the graph-on result is negative it is reported per
  D-49. D-83 forbids choosing by which option makes SC-4 pass, and this choice was made on what the graph should
  contribute, not on SC-4.
- The paths-only semantics are enforced in the production code of plans 14 and 15. Plan 13 writes no fusion or boost
  code. `seed_chunk_candidates` stays in the library only because the offline probe uses it to measure the option that
  was not chosen; nothing in the retrieval path calls it.
- **Caps confirmed:** `DEGREE_CAP` = 33 (p99 degree) and `MAX_PATH_FACTS` = 8 (p95 of 69 tokens per fact). Both are
  documented constants in `engine/src/graph/paths.rs`.

### Selection rule

A question qualifies when all five hold (the probe's 100 questions are the pool; "content seed" is defined below):

1. It is non-null, present in `questions.sample.jsonl` (the manifest's verbatim-text source), and not already a canary.
2. None of its seeds is the nameless (whitespace-only) entity that `90d76668` now skips. Its probe row predates that
   guard, so a question carrying it cannot be judged from the row.
3. It has at least 2 **content seeds**: not nameless, not a publisher name (the 43 gold `source` values, read as in
   section 3), not a month name, and not a hub (degree at most the probe's p95, 10).
4. `path_found` is true, the **top-ranked path** has both end entities among the content seeds, and its score is
   strictly above the next path's (or it is the only path). The engine ranks by score, then fewer hops, then entity ID,
   so the order is deterministic; the strict gap is the extra "stable" requirement.
5. At least one end of that top path is sourced from a gold evidence document of the question
   (entity, source chunk, document, resolved through `document_map.json` by title, as column (d) does).

Tie-break, stated before the list was read: the **lowest `question_id`**.

Criterion counts over the 100 questions (a question can fail several, so the rows do not sum): 10 null, 1 an existing
canary, 15 carry the nameless seed, 63 have fewer than 2 content seeds, 30 have no path, 57 have a top path whose ends
are not both content seeds, 5 have a top-path score tied with the next, 4 have no top-path end in a gold document.
