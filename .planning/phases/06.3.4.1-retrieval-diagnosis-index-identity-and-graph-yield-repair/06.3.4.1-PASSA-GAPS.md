### G2: no budgets exist from pass A, and the rule output has hazards (D-66, D-89)

- After G1, re-gate pass A under the new set. If both prongs are available and decay is
  not present, derive with `derive_budgets_from_records` (06.3.3's committed derivation
  rule, unchanged: p95 × 1.5, nesting slack 500 ms, harness ceilings), then complete what
  plan 11 Task 3 specified (config trio in one commit, agreement unit test, rewritten
  comment blocks, `LANCET_ENGINE__WORKFLOW__*` unset, release rebuild/restart, preflight on
  `multihop_rag_diag`). Plan 11's SUMMARY is written when this is done, so the phase's
  plan tracking closes plan 11 (it records that Tasks 2–3 were completed through the gap
  plan, with the pass A run as its measurement).
- Hazards found by the orchestrator that must be put in front of the user as a blocking
  `checkpoint:decision` BEFORE any value is written to config (the committed rule has no
  floor and was never designed for a sub-second release engine):
  - `measurement.json`'s void `proposed_budgets` carried the two unmeasured inner budgets
    (`query_embedding_timeout_ms`, `graph_operation_timeout_ms`) forward from the
    *effective* config, which during pass A was the temporary raised measurement
    ceilings (30000 / 120000). Nesting then raised `retrieve_timeout_ms` to 30500 and
    `graph_node_timeout_ms` to 150500. Carrying a temporary measurement ceiling into
    production is wrong; the source of those two inner values must be chosen explicitly
    (options include the committed TOML values 15000 / 40000, `config.rs`'s 06.3.3 values
    645 / 38595, or measuring them from sub-stage telemetry if it is complete enough).
  - The rule's raw outputs sit below pass A's own observed maxima. Counting pass A's 320
    measured records against ceil(nearest-rank p95 × 1.5): RetrieveHybrid 294 ms, 8 records
    above (max 403); ExtractGraphContext 1062 ms, 3 above (max 1438); AssemblePrompt 11 ms,
    7 above (max 43; 11 ms is also near Windows timer granularity). Drive 1's flatness
    proof needs zero RetrieveHybrid and harness timeouts (D-64, AI-SPEC §5), so a budget
    that pass A itself would have exceeded makes drive 1's flatness reading likely
    unavailable. Whether the nesting raise already lifts a budget clear of this, and what
    floor (if any) applies, is the user's decision; present the derived values, the
    nesting-resolved values, and per-budget exceedance counts on pass A's data.

### G4: `GenerateAnswer` failures at 41.7% (D-91)

- Evidence (`06.3.4.1-BUDGETS.md` "Incidental"): 52 `answer basis 'mixed' requires at least
  one cited evidence ID`; 44 `ModelOnly answer basis is not supported on Phase 03 QueryRAG
  path`; 22 `failed to deserialize ModelOutput schema: trailing characters ...`; 11
  `answer basis 'retrieval' requires at least one cited evidence ID`; 3 empty answer; 2
  `finish_reason 'length'`; 1 notice length > 1024. Graph-on 76/162, graph-off 59/162.
  07's paid replay (`paid-drive-era`: the drive-era commit `33e774bd` against the
  pre-reconcile store, so both code and store differ from pass A) saw 66/350, all `ModelOnly`; the
  06.3.4 baseline (D-69) was 25 mixed / 8 retrieval / 10 ModelOnly. The `mixed`/`retrieval`
  missing-citation classes and the `trailing characters` deserialization failures are new
  or much larger since plan 08 (`af23ab97`, D-71 final-answer instruction and citation
  repair) and are the first suspects; verify, do not assume.
- Committed gates at stake: `CITATION_REJECTION_TRIPWIRE = 0.159` (63/324 = 19.4% of pass A
  records are citation-constraint rejections), `VECTOR_BASELINE_USABLE_FLOOR = 0.512`.
- Required: a free diagnosis first, class by class, from existing artifacts (journal,
  Loki/raw events, engine code for the validator and the ModelOutput parser, plan 08's
  diff). Fix what is a bug or a regression (e.g. a parser rejecting valid output with
  trailing content, a prompt regression introduced by plan 08). Anything that changes the
  answer contract, the validator's acceptance rule or the D-71 prompt beyond a bug fix is a
  blocking `checkpoint:decision`. Any paid probe needed to confirm a fix is its own D-86
  capped stage behind a blocking checkpoint. No suppression (D-91).
- Include in this item: the harness cost estimate undercounts because failed-generation
  records carry zero wire tokens although the provider billed them ($0.0748 estimated vs
  $0.2178 billed). Stage caps are enforced on the estimate, so a cap can be overshot about
  3×. Make the stage-cap accounting count billed tokens of failed generations, or record a
  conservative correction the D-86 checkpoints of drive 1 and drive 2 must use. (Orchestrator
  addition: the user approved the five items above; this cost-safety fix is surfaced to them
  at plan review.)
