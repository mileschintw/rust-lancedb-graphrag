## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The warm-up test's stop markers were committed as raw line breaks**
- **Found during:** Task 1, when `cargo fmt --check` showed the string literal split across lines after the GREEN commit
- **Issue:** The `prompt_tokenizer_warmup_reads_the_singleton` body-slice markers (`"\nfn "`, `"\npub fn "`, `"\n#[cfg(test)]"`) were written into the RED and GREEN commits as literal line breaks inside the string, so the test depended on the source file's line endings. It passed on the LF copy it was written on and would not have matched a CRLF checkout.
- **Fix:** Replaced them with `\n` escapes and applied rustfmt to the four new tests only.
- **Files modified:** `engine/src/prompt.rs`
- **Verification:** `cargo test --locked --lib prompt::` 10 passed
- **Committed in:** `4dfb3ea1` (a fix to a defect in my own RED/GREEN commits, not a refactor despite its `refactor` type)

**2. [Rule 2 - Missing critical functionality] The accepted-miss message would have lost its decision ID on the console**
- **Found during:** Task 3, while writing the CLI tests
- **Issue:** The required message text `ACCEPTED KNOWN MISS [D-94]: ...` contains `[D-94]`, which Rich markup reads as a style tag and drops silently, so the console would have printed the miss without its decision ID.
- **Fix:** The CLI escapes the message of an `accepted_known_miss` row with `rich.markup.escape`. Other rows are printed as before, so the default output is unchanged.
- **Files modified:** `eval/src/lancet_eval/cli.py`
- **Committed in:** `e14e7f12`
