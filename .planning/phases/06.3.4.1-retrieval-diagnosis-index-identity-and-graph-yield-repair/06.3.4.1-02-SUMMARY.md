## Decisions Made

- **Alias check scope (Rule 1 bug, found via real data):** `compute_identity`'s `alias_present` check originally unioned alias keys and values into the "must be absent" set. Running the full suite against the real committed `eval/corpora/multihop_rag/document_map.json` (whose one alias entry maps the stale `0370301a-0ad7-4267-a337-ba2dda34595f` to the live, present `cc30a4d5-bb47-4331-bd0e-546f962942ea`) immediately produced a false-positive `alias_present` failure on every `multihop_rag`-backed test. Fixed to check only alias *keys*.
- **`delete_pg_extras` schema enforcement:** `assert_schema_isolated` alone accepts any valid, non-public, non-dev-colliding schema name (e.g. a hypothetical `other_eval`), but the DELETE SQL hardcodes `lancet_eval.documents`. Added an explicit `schema_name != "lancet_eval"` check so a differently-named isolated schema can't silently target the wrong table.
- **`delete_pg_extras` empty-`allow_ids` refusal (Rule 2):** an empty `allow_ids` would otherwise build `WHERE id NOT IN ()`, which is either a SQL error or — depending on how it were built — a delete-everything. Refused explicitly before any SQL is touched.
- **conftest.py autouse fixture design:** patches `identity.list_lancedb_document_ids` / `identity.list_pg_documents` to mirror whatever `load_document_map` resolves for the corpus under test (tracked via a thin wrapper around that same name), rather than hardcoding one corpus's data. This makes `graphrag_bench` (which has no committed `document_map.json` — it resolves to an empty map) trivially pass against empty LanceDB/PostgreSQL sets, so the dozens of pre-existing `graphrag_bench`-based `drive()` tests in `test_stage_cap.py` / `test_journal_reconcile.py` (neither in this plan's file list) needed no changes. The fixture is explicitly skipped for `test_identity.py` so that file's own tests still exercise the real `list_lancedb_document_ids` / `list_pg_documents` implementations against mocked `subprocess.run` / `run_psql`.
- **`record_index_generation` return-value handling in `seed_corpus`:** `record_index_generation` loads its own fresh `DocumentMap` via `load_document_map(corpus_name)` rather than taking `seed_corpus`'s in-memory object as a parameter (per the plan's fixed signature). `seed_corpus` now persists its in-memory `doc_map` before probing (so a from-scratch, zero-new-document seed still has a file to read back) and reloads from disk afterward, rather than assigning `doc_map.index_generation = ...` directly — keeping `record_index_generation` the only place in `seed.py` that mutates a `DocumentMap.index_generation` attribute.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `alias_present` check incorrectly included alias values alongside keys**
- **Found during:** Task 2, running the full test suite against the real committed `multihop_rag` document map
- **Issue:** `alias_ids = set(doc_map.aliases.keys()) | set(doc_map.aliases.values())` flagged the alias *target* (a normal, legitimately-present document) as a violation whenever it appeared in the stores — which it always does, since it's a real active document
- **Fix:** `alias_ids = set(doc_map.aliases.keys())` — only the stale IDs that resolve elsewhere via aliasing must be absent
- **Files modified:** `eval/src/lancet_eval/identity.py`
- **Verification:** `eval/tests/test_identity.py::test_alias_present_in_lancedb_fails` / `::test_alias_present_in_postgresql_fails` still pass; full `multihop_rag`-backed suite (486→495 tests across the plan) green afterward
- **Committed in:** `eee4c9ff` (Task 2 commit)

**2. [Rule 2 - Missing critical] `delete_pg_extras` did not explicitly reject a non-`lancet_eval` schema or an empty `allow_ids`**
- **Found during:** Task 1, writing behavior tests against the must_haves bullet "with a non-`lancet_eval` schema raises (via `assert_schema_isolated`)" — `assert_schema_isolated` alone does not reject a differently-named isolated schema, and the DELETE SQL hardcodes the table name
- **Issue:** a hypothetical alternate isolated schema (e.g. `other_eval`) would pass `assert_schema_isolated` and let `delete_pg_extras` run its hardcoded `lancet_eval.documents` DELETE against the wrong target; an empty `allow_ids` would build a malformed or overly broad `NOT IN ()` clause
- **Fix:** explicit `schema_name != "lancet_eval"` check and an explicit empty-`allow_ids` refusal, both before any SQL is built
- **Files modified:** `eval/src/lancet_eval/identity.py`
- **Verification:** `test_delete_pg_extras_refuses_non_lancet_eval_schema`, `test_delete_pg_extras_refuses_empty_allow_ids`
- **Committed in:** `c0514187` (Task 1 commit)

**3. [Rule 3 - Blocking] `record_index_generation`'s fixed signature (reloading via `load_document_map(corpus_name)`) desynchronized `seed_corpus`'s returned in-memory object**
- **Found during:** Task 3, running `test_seed_corpus_multipart_no_chunk_overrides` after the refactor

- **Files modified:** `eval/src/lancet_eval/seed.py`
