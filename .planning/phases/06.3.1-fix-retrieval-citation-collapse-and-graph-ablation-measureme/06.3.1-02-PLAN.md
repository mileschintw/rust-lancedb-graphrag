<objective>
Close the fail-open hole in `get_or_create_table`: today it treats **every** `open_table`
error as "table does not exist" and creates a fresh empty table, at the one function backing
all six LanceDB accessors.

Purpose: a transient runtime, I/O, or object-store error on a live store currently causes the
engine to quietly substitute an empty table for a populated one on the hot read path — a latent
data-loss and silent-wrong-answer risk. CONTEXT.md D-26 exonerates this defect as the cause of
the 2026-09-03 collapse but keeps it in scope precisely because it is genuine. Phase 06.3
carried it forward as a named "Known Issue Outside Phase Scope"; this plan closes it.

Output: an error-discriminating open path, a named helper for the missing-table condition, and
a regression test that fails if the discrimination is ever removed.
</objective>

   is the only way to make `open_table` genuinely return `TableNotFound` on this surface.

   (`src/connection.rs:521`, signature `drop_table(&self, name: impl AsRef<str>, namespace_path: &[String])`).
7. **Non-missing `lancedb::Error` variants ARE externally constructible, so synthetic
   discriminator tests are viable and are the primary mechanism for Test 2.** `pub enum Error`
   in `lancedb-0.31.0/src/error.rs:14` carries `#[snafu(visibility(pub(crate)))]`, which restricts
   the generated *context selectors* — not the enum variants. Variants with only public owned

   `Runtime { message: String }` (`:40`), `Timeout { message: String }` (`:42`),
   `Schema { message: String }` (`:38`), `InvalidInput { message: String }` (`:18`),

   (`:20`) is likewise constructible with any boxed error as `source`. This is what makes
   Antigravity's suggested "direct discriminator unit tests with synthetic variants" implementable
   without mocking the driver or corrupting a store on disk.
