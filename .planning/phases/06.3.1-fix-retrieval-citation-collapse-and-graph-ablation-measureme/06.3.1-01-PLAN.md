<critical_findings>
Read these before touching any file. They were established by direct inspection of the
codebase and of `eval/runs/2026-09-03-multihop_rag/journal.jsonl` during planning, and two of
them **correct** `06.3.1-PATTERNS.md`.

1. **Node timeouts are enforced OUTSIDE the node.** `engine/src/workflow/runner.rs:386` wraps
   `node.run(ctx, cancel)` in `tokio::time::timeout`. On expiry the node future is **dropped
   mid-execution**; code after the await point inside the node never runs.
   `06.3.1-PATTERNS.md` (lines 94-106) suggests emitting the new notice from inside
   `engine/src/workflow/nodes/retrieve.rs`. **That suggestion is wrong and would silently
   reproduce the original bug** — the same failure mode as the notice-conjunction trap
   CONTEXT.md D-29 warns about. Emit from the runner's node-error branch.
   Mutations already applied to `ctx` before the drop **do** persist, because `ctx` is owned by
   `run_workflow` and only mutably borrowed by the node future.
2. **`buf generate` regenerates BOTH trees in one command.** `buf.gen.yaml` declares four
   remote plugins writing to `engine/src/pb` (prost + tonic) and `gateway/proto` (protobuf-go +
   grpc-go, `paths=source_relative`). D-52's "both proto trees" is one invocation, not two
   hand-maintained edits. `buf` v1.72.0 is on PATH. The remote plugins require network access.
3. **Proto tag 19 is free.** `proto/lancet/v1/lancet.proto:72-99`: codes 1-5 and 10-16 in use,
   **17 explicitly `reserved`**, 18 = `GRAPH_ABLATION`, 20-22 = Phase 6.1 index codes.
4. **`derive_degraded_mode`'s match is exhaustive** (`engine/src/workflow/mod.rs:236-260`).
   Adding a proto enum variant breaks compilation until it is classified. This is a positive
   forcing function — do not add a wildcard arm to silence it.
5. **The gateway needs no logic change.** `gateway/main.go:543-566` renders
   `pb.NoticeCode(n.TypedCode).String()` with the `NOTICE_CODE_` prefix trimmed and
   `sort.Strings` for determinism. An unregenerated vendored pb.go makes `String()` return the
   bare `"19"`; regeneration is the entire fix.
6. **The transient non-compiling window in Task 1 is intra-plan and safe for wave-1 siblings.**
   Plans 02 and 03 share Wave 1 and assert `cargo build` / `cargo test --lib` / `cargo clippy`
   over the same `engine/` crate, so the plan-checker flagged a possible coupling. It does not
   materialize on either execution path: with worktree isolation (`workflow.use_worktrees`
   unset → defaults true, `execute-phase.md:102`) each plan executes in its own worktree forked
   from the pre-wave base and never observes this plan's intermediate state; and when isolation
   degrades to `none`, `execute-phase.md:813` forces non-worktree plans in the same wave to
   serialize, so Task 2 has closed the window before plan 02 or 03 starts. **Do not add
   `depends_on` edges to plans 02/03 to "fix" this** — that would serialize the wave for no gain.
   The window must still close within this plan: Task 1 and Task 2 are not independently
   committable, and the crate must compile before this plan reports complete.
</critical_findings>
