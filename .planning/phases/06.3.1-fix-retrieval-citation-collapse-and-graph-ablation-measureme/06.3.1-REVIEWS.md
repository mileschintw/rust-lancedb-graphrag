# Cross-AI Plan Review — Phase 06.3.1

## Cursor Review

The plans are source-grounded and correctly scoped, but Wave 1 will not compile as written: declaring the two new prost fields in plan 01 breaks existing Rust struct literals that plan 01 is not allowed to update.

### Summary

Phase 06.3.1’s four plans match the ROADMAP seam-1 goal: make retrieval death visible on the wire, attach provenance when the retrieve future is dropped, count graph influence at prompt packing, retain graph spans, document timeout nesting without changing values, and fail closed on non-`TableNotFound` LanceDB opens. The central mechanism claims check out against source: node timeouts are enforced in `runner.rs` (the node future is dropped), `NO_EVIDENCE` and the retrieval snapshot sit at the end of `retrieve.rs::execute` and are unreachable on timeout, graph operation timeout is inner and non-fatal, production `success=false` on any node `Err` already holds, and the 2026-09-03 false green is the harness (`run.py` hardcodes `outcome="success"`). Wave 1/2 file splits, generated-code ownership (`buf generate` once in plan 01), and “no eval / no budget values / no production success-semantic change” constraints are coherent. The blocking gap is that plan 01 declares `WorkflowMetadata.graph_prompt_fact_count` and `WorkflowCompletedEvent.partial_snapshot` but understates the prost compile break: those fields are not optional in Rust struct literals, `events.rs` is not in plan 01’s `files_modified`, and Task 2 never stubs the new fields. Until that is fixed, plan 01 cannot close, and plan 04 cannot populate fields the crate never compiled.

### Strengths

- **Timeout ownership is diagnosed correctly, and PATTERNS.md is explicitly superseded.** `WorkflowRunner::run_node` wraps `node.run` in `tokio::time::timeout` at `engine/src/workflow/runner.rs:386-388`; on expiry the future is dropped and `NodeError::timeout` is returned. Plan 01’s prohibition on emitting `NOTICE_CODE_RETRIEVAL_FAILED` from `retrieve.rs` is the right fix: snapshot construction and `NO_EVIDENCE` both sit at `engine/src/workflow/nodes/retrieve.rs:287-309`, after dense/BM25/fusion/rerank awaits, so a timeout never reaches them.
- **Partial-snapshot seeding is the only reliable D-33 mechanism.** `ctx` is owned by `run_workflow` and mutably borrowed by the node future (`runner.rs:512`). Mutations applied before the first await survive the drop. Plan 04 places the seed after variant defaulting and before `retrieve_dense` (`retrieve.rs:83-93`), keeps the terminal overwrite, and distinguishes an empty `result_hash` from a hash over zero chunks.
- **D-29/D-30 are reconciled against source rather than reimplemented wrongly.** `run_workflow` sets `overall_err` on any node `Err` and breaks (`runner.rs:512-514`); `emit_terminal_once` emits `success=false` and `final_response: None` (`runner.rs:665-676`). `workflow_phase5_retrieve_timeout_ten_seconds` already asserts `!completed_event.success` (`engine/src/tests/workflow_phase5.rs:1023-1024`). The journal false green is `eval/src/lancet_eval/run.py:58`.
- **Graph influence vs. presence is wired at the right seam.** Presence is set in `graph_context.rs:127-160`. Influence belongs after `pack_evidence_and_graph_prompt`; `graph_weight == 0.0` hard-excludes facts before packing (`engine/src/prompt.rs:356-360`).
- **Timeout nesting documentation matches live wiring.** Runner top-level budgets are in `runner.rs:298-306`. Inner graph-operation expiry is non-fatal (`graph_context.rs:162-187`). `10000 + 4000 < 15000` is asserted at `engine/src/tests.rs:362-366`.
- **LanceDB fail-closed shape is confirmed.** `get_or_create_table` discards every open error with `Err(_)` (`engine/src/db/mod.rs:111-128`). `lancedb 0.31.0` uses `Error::TableNotFound { name, source }`; six accessors at `db/mod.rs:131-154` share the function.
- **Proto/codegen and gateway rendering claims are accurate.** Tag 19 is free (`proto/lancet/v1/lancet.proto:72-99`), `buf.gen.yaml` writes both trees, gateway rendering is generic (`gateway/main.go:543-567`), and `derive_degraded_mode` is exhaustive (`workflow/mod.rs:249-266`).
- **Scope discipline is real.** Nothing under `eval/` is touched; budget values are deferred; graph tuning is forbidden; test-count scripts are owned by plan 04; OBS-05 is cited and OBS-02 is not.

### Concerns

#### HIGH

1. **Plan 01’s proto field declarations will not compile, and the plan neither stubs the fields nor lists `events.rs`.** After `buf generate`, prost requires every field in struct literals. Today `WorkflowCompletedEvent { ... }` is built at `engine/src/workflow/events.rs:366-374` without `partial_snapshot`, and `WorkflowMetadata { ... }` is built at `engine/src/workflow/runner.rs:620-631` without `graph_prompt_fact_count`. Plan 01 allows only the `derive_degraded_mode` non-exhaustiveness error and never closes these two errors. `events.rs` is deferred to plan 04.

#### MEDIUM

2. **D-33 makes a literal reading of D-29’s “and no snapshot” predicate false.** After early seeding, `ctx.snapshot` is present on timeout. The timeout test and 06.3.2 contract must explicitly distinguish audit-only partial snapshots using the retrieval-failure notice, empty chunks, empty `result_hash`, and `success=false`; snapshot presence alone must not imply usability.
3. **Plan 02 Test 1 likely never exercises the missing-table create branch.** `DatabaseManager::initialize` creates every schema first, while `open_and_validate` requires every table. Calling accessors after initialization exercises only the open-success branch. The corrupted-directory test may also be classified by LanceDB as `TableNotFound`.
4. **`cargo clippy --all-targets -- -D warnings` is a known-red repository gate.** The repository’s clean production surface is `--lib --bins`; all-target lint has pre-existing test findings.
5. **Wave 1 tests intentionally invalidate strict test-count scripts until plan 04.** Any global execute/CI gate run after plans 01–03 will fail despite the plans forbidding script updates.
6. **Plan 03 tests `ShouldSample` directly but does not prove the `tracing-opentelemetry` layer reaches it for graph child spans beneath a dropped parent.**

#### LOW

7. **Plan 01’s gateway body assertion may not pin proto regeneration.** SSE copies `Notice.Code` verbatim while span extraction derives the enum string. Hardcoding the body code would pass with stale generated code.
8. **`RetrievalSnapshotDTO` omits `variant_count` and `variant_identities`** (`gateway/internal/sse/dto.go:47-58`), so reusing it for the partial snapshot drops those fields on HTTP.
9. **`communities` is a seventh table schema but has no accessor.** Keep Plan 02’s six-accessor scope explicit.
10. **The new retrieval failure uses Error severity while sibling degradation notices use Info.** This is acceptable but should be intentional.

### Suggestions

1. In plan 01, add `engine/src/workflow/events.rs` to `files_modified`; initialize `partial_snapshot: None` and `graph_prompt_fact_count: 0` after codegen. Plan 04 can then replace those stubs with real values.
2. In plan 04’s timeout test, assert `success == false`, `RetrievalFailed` present, `NoEvidence` absent, non-empty index generation, empty chunks, and empty `result_hash`.
3. Strengthen Plan 02’s tests so the create branch is genuinely exercised and the non-missing error is asserted before checking failure.
4. Use `cargo clippy --manifest-path engine/Cargo.toml --lib --bins -- -D warnings`.
5. Add a provider-level graph-span retention test, or explicitly document that only the sampler seam is proven.
6. Derive the gateway notice body string from the generated enum before asserting the literal `RETRIEVAL_FAILED`.
7. Extract a snapshot DTO helper and decide explicitly whether variant provenance belongs on the HTTP partial snapshot.
8. State clearly that test-count scripts are expected red until plan 04 and are not intermediate Wave 1 gates.

### Risk Assessment

**MEDIUM, trending HIGH until the Plan 01 prost-literal compile gap is fixed.** The design and source analysis are strong, but the generated-field initialization gap prevents Plan 01 from completing as written.

## Consensus Summary

Both reviewers found the plans unusually well grounded in the current source and agreed that the central architecture is correct: retrieval timeout handling belongs in the runner; provenance must be seeded before the first await; graph influence must be measured after prompt packing and separately from graph presence; the LanceDB fix belongs in the shared accessor helper; proto generation must remain one atomic pass; and Phase 06.3.1 should not change eval code, timeout values, graph tuning, or production success semantics.

The reviewers identified two independent plan-blocking risks. Cursor found that Plan 01’s new generated Rust fields make existing struct literals fail to compile before Plan 04 is allowed to update them. Antigravity found that Plan 04 records a tracing field never declared on the query span, making the record call a silent no-op. Both should be corrected before execution.

### Agreed Strengths

- Correct timeout/drop analysis and runner-owned failure notice.
- Correct early provenance seeding with success-path overwrite.
- Correct presence-versus-influence distinction.
- Correct one-pass proto generation and generic gateway rendering.
- Correct centralized LanceDB error discrimination.
- Strong scope control and phase dependency ordering.

### Agreed Concerns

- Verification commands assume POSIX tools despite a Windows host; the plans should specify Git Bash or portable commands.
- Plan 02’s corrupted-store test is likely fragile on Windows and needs a deterministic fallback.
- Plan 04 needs explicit DTO conversion ownership rather than referring to a helper that does not exist.

### Divergent Views

- Cursor rates the Plan 01 generated-field initialization gap HIGH and potentially phase-blocking; Antigravity did not identify it and rated Plan 01 LOW.
- Antigravity rates the undeclared `graph_prompt_fact_count` tracing field HIGH because `Span::record` silently ignores undeclared fields; Cursor did not identify that specific defect.
- Cursor additionally flags the known-red all-target Clippy gate, intermediate test-count gate failures, and sampler integration-test depth. Antigravity treats the corresponding plans as low risk.

### Required Revisions Before Execution

1. Amend Plan 01 to initialize both newly generated Rust fields immediately after codegen, including `engine/src/workflow/events.rs` ownership.
2. Amend Plan 04 to declare `lancet.workflow.graph_prompt_fact_count` at query-span creation and add `engine/src/service.rs` to its file set.
3. Add explicit snapshot DTO helper ownership to Plan 04.
4. Replace known-red or host-incompatible verification commands with repository-supported equivalents.
5. Tighten the retrieval-timeout and LanceDB tests so partial audit snapshots and induced driver errors cannot produce false positives.
