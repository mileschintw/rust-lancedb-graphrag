## 1. System Classification

**System Type:** Hybrid — RAG / GraphRAG **evaluation harness** (the artifact) measuring a shipped
multi-hop RAG + knowledge-graph stack (the system under test).

> Classification note (inherited from 06.3-AI-SPEC §1, not reopened): the *system under evaluation*
> is already shipped in Rust (engine) and Go (gateway). The artifact this family changes is the
> Python `eval/` harness plus a small set of engine/config fidelity fixes that make failures visible.
> No new AI framework is being chosen.

**Description:**
The 06.3 harness already drives `/rag/query` over a committed MultiHop-RAG sample and publishes an
advisory report. That report is currently **not entitled to be believed**: infrastructure failure
was scored as quality, unpaired arms were averaged as an ablation, and a self-contradictory
success flag read as a perfect wire contract. This family makes the evaluation signal trustworthy
— persist the wire diagnostics the engine already emits, score per-path yield and latency
symmetrically, redefine ablation as a paired comparison with a confidence interval, exclude
unusable records from quality denominators, and re-drive — so Phase 6.4 documents a corrected run
rather than the 2026-09-03 collapse. "Good" is a number a reviewer can trace to usable records,
pairing coverage, and a CI, and that cannot go green while the query path is dead.

**Critical Failure Modes:**

1. **A quality score that is actually an infrastructure score.** Scoring timeout / transport /
   hard-node-failure records as zeros (or including them in any quality denominator) reproduces
   `answer_exact_match = 0.000` on a dead run (D-34). Unusable records must be excluded from every
   quality and path-health dimension and counted separately.
2. **An ablation delta that is not a paired comparison.** Averaging two independently-scoped lists
   (the 16 vs 18 scores sharing 8 questions) fabricates a graph-capability number. Unpaired
   questions must be dropped; pairing coverage and a CI must sit next to the delta (D-37, D-38,
   D-43). The 2026-09-03 `0.010` is non-comparable.
3. **A wire-contract score that ignores self-contradiction.** `outcome=success` with a hard
   `RetrieveHybrid` failure, a null snapshot and an empty answer is a contract violation, not a
   well-formed success. Shape-only conformance read `1.000` on 1000 such records (D-35).
4. **Gating graph emptiness as a run failure.** `GraphAugmentationOutcome::NoMatchFound` is a
   designed production state (D-29). Graph dimensions report numbers; they never fail a run. The
   MultiHop-RAG yield floor (D-32) is corpus-scoped investigation, not a production gate.
5. **A fabricated or silently-wrong number** — inherited from 06.3-AI-SPEC CFM #1 and still
   binding: `skipped`/`error` with a reason, never a simulated score (D-51 of 06-CONTEXT);
   judged dimensions not paired (D-39); spend bounded by per-stage caps (D-47).

### What Domain Experts Evaluate Against

**Dimension: Per-path yield visibility (vector, BM25, and graph reported the same way)**
- **Good:** The report shows retrieved-count (and latency) for vector, BM25, and graph on the same
  scale, from the same wire fields (`vector_count`, `bm25_count`, `graph_node_count` /
  `graph_edge_count`), for both ablation arms. A reviewer can see whether the baseline arm was
  alive before interpreting a near-zero graph delta.
- **Bad:** Graph yield is a sidecar or missing, while vector/BM25 are inferred from notices that
  never fire on timeout. 2026-09-03: `graph_node_count` appears **zero times** in the 1000-record
  journal because the client discarded `workflow_completed.metadata`; both arms collapsed
  (`RetrieveHybrid` timeout on 904 records), so a 0.010 "graph" delta could not be read as "graph
  adds nothing" versus "nothing retrieved on either path" (D-02, D-09).
- **Stakes:** High — this is how the High sub-case hid in plain sight.
- **Source:** 2026-09-03 journal forensics (`eval/runs/2026-09-03-multihop_rag/`); D-02, D-09;
  arXiv 2506.05690 — scoring only the final answer treats graph construction, retrieval, and
  generation as a black box, so contribution cannot be measured.

**Dimension: Graph presence versus graph influence as two different facts**
- **Good:** Presence (`graph_node_count` / `graph_edge_count` > 0: the store returned nodes/edges)
  and influence (`graph_prompt_fact_count` > 0: graph-derived facts reached the packed prompt) are
  reported side by side with the ablation delta. A zero answer delta with presence > 0 and
  influence = 0 reads as "found, then dropped at packing"; the same delta with influence > 0 reads
  as "found things the model ignored."
- **Bad:** A single "graph contributed" flag, or a zero delta that cannot tell "found nothing" from
  "found things the model ignored" (D-06). Treating graph emptiness itself as a product failure is
  also bad — see Known Failure Modes.
- **Stakes:** High
- **Source:** D-06; arXiv 2506.05690 (pipeline-internal graph quality and whether graph-derived
  context actually conditions generation, not only answer accuracy).

**Dimension: Ablation pairing honesty**
- **Good:** Graph-on and graph-off quality scores are an **inner join on `question_id` over usable
  records**. Unpaired questions are dropped. The report always shows `n_pairs`, **pairing
  coverage**, and a **confidence interval** next to the delta — a wide interval is published, not
  suppressed (D-37, D-38). Cost sits beside quality: paired latency delta and paired prompt-token
  delta (D-42). The 2026-09-03 `0.010` is marked non-comparable (D-43).
- **Bad:** Averaging two independently scoped lists as if they were one experiment. Forensic:
  16 graph-on vs 18 graph-off scores sharing **8 questions** → 8/500 = **1.6% pairing coverage**,
  published as `graph_ablation_delta = 0.010` at "n=33". Also bad: a point estimate with no CI, or
  hiding a null/negative delta.
- **Stakes:** High — this is the fabricated-looking number that fired the 06.3 High sub-case.
- **Source:** TREC / SIGIR paired comparison on the **same topics** (Voorhees & Buckley, SIGIR 2002;
  Sakai, *Statistical reform in information retrieval?*, SIGIR Forum 2014; paired tests are the IR
  default because topic variance dominates). Paired bootstrap / paired *t* CIs on per-query
  differences (Smucker, Allan & Carterette, SIGIR 2007). D-37, D-38, D-42, D-43.

**Dimension: Denominator honesty**
- **Good:** Infrastructure-failed records (RetrieveHybrid hard-fail / timeout, transport, deadline)
  are **out of every quality and path-health score**. The report states an explicit **unusable
  count and rate**. `NO_EVIDENCE` after a completed retrieve stays in the quality denominator.
  Graph `NoMatchFound` is usable, not unusable (D-29, D-34).
- **Bad:** Mixed denominators in one report. 2026-09-03: retrieval used `n=16` (snapshot-less rows
  excluded) while answer dimensions scored empty answers as zero → headline `answer_exact_match =
  0.000` on a dead run. That is an infrastructure score wearing a quality name.
- **Stakes:** High
- **Source:** 2026-09-03 split (retrieval n=16 vs answer EM=0.000); D-34; 06.3-AI-SPEC §1b failure
  mode "scoring an infrastructure failure as a quality result"; `ai-evals.md` — code-based checks
  on whether the system ran, before treating a score as product quality.

**Dimension: Contract self-consistency**
- **Good:** Wire-contract scoring checks that **fields agree**, not only that they have the right
  shape. `outcome=success` together with a hard `RetrieveHybrid` failure, a null/empty-chunk
  snapshot, and an empty answer is a **violation**. Conformance on 2026-09-03 would have read
  ~0.034 (mirroring retrieval success), not 1.000 (D-35).
- **Bad:** Shape-only conformance = **1.000** on 1000 records that all claimed `success` with a
  null error while 904 `RetrieveHybrid` timed out. A schema that validates and a story that
  contradicts itself both pass.
- **Stakes:** High
- **Source:** D-35; 2026-09-03 `wire_contract_conformance`; `ai-evals.md` "output structure
  validity" is necessary but not sufficient when fields must be mutually consistent.

**Dimension: Query-path canary before the scored drive**
- **Good:** Preflight drives committed questions with known floors: ≥1 retrieved chunk; graph-on
  canary IDs (hand-picked entities **known to be in the graph**) return ≥1 graph node; per-node
  `duration_ms` under budget (D-10, D-11, D-31). A dead retrieve fails loud **before** 1000 scored
  records. Canary is the only place a missing graph hit fails the run.
- **Bad:** Store / gateway / OpenRouter preflight that never touches retrieval — 2026-09-03
  preflight passed clean on a fully dead query path. Also bad: requiring ≥1 graph node on
  **arbitrary** MultiHop-RAG questions (that would gate production on a legitimate empty
  traversal).
- **Stakes:** High
- **Source:** D-10, D-11, D-31; 2026-09-03 preflight transcripts (06.3 recorded-run summary).

### Known Failure Modes in This Domain

1. **Unpaired ablation sold as a system comparison.** IR practice compares systems on the **same
   topics** (TREC paired tests). Averaging leftover survivors from each arm (8 shared questions,
   1.6% coverage) produces a delta whose name claims "graph capability" and whose sample is
   whichever queries happened not to time out. Silent skip of unpaired items is the same family of
   eval-methodology failure as dropping hard topics to inflate a mean.

2. **Infrastructure collapse scored as product quality (metric gaming by denominator).** Folding
   timeouts into EM as zeros, while quietly shrinking the retrieval *n*, always moves the headline
   in a direction that looks like a real regression. 06.3 named this; 2026-09-03 is the worked
   example (`n=16` vs EM=0.000). Distinct from generic hallucination: the generator often never ran.

3. **Black-box graph score that cannot be diagnosed.** arXiv 2506.05690: final-answer metrics treat
   graph build / retrieve / generate as opaque, so a near-zero delta is uninterpretable. Here that
   opacity was concrete: no per-path yields, no presence/influence split, client `pass` on the
   metadata that would have shown both arms dead.

4. **False-green contract / canary.** Shape-valid `success` plus a preflight that never queries
   makes a dead path look shippable. 1000/1000 `outcome=success` with 904 retrieve timeouts, and
   `wire_contract_conformance = 1.000`, is leakage of "the JSON parsed" into "the measurement is
   valid."

**Graph emptiness vs MultiHop-RAG `NoMatchFound` (keep adjacent — D-29 / D-32):** Graph emptiness
is a **legitimate production outcome** and must never be framed as a domain failure of the product
(D-29): traversal is conditional; a query whose entities were never extracted may return nothing;
graph timeout / unavailable / `NoMatchFound` stay non-fatal degradations. On **MultiHop-RAG
specifically**, widespread `NoMatchFound` **is** a defect signal (D-32) — the corpus is built so
answers require linking facts across documents — and is a corpus-scoped investigation floor, not a
production gate. The 2026-09-03 run produced 494 `GRAPH_TIMEOUT` and 4 `GRAPH_UNAVAILABLE`, so the
true `NoMatchFound` rate is still unknown; the corrected run establishes it.

## 2. Framework Decision

**Selected Framework:** **Locked existing stack — no new framework.** `lancet-eval` (`uv`-managed
Python 3.13 at `eval/`) driving the shipped Lancet engine (Rust) and gateway (Go) over HTTP/SSE,
with OpenRouter for generation and judging, LanceDB for the eval store, PostgreSQL for checkpoints.

`typer`, `rich`, `jinja2`, `tenacity>=9.1`; dev: `pytest>=9`, `pytest-httpx`, `ruff`. Engine: Rust
stable ≥1.85. Gateway: Go 1.25. Models: OpenRouter, judge ≠ generator, `temperature=0` (06.3
baseline D-52/D-62).

Framework selection is a **no-op** for this family. The stack is fixed and shipped. 06.3-AI-SPEC
§2 already chose "no AI/RAG framework" for the harness (httpx + Pydantic + hand-rolled
deterministic metrics + thin OpenRouter judge) and rejected LlamaIndex, RAGAS, LangChain,
Promptfoo, and Arize Phoenix against locked 06-CONTEXT decisions (D-48, D-49, D-50, D-54). This
run does not re-score that matrix. The work is evaluation-strategy design on top of the existing
harness.

class NodeCompleted(BaseModel):

    node_name: str
    outputs_summary: str = ""
    duration_ms: int = 0


class WorkflowMetadata(BaseModel):
    model_config = ConfigDict(extra="ignore")  # ignore unknown; do NOT omit known
    started_at_ms: int = 0
    completed_at_ms: int = 0
    reformulation_used: bool = False
    vector_count: int = 0
    bm25_count: int = 0
    graph_node_count: int = 0
    graph_edge_count: int = 0

    completion_tokens: int = 0
    degraded_mode: bool = False
    graph_prompt_fact_count: int = 0  # new; 0 until engine+proto land


class WorkflowCompleted(BaseModel):
    model_config = ConfigDict(extra="ignore")
    success: bool
    total_duration_ms: int = 0
    error_kind: int = 0
    error_message: str = ""
    final_response: RagAnswer | None = None
    notices: list[Notice] = Field(default_factory=list)
    metadata: WorkflowMetadata | None = None  # currently discarded

    @model_validator(mode="before")
    @classmethod
    def _remap_duration(cls, data: object) -> object:
        if isinstance(data, dict) and "total_duration_ms" not in data and "duration_ms" in data:
            data["total_duration_ms"] = data["duration_ms"]
        return data


# inside run_query's iter_sse match:
node_timings: list[NodeCompleted] = []
workflow_meta: WorkflowMetadata | None = None

match sse.event:
    case "node_completed":

### Common Pitfalls

1. **Discarding `node_completed` / `metadata` (`client.py` `pass` arm).** The engine already
   populated `graph_node_count` on the wire; the 1000-record journal never stored it. Path
   yield, graph presence, token cost, and per-node latency are then reconstructed from
   notices that **never fire on timeout**. Stop the discard before inventing new telemetry.

2. **Trusting `completion.success` blindly (D-27).** 2026-09-03: **1000/1000**
   `outcome=success` while **904** `RetrieveHybrid` timed out. The workflow continues past a
   dead node, AssemblePrompt/GenerateAnswer return empty, and `success` stays true.
   Journal outcome and eval-only `success=false` must inspect `node_failures` (and D-28's
   `NOTICE_CODE_RETRIEVAL_FAILED = 19`). Production wire contract stays the current
   semantics (D-30).

3. **Implementing D-29 as `RETRIEVAL_DEGRADED_DENSE` ∧ `RETRIEVAL_DEGRADED_BM25`.** Those
   notices emit at the **end** of `retrieve.rs::run`, same as `NO_EVIDENCE`. A node timeout
   never reaches that code, so the conjunction is false on the **966** timeout records it
   must catch. The predicate is: `RetrieveHybrid` failed (notice 19 and/or `node_failures`
   for that node) **and** no snapshot was produced. D-33 still emits a **partial** snapshot
   on failure for audit (`index_generation`, weights, limits) with an empty chunk list —
   that snapshot does **not** make the record usable for quality denominators.

4. **Treating graph emptiness as a failed run (D-29 / D-31).**
   `GraphAugmentationOutcome::NoMatchFound` is a designed production state. Graph timeout /
   unavailable / empty stay non-fatal degradations with notices and `degraded_mode`. Graph
   dimensions **report numbers**; they never fail a run. The canary is the only place a
   hand-picked entity is required to return ≥1 graph node. MultiHop-RAG yield (D-32) is a
   corpus-scoped investigation floor, not a production gate.

5. **Averaging unpaired arms.** `make_graph_ablation_delta` takes two independent means.
   The published `graph_ablation_delta = 0.010` at "n=33" was 16 graph-on vs 18 graph-off
   scores sharing **8 questions** (1.6% pairing coverage). Join on `question_id`, drop
   unpaired, put `pairing_coverage` / `ci_low` / `ci_high` in `detail` as floats. Mark the
   2026-09-03 `0.010` non-comparable (D-43).

6. **Shape-only `wire_contract_conformance`.** `score.py` currently scores
   `(total - outcome==error) / total`. Every collapsed record said `success` with a null
   error, so the dimension read **1.000**. Self-contradiction — `outcome=success` plus a
   hard `RetrieveHybrid` failure plus a null/empty-chunk snapshot plus an empty answer —
   is a contract violation (D-35).

06.3 §3 pitfalls that still apply and are **not** restated at length: httpx 5s default
timeout; Windows `cp950` vs UTF-8; `uv run --project eval` cwd = repo root; `node_failed`
is not terminal in production; score `final_answer.answer` not `answer_chunk`.

## 4. Implementation Guidance

**Model Configuration:**

**Unchanged from 06.3-AI-SPEC §4.** Generation pin lives in the engine (`dots-studio/dots-3-note-preview:free` in the baseline table — harness read-only). **Measurement pass (D-20) exception:** drive full end-to-end queries against a **cheap generation model**. That pass has **no judge**, so model-differentiation preflight does not constrain the choice. **Generation latency from this pass is not usable for `generation_node_timeout_ms`.** Budget that node from a representative generator, not the cheap stand-in.

**Core Pattern:**

(a) **Persist wire metadata on every journal record (D-01).** Copy `node_timings[]` and
`WorkflowMetadata` fields (including `graph_prompt_fact_count` once emitted) onto `RunRecord`.
`RunRecord` is `extra="forbid"` today — add explicit optional fields with defaults so old
JSONL still loads and new keys cannot be silently dropped.

(b) **Engine emits `NOTICE_CODE_RETRIEVAL_FAILED = 19` on RetrieveHybrid failure** and a
partial snapshot (D-28, D-33). Include 19 in `derive_degraded_mode`. Keep `NO_EVIDENCE` for
"completed retrieve, found nothing". Additive proto tag; both proto trees regenerated (D-52).
Gateway notice rendering is already generic (`gateway/main.go`) — add an end-to-end test
pinning code 19 so clients do not see the bare number.

(c) **Eval/test-only `success=false`** when RetrieveHybrid failed **and** no snapshot (D-29,
D-30). Production keeps current `success` semantics. Harness additionally refuses to treat
that shape as `outcome=success` even if a skewed binary is under test (D-27). Graph failure
of any kind never flips this predicate.

(d) **AssemblePrompt influence counter (D-06).** After a successful
`pack_evidence_and_graph_prompt`, set `ctx` / `WorkflowMetadata.graph_prompt_fact_count =
packed.graph_facts.len() as u32`. Graph-weight `0.0` hard-excludes facts before packing —
influence must be 0 on that path. Do not retune traversal (D-03).

(e) **`get_or_create_table` fail-closed except `lancedb::Error::TableNotFound` (D-24/D-25).**
Six accessors: `documents`, `staged_documents_v2`, `nodes`, `edges`, `entities`,
`entity_edges`. Propagate every other `open_table` error. Exonerated as the 2026-09-03
cause; still a latent data-loss bug. No post-create `validate_schema` on this path (considered, rejected).

(f) **Harness pairing join.** Inner-join usable graph-on/off rows on `question_id`. Drop
unpaired. Score paired differences; always emit the delta plus CI (no minimum-pair
suppression — a wide interval **is** the signal, D-38). Stratify by gold `question_type`
(D-40, review IN-01). Also emit paired latency delta and paired `prompt_tokens` delta (D-42).
CI via stdlib (`statistics.mean` / `stdev`, normal `1.96 * se`, or a stdlib bootstrap) —
no scipy/numpy, no LLM in the scoring path.

```python
# pairing helper (eval) — replaces independent list means
from statistics import mean, stdev

def pair_arms(on_rows: list[RunRecord], off_rows: list[RunRecord]) -> list[tuple[RunRecord, RunRecord]]:
    off_by_id = {r.question_id: r for r in off_rows}
    pairs = []
    for rec in on_rows:
        other = off_by_id.get(rec.question_id)
        if other is not None:
            pairs.append((rec, other))
    return pairs


def paired_delta(diffs: list[float], n_questions: int) -> dict[str, float]:
    n = len(diffs)
    mu = mean(diffs) if n else 0.0
    if n >= 2:
        se = stdev(diffs) / (n ** 0.5)
        half = 1.96 * se
    else:
        half = 0.0
    return {
        "delta": mu,
        "n_pairs": float(n),
        "pairing_coverage": (n / n_questions) if n_questions else 0.0,
        "ci_low": mu - half,
        "ci_high": mu + half,
    }
```

## 4b. AI Systems Best Practices

### Structured Outputs with Pydantic

**Journal / run-record — declare wire diagnostics; do not drop them.** `RunRecord` is
`extra="forbid"` (`journal.py`). Adding optional fields with defaults is required so
(1) old journals still validate and (2) new keys are not lost. Do **not** switch the journal
model to `extra="ignore"` — that would drop future metadata the scorer needs. Wire DTOs stay
`extra="ignore"` for forward-compatible SSE parse; the copy onto `RunRecord` is the persist
boundary.

```python
# eval/src/lancet_eval/journal.py — extend RunRecord (fields optional for old JSONL)

class NodeTiming(BaseModel):
    model_config = ConfigDict(extra="forbid")
    node_name: str
    duration_ms: float = 0.0


class WorkflowWireMeta(BaseModel):
    model_config = ConfigDict(extra="forbid")
    vector_count: int = 0
    bm25_count: int = 0
    graph_node_count: int = 0
    graph_edge_count: int = 0
    graph_prompt_fact_count: int = 0
    reformulation_used: bool = False
    degraded_mode: bool = False
    prompt_tokens: int = 0
    completion_tokens: int = 0


class RunRecord(BaseModel):
    model_config = ConfigDict(extra="forbid")
    # … existing 06.3 fields unchanged …
    node_timings: list[NodeTiming] = Field(default_factory=list)

def is_usable(record: RunRecord) -> bool:
    """Quality/path-health denominator predicate (D-34). Graph emptiness is not unusable."""
    if record.outcome == "error":
        return False
    retrieve_failed = any(f.node_name == "RetrieveHybrid" for f in record.node_failures)
    if retrieve_failed:
        return False  # D-33 partial snapshot is audit-only

```

**`DimensionResult` invariant — unchanged.** `status in {skipped, error}` cannot carry `score`
or `detail`; `ok` requires a score and no reason (`dimensions.py` `_validate_consistency`).
Pairing coverage and CI **must be floats inside `detail`** because `detail: dict[str, float]`:

```python
detail = {
    "delta": mu,
    "pairing_coverage": coverage,  # 8/500 → 0.016
    "ci_low": lo,
    "ci_high": hi,
    "n_pairs": float(n_pairs),
    "unusable_rate": unusable_n / total_n if total_n else 0.0,
}
```

Do not put strings (CI method name, `question_type` labels) in `detail`; put those in
`reason` only on skip/error, or in report prose / a side table. Stratification (D-40) is
additional `ok` rows or float keys such as `delta_comparison`, not a type change.

**Judge retry — unchanged from 06.3-AI-SPEC §4b:** `JudgeVerdict` Pydantic model;
`model_validate_json` after fence-strip; **one re-ask** on `ValidationError`, then
`DimensionResult(status="error", reason=...)`. Transport layer remains tenacity 5 attempts
honouring `Retry-After`. No `instructor`, no LangChain `.with_structured_output()`.

### Async-First Design

**Inherit 06.3: synchronous `httpx` + `connect_sse`, optional `ThreadPoolExecutor`
(`max_workers` default 1). Do not introduce `asyncio` / `aconnect_sse`.** OpenRouter free-tier
RPM is a server-side ceiling; async workers do not raise it.

**The one mistake to name:** treating httpx's **default 5s timeout** as a query budget
(https://www.python-httpx.org/advanced/timeouts/ — inactivity per operation, and `read` is
per-chunk). Live client already passes `httpx.Timeout(connect=10.0, read=300.0, write=30.0, pool=10.0)`
plus a wall-clock `deadline_s` inside `iter_sse`. Measurement-pass queries with a raised graph
budget will hang workers forever if someone "simplifies" back to the default.

Stream vs. wait: `/rag/query` is SSE-only — drain to `workflow_completed` before journaling.
Do not score partial `answer_chunk` text. Judge remains a non-streaming POST so structured
output is validated as one document.

### Prompt Engineering Discipline

**Judge rubrics unchanged** (06.3-AI-SPEC groundedness/faithfulness, system vs. user split,
`max_tokens=400`, no v1 few-shot, `judge_prompt_version` in the cache key). **Do not pair
judged dimensions (D-39)** — that would double judged spend and is not needed to answer
"did the graph change the retrieved set / EM / F1".

Canary questions are **not** judge prompts; they are committed queries with deterministic
floors (chunk count, graph-node count, duration).

### Context Window Management

Inherit 06.3 judge truncation (ranked tail, per-passage cap, `[TRUNCATED:…]` marker, empty
evidence → skip judge). Engine packing (`pack_evidence_and_graph_prompt`) is **not** retuned.

**Measurement distinction this family adds:** graph influence is counted at AssemblePrompt
(`graph_prompt_fact_count`). A zero paired answer delta with `graph_node_count > 0` and
`graph_prompt_fact_count == 0` means packing dropped the facts (budget competition). The same
delta with `graph_prompt_fact_count > 0` means the model saw graph context and the answers
still matched — "found things the model ignored", not "graph found nothing".

### Cost and Latency Budget

**D-47:** per-stage caps (measurement pass, staged drive, full drive, judging); **no** overall
phase ceiling. Each stage is capped against the daily OpenRouter limit.

**The 2026-09-03 `$0.0199` is not a usable estimate** — 966 queries generated nothing, so
generation barely ran. Re-drive cost tracks successful RetrieveHybrid + GenerateAnswer, not
that number.

**Judged dimensions are not paired (D-39)** — pairing them would double judge spend.
Deterministic pairing (recall, EM, F1, precision, ranking, latency, prompt tokens) is free
offline from the journal.

**Measurement pass:** cheap generation model, **no judge** (D-20). Discriminates budget vs.
decay (D-18/D-19) without burning judge quota. Its generation latency must not set
`generation_node_timeout_ms`.

**Caching:** inherit exact-match `judge_cache.json` (SHA-256 of question/answer/evidence +
prompt version). No semantic cache. No LLM in deterministic scoring.

#### Normative note — CI method (D-38)

| Quantity | Interval | Implementation |
|----------|----------|----------------|
| Paired quality / latency / token **deltas** | Nonparametric **bootstrap percentile 95% CI of the mean per-question difference**, **B = 10_000**, resample **question-pairs** with replacement | stdlib `random.Random` only — **no scipy/numpy** |
| Rates (`*_yield`, `graph_presence_rate`, `graph_influence_rate`, `unusable_rate`, `wire_contract_conformance`) | **Wilson score 95%** (Wilson 1927), `z = 1.96` | stdlib `math` |

**Always publish the interval** (D-38). Wide intervals are the signal; no minimum-`n_pairs` suppression.

```python
import math
import random
from statistics import mean

BOOTSTRAP_B = 10_000
BOOTSTRAP_SEED = 42  # commit this; print bootstrap_seed as float in detail

def bootstrap_mean_ci(diffs: list[float], *, seed: int = BOOTSTRAP_SEED, b: int = BOOTSTRAP_B) -> tuple[float, float, float]:
    n = len(diffs)
    if n == 0:
        raise ValueError("n_pairs=0")  # dimension status=error, no score
    mu = mean(diffs)
    if n == 1:
        return mu, mu, mu  # detail degenerate_ci=1.0
    rng = random.Random(seed)
    means: list[float] = []
    for _ in range(b):
        acc = 0.0
        for _ in range(n):
            acc += diffs[rng.randrange(n)]
        means.append(acc / n)
    means.sort()
    return mu, means[int(0.025 * b)], means[min(b - 1, int(0.975 * b))]


def wilson_ci(k: int, n: int, z: float = 1.96) -> tuple[float, float, float]:
    if n <= 0:
        raise ValueError("n=0")
    p = k / n
    z2 = z * z
    den = 1.0 + z2 / n
    center = (p + z2 / (2 * n)) / den
    half = z * math.sqrt((p * (1 - p) + z2 / (4 * n)) / n) / den
    return p, max(0.0, center - half), min(1.0, center + half)
```

**Latency percentiles** (stdlib, linear interpolation on sorted values; `q` in `[0,1]`):

```python
def percentile(xs: list[float], q: float) -> float:
    ys = sorted(xs)
    n = len(ys)
    if n == 1:
        return ys[0]
    pos = q * (n - 1)
    lo = int(pos)
    hi = min(lo + 1, n - 1)
    frac = pos - lo
    return ys[lo] * (1.0 - frac) + ys[hi] * frac
# score = percentile(ms, 0.50); detail retrieve_p95_ms = percentile(ms, 0.95)
```

**Citations:** Smucker, Allan & Carterette, SIGIR 2007 (paired bootstrap on per-query differences);
Wilson 1927. Optional Wilcoxon signed-rank **p-value may appear in `detail` as a float — NEVER a
gate.** If Wilcoxon is not implemented in stdlib, **omit the key** (do not add scipy).
