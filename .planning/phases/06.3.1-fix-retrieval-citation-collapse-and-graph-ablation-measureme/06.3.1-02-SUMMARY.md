## Gap Closure Amendment (2026-09-05, post-verification)

`06.3.1-VERIFICATION.md` scored this plan's SC-5 must-have `partial`: the fix in
`get_or_create_table` was confirmed correct, but the only test exercising its real
error-propagation branch (`get_or_create_table_fails_closed_on_non_missing_table_error`)
was unconditionally `#[ignore]`d and never ran on any platform. A revert test proved
every then-executing test stayed green against the original fail-open wildcard —
independently corroborating `06.3.1-REVIEW.md`'s finding WR-01.

**Fix:** `get_or_create_table` was split into a thin wrapper plus `finish_get_or_create`
— an async associated function taking an already-resolved `Result<Table, lancedb::Error>`
so the propagate-vs-create decision can be driven directly with a synthetic
`lancedb::Error::Runtime`, with no filesystem corruption involved. Test 3 was rewritten
against this seam (no longer `#[ignore]`d) and now asserts three things: the result is
`Err`, the error text confirms it came from the propagate branch (not the create
branch), and the table was not created as a side effect.

**Validated two ways:**
- Revert test: reverting `finish_get_or_create`'s match to the original wildcard makes
  the new Test 3 fail — it does catch the regression it exists to prevent.
- Counter-revert test: reverting the *wrapper* (`get_or_create_table`) to inline the
  original bug, bypassing `finish_get_or_create` entirely, leaves every test green
  (Test 1 still passes because it only exercises the Ok/create paths through the
  wrapper). This is a real, named residual — not fixed, because closing it would need a
  real, non-synthetic non-`TableNotFound` I/O error out of a live `open_table` call,
  which is exactly the platform-sensitive induction this rewrite exists to avoid. See
  the doc comment on `get_or_create_table` in `engine/src/db/mod.rs`.

Full regression suite re-run clean after the fix (458 lib tests, 455 pass / 2 ignored —
down from 3 — / 0 fail; `scripts/engine-test-targets.sh` invariant unchanged at 498).
