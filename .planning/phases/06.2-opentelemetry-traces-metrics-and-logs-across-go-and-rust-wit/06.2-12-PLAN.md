## Phase User Story

**As an** operator running Lancet with an optional or temporarily offline OTLP Collector, **I want** the gateway and engine to degrade silently to normal stdout/console logging without an endless stream of exporter errors flooding stderr, **so that** application logs remain clear and readable when observability backends are unavailable (D-38, SC7).

<objective>
Close gap G-06.2-4: Install custom OpenTelemetry error handlers in both the Go gateway (`otel.SetErrorHandler`) and Rust engine (`opentelemetry::global::set_error_handler`) during telemetry initialization. The custom error handlers bound/silence repetitive background exporter failures (`BatchLogProcessor.ExportError`, `exporter export timeout`, transport connection errors) so that stopping or missing the Collector degrades cleanly to standard stdout logging without spamming stderr. Add regression tests in both codebases and update test target counts.

Purpose: Without custom error handlers, both OpenTelemetry SDKs default to printing every background export error to stderr indefinitely (`log.Printf` in Go, `eprintln!` in Rust), violating the bounded degrade-to-stdout requirement (D-38, SC7).
Output: Custom error handler in `gateway/internal/telemetry/telemetry.go`, custom error handler in `engine/src/telemetry/mod.rs`, regression tests in both test suites, and updated test target scripts.
</objective>
