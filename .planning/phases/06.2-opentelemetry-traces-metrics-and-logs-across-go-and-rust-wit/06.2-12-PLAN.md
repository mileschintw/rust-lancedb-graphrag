## Phase User Story

**As an** operator running `go run` / `cargo run` with no Collector, **I want** both services to keep working and keep logging normally instead of scrolling export errors forever, **so that** the observability stack stays genuinely optional (G-06.2-4, D-38, roadmap SC7).

<objective>
Close G-06.2-4: bound the OpenTelemetry SDK's background export diagnostics in both services so a dead Collector degrades to ordinary stdout logging with at most a bounded warning, instead of an unbounded stderr stream at every 5s reader tick and batch flush.

Purpose: D-38 promises "missing collector degrades silently to stdout"; UAT Test 4 found the opposite — the engine repeating `BatchLogProcessor.ExportError` and metric connection-refused roughly every 3s, the gateway repeating `failed to upload metrics: exporter export timeout` roughly every 10s. Neither service had ever installed anything to bound that channel. This also substantiates COVERAGE.md's OTLP retry/queue-tuning OPT-OUT row: that row justifies opting out partly with "D-38 requires export failure to be non-fatal and rate-bounded, which is handled by the SDK error handler" — an aspirational claim until this lands. Precisely: this makes the row's Go half literal (an `otel.ErrorHandler` genuinely is the SDK error handler) and its Rust half true in spirit via a different mechanism (a `tracing_subscriber` per-layer `Filter`, because no SDK error-handler API exists at the pinned version — see the divergence below). The row's substantive claim, that export failure is non-fatal and rate-bounded so retry/queue tuning is unnecessary, holds for both. The OPT-OUT decision itself stays correct; no retry or queue tuning is added, and COVERAGE.md is not edited.
Output: a bounded `otel.ErrorHandler` in Go, a bounded `tracing` per-layer filter in Rust (NOT an SDK error handler — see the divergence below), one unit test per language, both pin scripts re-measured, and the validation map updated.
</objective>

// boundedErrorHandler bounds OpenTelemetry SDK background export diagnostics so a
// missing Collector degrades to ordinary stdout logging (D-38) instead of one
// stderr line per PeriodicReader tick and per batch flush.
type boundedErrorHandler struct {
	w     io.Writer
	limit uint64
	seen  atomic.Uint64
}

func newBoundedErrorHandler(w io.Writer, limit uint64) *boundedErrorHandler {
	return &boundedErrorHandler{w: w, limit: limit}
}

func (h *boundedErrorHandler) Handle(err error) {
	n := h.seen.Add(1)
	switch {
	case n <= h.limit:
		fmt.Fprintf(h.w, "WARNING: OpenTelemetry export error: %v\n", err)
	case n == h.limit+1:
		fmt.Fprintf(h.w, "WARNING: further OpenTelemetry export errors suppressed for the process lifetime (D-38)\n")
	}
}

var _ otel.ErrorHandler = (*boundedErrorHandler)(nil)

///
/// At `opentelemetry` 0.32 the SDK emits its own diagnostics as `tracing` events on
/// crate-named targets (`opentelemetry`, `opentelemetry_sdk`, `opentelemetry-otlp`);
/// `global::set_error_handler` no longer exists. Bounding therefore happens in the
/// subscriber, not in the SDK (D-38, G-06.2-4).
pub struct BoundedOtelDiagnostics {
    seen: std::sync::atomic::AtomicU64,
    limit: u64,
}

impl BoundedOtelDiagnostics {
    pub fn new(limit: u64) -> Self { /* seen: AtomicU64::new(0) */ }

    /// Returns true when this event should reach the wrapped layer.
    ///
    /// Application targets always pass. OpenTelemetry construction/lifecycle chatter
    /// (TRACE/DEBUG/INFO) is dropped without consuming the cap. Only WARN/ERROR
    /// competes for the bounded slot, so the one line an operator sees is a real
    /// failure rather than startup noise.
    pub fn should_emit(&self, target: &str, level: &tracing::Level) -> bool {
        if !target.starts_with("opentelemetry") {
            return true;
        }
        if *level != tracing::Level::WARN && *level != tracing::Level::ERROR {

            );
        }
        n <= self.limit
    }
}
