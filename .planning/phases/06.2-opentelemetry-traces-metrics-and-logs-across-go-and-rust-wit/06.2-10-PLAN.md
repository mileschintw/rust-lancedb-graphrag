## Phase User Story

**As an** operator looking at a slow `/rag/query` trace in Grafana, **I want to** click "Logs for this span" and land on that trace's Loki lines, then click a log line's TraceID back into Jaeger, **so that** trace, log and metric panes correlate on one `trace_id` without hand-copying IDs (G-06.2-1, D-34, D-40).

<objective>
Close G-06.2-1: remove the unresolvable `tags: [{key: trace_id, value: trace_id}]` mapping from the Jaeger datasource's `tracesToLogsV2` block so Grafana stops suppressing the trace-to-logs action; change Loki `derivedFields` from a body regex (`trace_id=([0-9a-fA-F]+)`) to `matcherType: label` / `matcherRegex: trace_id` so Loki→Jaeger works against OTLP structured metadata; lock both halves with a committed assertion.

Purpose: trace ID is intrinsic OTel span context (`SpanContext.trace_id`), not a span attribute, so Jaeger `tags` suppress "Logs for this span". Engine logs via `opentelemetry-appender-tracing` put trace identity in OTLP metadata, not an inline `trace_id=` body string, so the existing Loki body regex cannot drive the return link (Addresses review concern: Plan 10 Jaeger→Loki only / Loki body regex, 06.2-REVIEWS.md Claude HIGH).
Output: Jaeger three-line `tags` deletion, Loki `derivedFields` matcherType/matcherRegex edit, one Rust regression test, a re-measured engine pin, and VALIDATION.md map rows updated in place including an SC1 cross-reference (D-27, D-28).
</objective>
