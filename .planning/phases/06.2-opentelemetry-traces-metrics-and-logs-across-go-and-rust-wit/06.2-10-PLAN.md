## Phase User Story

**As an** operator inspecting traces in Grafana Jaeger, **I want to** click 'Logs for this span' and jump directly to the corresponding Loki log stream, **so that** I can correlate spans with application log output by trace ID without manual query copying (D-34, D-40).

<objective>
Close gap G-06.2-1: Remove the invalid `tags: [{key: trace_id, value: trace_id}]` mapping from `tracesToLogsV2` in `deploy/grafana/provisioning/datasources/datasources.yaml` while retaining `filterByTraceID: true`. Add a unit test verifying datasource provisioning configuration and protect against regression.

Purpose: In OpenTelemetry spans, trace ID is intrinsic span context, not a span tag/attribute. Grafana suppresses the 'Logs for this span' action when configured tag variables cannot be resolved from span attributes. Removing the tag entry while keeping `filterByTraceID: true` restores the trace-to-logs action in Grafana.
Output: Updated `datasources.yaml`, new unit test in `engine/src/tests/telemetry_metrics.rs`, updated `scripts/engine-test-targets.sh`, and verification.
</objective>
