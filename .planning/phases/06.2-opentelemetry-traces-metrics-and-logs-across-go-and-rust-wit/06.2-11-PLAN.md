## Phase User Story

**As an** operator opening the RAG Operations dashboard, **I want** the panel titled "RAG Query Duration" to actually plot query latency, **so that** I am not reading queries-per-second while believing I am reading milliseconds (G-06.2-2, D-35, D-40).

<objective>
Close G-06.2-2: change Panel 1's PromQL from a `_count` rate (throughput, queries/sec) to a p95 `histogram_quantile` over `_bucket` (latency distribution), regenerate the committed dashboard from the typed generator, and add the assertion that would have caught this.

Purpose: the panel rendered non-empty with no datasource error, so a naive "no errors" UAT check passes while the panel displays the wrong quantity. The existing test `dashboard_panels_resolve_to_defined_instruments` only asserted stem containment, which `..._count` satisfies — the test class, not just the panel, is the defect.
Output: a one-expression change in `main.go`, a regenerated JSON, one new Rust test with a real predicate, a cumulative pin re-measure, and two VALIDATION.md map rows.
</objective>
