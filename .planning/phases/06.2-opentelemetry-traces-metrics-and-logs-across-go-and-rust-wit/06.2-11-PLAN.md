## Phase User Story

**As an** operator viewing the Lancet RAG Operations dashboard, **I want to** see p95 query latency distribution in Panel 1 ('RAG Query Duration'), **so that** I can accurately monitor response latency across outcomes instead of seeing a mislabeled queries-per-second throughput metric (D-35, D-40).

<objective>
Close gap G-06.2-2: Fix Panel 1 ('RAG Query Duration') in `deploy/grafana/dashboard_gen/main.go` to compute p95 latency quantiles from `lancet_rag_query_duration_milliseconds_bucket` via `histogram_quantile`, matching the pattern used in Panel 9 ('Index Rebuild Duration'). Regenerate `deploy/grafana/dashboards/lancet-rag-operations.json` and strengthen `engine/src/tests/telemetry_metrics.rs` to validate that duration panels query `_bucket` / `histogram_quantile`.

Purpose: Panel 1 previously queried `rate(..._count[5m])`, which represents throughput rate (queries/sec), not latency duration (ms). Fixing the generator and regenerating the committed dashboard restores correct operational observability.
Output: Updated generator `main.go`, regenerated `lancet-rag-operations.json`, updated `telemetry_metrics.rs` tests, and updated test count script.
</objective>
