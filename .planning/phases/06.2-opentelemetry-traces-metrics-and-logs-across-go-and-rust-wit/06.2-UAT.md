### 1. Grafana trace<->log<->metric correlation click-through
expected: Open Grafana, run one query, follow the Jaeger trace's trace-to-logs link into Loki, then follow a Loki log line's derived TraceID field back to Jaeger; the same trace_id appears in all three panes, and a non-empty Prometheus series exists over the same window. (VALIDATION.md Manual-Only item a, OBS-01/D-34,D-40 — now newly runnable: CR-02's double-prefix defect that would have failed the Prometheus-series half is confirmed fixed and independently live-verified this session, but not yet passed by human observation.)
result: issue
reported: "Jaeger traces exist and display gateway/engine spans, but Grafana does not render the Logs for this span trace-to-logs action. The provisioned Jaeger datasource maps a required trace_id tag, while trace ID is intrinsic OTel context rather than a span/resource attribute; Grafana suppresses the link when configured tag variables are unresolved. Remove the tag mapping while retaining filterByTraceID: true, reprovision Grafana, then rerun the click-through."
severity: major

(VALIDATION.md Manual-Only item b, OBS-01/D-35,D-40 — now newly runnable per CR-02 fix, not yet passed against real traffic.)

The panel may render a non-empty series with no datasource or unknown-metric error, but it does not display the quantity named by the title or required by this UAT. Fix the typed dashboard generator to query histogram `_bucket` data (for example via `histogram_quantile`) and regenerate the committed dashboard before rerunning the dashboard UAT."

### 4. Collector degrade-to-stdout on missing backend
expected: Stop the collector container, issue a query, confirm both services keep logging to stdout/console, the request still completes, and no unbounded export-error stream appears. (VALIDATION.md Manual-Only item d, OBS-01/D-38 — also the runtime half of roadmap SC7.)
result: issue
reported: "fail: Stopping the Collector did not crash the services, and the gateway opened the RAG query stream, but the required bounded degrade-to-stdout behavior was not met. The engine emitted repeated `BatchLogProcessor.ExportError` and metrics export connection-refused failures at roughly 3-second intervals. The gateway repeatedly emitted `failed to upload metrics: exporter export timeout` at roughly 10-second intervals, plus a trace export failure. Both services therefore produced an unbounded OTLP exporter-error stream while the Collector was unavailable, rather than degrading silently to normal stdout/console logging with at most a bounded warning."
severity: blocker
