# Phase 06.2: OpenTelemetry Traces, Metrics and Logs across Go and Rust (OBS-01) - Research

**Researched:** 2026-08-23
**Domain:** OpenTelemetry, Distributed Tracing, OTLP Exporters, Prometheus, Jaeger, Loki, Grafana Provisioning as Code, Go & Rust Telemetry Bridges
**Confidence:** HIGH

## Summary

Phase 06.2 establishes production-grade observability across the Lancet RAG system by implementing unified OpenTelemetry (OTel) traces, metrics, and logs across the Go Gateway and Rust Engine. Both services export telemetry via OTLP (gRPC/HTTP) to an OpenTelemetry Collector, which fans out to Jaeger for distributed traces, Prometheus for time-series metrics, and Loki for structured logs. Grafana serves as the single correlated pane of glass, linking metrics, traces, and logs seamlessly by `trace_id`.

Crucially, this phase adheres to a **bridge architecture** rather than a code rewrite:
1. **Rust Engine**: Connects existing `tracing` spans and events via `tracing-opentelemetry` and `opentelemetry-appender-tracing` to `opentelemetry_sdk` providers, while using the native OTel Meter API for operational RAG metrics.
2. **Go Gateway**: Bridges `go.uber.org/zap` logs to OTLP using `otelzap`, attaches `otelhttp` / `otelgrpc` middleware for automatic W3C trace propagation, and wraps the `/rag/query` SSE handler in a root span covering user-perceived stream duration.
3. **Observability as Code**: Collector configuration, Prometheus scraping, Loki ingestion, and Grafana datasources/dashboards are 100% committed as code with zero manual UI state. Docker Compose profiles isolate the observability stack (`--profile observability`) from the core database profile.
4. **Resilience**: Telemetry initialization degrades silently to stdout if the collector is unreachable, ensuring local `go run` / `cargo run` workflows never fail.

**Primary recommendation:** Use `tracing-opentelemetry 0.33` + `opentelemetry-otlp 0.32` on Rust, `otelzap 0.20` + `otelhttp 0.70` on Go, and `otel/opentelemetry-collector-contrib` with Grafana auto-provisioning to deliver end-to-end trace correlation and RAG operational metrics without rewriting internal business logic.

### Locked Decisions (06-CONTEXT.md D-27 through D-43, D-09, D-74, D-78)

- **D-27:** The OTel trace ID is authoritative. `correlation_id` is recorded as a span attribute and retained in responses, notices, and checkpoints for continuity.
- **D-28:** Inbound W3C `traceparent` is honoured when present; otherwise the gateway starts the root. Standard propagator behavior; propagation onward into gRPC metadata is unchanged either way.
- **D-29:** Span depth in the engine is nodes + leaf I/O. Phase 05 D-31's five node spans (`query_reformulation`, `hybrid_retrieval`, `graph_context_extraction`, `prompt_assembly`, `llm_generation`) plus a child span per real external call: embedding request, dense LanceDB search, BM25 query, graph Cypher traversal, and **each LLM attempt** (so retry appears as two sibling spans). Roughly 8–10 spans per query.
- **D-30:** Ingestion is fully traced end to end: upload → admission → chunking → embedding → staging write → graph extraction → index rebuild, making Phase 6.1's rebuild-and-swap observable.
- **D-31:** The root span covers the whole SSE stream — opened on request, closed when the stream terminates, so span duration equals user-perceived latency and node spans nest inside it. The terminal outcome (completed/failed, `answer_basis`, degraded flags) is set as span attributes plus span status before close.
- **D-32:** Sampling is always-on, overridable through the existing TOML+env convention (`telemetry.sampler_ratio`).
- **D-33:** Metrics ship with a real backend — a deliberate widening of OBS-01's tracing text.
- **D-34:** Topology: both services export OTLP → OpenTelemetry Collector → Jaeger (traces) + Prometheus (metrics) + Loki (logs), with Grafana as the single pane correlating all three by `trace_id`.
- **D-35:** Metric set is RAG-quality operational:
  - Query latency histogram by outcome
  - Retrieval path failure counter (dense/BM25/graph, by kind)
  - Degraded-answer counter by `answer_basis`
  - Citation repair/drop counter
  - Generation retry counter
  - Evidence-set size histogram
  - Ingest document and chunk counters
  - Index rebuild duration and corpus generation gauge
- **D-36:** Instrumentation is a bridge architecture, not a rewrite:
  - Rust traces: `tracing` spans + `tracing-opentelemetry` → `SdkTracerProvider` → OTLP
  - Rust logs: `info!`/`error!` + `opentelemetry-appender-tracing` → `SdkLoggerProvider` → OTLP
  - Rust metrics: OTel Meter API directly
  - Go logs: zap + `go.opentelemetry.io/contrib/bridges/otelzap` → OTLP
- **D-37:** Go traces use `otelhttp` + `otelgrpc` middleware — `otelhttp` handler wrapping the chi router, `otelgrpc` stats handler on the engine client connection.
- **D-38:** Missing collector degrades silently to stdout. Telemetry initialization never fails the service: one startup warning, existing fmt/stdout logging keeps working.
- **D-39:** `docker-compose` uses profiles: core profile with PostgreSQL, and `observability` profile bringing up Collector, Jaeger, Prometheus, Loki, and Grafana.
- **D-40:** Observability as code, deterministically provisioned. Collector pipelines, Prometheus scrape config, Loki config, Grafana datasources and dashboards are all committed and auto-provisioned — no manual UI state anywhere. Dashboards are generated from typed code with both the source and generated JSON committed and a regeneration target. No alert rules and no recording rules.
- **D-41:** Phase 05 D-30's workflow metadata lands in both places: as span attributes and as additive `WorkflowCompletedEvent` protobuf fields.
- **D-42:** Naming follows OTel semantic conventions where they exist (`gen_ai.request.model`, `gen_ai.usage.*`, `db.system`, `http.*`, `rpc.*`), domain names elsewhere (retrieval fusion, graph traversal, index generation, degraded reasons).
- **D-43:** Service identity is explicit — `service.name` (`lancet-gateway` and `lancet-engine`), `service.version` from the build, and `deployment.environment`, set via the standard resource detector.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| **W3C Trace Context Parsing & Serializing** | Custom regex/split header parser | `go.opentelemetry.io/otel/propagation.TraceContext` & `opentelemetry::propagation::TextMapPropagator` | W3C `traceparent` has strict format, version, and flag requirements. |
| **Tracing to OTel Span Conversion** | Manual span translation in Rust | `tracing-opentelemetry::OpenTelemetryLayer` | Preserves all existing `#[instrument]` and `info_span!` calls with zero application rewrite. |
| **Log-to-Trace Correlation** | Manual string formatting of trace IDs into logs | `opentelemetry-appender-tracing` (Rust) & `otelzap` (Go) | Standard OTel logger bridges automatically attach active `trace_id` and `span_id` in OTLP format. |
| **Dashboard JSON Creation** | Manual drag-and-drop in Grafana UI or raw hand-coded JSON | Typed Go generator (`grafana-foundation-sdk/go`) | UI edits drift and cannot be tested or version-controlled deterministically. |
| **Collector Exporter Fanout** | Multiple SDK exporters inside services | Single OTLP exporter to OpenTelemetry Collector | Decouples services from backend topologies; handles batching, retries, and network buffering out-of-process. |

## Common Pitfalls

### Pitfall 1: Leaking Unclosed SSE Root Span
- **What goes wrong:** In Go, the `/rag/query` HTTP root span closes immediately when the handler returns headers rather than when the SSE stream terminates, resulting in span duration of <1ms instead of the full multi-second query stream.
- **Why it happens:** Standard HTTP middlewares wrap `next.ServeHTTP(w, r)`. In streaming/SSE handlers, `ServeHTTP` exits while flusher goroutines keep streaming.
- **How to avoid:** Manually create and manage the root span lifecycle in the SSE streaming handler, deferring `span.End()` until the stream writer finishes, and recording terminal attributes (`answer_basis`, `degraded_mode`, status) right before `span.End()`.

### Pitfall 2: Double Span Creation or Broken Propagation across gRPC
- **What goes wrong:** Tonic engine creates a disconnected root span for each gRPC call instead of attaching as a child to the Gateway's client span.
- **Why it happens:** Tonic does not automatically extract W3C headers unless a custom interceptor or `tracing-opentelemetry` context extractor reads `tonic::Request::metadata`.
- **How to avoid:** Implement a helper in `engine::telemetry::propagation` that extracts `opentelemetry::Context` from Tonic `MetadataMap` and sets it as the parent of the server request span.

### Pitfall 3: Blocking Startup when Collector is Unreachable
- **What goes wrong:** `cargo run` or `go run` hangs or crashes on startup if Docker/Collector is not running.
- **Why it happens:** OTLP exporters defaulting to blocking connection dials or failing on initialization errors.
- **How to avoid:** Use non-blocking gRPC dials (`grpc.WithBlock()` is omitted), set bounded connection timeouts, and catch exporter build errors to log a warning and fallback to no-op/stdout tracing (D-38).

### Pitfall 4: Metric Cardinality Explosion
- **What goes wrong:** Prometheus runs out of memory due to thousands of unique label combinations.
- **Why it happens:** Putting high-cardinality values like `session_id`, `query_text`, or raw `document_id` into metric labels.
- **How to avoid:** Only use bounded enums for metric labels (`answer_basis`: RETRIEVAL/MIXED/MODEL_ONLY, `outcome`: success/error, `path`: dense/bm25/graph, `model_name`). Trace IDs and session IDs belong exclusively in span attributes and logs.

## Code Examples

### Pattern 1: Rust Telemetry Initialization & Layering (D-36, D-38, D-43)

```rust
// engine/src/telemetry/mod.rs
use opentelemetry::trace::TracerProvider as _;
use opentelemetry::{global, KeyValue};
use opentelemetry_otlp::{WithExportConfig, SpanExporter, MetricExporter, LogExporter};
use opentelemetry_sdk::trace::{SdkTracerProvider, Sampler};
use opentelemetry_sdk::metrics::SdkMeterProvider;
use opentelemetry_sdk::logs::SdkLoggerProvider;
use opentelemetry_sdk::Resource;
use opentelemetry_semantic_conventions::resource::{SERVICE_NAME, SERVICE_VERSION, DEPLOYMENT_ENVIRONMENT_NAME};
use tracing_subscriber::layer::SubscriberExt;
use tracing_subscriber::util::SubscriberInitExt;

pub struct TelemetryGuard {
    tracer_provider: Option<SdkTracerProvider>,
    meter_provider: Option<SdkMeterProvider>,
    logger_provider: Option<SdkLoggerProvider>,
}

impl Drop for TelemetryGuard {
    fn drop(&mut self) {
        if let Some(tp) = self.tracer_provider.take() {
            let _ = tp.shutdown();
        }
        if let Some(mp) = self.meter_provider.take() {
            let _ = mp.shutdown();
        }
        if let Some(lp) = self.logger_provider.take() {
            let _ = lp.shutdown();
        }
    }
}

pub fn init_telemetry(endpoint: &str, sample_ratio: f64) -> Result<TelemetryGuard, Box<dyn std::error::Error>> {
    let resource = Resource::new(vec![
        KeyValue::new(SERVICE_NAME, "lancet-engine"),
        KeyValue::new(SERVICE_VERSION, env!("CARGO_PKG_VERSION")),
        KeyValue::new(DEPLOYMENT_ENVIRONMENT_NAME, "development"),
    ]);

    // Tracing Exporter & Provider
    let span_exporter = match SpanExporter::builder()
        .with_tonic()
        .with_endpoint(endpoint)
        .with_timeout(std::time::Duration::from_secs(3))
        .build() 
    {
        Ok(exp) => exp,
        Err(e) => {
            eprintln!("Warning: OTel span exporter initialization failed: {e}. Degrading to stdout.");
            return Ok(TelemetryGuard { tracer_provider: None, meter_provider: None, logger_provider: None });
        }
    };

    let tracer_provider = SdkTracerProvider::builder()
        .with_batch_exporter(span_exporter)
        .with_resource(resource.clone())
        .with_sampler(Sampler::TraceIdRatioBased(sample_ratio))
        .build();

    let tracer = tracer_provider.tracer("lancet-engine");
    global::set_tracer_provider(tracer_provider.clone());

    // Logger Provider & Appender Layer
    let log_exporter = LogExporter::builder()
        .with_tonic()
        .with_endpoint(endpoint)
        .build()?;
    let logger_provider = SdkLoggerProvider::builder()
        .with_batch_exporter(log_exporter)
        .with_resource(resource.clone())
        .build();
    let otel_log_layer = opentelemetry_appender_tracing::layer::OpenTelemetryTracingBridge::new(&logger_provider);

    // Metrics Provider
    let metric_exporter = MetricExporter::builder()
        .with_tonic()
        .with_endpoint(endpoint)
        .build()?;
    let meter_provider = SdkMeterProvider::builder()
        .with_periodic_exporter(metric_exporter)
        .with_resource(resource)
        .build();
    global::set_meter_provider(meter_provider.clone());

    // Layer with existing tracing subscriber
    let otel_trace_layer = tracing_opentelemetry::layer().with_tracer(tracer);
    let fmt_layer = tracing_subscriber::fmt::layer();

    tracing_subscriber::registry()
        .with(tracing_subscriber::EnvFilter::from_default_env().add_directive(tracing::Level::INFO.into()))
        .with(fmt_layer)
        .with(otel_trace_layer)
        .with(otel_log_layer)
        .init();

    Ok(TelemetryGuard {
        tracer_provider: Some(tracer_provider),
        meter_provider: Some(meter_provider),
        logger_provider: Some(logger_provider),
    })
}
```

### Pattern 2: Go Gateway Telemetry & Middleware (D-31, D-36, D-37)

```go
// gateway/internal/telemetry/telemetry.go
package telemetry

import (
	"context"
	"time"

	"go.opentelemetry.io/contrib/bridges/otelzap"
	"go.opentelemetry.io/otel"
	"go.opentelemetry.io/otel/exporters/otlp/otlplog/otlploggrpc"
	"go.opentelemetry.io/otel/exporters/otlp/otlpmetric/otlpmetricgrpc"
	"go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracegrpc"
	"go.opentelemetry.io/otel/propagation"
	sdklog "go.opentelemetry.io/otel/sdk/log"
	sdkmetric "go.opentelemetry.io/otel/sdk/metric"
	"go.opentelemetry.io/otel/sdk/resource"
	sdktrace "go.opentelemetry.io/otel/sdk/trace"
	semconv "go.opentelemetry.io/otel/semconv/v1.26.0"
	"go.uber.org/zap"
	"go.uber.org/zap/zapcore"
)

type ShutdownFunc func(context.Context) error

func Init(ctx context.Context, endpoint string, version string) (ShutdownFunc, *zap.Logger, error) {
	res, err := resource.New(ctx,
		resource.WithAttributes(
			semconv.ServiceNameKey.String("lancet-gateway"),
			semconv.ServiceVersionKey.String(version),
			semconv.DeploymentEnvironmentKey.String("development"),
		),
	)
	if err != nil {
		return nil, nil, err
	}

	// Trace Exporter
	traceExp, err := otlptracegrpc.New(ctx,
		otlptracegrpc.WithInsecure(),
		otlptracegrpc.WithEndpoint(endpoint),
		otlptracegrpc.WithTimeout(3*time.Second),
	)
	if err != nil {
		// Fallback gracefully (D-38)
		logger, _ := zap.NewProduction()
		logger.Warn("Failed to initialize OTel trace exporter, degrading to stdout", zap.Error(err))
		return func(context.Context) error { return nil }, logger, nil
	}

	tp := sdktrace.NewTracerProvider(
		sdktrace.WithBatcher(traceExp),
		sdktrace.WithResource(res),
		sdktrace.WithSampler(sdktrace.AlwaysSample()),
	)
	otel.SetTracerProvider(tp)
	otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(
		propagation.TraceContext{},
		propagation.Baggage{},
	))

	// Metric Exporter
	metricExp, err := otlpmetricgrpc.New(ctx,
		otlpmetricgrpc.WithInsecure(),
		otlpmetricgrpc.WithEndpoint(endpoint),
	)
	if err == nil {
		mp := sdkmetric.NewMeterProvider(
			sdkmetric.WithReader(sdkmetric.NewPeriodicReader(metricExp)),
			sdkmetric.WithResource(res),
		)
		otel.SetMeterProvider(mp)
	}

	// Log Exporter & Zap Bridge
	logExp, err := otlploggrpc.New(ctx,
		otlploggrpc.WithInsecure(),
		otlploggrpc.WithEndpoint(endpoint),
	)
	var zapLogger *zap.Logger
	if err == nil {
		lp := sdklog.NewLoggerProvider(
			sdklog.WithProcessor(sdklog.NewBatchProcessor(logExp)),
			sdklog.WithResource(res),
		)
		otelCore := otelzap.NewCore("lancet-gateway", otelzap.WithLoggerProvider(lp))
		stdCore := zapcore.NewCore(
			zapcore.NewJSONEncoder(zap.NewProductionEncoderConfig()),
			zapcore.AddSync(zapcore.Lock(zapcore.AddSync(zapcore.WriteSyncer(nil)))), // stdout
			zap.InfoLevel,
		)
		zapLogger = zap.New(zapcore.NewTee(stdCore, otelCore), zap.AddCaller())
	} else {
		zapLogger, _ = zap.NewProduction()
	}

	shutdown := func(ctx context.Context) error {
		_ = tp.Shutdown(ctx)
		return nil
	}

	return shutdown, zapLogger, nil
}
```
