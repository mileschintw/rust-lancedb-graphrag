# Phase 06.2 Plan 01 Summary: Foundation Tracer Slice & Observability Baseline

## Overview
Implemented the foundational cross-service telemetry slice spanning the Go gateway and Rust engine under OpenTelemetry 0.32 (Rust) / v1.45 (Go), establishing W3C `traceparent` propagation from incoming HTTP `/rag/query` requests through tonic gRPC client/server calls to the engine workflow execution root span `query_rag`.

## Work Completed
1. **Dependencies & Alignment**:
   - Added OpenTelemetry 0.32 crates to `engine/Cargo.toml` (`opentelemetry`, `opentelemetry_sdk`, `opentelemetry-otlp`, `tracing-opentelemetry`, `opentelemetry-appender-tracing`, `opentelemetry-semantic-conventions`).
   - Added OpenTelemetry v1.45 modules to `gateway/go.mod` (`go.opentelemetry.io/otel`, `sdk`, `otelzap`, `otelhttp`, `otelgrpc`, `otlptracegrpc`, `otlpmetricgrpc`, `otlploggrpc`).
   - Verified single version resolution in `cargo tree` for `opentelemetry` and `tonic`.
2. **Rust Telemetry Architecture (`engine::telemetry`)**:
   - `ensure_propagators()` initializes composite W3C `TraceContextPropagator` and `BaggagePropagator`.
   - `init(cfg)` constructs `SdkTracerProvider`, `SdkMeterProvider`, `SdkLoggerProvider` with resource attribution (`service.name=lancet-engine`, `service.version=0.1.0`, `deployment.environment=dev`), installs layers onto tracing subscriber.
   - `extract_parent_context()` in `propagation.rs` extracts incoming tonic metadata into `opentelemetry::Context`.
   - `metrics::record_query_duration_ms` records `lancet.rag.query.duration` with bounded outcome label.
   - Startup order in `engine/src/main.rs`: `load_settings()` runs before telemetry initialization so configuration errors fail fast to stderr.
3. **Go Telemetry Architecture (`gateway/internal/telemetry`)**:
   - `Init(ctx, cfg)` initializes tracer, meter, and logger providers, degrades gracefully on unreachable collector.
   - `SetupPropagator()` configures W3C composite propagator.
   - `WrapCore(base, lp)` and `Ctx(ctx)` connect zap logging to OTel log emission with trace/span ID correlation.
   - `gateway/main.go` wires `otelgrpc.NewClientHandler()` onto gRPC client and wraps HTTP router with `otelhttp.NewHandler`.
   - Emits `rag query stream opened` log carrying active request trace context.
4. **Configuration & Fail-Closed Validation**:
   - Added `[gateway.telemetry]` and `[engine.telemetry]` to `config/config.toml` and `config/config.example.toml`.
   - Fail-closed validation for `otlp_endpoint` (must be valid HTTP/HTTPS URL) and `sampler_ratio` (must be finite float in range 0.0..=1.0).
5. **Observability Infrastructure**:
   - Added `deploy/collector/otel-collector-config.yaml` for OTel Contrib Collector (ports 4317, 4318, 8889, 13133, 55679).
   - Updated `docker-compose.yml` with `collector` service, `observability` profile, and `lancet-net` bridge network.
6. **Tests & Invariants**:
   - Added `engine/src/tests/telemetry_query.rs` with 5 unit tests.
   - Added `engine/tests/config_startup.rs` telemetry tests (3 integration tests).
   - Added `gateway/internal/telemetry/telemetry_test.go` (5 tests).
   - Added `gateway/internal/config/config_test.go` (4 tests).
   - Added `TestRAGQueryLogCarriesRequestTrace` in `gateway/main_test.go`.
   - Updated invariant gates: `scripts/engine-test-targets.sh` (415 tests), `scripts/gateway-test-targets.sh` (90 tests).
