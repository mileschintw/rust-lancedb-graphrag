# Phase 06.2 Plan 02 Summary: Query-Path Span Surface

## Overview
Implemented the complete query-path trace surface across the Rust engine and Go gateway:
- In `engine`: 5 canonical D-29 workflow node spans owned by `WorkflowRunner`, 4 leaf spans wrapping production adapter ports, and 2 `llm_attempt` spans capturing retry attempts and token usage.
- In `gateway`: full SSE root span lifecycle management in `queryRAG` with terminal attributes (`lancet.answer_basis`, `lancet.workflow.success`, `lancet.notice_codes`, `lancet.correlation_id`), sorted and de-duplicated notice code enums, and explicit Ok/Error span status on all exit paths (including mid-stream and post-terminal client disconnects).

## Work Completed

1. **Workflow Context Observability Fields (`engine/src/workflow/mod.rs` & `nodes/graph_context.rs`)**:
   - Added `graph_node_count`, `graph_edge_count`, `generation_attempts` to `WorkflowContext`, defaulted to 0 on context construction.
   - Populated `ctx.graph_node_count` and `ctx.graph_edge_count` from extracted graph context elements in `ExtractGraphContextNode`.

2. **Five Canonical Node Spans (`engine/src/workflow/runner.rs`)**:
   - Implemented exhaustive `match kind` in `WorkflowRunner::run_node` creating the 5 D-29 spans:
     - `query_reformulation`
     - `hybrid_retrieval`
     - `graph_context_extraction` (declaring `graph_augmentation = tracing::field::Empty`)
     - `prompt_assembly`
     - `llm_generation`
   - Instrumenting `tokio::select!` execution with `node_span.clone()`.
   - Recording outcome attribute `lancet.node.outcome` (`ok`, `error`, `timeout`, `cancelled`), setting OTel Error span status on non-ok, and recording deferred graph/generation counts.

3. **Leaf Spans & LLM Attempt Spans (`engine/src/service.rs` & `engine/src/workflow/nodes/generate.rs`)**:
   - Instrumented 4 production adapter ports in `service.rs`:
     - `ProductionEmbeddingPort::embed_variant_zero` -> `embedding_request` (`gen_ai.request.model`)
     - `ProductionGraphQueryPort::query_graph` -> `graph_traversal` (`graph_augmentation`, `lancet.graph.node_count`, `lancet.graph.edge_count`)
     - `ProductionDenseRetrievalPort::retrieve_dense` -> `dense_search` (`db.system = "lancedb"`, `db.operation = "vector_search"`, `lancet.index.generation`)
     - `ProductionBm25RetrievalPort::retrieve_bm25` -> `bm25_search` (`lancet.retrieval.path = "bm25"`, `lancet.index.generation = "bm25-memory"`)
   - Preserved single `service.rs:493` `.record("graph_augmentation", tag)` call.
   - In `GenerateAnswerNode`, created `llm_attempt` spans for attempt 1 and attempt 2 (on retry) with `gen_ai.request.model = "google/gemini-2.5-flash"`, `lancet.attempt.outcome`, and token usage attributes (`gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`).

4. **SSE Root Span Terminal Attributes & Lifecycle (`gateway/main.go`)**:
   - In `queryRAG`, extracted server span with `oteltrace.SpanFromContext(r.Context())`.
   - Recorded terminal facts: `lancet.answer_basis`, `lancet.workflow.success`, `lancet.notice_codes` (sorted, de-duplicated enum names), `lancet.correlation_id`.
   - Explicitly handled early EOF and receive errors with `lancet.stream_error_code` and `lancet.stream_terminal_seen = false`.
   - Handled client disconnects with `streamErrorCodeClientDisconnected = "client_disconnected"` and accurate `lancet.stream_terminal_seen` tracking.
   - Deferred handler guarantees `otelcodes.Ok` or `otelcodes.Error` status is set on every exit path and never left unset.
