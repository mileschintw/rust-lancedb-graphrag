## Phase User Story

**As a** Lancet user issuing RAG queries while documents ingest, **I want** dense and BM25 retrieval to stay pinned to one corpus generation even when a rebuild swaps the index, and a failed post-ingest checkout to keep serving the previous generation with a warning, **so that** hybrid answers never mix generations and rebuild faults degrade honestly (D-21, D-22, D-24, D-25).

<objective>
Close VERIFICATION.md gaps SC2, SC3, and SC4 for RAG-03 / DEBT-RAG-04 by isolating LanceDB Table checkout state per call (CR-01/CR-02) and propagating checkout_latest failures into the existing rebuild_degraded path (WR-02).

Purpose: The clone-then-checkout pattern from 06.1-01 does not isolate pinned_version; this plan replaces it with database.nodes_table() per call and proves the LanceDB clone coupling with WR-01 tests.
Output: Isolated dense+rebuild Table handles, checkout_latest degrade, regression tests, updated engine-test-targets pins.
</objective>
