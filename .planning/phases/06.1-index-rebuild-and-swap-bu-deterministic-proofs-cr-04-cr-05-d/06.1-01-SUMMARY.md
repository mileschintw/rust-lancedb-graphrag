# Phase 6.1 Plan 01 Summary: Index Rebuild-and-Swap, CorpusStore Snapshot Isolation, Same-Snapshot Pinning, Worker Debounce, and Degraded Notice Handling

---

## 1. Plan Overview
- **Plan ID**: `06.1-01`
- **Goal**: Implement atomic index rebuild-and-swap for hybrid retrieval (dense LanceDB and lexical BM25), durable LanceDB table version-derived corpus generation labels (`lance-{nodes.version()}`), query-time snapshot pinning, worker burst debouncing, fail-closed debounce configuration (`rebuild_debounce_ms`), and degrade-with-notice lifecycle handling (`NoticeCode::IndexRebuildFailed` at `NoticeSeverity::Warning`).
- **Status**: `COMPLETED`
- **Requirements Addressed**: `RAG-03` / `DEBT-RAG-04` (D-20 through D-26, D-74, D-76, D-83, D-84).

## 2. Key Architecture & Production Changes

### A. CorpusSnapshot & CorpusStore (`engine/src/workflow/ports.rs`)
- Introduced `CorpusSnapshot`:
  ```rust
  pub struct CorpusSnapshot {
      pub bm25: Arc<Bm25Index>,
      pub generation: String,
      pub nodes_version: u64,
      pub rebuild_degraded: bool,
  }
  ```
- Defined `CorpusStore = Arc<RwLock<Arc<CorpusSnapshot>>>` with backward-compatible alias `Bm25IndexStore`.
- Implemented `corpus_generation_from_nodes_version(version: u64) -> String` yielding deterministic labels formatted as `lance-{version}`.

### B. Query Snapshot Pinning & Non-Blocking Readers (`engine/src/service.rs`)
- `LancetServiceImpl` stores `pub corpus_store: CorpusStore`.
- In `query_rag`, captured a single `Arc<CorpusSnapshot>` read guard clone at admission:
  ```rust
  let snapshot = self.corpus_store.read().await.clone();
  ```
- `build_production_workflow` accepts `Arc<CorpusSnapshot>` and instantiates:
  - `ProductionDenseRetrievalPort { nodes: self.nodes.clone(), nodes_version: snapshot.nodes_version, retrieval_settings }`, executing `.checkout(self.nodes_version)` on a cloned table handle per query.
  - `ProductionBm25RetrievalPort { bm25: snapshot.bm25.clone(), retrieval_settings }`, querying the immutable snapshot directly without locking.
  - `RetrieveHybridNode` stamped with `snapshot.generation` (and `rebuild_degraded` flag).

### C. Rebuild-and-Swap, Atomic Counter, and Worker Debouncing (`engine/src/ingest.rs`, `engine/src/main.rs`)
- Implemented `rebuild_and_swap(nodes, corpus_store, bm25_settings) -> Result<Arc<CorpusSnapshot>, String>`:
  - Clones table and calls `checkout_latest()` to obtain the latest table version.
  - Rebuilds `Bm25Index` *off* the write lock.
  - Swaps the `Arc<CorpusSnapshot>` under a brief write lock.
  - On failure, keeps serving previous snapshot with `rebuild_degraded: true` and logs error; clears degraded flag upon next successful rebuild.
  - Added atomic counter `REBUILD_COUNTER` (`rebuild_invocation_count()`, `reset_rebuild_invocation_count()`) and test fault injection hook `arm_rebuild_fail_next()`.
- Implemented `spawn_rebuild_debounce_task`:
  - Receives notifications via `rebuild_rx: watch::Receiver<u64>`.
  - Debounces rapid bursts over a configurable quiet duration (`rebuild_debounce_ms`), coalescing multi-document batches into a single rebuild.
  - Integrates `shutdown_rx: watch::Receiver<bool>` in `tokio::select!` to terminate cleanly during engine shutdown.
- Updated `spawn_worker` and `spawn_worker_with_boundary` to accept `rebuild_tx: watch::Sender<u64>` and trigger notifications upon successful document indexing.

### D. Configuration & Fail-Closed Validation (`engine/src/config.rs`, `engine/tests/config_startup.rs`)
- Added `rebuild_debounce_ms: u64` (default 2000 ms, strictly positive) to `WorkflowConfigSettings`, `WorkflowSettings`, and `to_workflow_settings`.
- Added fail-closed env var parser for `LANCET_ENGINE__WORKFLOW__REBUILD_DEBOUNCE_MS` (rejects 0 or invalid integers, treats empty/whitespace as absent).

### E. Degraded Notice Emission & Manifest Integrity (`engine/src/workflow/nodes/retrieve.rs`, `engine/src/tests/workflow_phase5.rs`)
- In `RetrieveHybridNode::execute`, if `self.rebuild_degraded == true`, emits `NoticeCode::IndexRebuildFailed` (`NoticeSeverity::Warning`, D-25).
- Strengthened notice reachability tests: `NoticeCode::IndexRebuildFailed` points to `engine/src/workflow/nodes/retrieve.rs`; `IndexStale` and `IndexGenerationMismatch` remain reserved with explicit rationales.

## 3. Deviations & Explicit Design Decisions
- **D-26 Derivation Deviation**: D-26 originally mentioned max staging generation; in steady state, `staged_documents` is completely empty after successful ingestion (`StagingDelete`). Thus, corpus generation is derived directly from durable LanceDB `nodes.version()`, formatted as `lance-{version}`, ensuring monotonic progression across all table updates.
