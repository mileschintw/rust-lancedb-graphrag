## Phase User Story

**As a** Lancet user ingesting documents and issuing RAG queries, **I want** the hybrid retrieval index (dense LanceDB and lexical BM25) to rebuild and atomically swap after ingestion batches without blocking active queries or serving mixed-generation evidence, **so that** query responses reflect consistent corpus generations and post-ingest rebuild failures degrade gracefully with clear notices.

<objective>
Implement index rebuild-and-swap, cross-index corpus generation derivation and pinning, worker debouncing, degrade-with-notice error handling, and fail-closed debounce configuration for RAG-03 / DEBT-RAG-04.

Purpose: Closes DEBT-RAG-04 by replacing startup-only BM25 construction with an atomic debounced rebuild-and-swap triggered by the ingestion worker, deriving a unified corpus generation from LanceDB `staged_documents`, pinning dense retrieval via `Table::checkout`, and failing closed on startup while degrading with `NOTICE_CODE_INDEX_REBUILD_FAILED` post-ingest.
Output: `CorpusSnapshot` / `CorpusStore` in `workflow/ports.rs`, corpus-wide generation derivation in `ingest.rs`, version-pinned dense retrieval in `service.rs`, debounced trigger in `ingest.rs`, fail-closed `rebuild_debounce_ms` in `config.rs`, and a comprehensive concurrency/atomicity test suite.
</objective>
