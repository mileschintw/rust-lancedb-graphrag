## 3. DEBT-CR-04: Network Ingress & Loopback Binding

### 3.1 Loopback Default Verification
In `gateway/main.go`, `formatListenAddr` formats the server listen address:
```go
func formatListenAddr(port string) string {
	if strings.Contains(port, ":") {
		return port
	}
	return "127.0.0.1:" + port
}
```
- A bare port string (e.g. `"8080"`) resolves to `"127.0.0.1:8080"`.
- This behavior is verified by unit test `TestGatewayAddressIsLoopback` in `gateway/main_test.go:1788`.

### 3.2 Residual Trigger & Colon Bypass Caveat
`formatListenAddr` enforces loopback by default, but **not as an uncircumventable invariant**. If `cfg.Gateway.Port` contains a colon (for example `"0.0.0.0:8080"` or `":8080"`), `strings.Contains(port, ":")` evaluates to true and the configured string passes through unmodified.

- **Trigger Analysis:** Binding to external/all network interfaces is one configuration string away (`LANCET_GATEWAY__PORT="0.0.0.0:8080"`).
- **Local-Only Acceptance:** In the current deployment topology, Lancet runs locally or in isolated development containers without public internet ingress. Authentication, authorization, mutual TLS, and rate-limiting quotas are intentionally omitted to avoid premature complexity.
- If public multi-tenant ingress is introduced in the future, explicit network authentication/TLS middleware must be mandated before binding non-loopback addresses.

## 4. DEBT-CR-05: Pre-Admission Bounds & Server Timeouts

### 4.1 Server Timeouts Audit
In `gateway/main.go:702`, `newHTTPServer` configures HTTP timeouts:
```go
func newHTTPServer(addr string, handler http.Handler) *http.Server {
	return &http.Server{
		Addr:              addr,
		Handler:           handler,
		ReadTimeout:       60 * time.Second,
		ReadHeaderTimeout: 10 * time.Second,
	}
}
```
- `ReadTimeout` is set to `60 * time.Second`.
- `ReadHeaderTimeout` is set to `10 * time.Second`.
- `WriteTimeout` and `IdleTimeout` are left unset (`0`) to support Server-Sent Events (SSE) streaming connections without premature timeout severance.
- Verified by unit test `TestHTTPServerReadTimeouts` in `gateway/main_test.go:1616`.
- *Note on Historical Documentation:* Early planning notes in `06-CONTEXT.md` stating that the server "ships without ReadTimeout" are stale; the current codebase explicitly sets `ReadTimeout: 60s` and `ReadHeaderTimeout: 10s`.

### 4.2 Body Bounds & Upload Limits
Empirical bounds in `gateway/main.go`:
- **Document Ingestion Uploads (`POST /documents`):**
  - Line 361: `r.Body = http.MaxBytesReader(w, r.Body, maxUploadBytes+(1<<20))` limits request stream to `10 MiB + 1 MiB slack = 11 MiB` (`11,534,336 bytes`).
  - Line 362: `r.ParseMultipartForm(maxUploadBytes)` parses up to `10 MiB` (`10,485,760 bytes`) into memory before buffering to disk.
  - Line 372: `header.Size > maxUploadBytes` enforces `10 MiB` limit on the document file part.
  - *Correction:* The upload bound is **11 MiB** at the `MaxBytesReader` layer and **10 MiB** at the multipart file layer. Claims of a 32MB upload bound were inaccurate.
- **RAG Query Request (`POST /rag/query`):**
  - Line 534: `r.Body = http.MaxBytesReader(w, r.Body, maxRAGQueryBodyBytes)` enforces `maxRAGQueryBodyBytes = 32 KiB` (`32,768 bytes`).
- **Upload Semaphore:**
  - No concurrency upload semaphore is implemented. For single-user local workloads, OS-level concurrency and database connection pooling provide sufficient protection against resource exhaustion.
