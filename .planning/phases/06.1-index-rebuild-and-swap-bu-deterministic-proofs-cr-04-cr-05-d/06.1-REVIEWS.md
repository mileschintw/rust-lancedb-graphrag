## 3. Concerns

### [MEDIUM] LanceDB Table Version Indexing at Zero State
- **File & Mechanism:** `engine/src/ingest.rs` / `engine/src/service.rs:497-539` (`ProductionDenseRetrievalPort`).
- **Risk:** On a fresh database before any document ingestion has occurred, `nodes.version().await` may return `0` or `1` depending on LanceDB's initialization sequence. Calling `Table::checkout(0)` on certain LanceDB storage engines can return an error if version numbering is 1-indexed.
- **Mitigation:** Ensure that `retrieve_dense` gracefully handles `nodes_version == 0` or empty tables (or only invokes `.checkout` when `nodes_version > 0`), and add a unit test asserting retrieval behavior on an unpopulated, freshly initialized database.

### [MEDIUM] Debounce Task Lifecycle on Engine Shutdown
- **File & Mechanism:** `engine/src/ingest.rs` (`spawn_worker`) & `engine/src/main.rs:67-74, 116-121`.
- **Risk:** `spawn_worker` receives a `shutdown_rx: watch::Receiver<bool>`. When the debounce loop is spawned as a companion task, if it only listens on `rebuild_rx.changed()`, a quiet period during shutdown could cause the debounce task to remain pending on `rx.changed()`, outliving `main()` or failing to perform a final pending swap.
- **Mitigation:** Ensure the debounce task's `tokio::select!` explicitly includes the `shutdown_rx` channel (matching `engine/src/ingest.rs:1434-1444`) so that pending debounced swaps either flush or terminate cleanly when `SIGINT` / Ctrl+C is signaled.

### [LOW] Test Target Count Script Synchronization
- **File & Mechanism:** `scripts/engine-test-targets.sh:56-89`.
- **Risk:** `scripts/engine-test-targets.sh` strictly enforces hardcoded test counts (`TOTAL=392`, `LIB=357`, `INTEG_CONFIG=17`). Adding new unit tests in `engine/src/tests.rs` and `engine/tests/config_startup.rs` without atomically updating the script within the exact same commit will break the gating script.
- **Mitigation:** Plan 01 Task 3 already notes this dependency; implementers must ensure the count updates in `scripts/engine-test-targets.sh` are committed simultaneously with the new test cases.
