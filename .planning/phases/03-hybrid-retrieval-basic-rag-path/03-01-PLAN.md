<objective>
Build the Rust retrieval data-plane slice that makes one normalized question produce deterministic dense-plus-BM25 candidates and a replaceable reranker result.

Purpose: Establish the semantic core before any cross-runtime contract or provider wiring so the later plans consume one tested retrieval interface.
Output: The approved Unicode dependencies and lockfile, reusable dense/BM25/fusion modules, isolated retrieval fixtures, and the async NoOpReranker port.
</objective>

<scope_note>
This plan implements successful dense and lexical retrieval, typed filter semantics, deterministic fusion, and the RAG-04 pass-through seam. It does not implement degraded retrieval, model-only fallback, citation repair/downgrade, graph extraction, provider retries/fallback, or dynamic re-ingestion/restart switching; those constraints remain explicit in deferred-items.md.

The ten-file list is intentionally kept as one cohesive Wave 1 retrieval contract: Task 1 keeps the approved Cargo manifest/lockfile, binary module wiring, BM25 implementation, and analyzer-owned test file together so the lexical tracer is runnable; Task 2 owns the shared dense/fusion/reranker expansion and its test ownership. The small cross-module overlap is sequential within this plan and does not add a sixth execution wave or broaden the MVP boundary.
</scope_note>

## Trust Boundaries

| Boundary | Description |
|---|---|
| Caller values to Rust retrieval | Query text, UUID filters, content types, and bounds are untrusted before typed normalization. |
| Canonical LanceDB rows to derived BM25 memory | Completed source content and nullable metadata become searchable in-memory state. |
| Cargo registry to build output | Approved Unicode crates enter the executable retrieval path and the lockfile controls their versions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-01-01 | Tampering | Typed filters and LanceDB predicates | high | mitigate | Normalize UUID/content-type values into one typed QueryFilters object and apply it before both candidate limits; never accept arbitrary predicate text. |
| T-03-01-02 | Tampering | BM25 analyzer and global statistics | high | mitigate | Use one full Unicode analyzer for build/query, preserve original fields separately, and compute IDF over the complete snapshot rather than the filtered subset. |
| T-03-01-03 | Denial of Service | Candidate and evidence precursor limits | medium | mitigate | Enforce query/filter/candidate bounds in RetrievalSettings before scanning or fusing candidates. |
| T-03-01-04 | Information Disclosure | Derived BM25 metadata | medium | mitigate | Carry only canonical bounded provenance into candidates and leave absent nullable fields absent. |
| T-03-01-SC | Tampering | Cargo package installation | high | mitigate | Use only the three packages marked Approved in the Phase 03 Package Legitimacy Audit and verify Cargo.lock with --locked checks. |
</threat_model>
