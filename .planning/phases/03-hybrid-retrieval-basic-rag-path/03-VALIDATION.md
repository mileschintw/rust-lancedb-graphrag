# Phase 03 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

**Scope gate:** The Phase 03 validation map covers current RAG-02/RAG-04 acceptance: the valid dense+BM25 query path, bounded evidence, one structured generation call, valid citations, the initial BM25 build/readiness safeguard, and gap closure for G1/D1/D2 plus P24-BODY, RAG02-CEIL, RRF-FINITE/WR-01, and PERSIST-RAW. G1 proves one effective limits carrier; D1 proves fail-closed embedding/dense infrastructure errors with identity while recording the accepted D1-LOG waiver; D2 proves valid zero-match success-empty behavior distinct from caller validation and infrastructure errors; the new rows add provider-body, retrieval-ceiling, finite-fusion/HTTP-commit, and raw-staging replacement gates. RAG-03 remains opted out of this phase and mapped to Phase 06 hardening; D3, D4, and D5 remain deferred-confirmed ledger boundaries rather than Phase 03 runtime behavior.

## Sampling Rate

- **After every task commit:** Run the task's focused Rust, Go, Buf, or API-coverage command from the map below.
- **After every plan wave:** Run the full-suite wrapper above; repeat the wrapped `buf generate` stability check after contract changes.
- **Before `/gsd-verify-work`:** Full suite must be green; the live provider smoke is run only when its user setup precondition is available.
- **Max feedback latency:** 60 seconds for local checks; external provider smoke is an explicit ignored check with network-dependent latency.
