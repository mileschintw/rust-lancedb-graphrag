<objective>
Close the current P25/P41, D-31, and startup-credential gaps by making the production provider adapter consume the validated effective settings, preserving request identity on generation failure, and rejecting unconfigured OpenRouter startup.

Purpose: The accepted RAG path must have one authoritative runtime configuration and an auditable failure boundary. Provider calls must be bounded by the same settings used to build evidence, failures must remain attributable to the caller session, and production must never silently run with fabricated credentials.

Output: A production-wired OpenRouter evidence budget, deterministic adapter coverage, structured identity-preserving generation errors, and an explicit credential validation test.
</objective>

<scope>
This is gap-closure work only. It does not add one-path degradation, model-only fallback semantics, citation repair/downgrade, retries, lifecycle recovery, graph fallback, or a new gateway/protobuf error response. ModelOnly remains rejected by the fail-closed contract from 03-13; this plan only carries identity through the existing Rust error boundary.
</scope>

- The existing tonic status metadata API is sufficient for the D-31 structured error envelope because the QueryRAG success response has no error payload branch.

</assumptions>
