## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Test process -> local provider mock | The cross-runtime test sends query text, model metadata requests, and structured generation requests to a test-owned localhost server. |
| Test process -> Rust engine child | Test-controlled configuration and a temporary LanceDB path cross into the real engine process. |
| Go gateway -> Rust gRPC | The HTTP request and typed filters cross the public service boundary into the Rust semantic owner. |
| Fixture seeder -> LanceDB | Deterministic test data is written to a temporary store that must not overlap a developer or production corpus. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-05-01 | Tampering | Local provider mock and structured response | high | mitigate | Assert exact endpoint, model, strict schema, evidence IDs, and one completion; reject unexpected paths or malformed response shapes. |
| T-03-05-02 | Information Disclosure | Test environment and provider credential | high | mitigate | Use a test-only credential, localhost endpoints, temporary paths, and assertions that logs/responses contain neither real keys nor raw corpus dumps. |
| T-03-05-03 | Denial of Service | Engine and mock child processes | medium | mitigate | Bound the test request, use context cancellation/timeouts, wait for child exit, and run each store under `t.TempDir`. |
| T-03-05-04 | Tampering | LanceDB fixture isolation | high | mitigate | Seed only an explicit per-test temporary path, use canonical schema validation, close handles before cleanup, and never point the smoke at configured shared data. |
| T-03-05-SC | Tampering | cargo/go dependency installs | high | mitigate | Run locked builds and retain the approved package-legitimacy audit; no new unreviewed package is introduced by this plan. |
</threat_model>
