## Phase Goal

**As a** chat service API user, **I want to** ask a question over indexed content and receive a grounded answer with trustworthy citations, **so that** I can verify every claim against the retrieved evidence.

<objective>
Close the RSC-1/P09/P24 provider-output gap for the valid Phase 03 retrieval-backed path.

Purpose: The current verifier found that citationless Retrieval/Mixed output and ModelOnly output can pass the existing grounding check, while the OpenRouter schema and wrapper parsing accept unbounded fields. This plan makes the already-built provider path fail closed at the shared validation and adapter boundary without adding any deferred response branch.
Output: Basis-specific grounding guards, explicit provider payload bounds, focused provider regressions, and a QueryRAG service regression that proves invalid output cannot become a public response.
</objective>

<scope_note>
This closure plan covers only RSC-1/P09/P24 and the provider-output portion of RAG-02. It preserves valid Mixed output when it cites supplied evidence and keeps the typed ModelOnly enum as compatibility capacity while rejecting that basis on the Phase 03 QueryRAG path. It does not implement DEBT-RAG-01 degraded/model-only behavior, DEBT-RAG-03 citation repair or downgrade, DEBT-RAG-04 lifecycle recovery, DEBT-RAG-05 exhaustive negative-input coverage, DEBT-RAG-06 graph fallback, provider retry/fallback, or any RAG-04 reranker change.
</scope_note>

## Artifacts this phase produces

- A shared `ModelOutput::validate_grounding` contract that requires evidence for Retrieval/Mixed and rejects ModelOnly for this path.
- A bounded strict OpenRouter schema and bounded response parsing for answer text, evidence IDs, notices, warnings, choices, and provider wrapper bytes.
- Focused local tests plus service-level proof that invalid provider output yields no fabricated answer and no partial `QueryRAGResponse`.

## Trust Boundaries

| Boundary | Description |
|---|---|
| provider HTTP response -> Rust generation adapter | Untrusted provider/intermediary JSON crosses into Serde and allocation paths. |
| validated ModelOutput -> public QueryRAG response | Model-supplied basis, IDs, markers, notices, and answer text cross into a caller-visible response. |
| retrieved corpus -> generation prompt | Corpus-controlled text remains untrusted data and must not become provider instruction. |
