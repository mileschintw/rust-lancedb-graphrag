## Phase Goal

**As a** chat service API user, **I want to** ask a question over indexed content and receive a grounded answer with trustworthy citations, **so that** I can verify every claim against the retrieved evidence.

<objective>
Close the core RAG-02 configuration blocker by threading one validated effective settings object from TOML to retrieval/evidence service state, provider configuration state, persistence identity input, prompt bounds, and RetrievalSnapshot per D-03 through D-05, D-23, D-25, D-27, D-30, D-32, D-33, D-39, D-46, and D-49.

Purpose: Operators and callers must be able to trust that configured values are both enforced and reported exactly.
Output: Validated effective settings, lossless retrieval configuration, service state, exact snapshots, and an opaque per-service index generation.
</objective>

<scope_note>
This plan preserves the existing protobuf surface. Because RetrievalSnapshot.rrf_k is int32, the reversible compatibility choice is to reject non-integral or out-of-range configured values before readiness. Provider adapter construction and the operator example are locked in `03-10`; startup wiring and process failures are proven in `03-11`.
</scope_note>

<spec_edge_resolution>
No Phase 03 SPEC exists. The core configuration edge is resolved concretely: settings validate before runtime construction; configured values reach their consumers; provider and persistence model identity agree; snapshots are lossless; and each service construction owns one opaque index generation.
</spec_edge_resolution>
