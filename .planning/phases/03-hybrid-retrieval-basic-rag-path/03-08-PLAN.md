## Phase Goal

**As a** chat service API user, **I want to** ask a question over indexed content and receive a grounded answer with trustworthy citations, **so that** I can verify every claim against the retrieved evidence.

<objective>
Close the RAG-02 gateway resource-bound blocker by enforcing an exact 32 KiB POST /rag/query body limit, a 60-second read timeout, and cross-runtime compatibility with Plan 03-06 strict provider output.

Purpose: Oversized JSON must be rejected cheaply at the HTTP trust boundary without consuming engine or provider work, while the real Go-to-Rust happy path remains runnable.
Output: Bounded gateway handler/server behavior, focused Go regressions, updated cross-runtime fixture, and a narrow public-surface coverage addendum.
</objective>

<scope_note>
The 32 KiB constant is an explicit reversible implementation choice within the agent's discretion: it covers the locked maximum query and filter counts plus framing while placing a finite bound at the first decoder read. The new 413 response is the only API-surface change in this plan, so COVERAGE.md is updated only for that behavior.
</scope_note>

<spec_edge_resolution>
No Phase 03 SPEC exists. The RAG-02 HTTP edge is resolved concretely: maxRAGQueryBodyBytes equals 32 shifted left by 10; one byte over the limit returns 413; oversized filters are rejected before the engine; malformed in-limit JSON retains its existing client-error mapping; and the server read deadline is 60 seconds.
</spec_edge_resolution>
