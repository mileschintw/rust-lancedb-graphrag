<objective>
**As a** Lancet API user, **I want to** have accepted ingestion work survive shutdown and restart, **so that** polling and the last completed LanceDB generation remain trustworthy.

Close the Rust-owned portions of CR-03 and WR-01 per D-45, D-46, and D-48.

Purpose: The engine currently acknowledges queued jobs but prioritizes shutdown over receiving them, and its durable staging row lacks enough information to rebuild an `IngestionJob` after restart. Rust must own the complete drain/recovery contract and the canonical chunk ceiling.
Output: A user-selected versioned staging transition, recoverable staging records, shutdown drain, startup replay, staging-aware status, the authoritative `MAX_CHUNK_SIZE`, and deterministic Rust regressions.
</objective>

  <decision>Choose how the engine will move from the current two-column `staged_documents(document_id, raw_content)` store to a complete recoverable staging record.</decision>
  <context>D-45 requires exact restart reconstruction, but existing rows do not contain filename or chunk settings and D-22 forbids automatic wipe or schema-drift mutation.   <options>
    <option id="versioned-side-by-side">
      <name>Versioned side-by-side table (Recommended)</name>
      <pros>Create a new complete-schema staging table under a versioned name; leave the legacy table byte-for-byte intact; if legacy rows exist, fail startup read-only with document-ID/count-only guidance until the operator supplies a per-row filename/settings migration manifest or explicitly archives/dispositions those rows.</pros>
      <cons>Temporarily retains two staging tables and requires an explicit operator step for any legacy rows.</cons>

      <name>Manifest-backed in-place migration</name>
      <pros>Retains the established table name after a versioned backup and reconstructs every row from an operator-supplied filename/settings manifest.</pros>
      <cons>Migration is one-way after cutover, needs a byte-preserving backup plus rollback proof, and must refuse the entire migration if any row lacks exact metadata.</cons>
    </option>
    <option id="archive-and-cutover">
      <name>Explicit archive and cutover</name>
      <pros>Copies every current-format row to a versioned read-only legacy archive, records an explicit operator disposition for each row, and starts new admissions in the complete-schema table.</pros>
      <cons>Legacy jobs are not replayed unless the operator supplies their missing metadata; the engine must remain blocked until every row has an explicit replay or archive disposition.</cons>
    </option>
  </options>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gRPC stream → bounded Rust queue | Untrusted metadata and bytes become acknowledged in-memory work. |
| in-memory queue/status → LanceDB staging | Volatile accepted work crosses into restart-recoverable state. |
| persisted staging → startup replay | Durable rows drive autonomous indexing after a process restart. |
| legacy staging format → recoverable staging format | Existing raw bytes cross a one-way on-disk contract transition whose metadata is incomplete without operator input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-22-01 | Tampering | staged recovery record | high | mitigate | Persist complete validated job fields, revalidate them on replay, and reject malformed rows with class-only errors. |
| T-02-22-02 | Denial of Service | shutdown drain and replay | high | mitigate | Close new receiver admission, retain the capacity-100 bounded channel, replay through the same single worker, and prove finite drain with multiple queued jobs. |
| T-02-22-03 | Spoofing | staged document identity | high | mitigate | Reuse UUIDv4 validation and require status/recovery responses to carry the exact staged document ID. |
| T-02-22-04 | Information Disclosure | recovery diagnostics | medium | mitigate | Report field/error classes only; never log raw bytes, document text, credentials, headers, or embedding values. |
| T-02-22-05 | Tampering | chunk-size metadata | high | mitigate | Enforce Rust-authoritative 1048576 before `IngestionJob` creation and verify tonic `InvalidArgument` above the boundary. |
| T-02-22-06 | Tampering | legacy staging transition | critical | mitigate | Gate the one-way choice, version the format, preserve IDs/raw bytes, require complete explicit metadata or disposition, and fail closed without cutover on any mismatch. |
</threat_model>
