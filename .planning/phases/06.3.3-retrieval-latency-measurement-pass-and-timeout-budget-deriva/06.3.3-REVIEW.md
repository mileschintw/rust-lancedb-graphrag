## Critical Issues

### CR-01: Empty survivor set omitted from derivation; nesting fabricates unmeasured outer budgets (BLOCKER)

**File:** `eval/src/lancet_eval/measure.py:327-367`

**Issue:** After gap 1, clipped durations are excluded from `extraction.by_node`. For each workflow node the loop does:

```python
        pct = percentile_with_ci(
            vals,
            p=thresholds.derivation_percentile,
            seed=thresholds.bootstrap_seed,
            censored_count=censored,
        )
        if pct.is_available:
            p_rec = derive_budget(cfg_key, pct, thresholds=thresholds)
            proposed_budgets[cfg_key] = p_rec.proposed_ms
            proposed_records.append(p_rec.__dict__)
```

`percentile_with_ci` on an empty list returns `is_available=False` (`latency.py:240-250`). The node is then **absent** from `proposed_budgets`. Pass-through still injects `query_embedding_timeout_ms` / `graph_operation_timeout_ms` (defaults or `effective_cfg`). `check_nesting_invariants` reads missing outers as `0`:

```python
    graph_node = resolved.get("graph_node_timeout_ms", 0)
    ...
    ret_node = resolved.get("retrieve_timeout_ms", 0)
```

If inner sum + slack exceeds that `0`, it **raises** the outer key (`latency.py:472-476`, `504-508`) and those integers become `BudgetDerivation.proposed_budgets` / the run summary’s `proposed_budgets`.

This is not hypothetical on the new fixture: `ceiling_censored_measurement_records` only stamps `RetrieveHybrid` timings (`conftest.py:148-183`). ExtractGraphContext and AssemblePrompt therefore have `vals=[]`, no `CENSORED_NODE_TIMEOUT`, and no proposed rows. Nesting then materializes `graph_node_timeout_ms` from `0 + query_embedding + graph_operation + slack` (14500 with the test cfg’s 10000+4000+500) **without** a `censored_status` row. The same hole fires if RetrieveHybrid is 100% at-ceiling (the historical collapse shape, `synthetic_all_at_ceiling_latencies`): retrieve is omitted, then nesting writes a retrieve budget from embedding+slack, labeled as a resolved proposed timeout.

Gap 1’s tests only inspect the RetrieveHybrid `proposed_records` row (`test_measure.py:646-679`). They cannot see the fabricated graph_node (or all-clipped retrieve) integer.

**Fix:** Do not call `check_nesting_invariants` on a partial map with missing outers defaulting to 0. For every measured node key, if `not pct.is_available`, refuse that key (no nesting fill-in) or seed it from `effective_cfg` and attach an explicit `censored_status` / `rule` such as `unavailable_empty_survivors`. Never persist an invariant-raised value that was computed from a missing measurement.

```python
        if not pct.is_available:
            proposed_records.append({
                "node_or_budget": cfg_key,
                "proposed_ms": None,
                "censored_status": (
                    f"unavailable({pct.reason}; censored_count={censored})"
                ),
                "rule": "derivation_refused_empty_or_unavailable",
                ...
            })
            continue
```

Then run nesting only over keys that were actually derived or explicitly carried forward.

## Warnings

### WR-01: Censoring flag never reaches the persisted run record (WARNING)

**File:** `eval/src/lancet_eval/measure.py:538-571`

**Issue:** Plan 05 stored `censored_by_node` and `proposed_records` on `BudgetDerivation` “so the run record can report it.” `run_measurement_pass` assigns `derivation.census` / nesting / ceiling reports into `summary` but **drops** `proposed_records` and `censored_by_node`. Durable `measurement.json` / `run_record.json` still contain only `proposed_budgets` integers. A future `lancet-eval measure` pass under real censoring can write lower-bound retrieve/graph numbers with no on-disk `censored_lower_bound(n)`.

**Fix:** Add `proposed_records` and `censored_by_node` to `summary` (superset of existing keys). Keep current keys unchanged.

### WR-02: Inner budgets still pass through unmeasured (WARNING) — prior WR-01, still open

**File:** `eval/src/lancet_eval/measure.py:356-363`

**Issue:** `query_embedding_timeout_ms` and `graph_operation_timeout_ms` are still copied from `effective_cfg` (defaults 10000 / 4000) with no `rule` distinguishing them from derived node budgets. Plan 05 deferred this; it remains in the extracted function.

**Fix:** Tag those entries `rule: "carried_forward_unmeasured"` on `proposed_records` / summary.

### WR-03: Calibration note still contradicts derivation (WARNING) — prior WR-02, still open

**File:** `eval/src/lancet_eval/measure.py:539-542`

**Issue:** Every `run_measurement_pass` summary still claims the micro-pass “is not an input to any derived budget” while the same function writes `proposed_budgets` from `derive_budgets_from_records`. Plan 05 deferred this; it remains.

**Fix:** Rephrase or drop `calibration_note` so it matches the CLI’s “derive proposed timeout budgets” contract.

### WR-04: Verify overlay provider timeout is now 3s and binds live generation (WARNING)

**File:** `config/config.verify.toml:9`, `engine/src/tests/workflow_phase5_production.rs:640-754`

**Issue:** `generation_timeout_secs` was lowered from 30 to 3 so `2 * 3 * 1000 <= 7000`. `SlowLiveProvider` still sleeps 30s and does not read that setting, so `workflow_phase5_config_verify_generation_timeout` still observes the 7000 ms **node** timer. Production code under `LANCET_ENV=verify` (`verify-ingestion.sh`) uses the real provider client: a generation that previously could run up to the 7000 ms node budget (provider attempt was 30s, so the node timer bound first) now dies at **3s per attempt**. Completions in (3s, 7s] that used to succeed on verify will fail. The phase5 elapsed assertion comment still calls 30000 ms “provider budget” (`workflow_phase5_production.rs:749`).

**Fix:** Confirm live verify only needs ingest/embeddings, not generation in the 3–7s band; if it does, keep node=7000 but set `generation_timeout_secs` to 7 (or 3 with an explicit overlay comment that live generation is expected to fail fast). Update the stale “30s provider budget” comment on the phase5 test.
