**Date written:** 2026-09-07

## Invariants

Passing `WorkflowSettings::validate` (graph node ≥ sum of inners) and `validate_against_provider` is **necessary but not sufficient**. The engine floor admits **equality**, in which an enclosing budget can never fire. That equality case is the incoherence D-17 documented and the 2026-09-03 run confirmed (494 inner graph-operation timeouts, zero outer graph-node timeouts). This record requires **strict inequality with slack ≥ 500 ms** (`COMMITTED_THRESHOLDS.slack_ms`).

### Nesting group 1 — `graph_node` contains `query_embedding` + `graph_operation`

- Inner sum: 645 + 38595 = **39240 ms**
- Outer: **45674 ms**
- Slack: **6434 ms** (≥ 500)
- Fires first: **`graph_operation_timeout_ms`** on traversal overrun (non-fatal `GRAPH_TIMEOUT`); the outer envelope can still fire if the whole `ExtractGraphContext` node exceeds 45674 ms.
- Conflict policy: **did not fire**. Independently derived outer p95×1.5 already exceeds inner sum + slack. Inner values were not shaved. The outer row is **not** labelled invariant-driven.

### Nesting group 2 — `retrieve` vs `query_embedding` (latency.py relationship)

- Inner: 645 ms
- Outer: 16647 ms
- Slack: **16002 ms**
- Fires first: **`query_embedding_timeout_ms`** if the inner embedding call overruns (that call actually lives inside `ExtractGraphContext`; this group is the committed nesting report shape, not a claim that RetrieveHybrid embeds).
- Conflict policy: **did not fire**.

### Harness ceilings (two different quantities)

Eval defaults: `gateway_timeout_secs = 300` (SSE per-read-gap), `question_deadline_secs = 600` (wall-clock).

**1. Largest single written runner-level node budget vs SSE read timeout**

- Largest: `generation_node_timeout_ms` = **65000 ms**
- SSE read timeout: **300000 ms**
- `65000 < 300000` — **pass**
- This check is **not** a sum.

**2. Worst-case sum of written runner-level node budgets vs question deadline**

Runner-level keys (same set `check_harness_ceilings` uses): reformulate 5000 + retrieve 16647 + graph_node 45674 + prompt 1070 + generation 65000 = **133391 ms**.

- Question deadline: **600000 ms**
- `133391 < 600000` — **pass**
- Inner budgets are not added on top of `graph_node` (that would double-count the graph path).

No check in this record compares a sum against the SSE read timeout.

## Graph question (roadmap criterion 7)

Store baseline verdict: **`populated`** (`06.3.3-STORE-BASELINE.md`: 27,971 entities, 46,092 entity-edges, canaries present and connected). The latency question is **answerable**.

Traversal is **genuinely slow**, not an engine defect: hub expansion over this graph costs on the order of **25–30 seconds** (outer graph-on p95 30.4 s; inner lower-bound p95 ≥ 25.7 s). Documentation phase honest-limitations should cite **~25–30 s** as the measured graph-context cost figure, not a tuning opportunity. Graph quality work is out of family scope; the decision is to **raise the budget and state the cost**.
