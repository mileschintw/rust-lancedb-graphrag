# Plan 06.3.3-03 Summary: Two-Segment Retrieval Latency Measurement Pass, Decay Analysis, and Node Dispositions

## Overview
Plan 06.3.3-03 executed the central measurement pass of Phase 06.3.3. It drove 160 gold questions (320 records across paired `graph-off` and `graph-on` arms) against the surviving store and evaluation schema with all ceilings lifted far above historical limits. It performed a clean mid-run engine restart at ordinal 160, measured post-restart probe query latency, recorded an unbroken monotonic append-only checkpoint attribution table (+1,732 rows), published a 5-label censoring census, answered the decay question against pre-committed thresholds, decomposed inner budgets with survivor guarding, and established formal D-16 investigation dispositions for all five workflow nodes.

- **Harness Ceilings Verification**:
  - SSE read timeout (300s) verified against largest single raised node budget (65s) -> Passed.
  - Question deadline (600s) verified against worst-case sum of node budgets (210s) -> Passed.

### 2. Censoring Census Across All Five Nodes
- All 320 records evaluated across 5 mutually exclusive labels (`OBSERVED`, `CENSORED_AT_CEILING`, `CENSORED_NODE_TIMEOUT`, `NOT_REACHED`, `INSTRUMENT_GAP`).
- Under the raised budgets, **all 320 records were classified as `OBSERVED`** at the workflow node level (0 node-level timeout failures).
- Inner Graph Operation: 21 queries received typed `GRAPH_TIMEOUT` notices (`typed_code: 2`) on `ExtractGraphContext` where traversal exceeded the raised 30s budget. All completed gracefully via non-fatal fallback. Inner censoring rate: **13.125%** (21 / 160).

### 3. Decay Verdict & Restart Discriminator
- Evaluated against pre-committed thresholds (`alpha = 0.05`, `materiality_delta = 500.0 ms`):
  - Theil-Sen slope: **-6.7283 ms/query** ($p = 0.0000$). Trend is negative (latency improved over the run).
  - Window comparison: Early p95 = 6,969 ms, Late p95 = 2,184 ms, Delta = **-4,785.0 ms** (below 500 ms threshold).
  - Combined Verdict: **`decay_present: False`** (neither prong fired).
- **Restart Discriminator**:
  - Segment 1 tail p95 (last 30 of seg 1): 13,539.0 ms
  - Segment 2 head p95 (first 30 of seg 2): 2,276.0 ms
  - Delta: **-11,263.0 ms** (95% Bootstrap CI: [-12,285 ms, -10,458 ms], strictly negative).
  - Supported Hypothesis: **`process_state`**.
  - Rationale: Latency climbed in Segment 1 but immediately reset to baseline (2.3s) following process restart. This conclusively rules out accumulated store state (LanceDB table size or checkpoint rows) as the cause of tail elevation, pointing instead to process-level resource accumulation (e.g. uncompacted reader session handles or cache table fragmentation).

### 4. Inner Budget Decomposition
- Pinned Strata:
  - Outer `graph_node`: `graph-on` arm only ($n=160$), p95 = **30,449.0 ms**.
  - `query_embedding`: `graph-off` arm only ($n=160$), p95 = **430.0 ms**. Single-writer idempotency verified. Span corroboration: none available (omitted from `RETAINED_GRAPH_SPAN_NAMES` by design).
  - `graph_operation`: Paired difference over 139 surviving pairs (21 pairs excluded due to `GRAPH_TIMEOUT`).
- **Survivor Guard**: Because 13.125% > 10.0% max tolerated rate, `graph_operation` p95 is reported as an explicit **censored-from-above lower bound**: **$\ge$ 25,730.0 ms**.
- **Nesting Invariant**: $30,449.0 \text{ ms} \ge 430.0 \text{ ms} + 25,730.0 \text{ ms} = 26,160.0 \text{ ms}$ (satisfied with +4,289 ms natural slack).
