every node actually cost, tell a real observation from one clipped by a ceiling, and turn
percentiles into a proposed budget set by a rule stated in advance — proven end to end on one

fix. Everything in this plan exists to make that failure mode impossible: censoring is counted,
percentiles over censored data are refused or flagged, and the decision inputs are committed to
the repository before any data is seen.

  <behavior>
    - **Two-armed:** driving a question list produces two records per question, one with graph
      context enabled and one with it disabled, using the existing arm-to-flag mapping. Driving N
      questions produces 2N records.
    - **Arm adjacency:** the two arms of a question are dispatched adjacently rather than in two
      separate passes, so both experience near-identical system state.
    - **Ordinal:** driving a fixed question list produces records whose ordinals are the
      consecutive integers from one, assigned in dispatch order at drive time, present on every
      record including error records, and shared by neither arm — each record has its own.
    - **Record schema:** the measurement record type carries the ordinal, the segment and the
      warm-up marker in addition to everything the benchmark record carries, and parsing a
      measurement journal with the benchmark record type is not attempted anywhere.
    - **Segment:** every record carries a segment label; a driver told to switch segments after
      a stated ordinal produces records whose segment changes exactly at that boundary and never
      changes back.
    - **Ordering is checked after sorting:** the analysis entry point sorts records by their
      recorded ordinal before checking anything. On the SORTED set it requires ordinals to be
      unique, gap-free, and strictly increasing across the segment boundary. Physical journal line
      order is not required to be monotonic: shuffling a sound journal's lines changes no verdict.
    - **Ordering refusal:** a record set whose sorted ordinals are duplicated, absent, or contain a
      gap is refused by the analysis entry point with a stated reason naming the offending ordinal,
      rather than analysed as if the order were sound.
    - **Censoring classification is four-way:** given a record's `node_timings`, `node_failures`
      and `notices`, plus the ceiling in force for each node, the classifier assigns every
      (record, node) pair exactly one of: `OBSERVED` (a duration strictly below the ceiling);
      `CENSORED_AT_CEILING` (a duration at or above the ceiling); `CENSORED_NODE_TIMEOUT` (a
      `node_failures` entry for that node whose `error_kind` is `1` — no duration exists, lower
      bound is the node ceiling); `NOT_REACHED` (no timing, no failure, and the node sits after a
      node that failed or after a no-evidence skip); or `INSTRUMENT_GAP` (no timing, no failure,
      and the node is NOT downstream of a terminating condition). The five labels are mutually
      exclusive and every pair gets exactly one.
    - **Inner graph censoring is separate:** an `ExtractGraphContext` node that completed
      successfully but carries a `GRAPH_TIMEOUT` notice yields `CENSORED_INNER_GRAPH_OP` for the
      graph-operation observation, censored at `graph_operation_timeout_ms`, while the node's own
      total is classified on its own duration. A record can therefore be `OBSERVED` at the node
      level and censored at the inner level simultaneously, and the classifier reports both.
    - **A timeout cascade produces no phantom instrument defects:** given a record whose retrieval
      node carries a timeout-kind failure and whose later nodes carry nothing at all, the later
      nodes classify `NOT_REACHED` and the `INSTRUMENT_GAP` count for that record is zero.
    - **Censoring at the boundary:** an observation exactly equal to the ceiling counts as
      censored, not as a valid tail sample.
    - **Censored counting:** the census reports, per node, the total and a breakdown across all
      labels, so a reader can tell a clipped node from an unreached one from a broken instrument.
    - **question_type stamped:** every emitted record carries the gold question's `question_type`
      as its own field; stratified analysis reads that field and performs no join to gold data.
    - **Two ceilings, two comparisons:** the harness-ceiling report compares the LARGEST SINGLE
      node budget against the SSE read timeout and the WORST-CASE SUM of node budgets against the
      question deadline, labels each comparison with which quantity and which ceiling it used, and
      never compares a sum against the read timeout.
    - **SSE read timeout is settings-derived:** the effective read timeout applied to the live
      query path equals the configured `gateway_timeout_secs`; setting that value to two different
      numbers produces two different effective read timeouts, with no source edit in between.
    - **Benchmark path unchanged by default:** with `gateway_timeout_secs` left at its default, the
      effective read timeout on the existing benchmark drive is the same value it was before this
      change, so 06.3.2's and 06.3.4's runs are unaffected.
    - **Percentile refusal:** asked for a percentile over an observation set whose censored count
      is non-zero, the function either refuses or returns a result explicitly flagged as a lower
      bound carrying the censored count; it never returns a bare number.
    - **Empty observations:** asked for a percentile over an empty observation set, the function
      returns a stated-reason outcome carrying an observation count of zero — not zero, not an
      omitted row, not an exception that loses the reason.
    - **Derivation reproducibility:** given a recorded percentile, a recorded multiplier and the
      recorded rule, the proposed budget recomputes to the same value; the returned record names
      all three plus the sample size and the censoring status.
    - **Nesting report:** given a proposed set, the report states for each nesting group which
      budget is expected to fire first and the slack between inner and outer; a set where an
      enclosing budget equals the sum of the budgets it contains is reported as a violation even
      though the engine's own floor check would accept it.
    - **Missing threshold:** a derivation or verdict requested without a committed multiplier or
      threshold refuses with a stated reason; no default value is substituted.
    - **Live timeout resolution:** the reader returns the base file's value when no override is
      present, the override's value when one is, and fails the check when the configuration
      cannot be read — never a permissive default.
    - **Spend stop-rule:** a stage whose observed spend reaches its cap halts and reports the
      observed figure; a stage whose remaining allowance cannot be read halts before issuing a
      query rather than proceeding.
    - **Spend covers embeddings:** a spend figure derived from token counts prices the embedding
      model in addition to the generation model; a figure computed from
      `workflow_meta.prompt_tokens` and `completion_tokens` alone is returned explicitly marked a
      lower bound and never as the observed spend.
    - **Isolation asserted:** the driver refuses to issue a calibration query when the resolved
      PostgreSQL schema equals the eval schema, reporting both names.
    - **Never raises:** a transport failure, a stream abort or a validation error becomes a
      durable error record carrying its ordinal and segment, exactly as `drive_one` does today.

    no evidence. Downstream of either break, nodes emit no event whatsoever — no `node_started`, no

    genuine source being the 64-entry `node_completed` frame cap at `client.py:300-306`.

    percentile over a set with a non-zero censored count must be returned explicitly as a lower

    fire — that is precisely the incoherence D-17 documents and the run confirmed, with 494 graph
    timeouts at the inner budget and none at the outer. Passing the engine's check is therefore
    not evidence the invariant holds, and this report is what supplies the missing evidence.

### Explicit planner decisions

Three points the reviewers left open. Each is decided here and stated in the plan that owns it, so
no resolution is silently absorbed.

1. **Plan 04's source of truth for timeout defaults → the Rust defaults change too.** Stated in
   Plan 04's task 1 action. Rationale in full there; in short, `config.rs:125-145` are serde
   fallbacks that the shipped binary runs on whenever a key is absent, and
   `workflow_phase5_production.rs` asserts them via `EffectiveRagSettings::default()` with no
   reference to `config.toml` at all. Changing only the TOML would leave the collapse values as the
   binary's fallback while a test named "production" stayed green asserting numbers nobody runs.
2. **Wave 1's parallelism is preserved; the calibration is isolated instead.** Stated in Plan 01's
   task 1 action and precondition. **No `wave:` or `depends_on:` value changed in any of the four
   plans**, so `ROADMAP.md`'s hand-written wave-dependency prose for this phase remains accurate.
3. **Plan 03 flips to `autonomous: false`.** Stated in Plan 03's new task 1. Rationale in full
   there; in short, D-47 requires a per-stage spend cap and Plan 01's `measure` command takes that
   cap as a **required argument with no default** — yet no artifact in the phase produces the
   figure. A `checkpoint:decision` is exactly the mechanism for a number that must come from a
   human, and it also gives the mid-run engine restart and the irreversible consumption of the
   as-is condition a deliberate authorisation point.
