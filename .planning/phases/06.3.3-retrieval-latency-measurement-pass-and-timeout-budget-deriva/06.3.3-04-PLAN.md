    already carries the rule: the node budget must accommodate the provider's attempt count times
    its per-attempt timeout, plus inter-attempt slack. Use that rule, record the slack, and mark the
    provenance as the provider contract. Report the measured generation latency beside it and mark
    it explicitly non-derivable from this pass, because the cheap model that made the pass
    affordable is not the model production runs. That is how the requirement to re-derive all six
    together and the constraint that generation latency is unusable are both honoured, rather than
    one being quietly dropped.

    Leave the reformulate budget alone. Report its measured latency in the derivation record and
    state that it is deliberately not derived: the stated success criterion names six budgets and
    does not name this one, and deriving a seventh would exceed it. Record it as an open input for a
    later decision rather than as an oversight.

    Handle any node for which the pass produced no usable observations by retaining its current

    forward as an open input. A retained value with a stated reason is honest; a value derived from

    Now check the invariants before writing, using the nesting report rather than the engine's own
    floor. The engine requires only that the graph node budget be at least the sum of the budgets
    nested inside it — a set that passes that check can still have an outer budget that can never
    fire, which is precisely the incoherence the family documented and which the recorded run
    confirmed with 494 timeouts at the inner budget and none at the outer. Require strict inequality
    with recorded slack, and for each nesting group state which budget is expected to fire first and
    why.

    Apply the stated conflict policy when the invariant does not hold on the derived set, rather
    than improvising — independently derived outer and inner percentiles can perfectly well produce
    a violating set, and 06.3.3-03 flags that case forward to here. The policy: **raise the
    enclosing budget** to the sum of its derived inner budgets plus the committed slack, and label
    that row invariant-driven so a reader can see the number did not come straight off a percentile.
    Never shave an inner budget to fit an outer one. The inner budgets carry measured evidence and
    the outer one is what must accommodate them; trimming the measured half to make the arithmetic
    close is how a fitted number acquires the appearance of a measurement, which is the whole class
    of error this phase exists to eliminate.

    Check the two harness ceilings against **two different quantities**, because they are
    structurally different constraints and the earlier "worst-case sum against both" formulation was
    wrong for one of them. The SSE read timeout is a per-read-gap ceiling — httpx applies it to the
    wait for the next chunk, and the stream emits a frame between nodes — so it binds the **largest
    single node budget**. The per-question deadline is wall-clock across the whole stream, so it
    binds the **worst-case sum**. State `max(written node budget) < read timeout` and
    `sum(written node budgets) < question deadline` as two separate results. Comparing a sum against
    the read timeout would over-constrain the written set for no reason.

    If the derived set cannot satisfy both the nesting invariant and a harness ceiling, that is a
    finding to record and resolve deliberately — including by raising the harness ceiling, which is
    a harness setting rather than a production default — not a reason to shave a budget until it
    fits.
