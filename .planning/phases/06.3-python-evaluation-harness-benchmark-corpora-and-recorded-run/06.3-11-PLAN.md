### Root cause (re-confirm at execution time, do not trust this snapshot blindly)

`eval/src/lancet_eval/score.py`, the block below the `# Select up to 20 representative items across query types` comment: when `not no_judge and judged_qids`, the selector is `[r for r in p_records if r.question_id in judged_qids][:20]`. `judged_qids` is the set of question IDs *sampled for judging* — it says nothing about whether that record actually produced a `judge_cache.json` entry with a usable verdict. A record with empty `structured_citations` is routed to `skipped_no_evidence` (score.py's judge-pass loop) and never reaches `judge_once`, so it never gets a cache entry at all; a record whose judge call itself errors gets a cache entry with `verdict: null`. Both kinds pass the current filter and both are unusable to a human scorer. Against the committed run, 98 of the 100 sampled questions had zero citations, so the naive first-20 slice caught only 1 of the 2 records that actually had a resolvable, non-null verdict.

06.3-09 Task 5 already fixed part of this (the pre-06.3-09 selector was `p_records[:20]` with no `judged_qids` filter at all) but stopped at membership, not resolvability — its own regression test (`test_worksheet_rows_are_drawn_from_the_judged_subset`) gives every one of its 30 fixture records a `structured_citations` entry, so it cannot exercise the exact failure mode (mostly-uncited real answers) that broke in production. That is the gap this plan closes.

### Amending the "twenty" must-have — stated explicitly, per this round's own instruction not to silently pick a path

06.3-10's own must-have (and 06.3-VERIFICATION.md's Truth 10) requires exactly "twenty calibration rows." Independently confirmed against `06-CONTEXT.md`: **no D-XX locked decision fixes the literal number twenty.** It traces to `06.3-06-PLAN.md`'s own prose and `eval/README.md`'s "Human evaluators grade ~20 representative questions," then hardened into a bare "twenty" by 06.3-10's self-authored must-have. Amending a self-imposed number that traces to a prior gap-closure plan's own prose — not to a locked `CONTEXT.md` decision, a ROADMAP success criterion, or RESEARCH.md — is not the scope reduction `scope_reduction_prohibition` guards against; that fence protects source-artifact decisions, and this isn't one.

Two paths were considered:

- **Path A (source calibration candidates from both arms to literally reach 20):** graph-on has 16 unique cited question_ids, graph-off has 18, the union is 26 with 8 overlapping — so only the union clears 20. **Rejected**, and not primarily on invasiveness grounds. Calibration measures agreement between a human and the judge *on the population the judge actually scores for the headline dimensions*. `score_run`'s judge pass only ever scores `p_records` (the primary/graph-on arm) — that is what `answer_groundedness`/`answer_faithfulness` measure. Sourcing calibration rows from graph-off would compare a human against judge verdicts for a population the report's headline dimensions never touch: the resulting "agreement" figure would not describe what the report claims it describes, regardless of how carefully it was engineered to avoid touching `groundedness_scores`/`faithfulness_scores` directly. A calibration figure has to be a subset of the judged population to mean what its name says.
- **Path B (chosen): correct the acceptance criterion to `min(20, N)`.** Judge the full primary-arm population (drop the `--sample 100` restriction in Task 2, so `judged_qids` covers all 500 graph-on records rather than a random subset of them) to reach the natural per-run ceiling of cache-resolvable rows (16 as of this snapshot — every graph-on record that ever carried a citation), then hand-score however many that turns out to be, capped at 20. This keeps the calibration population a strict subset of the judged population — the only version of the figure that is honest about what it measures — and costs roughly a dozen-plus new judge calls (16 candidates minus the 2 already cached) rather than Path A's ~24.

If the `assumption-delta` detector's singular→plural framing is raised against this round's own work (it fired only on the pre-existing, already-dispositioned ROADMAP "optional GraphRAG-Bench" signal when scanned during this planning session, not on anything new here): the calibration-candidate pool does **not** become "either arm" — Path A is rejected outright, on the measurement-validity grounds above, not folded in as an "add-alongside" option.
