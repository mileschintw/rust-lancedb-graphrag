# Plan 06.3-11 Summary: Calibration Worksheet Selector Defect Fix and Full Primary-Arm Judge Expansion

## Executive Summary

Plan 06.3-11 resolved the remaining defect identified in `06.3-VERIFICATION.md` (Truth 10 root cause): `eval/src/lancet_eval/score.py`'s calibration worksheet candidate selector previously filtered candidates solely on whether their `question_id` was sampled for judging (`judged_qids` membership), rather than checking whether each candidate possessed an actual cached verdict with a non-null result. Because only ~3.2% of primary-arm questions return citations, the prior selector emitted 20 rows of which only 1 had a corresponding judge verdict (`20 1` mismatch).

In Task 1, TDD regression tests were added and verified RED against the old selector and GREEN against the fixed selector. The selector now verifies that each candidate row has non-empty citations, resolves to a `JudgeCacheEntry` in `judge_cache.json`, and has `verdict is not None`.

In Task 2, the judge pass was run across the full primary-arm population (`sample_size_judged=500`, dropping the arbitrary `--sample 100` restriction), expanding the cache from 2 entries to all 16 cited records with 0 errors. A fresh calibration worksheet was re-emitted with strict 16/16 pairing.

Per user instruction and the blocking-human gate protocol, Task 2 concludes with `calibration pending`, strictly preserving human-scoring integrity without agent fabrication.
