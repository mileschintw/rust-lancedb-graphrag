# Phase 06.3 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

---

## Test Infrastructure

This phase spans three test stacks. The Python harness is new (`eval/` does not exist in the
repository today); the Rust engine suite and the Go gateway suite both already exist and are only
extended.

| Property | Python half (`eval/`) | Rust half (`engine/`) | Go half (`gateway/`) |
|----------|-----------------------|-----------------------|----------------------|
| **Framework** | pytest + pytest-httpx, run under `uv` | `cargo test` (built-in harness) + local mock HTTP server | `go test` |
| **Config file** | `eval/pyproject.toml` — **none today; Wave 0 (`06.3-01` Task 1) creates it** | `engine/Cargo.toml` — exists | `gateway/go.mod` — exists |
| **Quick run command** | `uv run --project eval pytest {test_file} -v` | `cargo test --manifest-path engine/Cargo.toml --locked {filter} -- --nocapture` | `cd gateway && go test ./internal/sse/... -run {filter} -v` |
| **Full suite command** | `uv run --project eval pytest` then `uv run --project eval ruff check --preview src tests` then `uv lock --project eval --check` | `cargo test --manifest-path engine/Cargo.toml --locked` then `sh scripts/engine-test-targets.sh` | `cd gateway && go test ./...` then `go vet ./...` then `sh scripts/gateway-test-targets.sh` |
| **Estimated runtime** | ~10–30 s (fully offline: synthetic SSE fixtures, no gateway, no network, no `OPENROUTER_API_KEY`) | ~120–180 s warm (~cold build longer) | ~20–60 s (no PostgreSQL required for the `internal/sse` package) |
| **Network required** | No — offline is an asserted invariant, not a convenience | No — every mock server binds `127.0.0.1:0` | No |

*Runtimes are projections; confirm and correct them when Wave 0 lands (`06.3-01` Task 1).*

**Third stack added on the replan pass.** Plan `06.3-08` (the retrieval-visibility wire extension, wave 1) touches `proto/`, the engine and the gateway, so the Go suite and `scripts/gateway-test-targets.sh` are now part of this phase's validation surface. Waves 1 and 2 touch the Rust and Go halves; waves 3 through 7 are Python-only.

## Sampling Rate

- **After every task commit:** run that task's `<automated>` command(s) — the per-task quick
  command from the map below.
- **After every plan wave:** run the full suite for the half that wave touched. Wave 1 (`06.3-08`)
  touches the Rust and Go halves; wave 2 (`06.3-01`, `06.3-02`) touches the Python and Rust halves;
  waves 3–7 are Python-only.
- **Before `/gsd-verify-work`:** all three full suites must be green, `uv lock --project eval --check`
  must report no drift, and both test-count invariant gates (`scripts/engine-test-targets.sh`,
  `scripts/gateway-test-targets.sh`) must exit 0.
- **Max feedback latency:** 30 s for the Python half (plans 01, 03–07 — every task); 180 s for the
  Rust half (plans 08 and 02, each Task 2's whole-crate run); 60 s for the Go half (plan 08 Task 2).
