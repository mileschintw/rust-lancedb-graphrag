Write `shipped_generation_model_pin_matches_preflight_test_model` asserting that helper's value equals a single module-level constant that the three preflight tests below also use to construct their generator. That constant is the only place the literal model id appears in the test module; the assertion is what makes the pair drift-proof, and it is the half of D-63 that actually closes WARN-NEW-01. Write `shipped_generation_model_structured_output_preflight_succeeds` following the `openrouter_json_schema_and_finish_reason_contract` idiom exactly: bind a `TcpListener` on `127.0.0.1:0`, spawn a thread that accepts one request and writes a models-metadata payload whose `data` array holds one entry with `id` equal to the shipped constant and `supported_parameters` containing `response_format` and `json_schema`, then build `OpenRouterGenerator::new("test-key", <shipped constant>)` with `with_endpoints` pointing the models URL at that mock, call `check_supported_parameters().await`, assert it succeeds, and join the server thread. There is no live network call and no environment API key anywhere in this test.

Write `shipped_generation_model_without_structured_output_params_fails_preflight` with the same shape but a `supported_parameters` array holding only `temperature` and `max_tokens`; assert the error kind is `GenerationErrorKind::SupportedParameters` and the message names the structured-output capability the model failed to advertise. This is the case that stops the success test from being tautological — it proves the preflight discriminates rather than always returning `Ok`.

Write `shipped_generation_model_absent_from_models_list_fails_preflight` with a payload listing one unrelated model id; assert `GenerationErrorKind::SupportedParameters` and that the message contains the shipped model id, which is the branch that fires when OpenRouter drops or renames a free-tier model out from under the pin.

Because `check_supported_parameters` caches successful results in a per-generator `Arc<tokio::sync::Mutex<HashMap<CapabilityKey, Arc<tokio::sync::OnceCell<ModelCapabilities>>>>>` (`engine/src/generation/openrouter.rs:235-237`, populated at `400-412`) — a map of single-flight cells keyed by `(models_endpoint, model)`, not one cell per generator — each test constructs its own `OpenRouterGenerator` so no verdict leaks between cases. The keying detail matters for why the isolation strategy is right rather than merely conventional: two tests sharing a generator and using the *same* model id would hit the same cell and the second would read the first's cached verdict, which is exactly what the success/failure pair below must not do. A fresh generator gives a fresh, empty map.
