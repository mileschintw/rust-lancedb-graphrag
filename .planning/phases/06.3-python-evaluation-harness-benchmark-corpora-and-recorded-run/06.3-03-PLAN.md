## Ruling: the evidence-match rule (planner decision, D-50 discretion)

06.3-AI-SPEC.md §1b and 06.3-RESEARCH.md Pitfall 7 both leave the chunk-boundary mitigation as an explicit planner input. It is decided here, once, and the executor implements it as stated.

**Primary source finding that corrects RESEARCH's recommendation.** RESEARCH names "raise the eval corpus's `chunk_overlap` above 538" as the *preferred* mitigation. That option self-destructs, verified in this repo's own code:

1. `gateway/main.go` rejects any upload where `chunk_overlap >= chunk_size`. Reaching an overlap of 538 therefore forces a `chunk_size` above 538.
2. `config/config.toml` `[engine.retrieval] excerpt_max_chars = 512`, and the citation `excerpt` is a bounded prefix of the chunk. A chunk larger than 512 characters makes `is_truncated` true on effectively every citation.
3. 06.3-AI-SPEC.md §5's normative note classifies a citation with `is_truncated == true` as **undecidable** for matching.

So the mitigation intended to make containment matching work is precisely the change that makes containment matching impossible. It is rejected.

**The rule, as it will be stated in the report in one sentence:**

> *A retrieved citation matches a gold evidence fact when the fact's whitespace-normalised text appears verbatim inside the citation's whitespace-normalised excerpt.*

**Decisions that follow, all binding on the executor:**

- **The eval corpus is seeded at the shipped chunking defaults** (`chunk_size = 500`, `chunk_overlap = 50`), with no per-upload override. Three converging reasons: the collision above; D-44 chose this corpus *because* full news articles exercise structure-aware chunking as shipped; and D-48 says the harness measures the shipped system. Plan 06.3-04's seeder sends no `chunk_size` or `chunk_overlap` form field.
- **The primary rule is used identically by recall@k, context precision@k, MRR@10 and nDCG@k.** One function, `fact_matches_excerpt()`. Divergence between them would make the metrics non-composable.
- **Residual boundary loss is measured, not hidden.** `defaultChunkOverlap = 50` is far below the median 161-character gold fact, so a fact straddling a chunk edge is contained in neither chunk and records a miss on a retrieval that was in fact perfect. This is a systematic downward bias. It is quantified by a **diagnostic that no headline metric consumes**: `boundary_attributable_misses`, computed by an anchored partial match — a normalised prefix of the fact of length at least `max(60, ceil(0.5 * len(fact)))` equal to the tail of the excerpt, or a normalised suffix of the same minimum length equal to the head of the excerpt. The 60-character floor is chosen because it exceeds the shipped 50-character overlap, so an overlap-window coincidence cannot trigger it. The report prints this count next to the strict recall figure.
- **Article-level matching is rejected** as the primary rule. It counts any chunk from a gold article as a hit even when that chunk contains none of the gold fact, and it collapses the gold denominator for the 7.5% of queries drawing two or more facts from one article — both errors inflate. The `document_id` → article map (plan 06.3-04) stays load-bearing for the coverage guardrail, not for scoring.
- **Undecidable is a third state.** A citation with `is_truncated == true` is neither a hit nor a miss, the anchored diagnostic does not fire on it, and the count of undecidable citations is reported. At the shipped 500/512 parameters this count should be zero; a non-zero value means the chunking parameters moved and the numbers are not comparable to the previous run.

Write `metrics.py` as pure functions with **zero network and zero LLM dependency** — the module imports only the standard library plus the local wire types. That constraint is D-50's central design property, and a later import that breaks it must be caught by test, not by review.

Implement `normalize_ws()` (collapse all whitespace runs, strip, casefold) and `squad_normalize()` (lowercase, strip punctuation, drop the articles a/an/the, collapse whitespace) as separate functions — the evidence rule and the answer rule are different normalisations and must not be conflated. Implement the aggregate metrics over a question's citations **in the order the wire returned them**, using each citation's own `rank` field as the authoritative position: the harness never sorts, re-ranks or filters. Implement `em_f1()` with SQuAD v1.1 normalisation over `final_answer.answer`, never over a concatenation of `answer_chunk` text. A confident answer on a null query with no such notice and non-empty citations is recorded as hallucinated-on-null.

Enforce the null exclusion structurally, not by convention: every retrieval and EM/F1 aggregator takes questions already partitioned into answerable and null by `GoldQuestion.is_null`, and handing it a null question is a programming error that raises.
