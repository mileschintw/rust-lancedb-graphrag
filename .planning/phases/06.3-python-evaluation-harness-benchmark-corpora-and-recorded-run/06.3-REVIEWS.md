## 3. Concerns

- **HIGH — 06.3-10 Step 3/4 omit `--judge`, so the published report will skip judged dimensions.** `score_benchmark` defaults `no_judge=True` (`cli.py:295-301`). `score_run(..., no_judge=True)` appends groundedness/faithfulness as `skipped` with n=0 (`score.py:578-608`) and never fills `judge_cache.json`. The copied command from 06.3-07 (`score --run … --sample 100` and emit-worksheet without `--judge`) disagrees with the README (`eval/README.md:71-77`: `--judge --sample 100`). Plan 10's must-haves require judged n, judge-error count, prompt version, and observed agreement. Executors following the task text will spend the drive quota and still fail SC8's judged half. **Fix:** every `score` invocation in Task 3 that is meant to judge or calibrate must pass `--judge`.

- **HIGH — `commit_sha: "local"` is produced by production scoring, not only the smoke test, and neither plan changes it.** `score_run` sets `commit_sha=os.environ.get("GIT_COMMIT_SHA") or "local"` (`score.py:729`). Probe already uses `get_commit_sha()` → `git rev-parse HEAD` (`cli.py:427-437,679`). `lancet-eval report` reloads `report.json` if present (`cli.py:378-386`) and will persist `"local"` into `metadata.json`. Plan 10's acceptance bar forbids that placeholder and `score.py` is not in `files_modified`. Setting `GIT_COMMIT_SHA` in the procedure, or routing score through `get_commit_sha()`, is required or the commit gate fails after days of driving.

- **HIGH — Plan 10 asserts `sample_size_deterministic` equals journal/dimension `n`; the scorer stores the corpus nominal size.** `sample_size_deterministic=len(sampled_questions)` (`score.py:736`) is the committed sample (500 in `multihop_rag.toml:12`), not `len(records)` or per-dimension `n`. A drive with generation errors (expected on free tier; 06.3-07 caveat about excluded retrieval n) will have dimension `n` < 500 while metadata still says 500 — the same class of lie as the smoke test's 500 vs 3, just smaller. Neither 09 nor 10 edits `score.py`. Either change the scorer, or weaken the acceptance criterion to "nominal sample size printed next to actual `n`" (which 07 already requires in the report body).

- **MEDIUM — CR-02 is not fully closed unless `run` passes `load_settings()` into `drive()`.** Today `run_benchmark` never calls `load_settings` and never passes `settings=` (`cli.py:270-276`); `drive` does `settings or EvalSettings()` (`run.py:94`). `EvalSettings()` reads `LANCET_EVAL__*` env, not `eval/config.toml` (`load_settings` at `config.py:122-129`). Probe uses `load_settings()` (`cli.py:548-570`). Threading `deadline_s` through `drive_one` is necessary but not sufficient for a TOML-configured deadline. The Task 4 test that constructs `EvalSettings(question_deadline_secs=…)` and passes it into `drive()` will go green while the CLI path still ignores the file.

- **MEDIUM — `resume=True` plus "reuse newest dated dir" makes a second recorded run append to the committed journal.** CLI `--resume` defaults true (`cli.py:241-247`). After SC8 lands, a bare `lancet-eval run --corpus multihop_rag` would resolve to the published directory and append. Plan 10 mitigates by requiring explicit `--out` during *this* drive; 09's README update does not require `--no-resume` / a new `--out` for a later run. Lexicographic `max` on `*-<corpus>` also prefers any `zzz-multihop_rag` over ISO dates.

- **MEDIUM — Plan 10 "reseed then seed" double-invokes a function that already seeds.** `reseed_corpus` always `return seed_corpus(...)` (`seed.py:303`). `reseed --confirm` is wipe **and** full ingest. A second `seed` is a no-op on mapped ids (`seed.py:166-168`) if the first finished; if `reseed` dies mid-ingest, the instructions say "re-run it" after the **seed** paragraph (correct) but an operator who re-runs **reseed** will unlink the map (`seed.py:298-301`) and re-pay embeddings. Spell: wipe once (`reseed` *or* drop+`seed`), resume with `seed` only.

- **MEDIUM — Branch B as specified drops schema via `settings.dev_database_url`.** Same-database multi-schema (`lancet` + `search_path`) makes that the admin DSN, which is right **only if** eval and dev share a database. If eval is retargeted at another DB, `DROP SCHEMA <eval_name>` runs on the **dev** server. Interpolating the schema name into SQL also needs identifier quoting (`pg_quote_ident` / reject non-`[A-Za-z0-9_]+`). Guard `assert_schema_isolated` does not check host/dbname equality.

- **MEDIUM — Plan 10 gateway-stopped bar requires a remedy string the code does not emit.** Failure text is `Gateway connection failed: {exc}` (`preflight.py:83`) with engine `Engine unreachable because gateway is down.` (`:88`). Service is named; there is no "run `go run` / start the gateway" remedy. The plan says record a finding rather than proceed — good — but then SC8 still waits on a product change 10 does not schedule. Either add a one-line remedy in 09 (tiny, in `preflight.py`) or accept "names gateway" as sufficient and drop "remedy" from 10's pass bar.

- **MEDIUM — `resolve_run_dir(corpus, resume)` as specified cannot use `tmp_path` without a root seam.** Implementation against `repo_root() / "eval/runs"` will hit the real tree unless tests monkeypatch `repo_root`. Plan does not name that seam; a naive test can create dated dirs under `eval/runs/` (exactly the scratch 09 is trying to keep uncommitted).

- **MEDIUM — Windows vs bash verify gates.** User environment is Windows. Task 1's `! git check-ignore -q` and Task 1's `wc -l` / `test "$(python …)" -eq "$(wc -l < …)"` are POSIX. PowerShell `!` is not exit-code negation. This repo has used Git Bash for similar gates; say so in 09/10 verify so the executor does not invert the ignore polarity (the bug the `!` comment exists to prevent).

- **LOW — Git un-ignore sometimes needs `!eval/runs/*-multihop_rag/**` as well as the directory exception.** Plan claims a scratch-repo proof and three `check-ignore` gates including `report.md`; those gates will catch a Git version that still ignores nested files. Keep the file-level gate; do not drop it.

- **LOW — README `eval/runs/latest` and hyphenated `2026-08-29-multihop-rag` (`README.md:68-83`) remain ignored after 09's exception.** Task 1 says update the checklist; it should delete or replace those examples or operators will write into ignored paths.

- **LOW — 01–08 residual (not reopened by this round, still true at HEAD).** Journal `RunRecord` does persist `snapshot` (`journal.py:30`; `run.py:58`) — prior HIGH-1 on journal drop is closed in code. `score.py:729` `"local"` and `--no-judge` default were already in 07's procedure; 10 copies them. Atlas isolation is now in-repo (`atlas.hcl` `env "eval"`).
