# Phase 06.3 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| harness → gateway `/rag/query` | The harness is an untrusted external HTTP client of the gateway; the gateway's own input validation (Phase 6 D-15 bad-input matrix) governs. | Operational / test artifacts |
| gateway response → harness parser | Response bodies are untrusted input to the harness's Pydantic models; a malformed or oversized frame must not crash or hang the run. | Operational / test artifacts |
| committed config → test assertion | `config/config.toml` is the source of truth the test reads; it carries no secret (the DSN and API key are env-supplied). | Operational / test artifacts |
| HuggingFace download → local cache | `corpus fetch` pulls untrusted third-party JSON over the network into the repo's working tree. | Operational / test artifacts |
| corpus JSON → scoring | Gold facts and article bodies are untrusted text used as matcher inputs and, later, as judge prompt content. | Operational / test artifacts |
| local cache → committed subset | Only the reduced subset crosses into the repository; the full dataset must not. | Operational / test artifacts |
| harness → gateway `/documents` | Article bodies are untrusted third-party text uploaded through the production ingestion surface. | Operational / test artifacts |
| environment → committed artifacts | The eval DSN and the API key live in the environment and must never reach a committed file. | Operational / test artifacts |
| gateway response → journal record | Untrusted response content is persisted verbatim into a committed artifact; it must be data, never something the scorer executes or trusts for control flow. | Operational / test artifacts |
| journal → published number | Everything the report claims derives from this file; a record that misrepresents what happened silently corrupts the claim. | Operational / test artifacts |
| corpus evidence → judge prompt | Third-party article text is fed to a model; text that reads like an instruction must not become one. | Operational / test artifacts |
| judge response → harness | Provider output is untrusted and may be malformed, fenced, oversized or absent. | Operational / test artifacts |
| harness → provider over the network | The only outbound call the harness makes on its own behalf. | Operational / test artifacts |
| run record → public repository | The committed report and journal are published artifacts; anything wrong or secret in them is published too. | Operational / test artifacts |
| scored dimensions → rendered claim | The render is where a measured number becomes a claim; provenance is checked here or nowhere. | Operational / test artifacts |
| gateway → HTTP/SSE client | The `/rag/query` caller now receives excerpt text for retrieved-but-uncited chunks in addition to cited ones. | Operational / test artifacts |
| corpus text → response payload | Chunk text is untrusted third-party content; a wider slice of it now reaches the response. | Operational / test artifacts |
| eval configuration → destructive PostgreSQL statement | A DSN read from environment or `config/config.eval.toml` decides which schema is destroyed **and which server it is destroyed on**. A misconfigured or absent `search_path` is the failure that reaches the developer's dev store; a retargeted eval DSN with an unguarded admin connection is the failure that reaches the wrong *server*. | Operational / test artifacts |
| resolved schema name → SQL identifier position | `pg_schema_of` returns an operator-controlled string verbatim from a DSN query parameter, and DDL cannot bind identifiers as parameters, so that string is interpolated into SQL text. Untrusted-shaped input crosses into a statement grammar here. | Operational / test artifacts |
| `reseed_corpus()` → external CLI process | The reset shells out to a tool outside the Python process; its argv, working directory and exit code are the whole contract. | Operational / test artifacts |
| `.gitignore` → the public repository | Narrowing an ignore rule changes what a later `git add` will publish. Anything that becomes trackable becomes publishable. | Operational / test artifacts |
| operator's OpenRouter credential → engine, harness and committed artifacts | One secret is read by two processes during the seed, the drive and the judge, and the artifacts those processes write are about to be published. | Operational / test artifacts |
| live external API → journal and judge cache | Provider responses — model answers, judge verdicts, error payloads — cross untrusted into files that become part of the repository. | Operational / test artifacts |
| human judgment → the report's agreement figure | The calibration number's entire value is that a person produced it; a synthesized one is indistinguishable downstream. | Operational / test artifacts |
| Committed run-record artifacts (`eval/runs/2026-09-03-multihop_rag/`) → public repository | Task 2 appends new judge verdicts, a re-emitted worksheet, and a human's free-text hand-scored file to an already-public, git-tracked directory. Nothing here is newly exposed to a new audience, but a human-authored `notes` field is free text a person writes and this plan commits verbatim. | Operational / test artifacts |
| Live OpenRouter judge calls (Task 2) → operator's API key and quota | Unchanged from the already-covered pattern in `06.3-06`/`06.3-AI-SPEC.md`; this plan adds no new call site, no new credential path, and no new dependency — it only widens which already-existing candidate records reach the existing `judge_once()` call by dropping a `--sample` restriction. | Operational / test artifacts |

| T-06.3-01 | Information Disclosure | `config.py` settings, `report.py` serialisation | high | mitigate | **Split mitigation, both halves named.** *This plan's half is structural:* `EvalSettings` declares no credential field at all — the OpenRouter key is read from the environment at the point of use in plan 06.3-06's judge client, never from a committed file, never given a default, and never placed on any Pydantic model that `report.py` or the journal serialises. Task 1's acceptance criteria pin `EvalSettings`' exact field list, so adding a credential field is a failing test rather than a review miss. *Plan 06.3-06 owns the empirical half:* `tests/test_secrets.py` sets a sentinel key value, runs a full scored render, and asserts the sentinel appears in none of the report, schema, journal, judge cache or captured log output. | closed |
