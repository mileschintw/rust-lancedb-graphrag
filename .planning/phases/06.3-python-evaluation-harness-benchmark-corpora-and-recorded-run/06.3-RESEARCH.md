# Phase 06.3: Evaluation Harness, Benchmark Corpora and Recorded Run (OBS-02, OBS-04) - Research

**Researched:** 2026-08-28
**Domain:** RAG/GraphRAG evaluation harness, benchmark-based offline scoring, deterministic IR metrics, LLM-as-judge methodology
**Confidence:** HIGH

## Summary

Phase 6.3 builds an external, black-box evaluation harness in Python (`eval/` directory, `uv`-managed with committed lockfile) that drives the shipped Lancet gateway's `/rag/query` HTTP/SSE endpoint against a ~500-question MultiHop-RAG benchmark corpus. The harness splits metrics into two tiers: **deterministic metrics (retrieval recall@k, context precision, MRR/nDCG, EM/F1) that run with no LLM and require no API key**, and **LLM-judged metrics (groundedness, faithfulness only) using a pinned free-tier judge model distinct from the generator, temperature 0, with cached verdicts**. The evaluation is advisory-only (D-54) — no pass/fail gates — and reports per corpus with full run metadata (commit SHA, judge model, sample size, index generation, seed) to enable trajectory tracking and offline recomputation. The harness also ablates graph capability by running the same questions with graph context on and off via a per-request flag, and closes Phase 05's WARN-NEW-01 debt by testing the shipped generation model's structured-output preflight capability.

**Primary recommendation:** 

1. **Framework is "no framework"** — no RAGAS, DeepEval, or LangChain; hand-rolled deterministic metrics (~120 lines), contract-asserting httpx/httpx-sse SSE client (D-65), Pydantic v2 for result models (D-51), thin raw-httpx OpenRouter judge. This keeps the deterministic half free of LLM and API-key dependency (D-50). [CITED: 06.3-AI-SPEC.md §2]

2. **Stack is httpx 0.28+, httpx-sse 0.4.3+, pydantic 2.11+, pydantic-settings 2.7+, typer 0.15+, rich 13+, jinja2 3.1+, tenacity 9.1+ (not 9.0.0 — `wait_exception` primitive does not exist), pytest 8+, pytest-httpx 0.35+, ruff**. Resolved via `uv` on Windows 11 / Python 3.13.3 (verified Sept 2026). [VERIFIED: 06.3-AI-SPEC.md §3, empirical uv build]

3. **Chunk-boundary mitigation for evidence matching is a planner input** — MultiHop-RAG gold facts are median 161 chars (p90 257, max 538) while `defaultChunkOverlap = 50`, so a fact straddling a boundary is unmatchable by exact containment, deflating recall systematically. Three options must be evaluated and one chosen: (a) raise eval corpus's `chunk_overlap` above 538; (b) relax matching to a longest-common-substring/normalized-sub-span threshold; (c) fall back to article-level matching (looser, incomparable to baselines). [CITED: 06.3-AI-SPEC.md §1b Critical Failure Mode #2]

4. **D-63 (structured-output preflight) targets Rust, not Python** — `engine/src/generation/openrouter.rs:425-434`. Must exercise the shipped model's (`dots-studio/dots-3-note-preview:free`) JSON schema preflight with at least one Rust test. Do not plan into `eval/` harness work. [CITED: 06.3-AI-SPEC.md scope correction]

### Pattern 1: Contract-Asserting SSE Client (D-65)

**What:** A thin httpx-sse wrapper that validates the `/rag/query` response sequence before scoring.
**When to use:** Every query call; raises typed exceptions on protocol violations (never scores as zero).

**Example:**
```python
# src/lancet_eval/client.py
from httpx_sse import connect_sse, SSEError
from pydantic import BaseModel, ConfigDict, ValidationError, model_validator

class StructuredCitation(BaseModel):
    model_config = ConfigDict(extra="ignore")
    chunk_id: str
    document_id: str
    excerpt: str = ""
    score: float = 0.0
    rank: int = 0

class RagAnswer(BaseModel):
    model_config = ConfigDict(extra="ignore")
    answer: str = ""
    structured_citations: list[StructuredCitation] = Field(default_factory=list)
    notices: list[Notice] = Field(default_factory=list)

def run_query(client: httpx.Client, *, query: str, session_id: str = "",
              graph_arm: Literal["on", "off"] = "on") -> QueryOutcome:
    """Drives /rag/query SSE stream, asserts D-65 sequence, returns typed QueryOutcome or raises."""
    body = {"query": query, "session_id": session_id}
    if graph_arm == "off":
        body["disable_graph_context"] = True  # D-47: flag is what turns graph OFF

    with connect_sse(client, "POST", "/rag/query", json=body, timeout=EVAL_TIMEOUT) as src:
        if src.response.status_code != httpx.codes.OK:
            raise PreStreamError(f"HTTP {src.response.status_code}: {src.response.text[:500]!r}")

        session = src.response.headers.get("X-Lancet-Session-ID", "")
        correlation = src.response.headers.get("X-Lancet-Correlation-ID", "")

        final_answer_count = 0
        answer: RagAnswer | None = None
        completion: WorkflowCompleted | None = None

        for sse in src.iter_sse():
            match sse.event:
                case "final_answer":
                    final_answer_count += 1
                    answer = RagAnswer.model_validate_json(sse.data)
                case "workflow_completed":
                    completion = WorkflowCompleted.model_validate_json(sse.data)
                case "stream_error":
                    raise StreamAborted(f"{StreamErrorFrame.model_validate_json(sse.data).code}")
                case "answer_chunk" | "node_started" | "node_completed" | "node_failed":
                    pass  # UX-only frames
                case other:
                    raise ContractViolation(f"unknown SSE event {other!r}")
        
        # D-65 assertions: terminal event required, ≤1 final_answer, success implies answer
        if completion is None:
            raise StreamAborted("stream ended without workflow_completed")
        if final_answer_count > 1:
            raise ContractViolation(f"{final_answer_count} final_answer frames, expected ≤1")
        if answer is None:
            answer = completion.final_response
        if completion.success and answer is None:
            raise ContractViolation("workflow_completed.success with no answer payload")

        return QueryOutcome(status="ok" if completion.success else "degraded",
                           answer=answer, completion=completion, session_id=session,
                           correlation_id=correlation, duration_ms=completion.total_duration_ms)
```

### Pattern 2: Deterministic Metrics (No LLM, No API Key)

**What:** Hand-rolled recall@k, MRR, nDCG, EM/F1 over gold evidence labels and answer spans.
**When to use:** Every run, always, regardless of API key or judge availability (D-50).

**Example (sketch):**
```python
# src/lancet_eval/metrics.py
from typing import NamedTuple

class RetrievalMetrics(NamedTuple):
    recall_at_4: float
    recall_at_10: float
    hits_at_4: int
    hits_at_10: int
    mrr_at_10: float
    ndcg_at_4: float
    ndcg_at_10: float

def compute_recall(question: dict, response: RagAnswer, *, gold_facts: list[str], 
                   k: int = 4, matching_rule: str = "containment") -> tuple[int, int]:
    """
    Returns (hits, gold_denominator) for recall@k.
    - hits: # of distinct gold facts matched in top-k citations
    - gold_denominator: total # of gold facts (always ≥2 for answerable questions)
    - Excludes null_query items entirely from denominator (Critical Failure Mode #1)
    """
    if not gold_facts:
        return (0, 0)  # null query; excluded from retrieval metrics
    
    matched_facts = set()
    for citation in response.structured_citations[:k]:
        for fact in gold_facts:
            if matching_rule == "containment":
                # Replicate reference: fact is substring (whitespace-normalised) of citation.excerpt
                if fact.replace(" ", "") in citation.excerpt.replace(" ", ""):
                    matched_facts.add(id(fact))  # avoid double-counting
    
    return (len(matched_facts), len(gold_facts))

def compute_em_f1(prediction: str, gold_answer: str) -> tuple[float, float]:
    """SQuAD v1.1 normalisation: lowercase, strip punctuation/articles, collapse whitespace."""
    import re
    def normalize(s: str) -> str:
        s = s.lower()
        s = re.sub(r'\b(a|an|the)\b', ' ', s)
        s = re.sub(r'[.!?;,]', '', s)
        s = ' '.join(s.split())
        return s
    
    pred_tokens = set(normalize(prediction).split())
    gold_tokens = set(normalize(gold_answer).split())
    
    if not pred_tokens or not gold_tokens:
        em = 1.0 if pred_tokens == gold_tokens else 0.0
        f1 = 1.0 if pred_tokens == gold_tokens else 0.0
        return (em, f1)
    
    common = pred_tokens & gold_tokens
    precision = len(common) / len(pred_tokens) if pred_tokens else 0.0
    recall = len(common) / len(gold_tokens) if gold_tokens else 0.0
    f1 = 2 * precision * recall / (precision + recall) if (precision + recall) > 0 else 0.0
    em = 1.0 if pred_tokens == gold_tokens else 0.0
    
    return (em, f1)
```

### Pattern 3: Dimension Result with Cross-Field Validation (D-51)

**What:** A Pydantic model that makes it impossible to construct a fabricated score.
**When to use:** Every dimension result; the type system enforces D-51 at construction time.

```python
from pydantic import BaseModel, Field, model_validator
from typing import Literal, Self

class DimensionResult(BaseModel):
    model_config = ConfigDict(extra="forbid")  # typo-proof
```

### Anti-Patterns to Avoid

- **Custom JSON serialization instead of `model_dump_json()`:** Pydantic's method handles `Path`, `datetime`, `float('nan')` correctly; `json.dumps(m.model_dump())` fails on these types. [Source: 06.3-AI-SPEC.md §3 Pitfall 9]
- **Relative paths instead of `Path(__file__).parent / "templates"`:** `uv run --project eval` changes cwd to repo root, not `eval/`. Anchor packaged assets to the module. [Source: 06.3-AI-SPEC.md §3 Pitfall 3]
- **Omitting `encoding="utf-8"` on file I/O:** Windows defaults to ANSI codepage (measured `cp950` on test machine); MultiHop-RAG articles have curly quotes, em-dashes, accented names — same corpus yields different EM/F1 on Windows vs Linux. Add `newline="\n"` on writes to prevent CRLF churn. [Source: 06.3-AI-SPEC.md §3 Pitfall 2; D-68 Windows/WSL verification requirement]
- **Matching evidence at article level and reporting as if it were the benchmark's fact-level metric:** Article-level matching counts any chunk from a gold article as a hit even when that chunk contains none of the gold fact — inflates recall. Must label as "looser criterion, not comparable to baselines" if used. [Source: 06.3-AI-SPEC.md §1b Dimension: Evidence-match rule fidelity]
- **Scoring `null_query` items with the same EM/F1 as answerable questions:** Gold is the literal string `"Insufficient information."` for all 301. Correct refusals never match, while hallucinated answers can accidentally share a token and score higher — the harness rewards fabrication on the benchmark's hallucination probe. [Source: 06.3-AI-SPEC.md §1b Dimension: Abstention on unanswerable questions, Critical Failure Mode #2]
- **Async concurrency via asyncio/aiohttp to speed up the judge:** OpenRouter free-tier is **20 requests/minute** server-side, per account. Client concurrency cannot move a server-side ceiling. Synchronous `httpx` + `ThreadPoolExecutor(max_workers=1)` is correct; config knob allows future paid tier changes. [Source: 06.3-AI-SPEC.md §4 Async-First Design]
- **Mixing the judge's own prompts between runs:** Any prompt edit is a `judge_prompt_version` bump that goes into the cache key. Two runs with different versions are **explicitly not comparable**; the report must state so. Forgetting the bump means stale cached verdicts on edited prompts. [Source: 06.3-AI-SPEC.md §4b Prompt Engineering Discipline]

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| SSE frame parsing from raw bytes | Custom regex/state machine for `event:`, `data:`, `id:` fields | `httpx-sse` + `httpx.Client.stream()` | Handles BOM, multi-line `data:` values, edge cases; `httpx-sse` is 4-file library, not a framework |
| Evidence truncation for the judge | Manual sliding-window slicing | `PER_PASSAGE_CHAR_BUDGET + EVIDENCE_CHAR_BUDGET` scheme + explicit `[TRUNCATED: N further passages omitted]` marker | Deterministic across platforms, hash-stable, budget-change detection via cache-key invalidation |
| Retry logic on HTTP 429 + `Retry-After` header | Exponential backoff from scratch | `tenacity.retry(wait=wait_combine(wait_exception(parse_retry_after), wait_random(0, 2)))` | Honors server directives, adds jitter, prevents re-collision; `tenacity>=9.1` required for `wait_exception` |
| Configuration from TOML + environment | Manual dict merging | `pydantic-settings.BaseSettings` + `pydantic.ConfigDict(toml_file="config.toml")` | One source of truth, env overrides precedence, validation at load time |
| CLI sub-commands and help text | argparse or manual sys.argv parsing | `typer` (wrapper on Click) | Auto-generated `--help`, type hints become argument parsers, integrates with `rich` |
| Structured output validation from an LLM | Prompt hacks ("you must output valid JSON") | `pydantic.BaseModel.model_validate_json()` + bounded re-ask on `ValidationError` | Pydantic gives precise field-path error messages; re-ask feeds errors back to the model; re-ask budget (1 attempt) is enough for a free-tier model at `temperature=0` |
| JSON report generation | String templates | `jinja2` with `StrictUndefined` | Loops, conditionals, filters; typo in a variable name raises `UndefinedError`, not silent `None` |

**Key insight:** The harness's only externally-dependent LLM call is the judge (and only for groundedness/faithfulness). Everything else — SSE parsing, metrics, retry logic, config, CLI, templating — is either a standard library or a thin, boring wrapper around one (httpx-sse, tenacity, typer are all <1MB and have <10 transitive dependencies). This keeps the lockfile lean and keeps `score --no-judge` genuinely free of external dependencies.

## Common Pitfalls

### Pitfall 1: httpx Timeouts Are Per-Operation, Not Per-Request

**What goes wrong:** A multi-hop RAG query can exceed the default 5-second timeout on the *first read chunk*, even if data is still flowing. The harness hangs on a stalled frame stream forever because `read` timeout is *inactivity* between chunks, not a total budget.

**Why it happens:** httpx applies timeouts per operation (connect, read, write, pool), not as one request budget. A gateway that keeps trickling `node_started` frames never resets the inactivity timer.

**How to avoid:** 
- Pass `httpx.Timeout(connect=10.0, read=300.0, write=30.0, pool=10.0)` to every query call — read timeout covers multi-hop latency.
- Implement a **wall-clock deadline** inside the `iter_sse()` loop itself: `if time.monotonic() - started > deadline_s: raise StreamDeadlineExceeded`. This is the only total budget that exists.
- Set timeout on the `connect_sse` call, not just the client, since the judge's POST has a shorter safe timeout.

**Warning signs:** A query that completes in 30s locally but hangs in a thread; a journal that stops mid-run with no exception logged.

### Pitfall 2: Windows ANSI Codepage Silently Breaks UTF-8 Evidence Matching

**What goes wrong:** Same `eval/corpora/multihop_rag/questions.sample.jsonl` and articles yield different EM/F1 scores on Windows vs Linux because MultiHop-RAG has curly quotes, em-dashes, accented names. The computation is deterministic *within* the OS but not *across*.

**Why it happens:** `locale.getpreferredencoding()` returns `cp950` on Windows 11 (or similar ANSI codepage). Every bare `open(path)` / `Path.read_text()` decodes with that codepage. D-68 requires verification on Windows *native* and Linux/WSL; they will fail to match if encoding is not pinned.

**How to avoid:** 
- Pass `encoding="utf-8"` at **every** `open()`, `Path.read_text()`, `Path.write_text()` call.
- Pass `newline="\n"` on all writes so Python doesn't translate `\n` to `\r\n` on Windows (which would churn on commit diffs).
- Export `PYTHONUTF8=1` in the harness entry point or test runner so `getpreferredencoding()` flips to `utf-8`.
- Enable ruff's `PLW1514` (unspecified-encoding) rule with `preview = true` in `[tool.ruff]` — this is a linter that catches every bare `open()` without `encoding=`. [Verified: PLW1514 is preview-only and requires `preview = true` in ruff config]

**Warning signs:** D-68 verification failure: "EM/F1 differ between Windows and Linux on identical corpus"; locale-aware sorting or collation in the metrics.

### Pitfall 3: `uv run` CWD Is Repo Root, Not `eval/`

**What goes wrong:** Every relative path — `templates/report.md.j2`, `corpora/multihop_rag.toml`, `runs/` — resolves against the repo root, not `eval/`. Seeding reads questions from `corpora/multihop_rag/questions.sample.jsonl` which doesn't exist at that path; you're measuring the wrong corpus.

**Why it happens:** `uv run --project eval` executes with cwd = repo root (verified: `os.getcwd()` prints parent directory). The project's working directory is not the `eval/` subdirectory.

**How to avoid:** 
- Anchor packaged assets (templates) to the module: `Path(__file__).parent / "templates" / "report.md.j2"`.
- Make every data path an explicit configuration value, `.resolve()`d to an absolute path at startup: `config.corpus_dir.resolve()`.
- Never assume relative paths work from `uv run`.

**Warning signs:** A run that fails with "file not found: templates/report.md.j2"; a corpus directory that works in one shell but not another.

### Pitfall 4: Judge Cache Key Must Include `judge_prompt_version`

**What goes wrong:** The judge prompt is edited (wording, scale anchors, formatting). A new run reuses old cached verdicts because the cache key is `sha256(question, answer, evidence)` — the prompt change is invisible.

**Why it happens:** The cache key must capture everything that determines the verdict. An edited prompt produces different verdicts on the same evidence; forgetting the version bump means silently wrong numbers.

**How to avoid:** 
- The cache key is `sha256(judge_prompt_version, judge_model, question, answer, evidence_truncated)`.
- `judge_prompt_version` is a config value, bumped on **any** prompt edit (wording, scale, ordering, whitespace).
- Record the version in run metadata and the report; two runs with different versions are **explicitly not comparable**.

**Warning signs:** A trajectory showing a metric move after a judge-prompt tweak; cached verdicts from an old prompt being reused on the new one.

### Pitfall 5: `node_failed` Is Not Terminal and Is Not a Run Failure

**What goes wrong:** A `node_failed` frame arrives mid-stream. The harness blanket-raises, discards the rest of the stream, and records the run as failed. The workflow would have recovered and succeeded anyway.

**Why it happens:** `node_failed` carries a `retryable` flag; the workflow can recover and still emit `workflow_completed{success: true}`. Raising on every `node_failed` throws away valid results and biases every metric downward.

**How to avoid:** 
- Record `node_failed` frames into the journal as diagnostics (not as run failures).
- Take the verdict from the terminal event (`workflow_completed.success`) alone.
- The contract assertion is: a terminal event is present and ≤1 `final_answer`, not that `node_failed` is absent.

**Warning signs:** A run with low metric values from a journal full of `outcome="error"` records; a metric improving after removing a `node_failed` early-raise.

### Pitfall 6: The `/rag/query` DTO Still Rejects Unknown Fields

**What goes wrong:** The harness sends `disable_graph_context=True` but the gateway rejects it with HTTP 400 because the field is misspelled (e.g., `disableGraphContext`, `disable_graph`) or wrong-typed (a string instead of bool).

**Why it happens:** `gateway/main.go:539` calls `dec.DisallowUnknownFields()`. The struct `ragQueryRequestBody` recognizes exactly `query`, `session_id`, `filter`, `allow_model_only`, and `disable_graph_context` — anything else is rejected. [VERIFIED: gateway/main.go lines 522–539]

**How to avoid:** 
- The exact field name is `disable_graph_context` (underscore-separated, lowercase, bool type).
- Use preflight (D-64) to probe the field by name — not to detect "does it exist" (it does) but to catch harness/gateway version skew.
- Test both arms (`graph-on` and `graph-off`) in the test suite to catch a typo early.

**Warning signs:** A preflight that succeeds but the first query fails with "unknown field: disable_graph_context" (because the version on disk is older and doesn't know about it).

### Pitfall 7: Chunk Boundaries Produce Systematic Evidence-Matching Bias

**What goes wrong:** A gold fact is 161 chars (median) while `defaultChunkOverlap = 50`. A fact straddling two 500-char chunks is contained in **neither** chunk. Containment-based matching records a miss on a retrieval that was in fact perfect — recall is **systematically deflated**, not randomly wrong.

**Why it happens:** MultiHop-RAG facts are median 161 chars (p90 257, max 538); chunking is 500 chars with 50-char overlap. Geometry.

**How to avoid:** This is a **planner input** that must be decided before scoring:
- **(Preferred) Raise chunk overlap above 538** for the eval corpus only: rebuild the eval LanceDB with `chunk_overlap = 600` so no fact straddles a boundary. Document this in the report.
- **(Fallback) Relax matching to longest-common-substring or normalized sub-span** instead of exact containment. Documented as a non-standard metric.
- **(Last resort) Fall back to article-level matching** and label explicitly as "looser criterion, not comparable to published baselines."
- If the chosen rule leaves any residual bias, state it plainly in the report next to the number.

**Warning signs:** A recall number that looks low even for a hard task; a manual spot-check of 10 scored questions finding matches the metric missed.

```python
def score_question(journal_record: dict, gold_labels: dict) -> dict:
    """
    Scores ONE question's response against its gold labels.
    Excludes null_query items from retrieval metrics entirely (Critical Failure Mode #1).
    """
    question_id = journal_record["question_id"]
    if journal_record["question_type"] == "null_query":
        # Only abstention metric applies
        has_no_evidence = len(journal_record["answer"]["structured_citations"]) == 0
        has_no_evidence_notice = any(n["typed_code"] == 1 for n in journal_record["answer"]["notices"])
        abstained_correctly = has_no_evidence and has_no_evidence_notice
        return {
            "question_id": question_id,
            "recall_at_4": None,  # excluded from retrieval denominator
            "abstention_rate": 1.0 if abstained_correctly else 0.0,
            "notes": "null_query"
        }
    
    # Answerable question: all deterministic metrics apply
    gold_facts = gold_labels[question_id]["evidence"]
    gold_answer = gold_labels[question_id]["answer"]
    
    # Recall@k
    hits_at_4 = sum(1 for fact in gold_facts 
                    if any(fact.replace(" ", "") in c["excerpt"].replace(" ", "")
                           for c in journal_record["answer"]["structured_citations"][:4]))
    recall_at_4 = hits_at_4 / len(gold_facts)
    
    # EM/F1
    em, f1 = compute_em_f1(journal_record["answer"]["answer"], gold_answer)
    
    return {
        "question_id": question_id,
        "recall_at_4": recall_at_4,
        "f1": f1,
        "notes": "answerable"
    }
```

### Example 2: Judge Prompt Versioning in Cache Key

```python
# src/lancet_eval/judge.py — excerpt
def judge_once(question: str, answer: str, evidence: str, *, 
               judge_model: str, judge_prompt_version: str) -> JudgeVerdict | None:
    """Judge a single (question, answer, evidence) triple. Caches by prompt version."""
    
    # Hash must include prompt version so cache invalidates on any edit
    evidence_truncated = truncate_evidence(evidence)
    cache_key = hashlib.sha256(
        f"{judge_prompt_version}|{judge_model}|{question}|{answer}|{evidence_truncated}".encode()
    ).hexdigest()
    
    # Check cache
    if cache_key in judge_cache:
        return judge_cache[cache_key]
    
    # Call judge
    messages = [
        {"role": "system", "content": JUDGE_SYSTEM_PROMPT_V1},  # v1 is versioned in the prompt text
        {"role": "user", "content": f"QUESTION:\n{question}\n\nANSWER:\n{answer}\n\nEVIDENCE:\n{evidence_truncated}"}
    ]
    
    raw = judge_post(judge_model, messages)  # raw OpenRouter response (with potential JSON fence)
    raw_clean = raw.lstrip("```json").rstrip("```").strip()  # strip markdown fences
    
    try:
        verdict = JudgeVerdict.model_validate_json(raw_clean)
        judge_cache[cache_key] = verdict  # cache the verdict
        return verdict
    except ValidationError as e:
        # One bounded re-ask (D-52)
        messages.append({"role": "assistant", "content": raw})
        messages.append({"role": "user", "content": f"Validation errors:\n{e.errors(include_url=False)}\n\nReply with ONLY the corrected JSON."})
        raw_2 = judge_post(judge_model, messages)
        try:
            verdict = JudgeVerdict.model_validate_json(raw_2.lstrip("```json").rstrip("```"))
            judge_cache[cache_key] = verdict
            return verdict
        except ValidationError:
            return None  # Give up; become DimensionResult(status='error')

def save_judge_cache():
    """Persist cache as plain-text, auditable JSON (D-52)."""
    cache_path = Path("runs") / "latest" / "judge_cache.json"
    # Sort keys for consistent diffs, indent for readability
    with cache_path.open("w", encoding="utf-8", newline="\n") as f:
        json.dump(judge_cache, f, indent=2, sort_keys=True, ensure_ascii=False)
```

## State of the Art

The v1 evaluation approach is an offline advisory harness with split metrics (deterministic / LLM-judged). This trades real-time adaptability for reproducibility: every number is traceable to a committed seed, a pinned model, and a specific index state. Alternative state-of-the-art patterns:

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| Interactive online RAGAS scoring via LLM for all metrics (recall, precision included) | Deterministic IR metrics (no LLM, no API key) for speed/cost; LLM judge only for judgments | 2024 → evaluation maturity shift in RAG benchmarking | Recall@k is now recomputable offline in seconds; judge uncertainty is explicit (6 judge errors recorded in report) |

| Cached judge results via embedding distance | Cached by SHA-256 hash of inputs (transparent, auditable) | 2024 → AI safety shift in evaluation | Cache is plain-text JSON, inspectable by humans; near-miss false-positives eliminated |

**Deprecated/outdated:**
- Semantic caching via embedding model (trades one LLM call for another, no net savings)
- Framework-driven evaluation (RAGAS, DeepEval) — adds overhead for a deterministic metrics tier that is straightforward to hand-roll (~120 lines)
- Per-model report output (one headline metric) — D-60 requires per-corpus splits and per-ablation-arm transparency

## Open Questions (RESOLVED)

*All three questions were closed during planning of Phase 06.3. Each carries its resolution and the plan that owns it. No question remains open; nothing here blocks execution.*

1. **Schema override mechanism in Atlas (D-57)**
   - What we know: `gateway/atlas.hcl` uses a simple `url` variable pointing to PostgreSQL; the plan says "point the eval `search_path`/schema at `lancet_eval`."
   - What's unclear: Does `atlas migrate` support a `--schema` flag or env var override, or must a separate `.hcl` file be created for the eval schema?
   - Recommendation: Verify Atlas CLI supports `--dir` / `--schema` before Wave 1; if not, create `gateway/atlas-eval.hcl` with identical DDL but different schema name, or use `psql` to create the schema manually before `atlas migrate`.
   - **RESOLVED — see `06.3-04-PLAN.md`, Task 1 ("Isolate the eval store — Atlas eval schema and the `LANCET_ENV` overlay").** No second `.hcl` file and no gateway change: the eval environment reuses the *existing* Atlas migration source `file://db/schema.hcl` and is pointed at the isolated schema by appending `search_path=lancet_eval` to the DSN carried in `LANCET_GATEWAY__DATABASE_URL`. Because the exact Atlas CLI surface could not be confirmed offline, the plan does not assume it — the branch choice (env/flag override vs. creating the schema with `psql` before `atlas migrate`) is settled at execution time by a **live precondition-probe**, and Task 1's `<human-check>` requires the operator to record the branch actually taken plus proof that a row landed in `lancet_eval.documents` while `public.documents` did not grow. This eliminates the drift risk a duplicated DDL file would have introduced (threat `T-06.3-15`).

2. **Chunk overlap parameterization for eval corpus (D-55 + Pitfall 7)**
   - What we know: Default chunking is `size=500, overlap=50`; gold facts are median 161 chars, so boundary-straddling facts are unmatchable by exact containment.
   - What's unclear: Can LanceDB ingestion parameters be overridden per run, or is chunking a one-time-at-seeding decision?
   - Recommendation: Decide (before scoring) whether to (a) raise eval corpus overlap to 538+, (b) relax matching to sub-span, or (c) fall back to article-level; this choice goes into the report and makes the metric interpretation transparent.
   - **RESOLVED — see `06.3-03-PLAN.md` (the `boundary_attributable_misses` diagnostic), with the seeding half in `06.3-04-PLAN.md` and the publication half in `06.3-07-PLAN.md`.** None of options (a), (b) or (c) was taken. The choice is **measure-and-report, not re-chunk**: the eval corpus is seeded at the *shipped* chunking defaults — `06.3-04-PLAN.md` requires the seeder to send no `chunk_size` and no `chunk_overlap` form field — so the number published describes the system as it ships rather than a tuned variant. A gold fact straddling a chunk boundary is scored as a MISS under the single shared containment rule, and is *additionally* counted in the `boundary_attributable_misses` diagnostic; adjacent chunks are never concatenated or stitched before matching, and a citation arriving with `is_truncated == true` is recorded as undecidable rather than as a hit or a miss. `06.3-07-PLAN.md` then requires the report to state the matching rule in one sentence and print the boundary-attributable-miss and undecidable-citation counts next to the retrieval numbers, which is what delivers the transparency this question asked for.

3. **Structured-output validation for D-63 Rust test**
   - What we know: `engine/src/generation/openrouter.rs:425-434` has a preflight check for the shipped model's JSON schema support.
   - What's unclear: What is the exact request shape / response format for testing `json_object` response format on `dots-studio/dots-3-note-preview:free`?
   - Recommendation: Cargo test this with a real OpenRouterGenerator + mock HTTP server; do not assume free-tier models consistently honor `response_format`.
   - **RESOLVED — see `06.3-02-PLAN.md`, Task 1 (`cargo test` implementation in `engine/src/generation/tests.rs`).** The recommendation was adopted and made concrete: a real `OpenRouterGenerator` drives `check_supported_parameters()` against a local mock HTTP server bound to `127.0.0.1:0`, with no live network and no API key, over three models-metadata payloads — one advertising `response_format` / `json_schema` (passes), one listing the shipped model with none of `response_format` / `json_schema` / `structured_outputs` (fails with `GenerationErrorKind::SupportedParameters`), and one omitting the shipped model entirely (fails naming the missing id). Crucially the test does **not** hard-code the model id: it parses `config/config.toml`'s `[openrouter] generation_model`, so the shipped pin and the tested model cannot silently diverge — which is the drift that WARN-NEW-01 named. The exact wire shape is therefore pinned by the committed test rather than by an assumption about free-tier behaviour.
