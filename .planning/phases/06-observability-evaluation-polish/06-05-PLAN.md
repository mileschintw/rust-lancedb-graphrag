## Phase User Story

**As a** client of Lancet's `/rag/query` endpoint, **I want to** receive an honest, machine-readable
answer even when the graph is unavailable, one retrieval path fails, evidence is absent, or the
model's citations do not resolve, **so that** I can tell a degraded answer from a healthy one — and a
grounded answer from a model-only one — without parsing prose.

> Planner-derived from the phase's only user-facing outcome (RAG-03 degraded mode). This plan is a
> pure refactor and delivers no slice of that story directly; it completes the Go half of the
> module-graph stage (D-81/D-82).

<objective>
Extract the gateway's gRPC engine client into `gateway/internal/engineclient`, completing D-82's
four-package split.

Purpose: research §2 measured this as the high-churn half — `app{` appears as a composite literal 50
times in `gateway/main_test.go` and `IngestOutcome` 24 times, so moving the engine interface out of
`package main` forces roughly 74 mechanical test edits. Research's explicit recommendation is to do it
alone so the diff stays reviewable. Plan 06-04 took the low-churn half.
Output: `internal/engineclient` compiling and imported, `main.go` free of engine-client declarations,
and 67 Go tests still green.
</objective>

<scope_rationale>
Two tasks, split on the churn line rather than on the code: task 1 creates the package and rewires
production code; task 2 is the mechanical test-file migration. They are separate because the second
one is roughly 74 near-identical edits, and interleaving it with the design decisions in the first
makes both unreviewable — which is the same reasoning that put this plan on its own in the first
place.

`internal/store` and `internal/ragapi` are deliberately not created. D-82 names exactly four packages
and 06-04 plus this plan deliver exactly those four. The `app` struct, the four handlers, the document
store and the reconciler stay in `package main`; extracting them is discretionary scope the decision
does not ask for and would add churn on top of the 74 edits already budgeted here.

`go-guidelines.md` applies and the target is Go **1.25** (`gateway/go.mod:3` declares `go 1.25.0`;
the installed toolchain is newer). Go 1.26 features are forbidden even though they would compile — in
particular the pointer-to-expression form of `new` and the generic `errors` type assertion. The
existing code uses the Go 1.25 error type assertion and must keep using it.

Shell note: every `<automated>` gate in this phase is POSIX shell, matching `.planning/config.json`'s
`test_command`. Run them through the Bash tool, not PowerShell.
</scope_rationale>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Gateway → engine gRPC connection | Request bodies and uploaded document bytes cross this hop. The connection is dialed with insecure transport credentials; that is a recorded, accepted backlog item, not a defect this plan may close. |
| Engine error → HTTP client | Pre-stream engine errors carry gRPC status and trailer metadata that become the HTTP status and the `X-Lancet-Error-Kind` header; the relocated error type is what preserves that identity. |
| `package main` → `internal/engineclient` | Previously unexported client identifiers become exported across a package boundary. |
