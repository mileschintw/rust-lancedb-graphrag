## Phase User Story

**As a** client of Lancet's `/rag/query` endpoint, **I want to** receive an honest, machine-readable
answer even when the graph is unavailable, one retrieval path fails, evidence is absent, or the
model's citations do not resolve, **so that** I can tell a degraded answer from a healthy one — and a
grounded answer from a model-only one — without parsing prose.

> Planner-derived from the phase's only user-facing outcome (RAG-03 degraded mode). This plan is a
> pure refactor and delivers no slice of that story directly; it makes the story's implementation
> land on a settled foundation (D-81).

<objective>
Close the second half of DEBT-P3-MODULE-GRAPH's production-code move: relocate the ingestion pipeline
and the entire gRPC service implementation out of `engine/src/main.rs` and into the `engine` library
crate, without changing a single observable behavior.

Purpose: D-80's acceptance criterion is "binary imports shared modules from library crate", and
research open question 3 resolves how far it goes — the ingestion worker moves too, because Phase 6.1's
rebuild trigger and Phase 6.2's ingestion spans both attach to it and leaving it behind re-creates the
debt one phase later. Research §1 calls the `LancetServiceImpl` move "the large step; do it alone",
which is why it is one task here rather than one line in a mixed plan.
Output: `engine::ingest` and `engine::service` declared by the library, `main.rs` importing both, and
the per-target test invariant re-verified after each move.
</objective>

<scope_rationale>
Two relocation steps, ordered leaf-ward. `engine::ingest` goes first because `LancetServiceImpl` holds
an `Arc<dyn EmbeddingProvider>`, constructs `IngestionJob`s and reads `IngestionStatus` — the service
depends on ingestion, not the reverse, so moving ingestion first means the second task never has to
reach back into the binary. Test-root rehoming (research's step 4, "the one that moves the counts") is
plan 06-03 and is deliberately not mixed in here: this plan must leave the five per-target counts
unmoved so that when 06-03 does move them, the movement is attributable to exactly one commit.

Shell note: every `<automated>` gate in this phase is POSIX shell, matching `.planning/config.json`'s
`test_command`. Run them through the Bash tool, not PowerShell.
</scope_rationale>
