## Phase User Story

**As a** client of Lancet's `/rag/query` endpoint, **I want to** receive an honest, machine-readable
answer even when the graph is unavailable, one retrieval path fails, evidence is absent, or the
model's citations do not resolve, **so that** I can tell a degraded answer from a healthy one — and a
grounded answer from a model-only one — without parsing prose.

> This plan delivers the "the model's citations did not resolve and I can still trust what the
> response claims" slice — the last of the four RAG-03 clauses.

<objective>
Replace the fail-closed citation-resolution branch with a local normalize-then-strip repair pass, make
the answer basis the result of a conservative reconciliation rather than a copy of the model's
self-report, and add the evidence-over-priors precedence instruction to the prompt.

Purpose: DEBT-RAG-03 today ends a run with an error when the model's cited identifiers do not all
resolve. D-14 converts that into a repair: near-miss markers are normalized locally, anything still
unresolved is stripped from the answer text and from both citation lists, notices record each outcome,
and the basis downgrades if the answer loses all grounding. D-18 makes the basis honest in the general
case, and D-17 states the precedence principle in the prompt — as text only, because D-19 keeps the
structured-output schema frozen.
Output: a new deterministic citations module, the repair wired at the single integration point, the
reconciliation at the single seam where the basis is set, and the precedence sentence.
</objective>

<scope_rationale>
Three tasks: the pure module and its configuration key, then the reconciliation plus the prompt
sentence, then the integration at the fail-closed branch. The pure module comes first because it is
testable in isolation against a fixed evidence set, which is where the boundary rules — what counts as
a near miss, what a tie does — are cheapest to pin down.

**The reconciliation seam comes before the repair integration, deliberately.** Total citation loss has
to downgrade the answer basis, and the basis has exactly one setting site; if the repair integration
landed first it would either have to create that site itself or write a second one. Establishing the
seam in task 2 means task 3 has something to call and no structural choice left to make. That ordering
is what keeps "exactly one site assigns the answer basis" a checkable criterion rather than a
conditional one.

The reconciliation and the prompt sentence share a task because they are the two halves of one claim:
the prompt tells the model that evidence outranks its priors, and the reconciliation makes sure the
engine's view of provenance outranks the model's self-report. Splitting them would put the statement
and its enforcement in different commits.

**Test-count gate protocol.** `scripts/engine-test-targets.sh` asserts *fixed measured* counts, and
this plan adds tests to two targets — the library target and the startup-configuration integration
target — so its current expected values stop holding the moment it lands. That is the design: the gate
exists to make a count change deliberate, not impossible. Run the enumeration, confirm each delta is
exactly the tests the task added, write the newly measured values into the script's assertions **in
the same commit as the tests that moved them**, and record the before and after rows verbatim in the
summary. Never lower an expected value to make the gate pass, and never delete an assertion: the
expected value must equal the measured value and the delta must be explainable test by test. A delta
the task cannot account for is a finding to report, not a number to overwrite. The script's
*structure* — one row per target, a named failure message per assertion — is never edited; only the
expected values move. Task 1 updates the startup-configuration target, from the 13 plan 06-10 left it
at to 17. All three tasks add library tests, so the library target is updated once, at the end of
Task 3, and that single update accounts for every library test this plan added.

This continues the tracer-first shape started in 06-08 and expanded by 06-09 and 06-10. Each task
leaves a user able to get something they could not before rather than laying foundation.

No new dependency. The Unicode normalization, case-folding and segmentation crates were added by plan
03-01 and are already declared; the repair is deliberately simple enough that they cover it. Proposing
a new crate here would be a signal the plan has drifted outside Phase 6's scope, and would require a
package-legitimacy checkpoint that 06-RESEARCH.md's audit records as unnecessary for this phase.

Shell note: every `<automated>` gate in this phase is POSIX shell, matching `.planning/config.json`'s
`test_command`. Run them through the Bash tool, not PowerShell.
</scope_rationale>
