## Phase User Story

**As a** client of Lancet's `/rag/query` endpoint, **I want to** receive an honest, machine-readable
answer even when the graph is unavailable, one retrieval path fails, evidence is absent, or the
model's citations do not resolve, **so that** I can tell a degraded answer from a healthy one — and a
grounded answer from a model-only one — without parsing prose.

> Planner-derived from the phase's only user-facing outcome (RAG-03 degraded mode). This plan is a
> pure refactor and delivers no slice of that story directly; it is the last step that makes the
> story's implementation testable from the library crate (D-81).

<objective>
Rehome the binary test root into the library target and reduce `engine/src/main.rs` to startup wiring,
completing DEBT-P3-MODULE-GRAPH.

Purpose: research §1(c) records the hard blocker — `engine/src/tests.rs` opens with `use super::*`,
binding it to whatever `main.rs` happens to have in scope, and `workflow_phase5_production.rs`
resolves `crate::…` against the binary crate. Plans 06-01 and 06-02 moved the items those roots name;
this is the step that lets the 128 cases follow them. Research calls it "the one that moves the
counts", so it is deliberately alone in its own commit and its own wave.
Output: `engine/src/tests.rs` declared from `lib.rs`, `main.rs` with zero module declarations, and a
per-target enumeration showing 261 / 0 / 18 / 0 / 9 = 288.
</objective>

because the first one is where a compile failure is expected and iterated on (roughly 119 test
