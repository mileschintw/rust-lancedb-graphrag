## Phase User Story

**As a** client of Lancet's `/rag/query` endpoint, **I want to** receive an honest, machine-readable
answer even when the graph is unavailable, one retrieval path fails, evidence is absent, or the
model's citations do not resolve, **so that** I can tell a degraded answer from a healthy one — and a
grounded answer from a model-only one — without parsing prose.

> This plan delivers the "evidence is absent and I still want an answer — clearly labelled as
> ungrounded" slice, which is the core of DEBT-RAG-01.

<objective>
Support model-only answers as an explicit, per-request, default-off opt-in: a configuration default, a
request override, both grounding guards made conditional, both zero-evidence gates bypassed, and an
answer that says plainly it was not grounded.

Purpose: D-10 records the user's reasoning as data — retrieval legitimately returns nothing and an
answer is still wanted — while keeping the load-bearing principle that when retrieved data contradicts
model knowledge, the retrieved data wins. The opt-in is the deliberate first step toward per-question
routing, which is itself deferred. Two research findings shape the plan: there are two grounding
guards, not one, and lifting only the first is the most likely cause of a plan that looks complete and
fails at runtime; and there are two zero-evidence gates, of which one has a second disjunct the other
lacks.
Output: the configuration key with fail-closed parsing, the resolved flag threaded to both guard
sites, and the model-only answer contract proven by test.
</objective>

<scope_rationale>
Three tasks, ordered so each one's output is the next one's input: resolve the flag, then make
validation honour it, then make dispatch honour it. Splitting differently would mean writing a guard
against a flag that does not yet reach it.

This continues the tracer-first shape: 06-08 proved the request-to-response spine, 06-09 expanded it to
retrieval degradation, and this plan expands it to the zero-evidence case. Each task leaves the system
able to do something it could not before rather than laying foundation.

Task 2 is the one research warns about twice. The AI-SPEC and the decision record both name only the
answer-basis guard; the second guard, which rejects an empty cited-evidence list, sits a few lines
below it and rejects every model-only answer because a model-only answer carries zero citations by
contract. Both must become conditional or the feature appears to land and fails on first use.

Task 3 is the one with the asymmetry: the production dispatch gate has a second disjunct that the
tracer gate does not. Bypassing only the notice test leaves an opted-in query that reached zero
candidates without a zero-evidence notice still short-circuiting.

Shell note: every `<automated>` gate in this phase is POSIX shell, matching `.planning/config.json`'s
`test_command`. Run them through the Bash tool, not PowerShell.
</scope_rationale>
