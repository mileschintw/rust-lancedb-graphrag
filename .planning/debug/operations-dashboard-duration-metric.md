## Resolution

root_cause: "In `deploy/grafana/dashboard_gen/main.go:37-41`, Panel 1 ('RAG Query Duration') was constructed with PromQL expression `sum by (outcome) (rate(lancet_rag_query_duration_milliseconds_count[5m]))`. The `_count` suffix measures the total count of observations; applying `rate()` over `_count` computes query throughput (queries/sec) rather than latency distribution (duration in ms). Additionally, `telemetry_metrics.rs` unit tests only checked stem containment, allowing this semantic bug to slip through."
fix: "Update `deploy/grafana/dashboard_gen/main.go` Panel 1 target expression to `histogram_quantile(0.95, sum(rate(lancet_rag_query_duration_milliseconds_bucket[5m])) by (le, outcome))` with LegendFormat `p95 - {{outcome}}` (matching Panel 9), re-run `scripts/generate-dashboards.sh` to update `deploy/grafana/dashboards/lancet-rag-operations.json`, and optionally strengthen `engine/src/tests/telemetry_metrics.rs` to verify that duration histogram panels query `_bucket` / `histogram_quantile`."
verification: "Run `scripts/generate-dashboards.sh` to ensure dashboard JSON is regenerated byte-identically, run `cargo test --manifest-path engine/Cargo.toml --test telemetry_metrics` and `scripts/verify-collector-prom-export.sh`."
